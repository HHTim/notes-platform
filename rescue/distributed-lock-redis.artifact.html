分散式鎖與 Redis 四種擺法

分散式鎖 / REDIS

一把鑰匙，
很多台機器在搶

「分散式」就是同一套程式同時跑在好幾台機器上。機器一多，原本好好的鎖就失效了。這頁講為什麼，以及 Redis 的四種擺法差在哪。

先講「鎖」

鎖就是廁所門閂

一個人進去、把門閂上，其他人只能在外面等。等他出來、門閂打開，下一個才進得去。

程式裡也一樣：同一份資料（例如帳戶餘額）同一時間只准一個人改，避免兩個人同時扣款、扣成一次。

問題來了

變成三台機器，門閂就管不到別人了

為了撐流量，同一套程式會複製成好幾台一起跑。可是每台機器的記憶體是各自獨立的——A 台舉的旗子，B 台看不到。

解法

分散式鎖 = 大家去同一個櫃檯拿鑰匙

把鎖搬出去，放到一個所有機器都看得到的地方。誰先拿到那把唯一的鑰匙，誰才能動手。

Redis 常被拿來當這個櫃檯，因為它夠快（毫秒等級）而且大家本來就有裝。

實際上怎麼寫

一行指令就是一把鎖

SET 訂單123 我的名字 NX EX 30

NX 的意思是「這個名字目前沒人用，才寫得進去」——所以第一個寫進去的人贏，其他人會收到失敗。EX 30 是「30 秒後這筆自動消失」。

做完事情就把它刪掉，換下一個人。

三個常見的坑

1

忘了設過期時間。拿到鎖的機器當場斷電，鎖永遠留在那裡，後面全部卡死。所以 EX 一定要寫。

2

刪到別人的鎖。我的鎖過期了、換 B 拿到，我這時才做完、順手一刪——刪掉的是 B 的。所以要先確認「這把鎖上面寫的是不是我的名字」，而且確認和刪除必須是同一個不會被插隊的動作（實務上用 Lua 腳本，一小段送進 Redis 裡面整段一起跑的程式）。

3

事情做太久，鎖先過期了。你以為還鎖著，其實別人已經進來了。解法是背景每隔一段時間幫鎖續命，或是把過期時間設得比最慢的情況再長一些。

REDIS 的四種擺法

從一台，到一整排

這四種是「Redis 本身怎麼架」，跟鎖是兩件事，但等一下會發現它們會互相打架。

四種擺法一次看完

差別在「容量」和「掛了誰救」

擺法 能裝多少資料 主機掛了 維運麻煩度 什麼時候用
單機 一台的量 全停 最低 本機開發、測試
主從複製 一台的量 要人工切換 低 想多一份備份、讀取想分流
哨兵 一台的量 自動換人（幾十秒） 中 資料塞得下一台，但不能停
叢集 加機器就能加 自動換人（每組各自換） 高 一台裝不下，或流量很大

雲端的託管服務（例如 GCP 的 Memorystore、AWS 的 ElastiCache）幫你把哨兵那一段包起來了，你只會看到「基本版」和「高可用版／叢集版」這種選項。

最重要的一段

換成哨兵或叢集，鎖還是會破

很多人以為「架成哨兵就安全了」。剛好相反——自動換主機這件事，正是鎖出事的時候。

因為主機把資料複製給從機是非同步的：主機先回你「好，鎖給你」，才慢慢把這筆送去從機。中間那零點幾秒如果主機掛了，那筆鎖就消失了。

Redis 官方提出過一種叫 Redlock 的做法：向五台互相獨立的 Redis 同時要鎖，超過一半答應才算數。但學界對它是否真的安全一直有爭論，而且要多養五台，用的人不多。

那到底怎麼辦

先問一句：鎖破了會怎樣？

這題沒有「一定要怎樣」的答案，取決於重複做一次的後果有多嚴重。

重做一次沒差

直接用 Redis 就好

例如「同一支排程不要同時跑兩份」「按鈕連點兩下擋掉」。真的漏了，頂多多跑一次，資料不會壞。

不能重複，但想留著 Redis

加一個遞增編號

Redis 發鎖時順便發一個一直變大的號碼，寫資料時把號碼帶上；後端只收比看過的最大號碼更大的。晚到的舊號碼直接擋掉。這招英文叫 fencing token。

絕對不能重複

別用 Redis 當鎖

改用 etcd 或 ZooKeeper。它們寫入時要多數節點都點頭才算成功，所以換主機不會把已答應的東西弄丟。代價是比較慢、要多維護一套。

常被忽略

其實資料庫就能擋

唯一索引、SELECT ... FOR UPDATE、樂觀鎖版本號。只有一個資料庫的情況下，這通常比自己架分散式鎖更穩也更省事。

回到我們的專案

KPI 平台用 Redis 做什麼

目前規劃是把登入者的身份與權限放在 Redis（雲端上是 GCP 的 Memorystore）。這個用途沒有上面的問題——換主機時真的掉了幾筆，使用者頂多重新登入一次。

要留意的是哪天想拿 Redis 來當鎖的時候，例如「同一份 KPI 不要被兩個人同時送出覆核」。那種情境屬於上面的「不能重複」，建議先看資料庫的唯一索引擋不擋得住，擋得住就不用架鎖。

這段是根據專案 CLAUDE.md 記的技術決策寫的，不是既有的程式行為——目前這個 repo 還沒有程式碼。

帶走這五句

  • 機器變多，各自記憶體裡的鎖就互相看不到，等於沒鎖。
  • 分散式鎖就是把鎖搬到一個大家都看得到的地方，Redis 是常見選擇。
  • Redis 四種擺法差在「裝得下多少」和「主機掛了誰來救」：單機沒人救、主從要人工救、哨兵自動救、叢集自動救而且裝得更多。
  • 但四種都救不了鎖——因為複製是非同步的，換主機的瞬間鎖會憑空消失。
  • 先問「重複做一次會怎樣」。沒差就用 Redis；不能重複就加遞增編號，或乾脆用資料庫、etcd。

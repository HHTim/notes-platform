- **黃底更正標記與 muted 補充的分界**（2026-09-22 拍板）：黃底＝**照原筆記做今天會出事**（查證後確認寫錯的事實、會編譯失敗或已經行不通的舊寫法）；muted＝**原筆記是對的**，只是簡略、只講一半、或需要補前提，照著做不會出事。兩者的 `data-note` 都要誠實寫出屬於哪一種，不能讓可見文字跟標記顏色打架（出現過「可見文字寫『這點原筆記沒講錯』卻掛黃底」的情形）。muted 只要引了官方文件原文，一樣要附 `<a class="fixsrc">` 連結——Tim 沒有連結就驗證不了，這是這整套規則存在的理由。
- **課文是教材，不是工作紀錄**（Tim 2026-09-24 拍板，推翻本檔先前的反向標註慣例）：讀者看得見的每一個字都要在教東西。「原筆記寫…」「查證後…」「這裡照它的用意處理」這類話一律不准出現在正文，第一人稱也不准。查證軌跡放 `data-note`（滑過去才顯示的提示框，是給 Tim 驗證用的），正文放教材。**「查證後確認原筆記是對的」這種反向註記不寫進頁面**——有教學價值的部分（限制、前提、為什麼）直接當教材寫，沒有的就不寫。他的原話：「所謂筆記應該是讓使用者學習的地方，甚至要說是教材，這種什麼『原筆記…』是你自己思考的對吧？應該要改掉」。自我檢查：把 `data-note="…"` 整段拿掉後，課文裡不該剩下「原筆記」三個字。
- **官方文件會改版，出處要定期重比對**（2026-09-24 的發現）：VS Code 的 Copilot 文件在 9 月 22 日查證之後兩天內就大改版——工具清單整批搬到另一頁，原本三個出處連結點過去已經找不到它要支持的內容，`#changes` 這類名稱也換了。連結回 200 不代表引文還在那一頁上。之後每次動到某個模組，順手把該模組引用同一個網站的引文全部重開一次比對；引文對不上就換成現行字句，內容搬家就換連結，找不到就把那句引文拿掉——**不留任何一句頁面上找不到的引文**。變動快的來源（VS Code、Copilot、各家 AI 工具）風險最高。
- **來源註記一律寫確切檔名**（收錄覆蓋率稽核的教訓）：`lesson.html` 第一行的 `<!-- 來源：… -->` 要寫得出是哪一個檔，不能只寫「JavaScript 筆記八篇」「AIF-C01 模擬考題庫」這種描述。多篇合併成一課就把檔名逐一列出，一篇拆成多課就在每一課都寫同一個檔名並註明拆法。2026-09-23 的稽核要比對 166 篇來源，有四課全靠人工推斷才對得回去。
- **課文不用第一人稱，範圍要指名**（第十波與補收那輪各犯一次）：把查證範圍綁緊是對的，但寫成「我只查得到這兩頁沒有列」有兩個問題——課文裡沒有「我」這個人（全站九十幾課只有這兩處出現過），而且「這兩頁」讀者無從對應。改成不帶人稱、並**指名是哪兩頁**：「官方的斜線指令總表與工作階段那一頁都沒有列」。
- **修正本身會引進新名詞**（第十波的教訓）：改完要把自己新寫的句子再當「第一次出現」掃一遍。實例：修 QoS 那句時為了說明「這不是排班順序」而寫了 PriorityClass，卻沒給白話；同一個坑在 EndpointSlice 也差點發生。出處連結同理——修正時新引的原文一樣要附得到、驗得動的連結，連到長篇原始碼要指出搜哪個關鍵字。
- **審查意見要先驗證存不存在再動手**（第八波的教訓）：審查代理給的清單裡出現過指向不存在文字的條目——行號超出檔案總行數、引用的字串全模組零命中。實作代理收到清單的第一件事是逐條打開檔案核對「這段文字現在真的長這樣嗎」，對不上就**不要照改**（照改會把正確的敘述改錯，第八波差點發生），在回報裡逐條寫出核對結果。反過來，審查代理提意見時要抄出當下檔案裡的原句，不能只給行號。同一波若同時有多個模組在跑，審查代理務必先確認自己讀的是哪個模組的檔案。
- **push 會把別人疊在上面的 commit 一起送上線**（第十波的教訓）：多個代理共用同一個 repo 時，`git push` 推的是整條分支，不是你剛才那一筆。第十波的 7 課就是被一筆文件更新的 push 順手帶上線的，當時審查還沒跑完。**push 前一定先看 `git log --oneline origin/main..HEAD`**，確認中間夾的每一筆都可以上線；有還在審查中的模組 commit 就先別 push，等審查過再一起送。註冊在 `content/modules.json` 的既有模組尤其要小心——新課一進 `module.json` 就直接出現在網站上，不像新模組還隔著一層註冊。
- **短文類來源先全文後拆解**（Tim 拍板 2026-09-21）：有全文可引的來源（非歌詞台詞），課文先用 blockquote 引用塊完整呈現原文，再逐段拆解；引文與講解必須視覺可分。歌詞台詞課維持片語式並註明原因。
- **歌詞與影劇台詞**：不引用原文（版權＋模型輸出限制）。收「片語＋意思＋自編例句（標明自編）」，歌名、劇名只當學習來源提及。
- **重疊處理**：Docker/K8s 新課掛進既有 k8s 模組的「實作篇」分組；概念與既有 13 課重疊處不重寫、以「見第 N 課」引用；「應用程式部署技術演進史」只把新事實補強進既有第 1〜3 課。

## 1. 目的與緣起

長年累積在 HackMD 的筆記沒有持續維護，內容也沒經過查證。要做一個個人筆記平台：

- 一個大平台、多個模組（Java、K8s、GCP、AWS、多益、面試集、好用工具…）
- 每個模組是一個課程站，風格沿用已定稿的「容器與 K8s 課程站」（亮暖色、側邊欄、每課測驗）
- 之後新增筆記走 `/add-note`：貼網址給 Claude Code，它讀內容、查證、歸模組、改寫成課程頁、發佈
- 任何裝置打開網址都看得到最新內容；學習進度跨裝置同步

## 3. 整體架構

內容公開、純靜態網頁；只有「進度」走雲端資料庫。

- 內容的老家是這個 git repo。改內容 → push → GitHub Actions 自動建置 → GitHub Pages 發佈。
- 建置與部署都在 GitHub 的雲端跑，不依賴任何一台自己的機器；手機上的雲端 Claude Code 只要能 push 就能發佈。
- Firebase 只用兩個零件：Google 登入、Firestore。不自架伺服器。
- 費用目標：全部落在免費額度內。

否決的替代方案：整包放 Firebase Hosting（要多學一套部署指令，內容反正在 GitHub）；自架前後端（唯一動態需求只有進度，殺雞用牛刀）。

## 4. repo 佈局與內容格式

核心原則：**內容與外觀分開**。內容檔不含樣式；版面、配色、測驗互動集中在建置工具。

```
notes-platform/
├── content/
│   ├── modules.json          ← 模組總表：有哪些模組、顯示順序、圖示
│   └── k8s/
│       ├── module.json       ← 模組名稱、一句話簡介、課程順序
│       ├── 01-physical/
│       │   ├── lesson.html   ← 課程內文（不含樣式的 section 內容）
│       │   ├── quiz.json     ← 這一課的測驗，5〜10 題
│       │   └── assets/       ← 這一課用到的圖片
│       └── ...
├── builder/
│   ├── build.py              ← 讀 content/ 全部，組出整個平台到 dist/
│   └── templates/            ← 版面與配色（亮暖色定稿）
├── rescue/                   ← 從舊對話搶救出來的原始檔（遷移完成後可刪）
├── .claude/skills/add-note/
├── .github/workflows/deploy.yml
└── docs/superpowers/specs/   ← 本文件
```

內容格式的固定慣例：

- **來源註記**：每課 `lesson.html` 檔頭一行註解記「來源網址＋收錄日期」。不留原始材料副本。
- **圖片**：一律下載存進該課 `assets/`，不連外站的圖（外站的圖會失效）。示意圖（架構圖、流程圖）優先重畫成全站一致風格的向量圖；照片、畫面截圖保留原檔。
- **更正標記**：查證後改掉原筆記錯誤的地方，用固定寫法標記——該段文字加明顯底色（與暖色系不衝突但一眼可辨），旁附直達查證出處的小連結；滑鼠移上（手機點一下）顯示「原筆記此處寫 X，查證後更正」。
- **測驗**：每課至少 5 題、最多 10 題，選項順序由前端隨機打亂。

## 5. 平台外殼

兩層結構，現有 K8s 課程站整套保留、往上加一層平台：

- **平台首頁**：側邊欄列模組；主畫面是模組卡片（名稱、一句話簡介、課數、完成度）。資料來源 `modules.json`。
- **模組頁**：即現在 K8s 站的樣子（課程側邊欄＋內容＋測驗），頂欄加「回平台首頁」連結與模組下拉選單。
- 首頁點模組**同分頁切換**，不另開瀏覽器分頁。

網址結構（每課都有自己的網址，可直接分享、書籤）：

```
https://hhtim.github.io/notes-platform/                        平台首頁
https://hhtim.github.io/notes-platform/k8s/                    模組頁
https://hhtim.github.io/notes-platform/k8s/#/lesson/pod-node   直達某課
```

風格：全站同一套亮暖色（奶油底 #F7F0E3＋白卡片、古銅 #B5730F、灰藍 #5E7A9B），刻意不做深色模式；模組之間用圖示與名稱區分，不各配一套顏色。支援手機、平板、桌機（RWD 沿用現況作法）。

## 6. 建置與部署

`builder/build.py` 做四件事：讀 `modules.json` → 逐模組組 HTML（內容＋模板）→ 組平台首頁 → 全部輸出到 `dist/`（不進 git）。本機預覽＝跑一次 build 後直接開 `dist/index.html`，不需要伺服器。

部署：`.github/workflows/deploy.yml` 三步——抓 repo、跑 build.py、把 `dist/` 發佈到 GitHub Pages。

明訂的邊界：

- **push 到 main 即發佈**。個人站不設覆核流程；要先看再發就用本機預覽或 artifact 預覽。
- **每次建置都把整個網站從頭重新產生一遍**，不做「只重做有改到的頁」的機制——那種機制漏判一次就會出現「改了但某頁還是舊的」的難查問題；個人站的量整站重建也只要幾秒。

## 7. 進度跨裝置同步

- 沒登入：一切可看可用，進度存該裝置瀏覽器（localStorage）——現況行為。
- Google 登入且 email 在白名單：進度存 Firestore，跨裝置。
- 登入但不在白名單：明講「此帳號未獲授權，進度僅存於本機」，其餘不受影響。

白名單＝Firestore 裡一份 email 清單，Tim 本人在 Firebase 管理網頁（或請 Claude Code）增刪。資料庫規則三條：名單只有 Tim 能改；名單上的人只能讀寫自己的進度；其他一律拒絕。

進度資料：每人一份——模組、課、勾了沒、測驗答對題數、時間。量級每人幾 KB。

**合併規則**：本機與雲端進度不一致時取聯集——勾過就算勾過，測驗成績取較好那次。絕不以單邊蓋掉另一邊。

**提示文字**（固定位置，側邊欄進度數字旁一行小字，不跳視窗）：

| 狀態 | 顯示 |
|---|---|
| 沒登入 | 進度只存在這台裝置 · 登入後跨裝置同步（後半句是登入連結） |
| 已登入＋白名單 | 已同步（Google 帳號名） |
| 已登入但不在白名單 | 此帳號未獲授權，進度僅存於本機 |

## 8. `/add-note` 流程

輸入：一個網址、一段文字或一個檔案。七步：

1. **讀取來源。** 抓不到不放棄：先診斷該站要什麼（登入、驗證碼、擋機器人），回報缺什麼並配合使用者提供的帳號、驗證碼完成正常登入。界線：正常登入可做；偽裝、繞過封鎖等手段預設不做，除非使用者明確要求才照辦。
2. **查證內容。** 放手用網路搜尋比對官方文件，查技術錯誤、過時內容、與平台既有課程的矛盾。**發現錯誤直接改寫成正確版本，不先徵詢**，但更正處必須照第 4 節的「更正標記」呈現，讓 Tim 閱讀時一眼看到並可點出處自行驗證。
3. **歸模組。** 明確吻合既有模組→直接歸入，事後報告說明放哪、為什麼。不確定或不屬於任何既有模組→停下來問：列出所有既有模組當選項，最後一項「新增模組」附建議名稱與理由；**未經 Tim 點頭絕不新開模組**。
4. **防重複。** 與既有某課高度重疊時不硬開新課，問 Tim 要合併補強還是另立一課——避免同一件事散在多處、各講各的版本。
5. **改寫成課程頁。** 套全站風格與 Tim 的用詞規則（白話、比喻括號附正式名詞）；產出 `lesson.html`＋5〜10 題 `quiz.json`＋`assets/`；檔頭記來源與日期。
6. **預覽確認。** 本機環境：跑 build 給截圖或開本機檔案。手機／雲端 Claude Code：把組好的模組頁發成私人 artifact 供手機檢視。Tim 說 OK 才進第 7 步。
7. **push 發佈。** 推上 GitHub、Actions 自動部署、回報最終網址。

會停下來找 Tim 的點：3（新模組）、4（重疊）、6（預覽）。查證（第 2 步）不停——直接改、靠標記讓 Tim 事後看得到。順利時只有第 6 步問一次。

## 10. 明確不做的事

- 不做深色模式（定稿決策）
- 不做排行榜、看別人進度、評論；白名單成員彼此完全隔離
- 不做內容鎖（內容全公開；只有進度需要登入）
- 不做「只重建有改的頁」的機制
- 不保留收錄來源的原始材料副本（僅記網址）
- 平台內任何東西不進公司 repo，也不從公司文件引用

## 11. 風險與注意

- rescue/ 內的 `distributed-lock-redis.artifact.html` 是從已發佈的 artifact 抓回來的，外層包著發佈系統自己的程式碼；遷移拆內容時剝掉外層、取 `<title>` 之後的本體。
- 本機 git 身分：本 repo 已設定 repo 內專用的 user.name=HHTim、user.email=clown0715@gmail.com（HHTim 帳號登記的 email）。
- Angular、框架一概不用；網站是建置工具產出的靜態 HTML，維護點只有 builder 與 content。

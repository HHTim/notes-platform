# 選字問 AI 設計（2026-10-14 Tim 拍板）

Tim 的交代：「選一段文字，然後這個文法我不懂，可以直接問 AI」；要免費或用已訂閱的方案；「先用免費版寫規格」。

## 拍板的事

1. **在網站裡選一段字就能問 AI**，對話在網站裡進行，不跳去別的網站。
2. **用 Google 的 Gemini 免費版**，透過 Firebase 的 AI 功能（Firebase AI Logic）直接從網頁呼叫。不架自己的轉送服務，Firebase 維持免費方案（Spark），不綁信用卡。
3. **不用 CopilotKit**：它要 React 和自己的後端，我們網站沒有框架、放在 GitHub Pages，裝不上也用不到它的強項。
4. **不用登入者的訂閱**：Google 沒有正式做法，網站也看不出誰有訂閱；把 Gemini CLI 登入憑證轉給別的程式用違反條款、會被停權。Claude 的訂閱同理（2026-02 起禁止）。
5. **誰能用＝白名單**：登入且在白名單（Firestore 的 `whitelist`）裡的人才看得到「問 AI」。
6. **先開日文、英文兩個模組**，Tim 用幾天看回答品質與每天額度，再決定要不要開到其他模組、要不要改用付費（Tim 的 Google AI Pro 每月附 10 美元 Google Cloud 額度，能不能拿來付要 Tim 到帳單頁面確認）。

## 用起來的樣子

- 在課文、課中練習、測驗題目或解析裡選一段字（電腦拖曳、手機長按）。
- 選取範圍旁出現小按鈕「問 AI」。手機上放在選取範圍**下方**，避開系統自己的「拷貝／查詢」選單（它在上方）。
- 按下去開對話框：電腦從右側拉出，手機從下方拉出（佔畫面約七成，可關）。
- 對話框最上面顯示「你選的字」，下面一個輸入框，預設問題「這段的文法是什麼意思？」，可以改或直接送出。
- 回答逐字出現（串流），可以接著追問。關掉對話框就清掉，**不存紀錄**、不同步。
- 對話框底部固定一行小字：「免費版：問題與回答會被 Google 用來改進產品，不要貼個人資料。」
- 沒登入、不在白名單、模組沒開：不出現按鈕，網站其他行為完全不變。

## 送給 AI 的內容

- **選的字**：日文要先濾掉讀音。選取「<ruby>私<rt>わたし</rt></ruby>」時瀏覽器抓到的是「私わたし」，做法是複製選取範圍、拿掉 `rt` 與 `rp` 再取文字。上限 500 字，超過截斷並在對話框提示。
- **位置**：模組名、課名、所在小節標題（往上找最近的 `h3.head`）。
- **前後文**：選取所在的那一段（`p`、`li`、練習題整題）文字，一樣濾掉讀音，上限 800 字。
- **給 AI 的固定指示**（系統指示）：
  - 你是幫台灣學生解釋文法的老師，用繁體中文、台灣用語回答。
  - 先一句話講結論，再條列說明；不寫長段落。
  - 日文漢字後面用括號附讀音，例：私（わたし）。不用羅馬拼音。
  - 有不確定的地方直接說不確定，不要編。
  - 日文模組多一句：讀者程度是剛學完 N5 文法；英文模組：讀者在準備多益。

## 回答怎麼顯示

- AI 回的是 Markdown 文字。只支援：粗體、條列（`-`、`1.`）、換行、行內程式碼。其他一律當純文字顯示。
- **先把整段文字跳脫（`<` `>` `&` 變成實體）再轉格式**，AI 回什麼都不會變成網頁上的標籤或程式。
- 日文部分包 `<span lang="ja">`（偵測到假名的那幾段），套日文字型。

## 技術做法

- **新檔 `builder/templates/askai.js`**，跟 `sync.js` 一樣是不用框架的 JavaScript。
- 網站現在用的 Firebase SDK 是舊式寫法（compat 10.14.1），Firebase AI Logic 只有新式寫法（modular）。做法：**第一次按「問 AI」時才載入**新式 SDK（從 gstatic 用 `import()` 載入，版本在計畫裡定死），用同一組 `content/firebase.json` 設定另外初始化一個名為 `askai` 的 app。平常不按就不多載任何東西。
- 型號：`gemini-3.6-flash`。原本定 `gemini-3.8-flash`（2026-10 定價頁標示免費版可用），2026-10-29 上線實測：免費版連「hi」都要等 3 分鐘才回 503「Deadline expired」，論壇也有多人回報同樣問題；`gemini-3.6-flash` 約 6 秒回、`gemini-3.5-flash-lite` 約 2 秒回，選 3.6 是因為解釋比較準。舊的 `gemini-2.5-flash` 新使用者已不能用。等太久（45 秒沒開始回答）就放棄，顯示「AI 暫時沒有回應」。AI 的設定放新檔 `content/askai.json`（`model`、`app_id`、`recaptcha_site_key`，三個都是公開值），改型號不用改程式。不塞進 `firebase.json`，因為那份會整份交給登入用的舊式 SDK。
- App Check 需要 Firebase 網頁 app 的 `app_id`（公開識別碼），現在的 `firebase.json` 沒有，Tim 在主控台註冊網頁 app 後取得。
- **App Check**（確認呼叫來自我們的網站，別的網站拿我們的設定也呼叫不了）：用 reCAPTCHA Enterprise。免費版每月 1 萬次驗證、不用綁卡；2026-11-02 起 Firebase 強制要求。網站金鑰（site key）是公開值，放 `content/askai.json`。開啟一次性用的驗證碼（`useLimitedUseAppCheckTokens: true`）。
- **白名單判斷**：沿用 `sync.js` 已做的白名單查詢結果。`sync.js` 確認在名單上後設 `document.documentElement` 的 `data-sync="ok"`，`askai.js` 只在這時顯示按鈕。這是網頁端的判斷，懂技術的人繞得過；免費版不產生費用，最壞情況只是當天額度被用完，接受。
- **哪些模組開**：`module.json` 加 `"ask_ai": true`。`builder/build.py` 只在有這個欄位、而且 `content/askai.json` 存在時才把 `askai.js` 放進頁面。
- 樣式放 `style.css`，亮暗兩種模式都要加；圖示畫在 `icons.svg`（不用 emoji）。

## 發佈：哪個分支上線

- `main`：沒有任何 AI 的網站。`ask-ai`：本規格的 AI 版。
- GitHub repo 設定裡的 Actions 變數 `DEPLOY_BRANCH` 決定哪條上線，先設 `ask-ai`。
- 發佈設定（`.github/workflows/deploy.yml`）改成 push 到 `main` 或 `ask-ai` 都跑測試與建置，只有分支等於 `DEPLOY_BRANCH` 才發佈。兩條分支的這個檔案要一樣。
- 發佈環境 `github-pages` 的允許清單加上 `ask-ai`。
- 切回沒有 AI：把 `DEPLOY_BRANCH` 改成 `main`，在 Actions 頁面對 `main` 手動跑一次。
- `ask-ai` 上線期間，`main` 的新課要併進 `ask-ai` 才會出現在網站上；Tim 同意這樣做（只是課綱更新）。

## 錯誤時顯示什麼

| 狀況 | 對話框裡顯示 |
|---|---|
| 今天免費額度用完（429） | 今天的免費額度用完了，明天再試。 |
| 每分鐘次數太多（也是 429，訊息不同） | 問太快了，等一分鐘再問。 |
| App Check 沒過 | 驗證沒通過，重新整理頁面再試。 |
| 網路斷線、逾時 | 連不上 AI，檢查網路後按「再試一次」。 |
| AI 拒答（安全過濾） | AI 沒有回答這題，換個問法試試。 |

錯誤都不影響網站其他功能，只在對話框裡顯示。

## 品質把關

- 自動測試（node，跟 `sync.js` 一樣只測純函式）：
  - 濾讀音：含 `ruby`／`rt`／`rp` 的片段取出的文字正確。
  - 截斷：超過 500、800 字的處理。
  - 回答顯示：含 `<script>`、`<img onerror>` 的回答顯示成純文字；粗體、條列正確轉換。
  - 錯誤分類：各種錯誤對到上表的訊息。
- 建置測試：有 `ask_ai` 的模組頁含 `askai.js`，沒有的不含；沒有 `content/askai.json` 時整站都不含。
- 新加的顏色變數亮暗兩段都有（既有測試會擋）。
- 上線前用瀏覽器實測：電腦與手機寬度、亮暗模式、日文選字含讀音、各種錯誤顯示。
- Tim 驗收：用自己的手機在日文課選字問幾題。

## 明確不做

- 付費版、用訂閱付費、自己架轉送服務。
- 對話紀錄保存或跨裝置同步。
- 日文、英文以外的模組（驗收後另外決定）。
- AI 回答裡的漢字標 `<ruby>`（改用括號附讀音）。
- 語音、圖片、上傳檔案。

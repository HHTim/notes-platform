讀完這課你會

  • 說明 MCP 在這裡扮演什麼角色，以及它不負責解決哪些問題
  • 分清楚指示檔、提示檔、自訂代理人、工具組與工具各自放什麼
  • 把工作區以外的材料（別人的儲存庫、網頁、瀏覽器畫面）指給它看
  • 把外部內容當成不可信的資料，避開提示注入

先講 MCP

替 AI 工具準備一個通用插座

MCP（Model Context Protocol，模型上下文協定）是一套讓應用程式用標準方式連接外部資料與工具的協定。有一個很好記的比喻：它像 AI 世界的 USB-C，主機不必為每個模型、每項服務都另外做一套接頭。

它是 Anthropic 在 2024 年 11 月 25 日正式公開的開放標準，訊息格式用 JSON-RPC 2.0，官方提供多種語言的 SDK。

它解決的是「多對多整合」的重複工：以前 M 種模型要接 N 種工具，就得做 M×N 套接頭。但「用同一種插頭」不等於「插上去就安全」。伺服器仍可能碰到本機檔案、公司系統或外部服務，認證、授權、輸入驗證與稽核都得另外處理。

三個角色

主機、用戶端、伺服器各司其職

角色白話比喻責任
主機（Host）你在用的那張工作台承載聊天或代理人介面，管互動與權限
用戶端（Client）專線接頭代表主機跟某一台伺服器建立協定連線
伺服器（Server）工具箱或資料櫃對外公開可呼叫的能力或可取得的內容

本機的伺服器可能讀檔案或操作本機程式；遠端的可能連到工單系統、設計檔、雲端或公司資料。不管跑在哪裡，先把資料流畫出來：送出了什麼、交給誰、保存多久、回傳的內容會不會被其他工具再用一次。

傳輸與能力

工具只是 MCP 的其中一塊

現行規格的兩種標準傳輸是標準輸入輸出（stdio）與 Streamable HTTP；原本單獨列的 HTTP 加 SSE 那一種已經由 Streamable HTTP 取代出處。標準輸入輸出用在主機自己啟動的本機程序；走網路的那種適合遠端服務，但需要更完整的身分驗證、加密與授權設計。

能力用途主要風險
工具（Tools）讓模型要求執行查詢或動作越權修改、危險參數、外部副作用
資源（Resources）提供可讀取的資料或內容敏感資料外洩、過期內容被誤用
提示模板（Prompts）提供可重複使用的互動樣板樣板夾帶不當指示或已不符現況
取樣（Sampling）讓伺服器反過來請主機用模型生成內容互相呼叫、成本、資料邊界不清

這四項現行 VS Code 都支援了：工具、資源、提示模板列在 MCP 伺服器說明頁，取樣則寫在擴充功能開發指南裡（伺服器可以用你設定的模型發出請求，第一次呼叫時會跳出授權提示），並有 chat.mcp.serverSampling 這個設定可以控管出處。

用戶端這邊還有 Elicitation（伺服器中途向使用者要一項補充資訊）。要注意的是「協定有這項能力」推論不出「我手上這套產品一定支援」，兩者是不同層次。

取樣則要再多看一步。它跟 Roots 已經準備退場：MCP 規格在 2026-07-28 版把這兩項標為淘汰，最快會在 2027-07-28 之後的版本被移除，並給了替代做法——取樣改成直接串模型供應商的介面，Roots 改用工具參數、資源網址或伺服器設定來傳路徑。出處所以取樣現在的狀態是「編輯器支援得到，規格卻已經不建議」：舊的實作還會動，但新的流程不要再建立在它上面。

設定 MCP

接之前先看清楚它要什麼權限

新增伺服器前，先檢查來源、維護者、啟動指令、相依套件、會連到哪些網路位址、環境變數與可存取的路徑。專案設定如果會進版本控制，就不能直接放金鑰。

{
  "servers": {
    "example": {
      "command": "example-server",
      "args": ["--read-only"],
      "env": { "EXAMPLE_TOKEN": "${input:exampleToken}" }
    }
  }
}

專案設定檔放在 .vscode/mcp.json，命令列也有 --add-mcp 參數可以加；現在正式版的 VS Code 就支援，不必再裝預覽版出處。管理指令有 MCP: Add Server、MCP: List Servers、MCP: Reset Cached Tools、MCP: Open User Configuration、MCP: Open Workspace Folder MCP Configuration、MCP: Browse Resources、MCP: Reset Trust、MCP: Show Installed Servers。出處

  • 優先用唯讀帳號、測試環境與範圍受限的權杖。
  • 寫入、刪除、付款、部署、對外發訊這類動作，保留人工確認。
  • 固定或審查套件版本，不要每次啟動都抓一份沒檢查過的新程式。
  • 留下工具呼叫、參數、結果與核准人的稽核紀錄。
  • 定期把不用的伺服器、權杖與權限清掉。

現成的伺服器很多（瀏覽器操作、雲端服務查詢、設計稿轉程式碼、聯網搜尋、抓網頁、查時間都有人做），有些還搭配自己的付費方案與額度。這類清單與價格變動很快，挑伺服器該從任務與風險出發，不要只因為「熱門推薦」就裝上去。

除錯

連線、能力、權限、業務邏輯分開查

官方有一支檢查工具（MCP Inspector），可以觀察伺服器啟不啟得起來、宣告了哪些能力、呼叫的輸入輸出長什麼樣。啟動方式是用 npx 執行官方套件，再開瀏覽器連本機的埠號；版本與埠號會變，用之前先確認套件來源。出問題時照這四層往下查：

  • 連線層：程序有沒有啟動、傳輸方式與環境變數對不對。
  • 協定層：初始化成不成功、宣告的能力與參數結構對不對得上。
  • 權限層：這個帳號到底准不准存取目標資源。
  • 業務層：工具跑成功了，結果是不是真的符合需求。

四種客製化元件

規則、任務、角色、工具不要混在一起

元件像什麼適合放什麼檔案形式
指示檔常設規章團隊風格、架構界線、安全與測試政策.github/copilot-instructions.md、.github/instructions/*.instructions.md
提示檔可以重跑的工作單建介面、審弱點、產遷移計畫等任務流程.github/prompts/*.prompt.md
自訂代理人角色與工作環境規劃者、文件編輯、唯讀審查等模式與工具限制已改名為 *.agent.md，工作區放在 .github/agents；官方說「自訂代理人的前身就是聊天模式」，舊的 .chatmode.md 要改名搬過去出處
工具可以操作的器材讀檔、搜尋、查資料庫、呼叫外部服務、執行指令內建或由 MCP 伺服器提供

提示檔可以要求遵循指示檔，也可以建議用哪些工具，但它本身不是工具。就像工作單可以寫「用扳手鎖緊」，工作單不會變成扳手。

工具組

工具一多，就替常用的那幾把綁一個名字

接上兩三台 MCP 伺服器之後，可以選的工具很快就是幾十個，每次要手動勾選很煩。工具組（Tool Sets）就是為這件事存在的：官方的定義是「A tool set is a reusable collection of agent tools that you can reference as a single entity.」——把一組相關的工具包成一個名字，之後用一個名字整組叫出來。出處

建立方式是在命令面板（VS Code 上方那個打指令的搜尋框）跑 Chat: Configure Tool Sets，選「Create new tool sets file」，在開出來的 .jsonc 檔（可以寫註解的 JSON）裡定義：

{
  "reader": {
    "tools": ["search/changes", "search/codebase", "read/problems", "search/usages"],
    "description": "Tools for reading and gathering context",
    "icon": "book"
  }
}

之後在對話裡打 #reader，這一整組就一起帶進去。官方也說明三個欄位各是什麼：tools 是工具名稱的陣列（可以放內建工具、MCP 工具或擴充功能提供的工具），description 是在工具選單裡顯示的說明，icon 是圖示。

VS Code 自己也內建了幾組，在工具總表裡直接標成 tool set：#read（讀工作區的檔案）、#search（搜工作區）、#edit（改工作區）、#execute（在你的機器上執行程式）、#web（取用網頁內容）、#browser（操作內建瀏覽器）、#agent（把工作分派給其他代理人）。出處

自訂代理人

同一套工具，換個角色用

前面那張表提過這類檔案已經從自訂聊天模式改名叫自訂代理人。這裡講它實際能做什麼。官方的說法是「Custom agents enable you to configure the AI to adopt different personas tailored to specific development roles and tasks.」——替不同的開發角色各設一份設定，每份有自己的行為、可用工具與指示。出處

官方舉的例子是：「a "Plan" agent could include instructions for generating an implementation plan and only use read-only tools.」——一個只給唯讀工具的規劃角色，就不會在你還在想的時候動到程式碼。

要設的東西寫在哪
檔案本身一個 .agent.md 的 Markdown 檔
工作區共用.github/agents 資料夾（Claude 格式則放 .claude/agents）
只給自己、跨專案用~/.copilot/agents 或 ~/.claude/agents
檔頭設定（YAML 前置區，檔案開頭用三個減號框起來的設定段）description（說明）、name（名稱，不寫就用檔名）、tools（准用哪些工具或工具組）、model（指定用哪個模型）等

建立用命令面板的 Chat: New Custom Agent，要用的時候在對話視窗的代理人下拉選單裡切換。

這個功能在 VS Code 1.101（2025 年 6 月）還是預覽功能，現在已經是正式文件裡的一般功能，名稱也換了。官方在問答區直接寫「Custom agents were previously known as custom chat modes. The functionality remains the same, but the terminology has been updated to better reflect their purpose in customizing AI behavior for specific tasks.」，並要求把舊的 .chatmode.md 改名搬過去。出處

提示檔

把成功的對話變成可以維護的資產

提示檔適合那種會重複出現、輸入可以替換、輸出可以驗收的任務。放在專案的 .github/prompts/ 就能跟同事共用、進版本控制，在對話裡打 / 加名稱就叫得出來；放在個人設定裡則是自己跨專案用。內容支援 ${selection}（目前選取內容）、${input:變數名}（執行時問你要填什麼）這類變數，也可以用 Markdown 連結去引用另一份提示檔或指示檔，把流程拆成好幾份小的。

---
description: 審查指定介面的授權風險
---

目標：
檢查 ${input:routeName} 的身分驗證與授權流程。

參考：
- ${file}
- 專案安全規範

限制：
- 只分析，不改檔案、不執行外部指令。
- 不顯示權杖、Cookie 或個資內容。

輸出：
1. 依嚴重度排序的發現
2. 每項發現對應的程式碼依據
3. 建議修正與待確認的假設

不要把整段聊天原封不動存起來；刪掉當時才有的偶然資訊，留下用途、必要輸入、允許範圍、禁止事項、輸出格式與完成條件。流程長的話拆成幾份小提示、明確傳遞中間產物，比做一份越長越大的提示好維護。

現行官方頁面已經沒有 chat.promptFiles 這個設定，不必再手動開啟；同一頁還標示提示檔在 Agent Host 工作階段已淘汰、不會被載入，只有本機代理還讀得到，而本機代理未來也會移除出處——所以這套做法的觀念可以學，但長期別把流程全押在這個檔案格式上。另外，把對話存成提示檔、或匯出成一份檔案給別人匯入這類功能，分享前要先把祕密、個資、內部路徑與客戶資料清掉——可重用不等於可公開。

對話管理

換一個乾淨的開始，或把這段留下來

對話越長，舊的資訊越容易干擾新的問題。常見的需求有三種：清空上下文、把這次的對話存成之後可以重跑的檔案、把整串對話留底或給別人。對應的做法如下。

你想做的事現行官方列的做法
不要讓舊對話影響新問題/clear：官方的說明是「Start a new chat and archive or mark the current chat as done.」——開一個新對話，並把目前這個封存或標記為完成
對話太長、超出模型能看的範圍/compact：「Compact the conversation context in a supported agent session. Useful when a conversation grows too long for the model's context window.」——把前面的內容壓成摘要，繼續同一串
把這次的做法變成下次可以重跑的檔案/create-prompt：「In a local agent session, generate a prompt file.」
整串留底或給別人命令面板的 Chat: Export Chat...，存成一個 JSON 檔

官方對匯出的描述是「Exporting a chat session creates a JSON file that contains all prompts and responses from the session.」——全部的提示與回覆都在裡面。出處同一頁還列了右鍵複製成 Markdown 的三種：Copy（單則）、Copy All（整串）、Copy Final Response（只要最後那段結論）。既然是整串照抄，分享前一樣要先清祕密與個資。

要把對話變成可重複執行的檔案，官方現行的斜線指令總表列出來的是 /create-prompt。工作階段那一頁也只寫了匯出，沒有寫對應的匯入指令。不過總表自己註明「Type / to see commands available in the current session. Availability depends on the chat surface, harness, role, and enabled features.」，所以「總表沒有列」不等於「官方說這個指令不存在」，實際還是以你手上那個版本打 / 跳出來的清單為準。出處另外要記得這一課前面講過的前提：提示檔這個格式在部分工作階段已經被官方標為淘汰，所以別把長期流程全押在它身上。

再多三種材料

專案以外的東西，怎麼指給它看

第 3 課有一張表，列了怎麼把選取的程式碼、問題清單、版本控制的差異、整個工作區指給它看。還有三種材料來自工作區以外，補在這裡。

想給的材料現行寫法官方說明
GitHub 上某個儲存庫的原始碼#githubRepo，後面接 owner/repo（GitHub 上「帳號／儲存庫名稱」的寫法）「Semantic search a GitHub repository for relevant source code snippets. Specify a repository using owner/repo.」（語意搜尋＝照意思找相關的段落，不是只比對字面）
同上，但要照關鍵字精確找#githubTextSearch「Text search a GitHub repository or organization for files containing specific keywords or code patterns.」
某一頁網頁的內容#web/fetch「Fetch the content from a given web page.」官方示範是「Summarize #web/fetch code.visualstudio.com/updates.」

抓網頁那個現在要打 #web/fetch——官方的內建工具總表把它歸在 #web 這組底下，跟第 3 課提過的 #codebase 改成 #search/codebase 是同一波改名出處。

早期用 #openSimpleBrowser（在編輯器裡開一個簡易瀏覽器，讓 AI 看得到網頁結構）做這件事，現行官方的內建工具總表與瀏覽器工具那一頁都沒有列這個名字。同一件事現在由內建瀏覽器那一組工具做：官方說「Browser tools give agents a visual and interactive feedback loop for web development.」，工具包括 openBrowserPage、navigatePage、readPage、screenshotPage、clickElement 等，用 workbench.browser.enableChatTools 這個設定開關，預設是開的。出處

這三種材料都來自你的工作區以外，所以下一段那條規矩對它們特別重要。

上下文與信任邊界

資料要剛好，而且要分得出哪些不可信

選取內容、問題清單、版本控制差異、專案搜尋與外部網頁各自回答不同的問題。先問「完成這件事最低限度需要哪些證據」，再附上對應的資料。

外部內容尤其要當成不可信的輸入。網頁、工單、文件或工具回傳的結果，可能夾帶提示注入（prompt injection，把惡意指令藏在資料裡，騙模型當成命令執行），例如叫它忽略原本的規則、去讀祕密、或執行某個指令。這些文字只能當資料，不能自動升格成命令。

信任層級要固定：使用者與專案政策決定目標；外部資料只提供事實，不能自己改寫權限與任務。

串成可重複的流程

用契約把提示、工具與驗收接起來

可靠流程 ＝ 固定規範 ＋ 任務模板 ＋ 最小工具權限 ＋ 看得到的證據 ＋ 人工驗收

  1. 用指示檔宣告長期規則。
  2. 用提示檔定義單次任務的輸入、步驟與輸出。
  3. 只給相關的上下文，並標明哪些是不可信的外部資料。
  4. 只開必要的工具，對有副作用的呼叫設核准點。
  5. 用差異、測試、日誌或查詢結果驗收，不用模型的自述驗收。
  6. 規格或工具改了，同步更新模板並重新測一次。

重點整理

  • MCP 讓 AI 與外部工具、資料的連接方式標準化，但不會自動解決安全問題。
  • 協定有哪些能力，跟某套產品實際支援哪些，是兩件要分開確認的事。
  • 指示檔管長期規則，提示檔管可重複的任務，自訂代理人管角色與工具邊界，工具組只是把常用工具綁一個名字。
  • 工作區以外的材料各有寫法：別人的儲存庫用 #githubRepo，某一頁網頁用 #web/fetch，要看實際畫面則用內建瀏覽器那組工具。
  • 想換個乾淨的開始用 /clear，對話太長用 /compact；匯出會把整串提示與回覆寫成一個 JSON 檔，分享前先清乾淨。
  • 外部內容可能夾帶提示注入，一律當成資料而不是命令。
  • 有副作用的工具呼叫都照最小權限給、留紀錄、設人工核准點。

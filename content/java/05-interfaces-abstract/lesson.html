先建立觀念

抽象類別是不能直接用的半成品

「動物」是一個概念，真正存在的是狗、鳥、魚。程式裡也可以用抽象類別（abstract class）表示這種概念：先把子類別共有的資料與行為整理好，把還沒決定的細節留給子類別完成。原筆記的比喻很貼切——它像一份範本，因為只是範本，所以不能直接拿來建立物件。

abstract class Pen {
    private final String brand;

    protected Pen(String brand) {   // 抽象類別可以有建構子
        this.brand = brand;
    }

    public String getBrand() {      // 也可以有寫好的一般方法
        return brand;
    }

    public abstract void write();   // 抽象方法：沒有大括號
}

class Pencil extends Pen {
    Pencil(String brand) {
        super(brand);
    }

    @Override
    public void write() {
        System.out.println("用石墨書寫");
    }
}

抽象方法沒有方法主體，連 { } 都拿掉。兩條規則要記住：只要類別裡有抽象方法，這個類別就一定要宣告成抽象類別；但反過來不成立——抽象類別不一定要有抽象方法，有時候只是設計者刻意不讓別人直接建立它的物件。

抽象類別不能建立物件，那它的建構子做什麼用？給子類別透過 super(...) 呼叫，負責初始化共同的那一段。

繼承之後的責任

具體子類別必須補齊所有抽象方法

子類別繼承抽象類別後，如果沒把所有抽象方法補完，它自己也只能是抽象類別。一路補到某個子類別把欠的都做完，才成為可以建立物件的具體類別（concrete class）。

從語法看，把抽象方法寫完就是覆寫；語意上大家習慣叫它「實作」——因為原本那個方法根本沒有內容，是從無到有做出來的。

Pen pen = new Pencil("ABC");
pen.write();   // 執行 Pencil.write()

變數的型別是 Pen，實際物件是 Pencil，執行時按真正的物件挑方法——這就是第 4 課講的動態繫結。抽象類別不能建立物件，不代表它不能當變數的型別。

行為契約

介面像插座規格：只約定怎麼接

介面（interface）用來定義一組能力。鳥、飛機跟超人沒有現實上的「是一種」關係，卻都會飛，所以都能實作同一個 Flyable。原筆記把介面的用途列成五項：多重繼承、定義規格、貼標籤、型別轉換、降低相依性。

interface Flyable {
    int MAX_HEIGHT = 10_000;   // 自動是 public static final，宣告時就要給值
    void fly();
}

class Bird implements Flyable {
    @Override
    public void fly() {
        System.out.println("拍動翅膀飛行");
    }
}

介面裡直接宣告的欄位隱含是 public static final，也就是大家共用的常數，所以一定要給初始值。介面沒有建構子，也不能建立物件，但跟抽象類別一樣可以當參考型別。

這一段舊教材要改

Java 8 之後，介面不再只有抽象方法

「介面裡的方法一律是抽象方法」已經是 Java 8 以前的答案。Java 8 起介面可以有帶實作的 default 方法與 static 方法，Java 9 起還能有 private 方法出處。面試集第 1 課〈Java 基礎快答〉也標了同一件事。

interface Greeter {
    String name();

    default String greet() {          // Java 8：有預設實作，實作類別可以不寫
        return "Hello, " + name();
    }

    static Greeter of(String n) {     // Java 8：介面自己的工具方法
        return () -> n;
    }
}

為什麼要加 default？因為以前只要往一個已經上線的介面加方法，所有實作它的類別就全部編譯不過。有了預設實作，介面才能在不弄壞既有程式的前提下長大。

現在只有「沒寫方法主體」的介面方法才隱含 public abstract——寫了主體的不是

組合能力

類別只能單一繼承，卻能實作多個介面

Java 類別只能直接繼承一個父類別，但可以同時實作多個介面。這不是繼承好幾份狀態，而是「這個物件承諾具備這幾種能力」。

class 子類別 extends 父類別 implements 介面一, 介面二

interface Writable { void write(String text); }
interface Erasable { void erase(); }

class SmartPen extends Pen implements Writable, Erasable {
    SmartPen(String brand) { super(brand); }

    @Override public void write() { write("預設內容"); }
    @Override public void write(String text) { System.out.println(text); }
    @Override public void erase() { System.out.println("清除筆跡"); }
}

介面跟介面之間用 extends 延伸，而且一個介面可以延伸多個介面。口訣：類別繼承類別用 extends，類別履行介面用 implements。

多型設計

依賴介面，使用端就不必綁死實作

如果一段流程只需要「會寫字」這個能力，參數就宣告成 Writable，不要指定鉛筆、鋼筆或毛筆。像物流中心只要求箱子符合輸送帶尺寸，不必知道箱子裡裝什麼。

class WritingService {
    void publish(Writable tool, String text) {
        tool.write(text);
    }
}

之後新增工具只要實作 Writable，WritingService 通常一個字都不用改。這就是原筆記講的兩個詞：相依性（耦合，coupling，一個類別有多依賴另一個具體類別）要低，凝聚性（內聚性，cohesion，一個類別的職責有多集中）要高。

特殊用途

空介面只負責貼標籤

沒有宣告任何方法的介面叫空介面，或標記介面（marker interface）。它不要求你多做什麼，只是替型別貼一個標籤，讓 Java 或框架認得出來。最有名的兩個是 java.io.Serializable（可以序列化）與 java.lang.Cloneable。

實作 Cloneable 本身不會讓物件變得可複製——它只是讓 Object.clone() 不要丟 CloneNotSupportedException。真要複製，還得自己覆寫 clone() 並把它開放出來，而且 Object.clone() 做的是淺層複製（內部的物件還是共用的）出處。同理，實作 Serializable 只是取得入口資格，不保證每一種操作都會成功。

選擇指南

抽象類別與介面怎麼選

比較項目抽象類別介面
核心關係同一家族的「是一種」跨家族的「具備某能力」
能不能建立物件不能不能
實體狀態可以有實體欄位直接宣告的欄位都是常數
建構子有，供子類別呼叫沒有
一個類別能用幾個只能繼承一個可以實作多個
適合什麼共用狀態、基礎流程與部分實作定義契約、替換實作、降低耦合

沒有「介面永遠比抽象類別好」這種答案。看關係自不自然：有共同狀態跟建構流程就用抽象類別；跨越不同家族的共同能力就用介面。兩者也常常一起用——抽象類別保存共同狀態，介面把對外能力定成穩定的契約。

重點整理

  • 抽象類別不能建立物件，但可以有建構子、欄位與寫好的一般方法。
  • 有抽象方法的類別一定要是抽象類別；抽象類別不一定要有抽象方法。
  • 類別只能繼承一個父類別，卻能實作多個介面；介面之間也能互相延伸。
  • Java 8 起介面可以有 default 與 static 方法，Java 9 起還有 private——「介面方法一律抽象」已是舊答案。
  • 介面欄位隱含是 public static final；介面沒有建構子，但可以當參考型別。
  • 空介面只貼標籤；實作 Cloneable 不等於自動就複製得了。

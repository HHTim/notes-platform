程式碼的地址

套件替類別分組，也避免名稱撞車

套件（package）像類別的地址。不同團隊都可以有自己的 Date 或 User，只要住在不同套件，完整名稱就不一樣。慣例是全小寫，並用反過來寫的網域名稱降低撞名機會，例如 tw.example.billing。

一個 Java 原始檔裡的三種元素都不是必要的，但只要出現就得照這個順序：

package 宣告 → import 敘述 → 類別等型別宣告

package tw.example.app;

import java.time.LocalDate;
import java.util.ArrayList;

public class Main {
    public static void main(String[] args) {
        ArrayList<LocalDate> dates = new ArrayList<>();
    }
}

一個原始檔最多只能有一個 public 頂層類別，而且檔名要跟它一致；同一個檔案裡還是可以放其他非公開的類別。原筆記給的理由很實際：那些類別別的地方用不到，放在一起互相搭配還比較好讀。

常用的標準套件：java.lang（語言核心，String 就住這）、java.io（輸入輸出）、java.net（網路）、java.util（工具與集合）、java.sql（資料庫）。Java 9 之後這些都被收進 java.base 這個模組裡。

尋找類別

import 省的是名稱，不是把程式載進來

import 只是讓你可以寫簡短的類別名稱，不會把任何東西複製或載入到你的檔案裡。兩個地方不必匯入：java.lang 裡的型別，以及跟你同一個套件的型別。

import java.sql.Date;

Date sqlDate = new Date(System.currentTimeMillis());
java.util.Date utilDate = new java.util.Date();   // 完整限定名稱

兩個套件都有 Date 的時候，不可能讓兩個都用簡名，至少要有一個寫成完整限定名稱（fully qualified name，連套件一起寫）。

星號只涵蓋指定的那個套件，不會連子套件一起匯入——import java.util.*; 不會匯入 java.util.function 裡的東西。

靜態匯入（static import，Java 5 起）可以連類別名稱都省掉：

import static java.lang.Math.PI;
import static java.lang.Math.sin;

double value = sin(PI / 2);   // 不必寫 Math.sin(Math.PI / 2)

數學式用一點會清楚很多，但用太多讀的人就看不出這個成員是從哪來的，原筆記也特別提醒了這點。

編譯與執行

目錄位置與類別路徑要對得上套件名稱

套件名稱對應目錄階層。類別宣告在 tw.example.app，編譯出來的 .class 就會放在 tw/example/app 底下。執行時要用完整類別名稱：

javac -d out src/tw/example/app/Main.java
java -cp out tw.example.app.Main

-d 指定編譯輸出的根目錄；類別路徑（classpath）則告訴編譯器與 JVM 去哪些根目錄或 jar 檔找類別。注意它指的是套件樹的起點，不是某個 .class 檔本身的路徑。

原筆記把搜尋順序分成 Bootstrap、Extension、User 三類，那是 Java 8 的世界。Java 9 把執行環境改成模組化映像檔之後，rt.jar 與 jre/lib/ext 這個擴充機制都已經拿掉了，現在實務上只剩你自己設定的類別路徑（以及模組路徑）出處。日常開發多半交給 Maven 或 Gradle 處理，很少手動設。

共同祖先

所有類別追到底都是 Object

沒寫父類別的類別直接繼承 java.lang.Object；有父類別的，也會沿著繼承鏈間接連到它。所以任何物件都用得到 Object 定義的那幾個方法。

方法做什麼
toString()給物件一段文字表示，方便記錄、列印與除錯
equals(Object)由你定義「兩個物件算不算相等」
hashCode()給一個整數，供雜湊型集合搭配 equals 使用
getClass()取得物件執行時的類別資訊
wait()、notify()、notifyAll()執行緒之間的協調（第 10 課）

equals(Object obj) 的參數之所以是 Object，就是要讓任何物件都傳得進來比較。System.out.println(物件) 印的是 toString() 的結果；沒覆寫的話那串預設內容對人類沒什麼意義，所以自訂類別通常會給一個好讀的版本。

Object 還有一個 finalize()，原筆記說它在 Java 9 被標記廢棄，這是對的；後續還有一步——Java 18 起已經標記為準備移除，官方明講不要靠它釋放資源出處。要收尾請用 try-with-resources（第 7 課）。

相等的定義

== 看是不是同一個，equals 看內容一不一樣

對參考型別而言，== 比的是兩個參考指不指向同一個物件；equals() 則可以由類別自己覆寫，定義什麼叫「內容相等」。

final class Member {
    private final int id;
    private final String name;

    Member(int id, String name) {
        this.id = id;
        this.name = name;
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (!(obj instanceof Member other)) return false;   // Java 16 起的寫法
        return id == other.id && Objects.equals(name, other.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id, name);
    }

    @Override
    public String toString() {
        return "Member{id=" + id + ", name='" + name + "'}";
    }
}

覆寫了 equals() 就要一起覆寫 hashCode()。不然物件丟進 HashSet、或當 HashMap 的鍵時，會出現「明明放進去了卻查不到」這種怪事。

官方約定只有兩個方向：同一個物件多次呼叫 hashCode() 要給同樣的值；equals() 相等的兩個物件，hashCode() 必須相同。反過來沒有要求——equals() 不相等的物件，雜湊碼完全可以一樣，那叫雜湊碰撞（hash collision），是正常現象出處。

先用 hashCode() 粗篩位置，再用 equals() 精確確認——像先看郵遞區號，再核對完整地址

這裡的因果反了：hashCode() 是先產生一個整數，HashMap 這類雜湊表再拿它去用，不是雜湊表算出 hashCode。官方文件只規定「同一個物件每次要回傳同樣的值」，至於那個值怎麼算出來（是不是由記憶體位址來的）並沒有規定出處。這也是為什麼不覆寫就直接丟進 HashSet，兩個內容相同的物件會被當成兩筆。

基本型別的物件外衣

包裝類別、裝箱與拆箱

整數byte→Byte、short→Short、int→Integer、long→Long
浮點數float→Float、double→Double
其他char→Character、boolean→Boolean

把基本型別包成物件叫裝箱（boxing），反過來取出值叫拆箱（unboxing）。為什麼要裝箱？因為集合、泛型這些地方只收參考型別。Java 5 起編譯器會自動幫你裝拆，所以平常寫起來沒什麼感覺。

Integer boxed = 10;   // 自動裝箱
int number = boxed;   // 自動拆箱

int parsed = Integer.parseInt("42");      // 回傳 int
Integer wrapped = Integer.valueOf("42");  // 回傳 Integer

parseXxx() 給你基本型別，valueOf() 給你包裝物件

原筆記說 Java 9 起改用 Integer.valueOf()，這是對的；後續還有一步——Java 16 起，包裝類別的建構子已經標記為準備移除，現在等於是不能再寫 new Integer(...) 了出處。valueOf() 省的不只是一次配置——小範圍的整數它會重複使用快取好的物件。

兩個常見的坑：

  • 比包裝物件的值要用 equals()。因為有快取，== 在小數字時看起來會相等、換成大數字又不相等，很容易誤判。
  • 自動拆箱一個 null 會丟 NullPointerException。Integer 可以是 null，int 不行。

重點整理

  • 套件是類別的命名空間，也對應目錄階層；套件名稱全小寫、用反向網域。
  • import 只是讓名稱可以寫短；星號不包含子套件。
  • classpath 指的是套件樹或 jar 的搜尋起點；Java 9 之後 rt.jar 與 ext 機制已經沒了。
  • == 比是不是同一個物件，覆寫過的 equals() 才比內容。
  • 覆寫 equals() 就要一起覆寫 hashCode()；但雜湊碼相同不代表物件相等。
  • parseInt() 給 int、valueOf() 給 Integer；比包裝物件的值用 equals()，小心拆箱 null。

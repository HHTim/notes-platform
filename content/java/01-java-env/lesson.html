先建立全貌

Java 是什麼

Java 是一種高階、物件導向、強型別的程式語言。它刻意不讓你直接去碰記憶體位址，不再使用的物件也交給垃圾回收器（garbage collector，自動把沒人用的記憶體收回去的機制）處理，所以比起要自己管記憶體的語言好入門得多。

它最有名的特色是跨平台：原始碼先編譯成跟作業系統無關的位元碼（bytecode），再交給各平台自己的 Java 虛擬機器（JVM）執行。像是先把稿件翻成一份共通格式，再由各地的口譯員轉成當地語言。

Java 由昇陽電腦（Sun Microsystems）在 1995 年推出，早期叫 Oak；2009 年 4 月 20 日 Oracle 發的是「雙方簽訂收購協議」的公告，實際完成合併要到 2010 年 1 月出處。它主要用在伺服器端系統、企業應用、開發工具，以及各種要跨平台的軟體。初學語法通常從 Java SE（標準版）開始，企業端那一套後來改名叫 Jakarta EE。

程式怎麼跑起來

從 .java 到 .class

你寫的檔案叫原始碼（source code），副檔名是 .java。編譯器 javac 會檢查語法、產生含有位元碼的 .class 檔；接著 JVM 把這個 .class 載進來執行。

HelloWorld.java
      │ javac HelloWorld.java   ← 編譯
      ▼
HelloWorld.class
      │ java HelloWorld         ← 執行
      ▼
JVM 載入位元碼，在目前這台機器上跑

負責編譯的是 javac，負責執行的是 JVM——不是「JVM 編譯、JRE 執行」，也不能說 JVM 是編譯器出處。JRE 是「JVM＋標準函式庫」這一整包執行環境，它本身不做編譯。

「一次編譯，到處執行」不是說平台差異全部消失，而是同一份相容的位元碼，可以交給 Windows、macOS、Linux 上各自適用的 JVM 去跑。

三個縮寫一次分清楚

JVM、JRE 與 JDK

縮寫全名它負責什麼
JVMJava Virtual Machine
Java 虛擬機器		載入並執行位元碼
JREJava Runtime Environment
Java 執行環境		JVM＋執行程式需要的標準函式庫
JDKJava Development Kit
Java 開發工具組		開發與執行都有：javac、java、javadoc 等

JVM 是引擎，JRE 是能把車開上路的整套設備，JDK 再加上製造與維修的工具

要寫程式，直接裝 JDK 最省事。Java 9 把執行環境改成模組化映像檔之後，JDK 內就沒有獨立的 jre 目錄了，Oracle 也不再單獨發行 JRE 安裝檔出處。概念上 JRE 還在（就是 JDK 裡那份執行環境），但你不會再看到那個資料夾。

拿 JavaScript 來對照可以幫助理解：Node.js 讓 JavaScript 能在瀏覽器以外執行，JVM 讓位元碼能在各平台執行。但這只是比喻——Node.js 是一套執行環境，JDK 除了執行還包含編譯器與各種開發工具，涵蓋範圍不一樣。

準備工具

裝 JDK、設環境變數

依你的作業系統與處理器架構下載對應的 JDK 裝好，然後在終端機（Windows 是命令提示字元）打：

java -version
javac -version

兩個指令都印得出版本，表示指令搜尋路徑大致設對了。java 是啟動程式的工具，javac 是編譯器。

PATH作業系統的地址簿，讓你在任何資料夾都叫得到 java 與 javac。
JAVA_HOME指向 JDK 的安裝目錄，讓建置工具（Maven、Gradle）和其他程式找得到 JDK。
CLASSPATH告訴編譯器與 JVM 去哪些根目錄或 jar 檔找類別。現在多半交給建置工具處理，很少手動設。
JAVA_HOME = JDK 安裝目錄
PATH 加入 %JAVA_HOME%\bin（Windows）或 $JAVA_HOME/bin（macOS、Linux）

路徑寫起來像 JAVA_HOME C:\jdk-17.0.6 這樣。實際畫面與路徑會隨作業系統和你挑的 JDK 發行版而不同。

現在該裝哪一版

版本界線：長期支援版與幾個分水嶺

Java 每半年出一版，但只有少數版本是長期支援版（LTS，Long-Term Support，官方保證長期修補的版本）。到 2026 年，手上在用的長期支援版是 Java 21（2023 年 9 月）與 Java 25（2025 年 9 月）；新專案通常直接從這兩個挑出處。

這個模組後面會一路標出哪些寫法是哪一版才有的。先記住幾個分水嶺就好：

  • Java 8：介面可以有帶實作的方法（default、static），Lambda 與 Stream 進來。
  • Java 9：模組化，rt.jar 與獨立的 jre 目錄消失。
  • Java 10：區域變數可以寫 var。
  • Java 14〜17：switch 可以當運算式用、文字區塊、record、sealed 類別。
  • Java 21：虛擬執行緒、switch 的型樣比對正式定案。

第一支程式

編譯與執行 Hello World

public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello World!");
    }
}

存成 HelloWorld.java。檔名必須跟公開類別（public class）的名稱完全一致，大小寫也要一樣；非公開的類別不受這條限制。至於「類別名稱大寫開頭」是命名慣例，不是編譯器會擋的規定出處。

javac HelloWorld.java
java HelloWorld

第一行產生 HelloWorld.class；第二行傳的是類別名稱，不要加 .class。成功就會印出 Hello World!。

那一行宣告裡的四個字各有職責：

public讓啟動器存取得到這個方法。
static不必先建立物件就能呼叫。把類別載進來的是 JVM 的類別載入機制，不是作業系統出處。
void這個方法不回傳資料。
String[] args接收命令列引數的字串陣列。

JVM 去找 main() 方法來執行，是 java 啟動器這一端的事；javac 只出現在編譯階段，兩者不要混在一起講出處。

開發工具

IDE 與 Eclipse

整合開發環境（IDE，Integrated Development Environment）把編輯、編譯、執行、除錯與程式碼提示集中在同一套工具裡。Java 界常見的是 Eclipse、IntelliJ IDEA 與 Visual Studio Code。

Object Technology International 確實在 1996 年被 IBM 併購，但 Eclipse 專案是 IBM 在 2001 年 11 月才建立並釋出、由一群廠商組成聯盟支持；獨立的 Eclipse 基金會要到 2004 年初才成立出處。

Eclipse 的設計特色是「什麼都是外掛」，核心之外的功能都用外掛加上去，所以擴充性強。但用 IDE 並沒有改變 Java 的流程——它只是代替你去呼叫編譯器與執行工具，再把結果畫得好看一點。

重點整理

  • .java 是原始碼，javac 把它編成含位元碼的 .class，JVM 負責執行——編譯跟執行是兩個人的事。
  • JVM 執行、JRE 是執行環境、JDK 是開發工具組；要寫程式就裝 JDK。
  • 跨平台靠的是各平台自己的 JVM，不代表所有系統細節都一樣。
  • 只有 public 類別強制跟檔名同名；大寫開頭是慣例不是規定。
  • Java 9 之後 JDK 裡沒有獨立的 jre 目錄了，舊教材的目錄圖要換掉。
  • 現在挑版本從長期支援版下手：Java 21 或 Java 25。

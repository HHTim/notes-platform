先保護物件狀態

封裝與存取修飾子

封裝（encapsulation）像替物件裝一道有管理員的門：資料不讓外面隨便動，要改得透過方法，方法可以先檢查這樣改合不合理。標準做法是欄位設 private，再開必要的公開方法。

修飾子同一個類別同套件不同套件的子類別其他任何類別
public可可可可
protected可可可，但有限制不可
不寫（package-private）可可不可不可
private可不可不可不可

protected 那一格的「可，但有限制」是重點：不同套件的子類別確實看得到 protected 成員，但只能透過自己或自己子型別的參考去存取，不能拿一個父類別型別的參考就隨便碰出處。面試集第 1 課〈Java 基礎快答〉的表格寫「同套件的類別＋所有子類別」，那是速查用的簡版，這裡補的是規格上的細節。

兩個限制要記得：頂層類別只能用 public 或不寫（內部類別四種都能用）；區域變數不能加任何存取修飾子，因為它的能見範圍早就由所在的方法決定了。

不是每個欄位都要開放

Getter、Setter 與有效狀態

class Product {
    private int price;

    public int getPrice() {
        return price;                  // 讀：有回傳型別、有 return
    }

    public void setPrice(int price) {  // 寫：通常是 void、一定有參數
        if (price < 0) {
            throw new IllegalArgumentException("價格不可為負數");
        }
        this.price = price;
    }
}

Getter 讀、Setter 寫，但兩者不一定要成對出現。建立之後就不該改的資料，只給 Getter 就好；要同時維持好幾個欄位的一致性時，設計一個有意義的方法（像 applyDiscount()）會比機械式地每個欄位配一組 get/set 好得多。

抽出共同特徵

繼承、is-a 與 has-a

繼承（inheritance）讓子類別延伸父類別可存取的狀態與行為，語法是 extends：

class Employee {
    protected String name;
}

class FullTimeEmployee extends Employee {
    private double monthlySalary;
}

FullTimeEmployee 是一種 Employee——這是 is-a；它有一個 monthlySalary——這是 has-a。只有真的符合「是一種」才適合用繼承。原筆記把「濫用繼承」的兩個徵兆講得很清楚：資料關係跟現實邏輯對不上，還有子類別拿到錯誤或不必要的能力。

三件要記的事：Java 類別只能繼承一個父類別；建構子不會被繼承（因為建構子名稱必須跟自己的類別同名）；所有類別追到底都是 java.lang.Object 的後代。另外，父類別的 private 方法不會被子類別繼承——子類別寫同名方法也不算覆寫。

父類別先準備共同部分

super、建構順序與 final

class Employee {
    private final String name;

    Employee(String name) {
        this.name = name;
    }
}

class Manager extends Employee {
    Manager(String name) {
        super(name);      // Java 24 以前一定要放第一行
    }
}

建立子類別物件時，先完成父類別那一段，再完成子類別，這樣才能保證共同資料一定初始化過。super(...) 呼叫的是直接父類別的建構子；沒寫的話編譯器會自己補一個 super()。super(...) 與 this(...) 只能擇一。

「一定要放在第一個敘述」這條到 Java 24 為止都成立，Java 25 放寬了：super(...) 與 this(...) 前面可以先寫敘述，常見用途是先驗證參數再呼叫父類別建構子；限制是那段前置程式不能存取正在建立中的物件出處。不變的是：兩者仍然只能擇一，而且父類別那一段一定先完成。

原筆記寫「super：1. 只會出現在override方法裡」。實際上 super.方法() 寫在子類別的任何實體方法裡都合法，只是最常出現在覆寫方法中——因為那裡不加 super. 就變成自己呼叫自己（原筆記的第 3 點講的正是這個，那句沒錯）。真正的限制是不能用在靜態環境裡。這一條沒有在官方文件上找到可以直接對照的原文，所以標成補充而不是更正。

另外 super. 不能越級，只找得到直接父類別。

final 放在不同位置有不同意思：

final 類別不能被繼承。String、Math 都是。
final 方法不能被覆寫。
final 基本型別變數值不能再改，就是常數。
final 參考變數不能再指向別的物件；但那個物件內部可不可變，由它自己的設計決定。

保留名稱，換上專屬行為

方法覆寫

覆寫（override）是子類別不滿意繼承來的方法，重新寫一份自己的。規則：

  • 方法名稱、參數的數量與型別都要跟父類別一樣。
  • 回傳型別要相容——Java 5 起，如果回傳的是類別，可以改成原本那個型別的子型別（叫共變回傳型別）。
  • 存取權限只能相同或更開放，不能縮小。
  • 丟出的受檢例外不能比父類別那個更廣（第 7 課細講）。
class Animal {
    public void makeSound() {
        System.out.println("動物的聲音");
    }
}

class Dog extends Animal {
    @Override
    public void makeSound() {
        System.out.println("汪汪");
    }
}

@Override 請編譯器幫你確認「我真的覆寫到了」，拼錯名稱或參數寫錯它會直接報錯，很值得養成習慣。

多載＝同名、參數不同，編譯期就決定；覆寫＝繼承關係裡重寫同一個方法，執行期才決定

原筆記提到「static 方法不拿來討論覆寫，因為覆寫是物件導向機制」——這句是對的。子類別寫一個同名的 static 方法叫「隱藏」（hiding），不會有多型效果。

同一個操作，各自回應

多型與動態繫結

多型（polymorphism）＝用父型別的變數指向子類別的物件。呼叫被覆寫的方法時，JVM 會看執行時實際是哪個物件來挑版本，這叫動態繫結（dynamic binding，也叫延遲繫結）。

Animal[] animals = {
    new Dog(),
    new Cat(),
    new Duck()
};

for (Animal animal : animals) {
    animal.makeSound();   // 同一行，三種結果
}

這就是多型的價值：再多加一種 Animal 子類別，走訪這個陣列的程式通常一個字都不用改，也省掉一長串 if (是狗) … else if (是貓) …。

變數叫得動哪些方法，看宣告型別；實際執行哪個版本，看執行期的物件

原筆記的比較表寫「靜態繫結速度較快、動態繫結速度較慢」。觀念上沒錯，但現在的 JVM 會在執行期分析實際型別並把呼叫最佳化掉，實務上大多數情況量不出差別——不要為了這個理由避開多型。

向下轉型要先確認

型別轉換與 instanceof

子類別物件可以自動當成父型別用（向上轉型，不會失敗）。反過來要把父型別參考轉回子型別，得自己明寫轉型，而且是執行時才檢查——轉錯就是 ClassCastException。

Animal animal = new Dog();

if (animal instanceof Dog) {
    Dog dog = (Dog) animal;
    dog.fetch();
}

// Java 16 起可以合成一行：
if (animal instanceof Dog dog) {
    dog.fetch();
}

instanceof 檢查左邊的物件能不能當成右邊的型別用。Java 16 起 instanceof 可以在檢查成功的同時順手宣告好變數，省掉那行重複的轉型出處。

如果程式到處都在判斷具體子型別，通常表示共同介面或多型方法沒設計好——真正該做的是把那個行為變成父型別上的一個方法。

哪些類別可以繼承我

補充：sealed 類別

原筆記講繼承控制時只有 final 這個選項——要嘛誰都能繼承，要嘛誰都不能。Java 17 起多了 sealed：可以指名只允許哪幾個類別繼承出處。

public sealed class Shape permits Circle, Square { }

final class Circle extends Shape { }
final class Square extends Shape { }

好處是「這個型別總共就這幾種」變成編譯器知道的事，搭配 switch 的型樣比對時，少漏一種它會直接提醒你。

重點整理

  • 封裝＝欄位設 private，透過有規則的方法維持資料有效；Getter、Setter 不必成對。
  • 繼承表達 is-a，欄位與組合表達 has-a；「是一種」對不上就別用繼承。
  • 覆寫時存取權限只能放寬不能縮小；@Override 幫你抓打錯。
  • 多載編譯期決定、覆寫執行期決定；多型讓同一行程式對不同物件做對的事。
  • 向上轉型安全，向下轉型會在執行期檢查，先用 instanceof 確認。
  • super.方法() 可以寫在子類別的任何實體方法裡，不限覆寫方法。

先選對容器

List、Set 與 Map 怎麼挑

集合像不同用途的收納櫃：有的保留放進去的順序，有的負責排掉重複，有的用標籤查內容。挑的時候先看資料的語意，不要只挑自己最熟的那個類別。

介面特性常見實作適合什麼
List有位置順序、允許重複ArrayList、LinkedList購物清單、訊息紀錄
Set元素不重複；順序看實作HashSet、LinkedHashSet、TreeSet標籤、不重複的會員編號
Map一對鍵與值；鍵不重複HashMap、LinkedHashMap、TreeMap用學號找學生、用商品編號找庫存
 
List<String> names = new ArrayList<>();
names.add("小華");
names.add("小華");   // List 允許重複，現在有兩筆

Set<String> tags = new HashSet<>();
tags.add("Java");
tags.add("Java");    // 第二次不會加進去

Map<String, Integer> stock = new HashMap<>();
stock.put("A001", 10);
stock.put("A001", 8);  // 同一個鍵，新值蓋掉舊值

Map 用的是 put()、get()、keySet()、values() 這一組。keySet() 回傳 Set（因為鍵不重複），values() 回傳的卻是 Collection——原筆記解釋得很好：值可以重複，所以 Set 不適合；值又沒有順序保證，所以 List 也不適合，只好往上找共同的父介面。用鍵查不到東西時回傳 null。

Map 是集合框架（Collections Framework）的一員，只是它沒有繼承 Collection 這個介面——這兩件事不一樣。官方文件把 Map 明列為框架的核心介面之一出處。它之所以不繼承 Collection，是因為那個介面的方法（add(E) 之類）套在鍵值對上講不通。

順序不是共同保證

Hash、LinkedHash 與 Tree 家族

「Set 沒有順序」講的是這個介面本身不做保證，這沒錯；但容易被讀成「所有 Set 都沒順序」。Set 只規定元素不重複，要不要維持順序完全看實作類別。至於 HashMap，官方說的是「不保證走訪順序」，並不是每次跑都隨機洗牌——官方文件的用字是 makes no guarantees as to the order，意思是你不該依賴它，而不是它真的在擲骰子出處。

實作走訪順序靠什麼判斷重複或排序
HashSet / HashMap不保證hashCode() 搭 equals()
LinkedHashSet / LinkedHashMap維持放進去的順序hashCode() 搭 equals()
TreeSet / TreeMap依自然順序或你給的比較規則排序比較結果是不是 0

雜湊型集合：先用 hashCode() 找可能的位置，再用 equals() 確認是不是同一筆

所以自訂物件若覆寫了 equals()，就必須一起覆寫 hashCode()，否則放進 HashSet 會出現「明明一樣卻被當成兩筆」。這個約定的細節（包括原筆記寫錯的那一條）在第 6 課有完整說明。

Tree 家族走的是另一條路：靠 compareTo() 或 Comparator 的比較結果判斷重不重複，跟 equals()、hashCode() 沒關係。比較結果為 0 就被視為同一個排序鍵。所以自訂類別要放進 TreeSet，得實作 Comparable 並覆寫 compareTo()，而且一樣大的元素要記得回傳 0。

原筆記把 LinkedHashSet、LinkedHashMap 的順序說成「先進先出」。它們維持的是走訪時照放進去的順序，跟佇列那種「先進先出取出後就消失」不是同一件事，叫「插入順序」比較不會誤會。

把型別錯誤提前抓出來

泛型讓集合更安全

泛型（generics，Java 5 起）像在容器外面貼一張「只收字串」的標籤。編譯器會擋掉不相容的型別，取出來時也不必再從 Object 手動轉型。

List<String> cities = new ArrayList<>();
cities.add("臺北");
// cities.add(100);          // 編譯就錯，不會拖到執行期

String city = cities.get(0); // 不必轉型

原筆記把好處講得很清楚：原本要等到執行期才炸出來的 ClassCastException，現在編譯階段就擋住了。

角括號裡只能放參考型別（類別、介面、陣列），所以整數要用包裝類別：

List<Integer> scores = new ArrayList<>();   // 對
// List<int> scores = new ArrayList<>();    // 錯

自訂類別也可以宣告型別參數。設計類別時還不確定使用者會傳什麼進來，就用 T 先頂著：

class Box<T> {
    private T value;
    public void set(T value) { this.value = value; }
    public T get() { return value; }
}

Box<String> box = new Box<>();
box.set("教材");

上下界不是「什麼都能放」

extends 與 super 的方向

? 是萬用字元，代表「某個還沒確定的型別」。加上上下界，方法就能接受一整群相關型別，又不會失去安全性。

  • ? extends Number：實際型別是 Number 或它的子型別。適合拿來讀——不管實際是什麼，讀出來一定當得成 Number。
  • ? super Integer：實際型別是 Integer 或它的父型別。適合拿來寫——不管實際是什麼，塞 Integer 進去一定合法。

要讀就用 extends，要寫就用 super

double total(List<? extends Number> values) {
    double sum = 0;
    for (Number value : values) {   // 讀出來都是 Number
        sum += value.doubleValue();
    }
    return sum;
}

void addDefaults(List<? super Integer> values) {
    values.add(0);                  // 寫 Integer 一定安全
    values.add(1);
}

為什麼 List<? extends Number> 不能隨便 add？因為編譯器不知道它實際是 List<Integer> 還是 List<Double>，塞錯就爆了，乾脆一律不准。

用同一套方式走訪

Iterator、Iterable 與 for-each

把資料一個一個取出來叫遍歷（traverse），迭代器（Iterator）就是它的實作。Collection 提供 iterator() 方法回傳一個迭代器，常用的就兩個方法：hasNext() 問還有沒有下一個，next() 取下一個。

Iterator<String> iterator = names.iterator();

while (iterator.hasNext()) {
    String name = iterator.next();
    System.out.println(name);
}

為什麼 Iterator 要做成介面？原筆記答得很好：ArrayList 有迭代器、HashSet 也有，通通叫 Iterator，用法就一致了。

Iterable（Java 5 加入）表示「我生得出迭代器」，它唯一的方法 iterator() 回傳的是 Iterator<T>，不是 Iterable——原筆記兩處都抄錯了出處。Collection 從 Java 5 起繼承 Iterable，所以 List、Set、Queue 全都能用增強式 for 迴圈（for-each）走訪。

for (String name : names) {
    System.out.println(name);
}

Map 本身沒有繼承 Iterable，不能直接對它 for-each，但可以走訪它提供的檢視集合。同時要鍵和值，走 entrySet() 最直接：

for (Map.Entry<String, Integer> entry : stock.entrySet()) {
    System.out.println(entry.getKey() + ": " + entry.getValue());
}

「傳統 for 比 for-each 快」只在陣列、ArrayList 這種能用索引直接取值的結構上說得通。換成 LinkedList，每次 get(i) 都要從頭走一遍，整個迴圈會從線性變成平方級——那時候 for-each（走迭代器）反而快得多出處。原筆記說的「彈性較大」是對的：要索引、要反向走、要精細控制時，傳統 for 還是比較合適。

走訪途中想刪掉目前這個元素，要用迭代器的 remove()，不能直接動集合，否則會拿到 ConcurrentModificationException。

名稱只差一個 s

Collection 與 Collections

Collection集合階層裡的介面，底下主要有 List、Set、Queue 三個子介面。
Collections提供集合工具方法的類別，全是靜態方法：排序、反轉、找最大最小值。
List<Integer> numbers = new ArrayList<>(List.of(3, 1, 2));

Collections.sort(numbers);            // 依自然順序由小到大
int maximum = Collections.max(numbers);

自訂物件要有「自然順序」就實作 Comparable、覆寫 compareTo()；不想把排序規則寫死在類別裡，就另外給一個 Comparator。

原筆記寫在這些語法出現之前，所以全部用 new ArrayList<>() 再一筆筆 add。Java 9 起有 List.of(...)、Set.of(...)、Map.of(...) 可以一行建好，但要注意它們產生的是不可修改的集合，再 add 會丟例外——想要能改的就像上面那樣再包一層 new ArrayList<>(...)。

集合的取捨（ArrayList 與 LinkedList 怎麼選、Vector 為什麼被淘汰）在面試集第 1 課〈Java 基礎快答〉有速查版。

重點整理

  • List 有順序可重複、Set 元素唯一、Map 一個鍵對一個值。
  • Set 只保證不重複，順序看實作：Hash 不保證、LinkedHash 維持插入順序、Tree 依比較規則排序。
  • Hash 家族靠 hashCode()＋equals() 判重複，Tree 家族靠 compareTo() 是不是 0。
  • Map 是集合框架的一員，只是沒有繼承 Collection。
  • 泛型把型別錯誤提前到編譯期；角括號裡只能放參考型別。
  • 要讀用 ? extends，要寫用 ? super。
  • Iterable.iterator() 回傳的是 Iterator；for-each 在 LinkedList 上比傳統索引 for 快得多。

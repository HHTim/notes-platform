讀完這課你會

  • 從零建立一個現代 Angular 專案，或正確接手別人的既有專案
  • 拿到一張「需求 → Angular 工具」的對照地圖，涵蓋表單、HTTP 與路由
  • 知道交付前至少要做哪些品質檢查

開始之前

準備工具與版本

需要 Node.js、隨附的套件管理工具 npm、Git，以及支援 TypeScript 的編輯器（VS Code 加 Angular Language Service 擴充是常見組合）。Node.js 的版本要看目標 Angular 版本的相容性表：Angular 17 要求 ^18.13.0 || ^20.9.0，Angular 20 要求 ^20.19.0 || ^22.12.0 || ^24.0.0，「16+」已經不夠出處。

node -v
npm -v
git --version

建立與執行

用 CLI 建立 standalone 專案

npx @angular/cli new notes-app
cd notes-app
npm start

npx 會直接執行指定版本的 CLI，避免「全域裝的版本」和「專案要的版本」不一致。已全域安裝 Angular CLI 的話，ng new、ng serve 也一樣能用。開發伺服器常用參數：

ng serve --open        # 啟動後自動開瀏覽器
ng serve --port 8888   # 換連接埠
ng serve --host 0.0.0.0  # 讓同網路的其他裝置連入

綁 0.0.0.0 等於向整個區域網路開放開發伺服器，只在確有需要（例如給後端同事連）且網路可信時使用。

接手既有專案

先照 lockfile 安裝相依套件

git clone <repository-url>
cd <project-directory>
npm ci
npm start

lockfile（package-lock.json，記錄每個套件確切版本的鎖定檔）同步且可信時，乾淨安裝優先用 npm ci——照鎖定檔一字不差地重現；日常新增或調整套件才用 npm install。

樣板驅動表單直接在 HTML 上用 ngModel 疊，欄位少最快；響應式表單在 TypeScript 裡明確建立結構與驗證器，欄位多、驗證嚴的表單好測試也好維護。

品質與效能

完成不等於畫面能動

  • 用 ng build 驗證正式建置能過。
  • 跑專案設定的測試指令（預設 ng test）。
  • 大型功能用路由層級的延遲載入（loadComponent），首包不揹全部程式。
  • 清單用穩定的 track 值。
  • 驗證輸入並使用 HTTPS；前端驗證擋不住直接打 API 的人，後端驗證不能省。

舊教材的 ng build --prod 已經不能用：這個參數在 CLI v12 棄用、v14 移除，現代 CLI 的 ng build 預設就是正式組態，要指定時用 ng build --configuration production出處。

原筆記也列了 ng lint：新專案預設沒有安裝 lint（程式碼風格與常見錯誤的靜態檢查）工具，第一次執行會問你要不要裝 angular-eslint，裝好才有得跑。

重點整理

  • Node.js 版本照目標 Angular 版本的相容性表挑，Angular 17 起最低 18.13。
  • 新專案用 npx @angular/cli new；接手專案乾淨安裝用 npm ci。
  • API 用 provideHttpClient()、路由用 provideRouter(routes) 在應用層明確提供。
  • 簡單表單用 ngModel、複雜表單用響應式表單。
  • ng build --prod 已移除；交付前至少過正式建置與測試。

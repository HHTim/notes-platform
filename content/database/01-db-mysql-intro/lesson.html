先從電腦怎麼放資料開始

記憶體像工作桌，硬碟像檔案櫃

程式執行時，資料會在不同儲存位置之間移動。中央處理器（Central Processing Unit，CPU）負責運算；主記憶體（Random Access Memory，RAM）暫放正在執行的程式與資料；硬碟或固態硬碟則負責長期保存。

位置白話比喻特性
CPU 暫存器與快取手上正在看的便條紙速度最快、容量很小
主記憶體工作桌方便快速取用，但斷電後內容會消失
硬碟或固態硬碟檔案櫃速度較慢，但可長期保存大量資料

例如開啟通訊軟體時，程式會從硬碟載入主記憶體，再由 CPU 執行。尚未存檔的圖片先放在記憶體；按下儲存後，才會寫入硬碟長期保存。

由快到慢：CPU 暫存器與快取 → 主記憶體 → 硬碟等長期儲存裝置。

有資料，還要有人管理

資料庫不等於資料庫管理系統

資料庫（Database，DB）是有組織的資料集合；資料庫管理系統（Database Management System，DBMS）則是負責建立、讀取、修改、保護與備份資料庫的軟體。

可以把資料庫想成倉庫裡的貨物與貨架，把 DBMS 想成倉儲管理中心。應用程式通常不會自行翻動硬碟上的資料，而是向 DBMS 提出要求，再由 DBMS 處理權限、並行操作與資料一致性。

DB有組織地保存資料的集合。
DBMS管理資料庫的軟體，例如 MySQL、PostgreSQL。
SQL操作關聯式資料庫的語言。
資料庫伺服器執行 DBMS、接受用戶端連線的主機或服務環境。

原筆記說「一台電腦，安裝且開啟了 DBMS，即為資料庫伺服器」——這是最常見的情況，但資料庫伺服器不一定獨占一台實體電腦，也可能是虛擬機器、容器或雲端代管服務。

把資料排成有規則的表格

關聯式資料庫的核心物件

關聯式資料庫（Relational Database）以資料表表達資料與關係。MySQL、PostgreSQL、Oracle Database 與 Microsoft SQL Server 都屬於常見的關聯式資料庫管理系統（RDBMS）。

物件用途例子
資料庫／綱要組織一組相關物件商店系統
資料表（Table）保存同類型的資料customers
欄位（Column）定義每項資料的名稱與型態customer_name
資料列（Row）代表一筆紀錄某一位顧客
值（Value）某筆紀錄在某欄位的內容「阿寶」
檢視表（View）以查詢定義的虛擬資料表active_customers
索引（Index）以額外空間換取特定查詢速度email 索引

在 MySQL 中，SCHEMA 與 DATABASE 是同義詞；其他資料庫產品（例如 PostgreSQL、SQL Server）則把綱要（Schema）設計成資料庫之下的一層命名空間（namespace，同名物件靠它分隔、不打架）。

原筆記把綱要列為第 3 層並註明 MySQL 沒有這一層、等同於資料庫——這個講法是對的；補充：MySQL 連 SCHEMA 關鍵字都有，官方明訂 CREATE SCHEMA 是 CREATE DATABASE 的同義詞出處。

一張資料表像試算表，但不只是格子：欄位有型態、資料可受約束，而且資料表之間能建立關聯。

資料型態是資料的使用說明

為欄位選擇合適的資料型態

電腦底層以位元（bit）表示 0 或 1，8 個位元合起來是 1 個位元組（byte）。資料型態則告訴 DBMS：這串位元應被當成整數、文字、日期，還是其他內容。

類型常見 MySQL 型態適用資料
整數INT、BIGINT數量、流水號
精確小數DECIMAL金額、需精確計算的比例
浮點數FLOAT、DOUBLE允許近似值的科學量測
文字CHAR、VARCHAR、TEXT代碼、姓名、文章內容
日期時間DATE、DATETIME、TIMESTAMP生日、訂單時間
真假值BOOLEAN啟用狀態；在 MySQL 中是 TINYINT(1) 的別名

CHAR(n) 適合長度固定的內容，例如固定格式代碼；VARCHAR(n) 適合長度不固定的文字。實際占用空間由欄位的字元集決定：MySQL 建議的 utf8mb4 每個字元占 1〜4 個位元組（英文字母 1 個、常用中文字 3 個），不能用「英文 1 個位元組、非英文 2 個位元組」概括出處。

那套「n 開頭型態存 Unicode」的分類是 SQL Server 的規則。MySQL 雖然也接受 NCHAR、NVARCHAR 寫法，但會被當成過時的 utf8mb3 字元集並發出警告；官方建議直接用 CHAR／VARCHAR 搭配 utf8mb4，即可完整保存中文與各國文字出處。

金額用 DECIMAL；不要用 FLOAT 或 DOUBLE 承擔必須精確到分的帳務計算。

MySQL 是系統，SQL 是溝通語言

認識 MySQL 與 SQL

MySQL 是一套 RDBMS（現由 Oracle 開發維護）；結構化查詢語言（Structured Query Language，SQL）才是用來操作關聯式資料庫的語言，自 1986 年起有 ANSI/ISO 標準出處。SQL 有共同標準，但不同資料庫產品仍有語法與功能差異。

子語言工作常見指令
DDL定義結構CREATE、ALTER、DROP
DML新增、修改、刪除資料INSERT、UPDATE、DELETE
DQL查詢資料SELECT
DCL控制權限GRANT、REVOKE
TCL控制交易COMMIT、ROLLBACK、SAVEPOINT

不同教材可能把 SELECT 歸入廣義 DML，而不是獨立列為 DQL；分類方式不同，不影響 SQL 的實際用途。下一課會把 DDL、DML、DQL 逐一展開。

先會觀察，再開始改資料

第一組 MySQL 指令

SHOW DATABASES;

USE shop;

SHOW TABLES;

SELECT customer_id, customer_name
FROM customers;

SHOW DATABASES 列出目前帳號可看見的資料庫；USE 選擇預設資料庫；SHOW TABLES 列出資料表；SELECT 則取得指定欄位。

MySQL 安裝後會看到幾個系統資料庫：information_schema（記錄有哪些資料庫、資料表等描述性資訊）、mysql（帳號與權限）、performance_schema 與 sys（效能觀測）。它們是 MySQL 自己要用的，不要當成一般業務資料庫隨意修改。

看到 SELECT * 時，星號代表所有欄位。練習時很方便，但正式程式通常應明列需要的欄位，以降低不必要的資料傳輸與結構變動風險。

重點整理

  • 資料庫保存有組織的資料，DBMS 負責管理它，SQL 則是操作關聯式資料庫的語言。
  • 關聯式資料表由欄位與資料列組成，索引用額外空間協助特定查詢。
  • MySQL 是 RDBMS，不是 SQL 語言本身；在 MySQL 裡 SCHEMA 與 DATABASE 是同義詞。
  • 資料型態會影響可存內容、驗證方式、空間與計算結果；金額用 DECIMAL。
  • 文字欄位搭配 utf8mb4 字元集，即可保存中文與各國文字，不需要 SQL Server 式的 n 開頭型態。

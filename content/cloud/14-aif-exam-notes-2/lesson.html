主題一｜先看資料與任務，再挑學習方法

觀念整理：標籤、分群與偏差和變異

選機器學習方法時先問兩件事：資料有沒有標準答案（標籤），以及模型是要預測答案還是找出結構。有標籤又要預測類別或數值，通常是監督式學習（supervised learning）；沒有標籤、希望模型自己找出群組或把特徵簡化，通常是非監督式學習（unsupervised learning）。

K-Means 像是請店員只看顧客行為，自己把相似的人排成幾隊，屬於非監督式分群（clustering）。K-最近鄰（K-Nearest Neighbors，KNN）則像拿新顧客去比對已經有答案的鄰居，再用多數決或平均值預測，所以通常屬於監督式的分類或迴歸。兩個名字裡都有 K，但任務和需不需要標籤完全不同。

模型太簡單、連主要規律都沒學到，叫欠擬合（underfitting），通常呈現高偏差（high bias），訓練與測試都差。模型連訓練資料的雜訊都背起來，叫過度擬合（overfitting），通常呈現高變異（high variance），訓練表現很好，遇到新資料就明顯退步。

欠擬合＝高偏差；過度擬合＝高變異。

代表題：公司只有沒標記的顧客消費資料，希望自動找出客群，該選 K-Means 還是 KNN？

正解：K-Means。題目沒有既有的客群標籤，目標是找出自然形成的群組，符合非監督式分群。

常見誘答是 KNN，因為名字裡也有 K；但 KNN 必須參考已標記的鄰近範例才能預測。降維也是常見的非監督式方法，但它的主要目標是壓縮特徵，不是直接建立客群。

代表題：某模型在訓練資料和測試資料上都表現不佳，最可能是哪種問題？

正解：欠擬合與高偏差。模型對問題做了過度簡化的假設，連訓練資料裡的主要模式都掌握不了。

如果是訓練表現極佳、測試表現很差，那才比較像過度擬合與高變異。

題目若問「機器學習的三大典型範式」，學術上一般是指監督式、非監督式與強化學習。深度學習是多層神經網路這項技術，可以用在不同的學習範式裡，嚴格說不該跟學習範式並列。

但這份題庫沒有照學術分類走——它的標準答案把三大類寫成監督式、非監督式與深度學習。實際考試遇到時，照題庫的答案選；心裡知道嚴謹的講法是另一套就好。

主題二｜神經網路與生成模型

觀念整理：空間、時間與逐步去雜訊

卷積神經網路（Convolutional Neural Network，CNN）擅長處理像素網格這類空間結構，可以從影像中找出邊緣、紋理與形狀。循環神經網路（Recurrent Neural Network，RNN）會保留前面步驟的資訊，適合處理「順序會影響意義」的序列資料。

影片同時包含每一格畫面的空間資訊，以及前後畫面之間的時間關係。傳統的組合方式是讓 CNN 負責「看懂每張畫面」，再由 RNN 負責「理解畫面前後發生了什麼」。考題如果只做基本配對，通常會把單張影像對應 CNN、序列或影片的時間關係對應 RNN。

擴散模型（diffusion model）像從滿是雪花雜訊的畫面慢慢擦出圖像。訓練時，前向過程逐步替真實資料加入雜訊；生成時，反向過程從隨機雜訊開始反覆去除雜訊，一步步形成新資料。

代表題：要分析影片中人物動作的前後變化，為什麼不能只把影片當成一張圖片處理？

正解：因為還要替時間相依性建模。CNN 可以擷取每一格畫面的空間特徵，RNN 這類序列模型則處理畫面之間的順序關係。

把 RNN 說成單張影像的首選，忽略了它處理序列的核心；把 CNN 說成單獨就能完整處理影片，則忽略了時間資訊。

代表題：哪一種敘述最符合擴散模型的生成方式？

正解：從雜訊開始，經過多次受控的去雜訊步驟形成資料。

「兩個網路互相競爭」比較接近生成對抗網路（GAN）；「用自注意力處理序列」是在描述 Transformer；「學習潛在表示」則不是擴散模型獨有的判斷線索。

主題三｜SageMaker 工具與推論模式

觀念整理：依工作階段辨認服務

遇到 SageMaker 服務配對題，可以把機器學習流程想成一條生產線：Data Wrangler 整理原料（資料準備與轉換）；Ground Truth 請人貼標籤（資料標記與人工參與）；Canvas 讓不寫程式的人用視覺化介面建模型；Clarify 檢查決策有沒有偏頗並說明原因（偏見檢測與可解釋性）。

Data Wrangler 常被題目拿「超過 300 種內建資料轉換」當線索。AWS 產品頁的原句是「用 SQL 與超過 300 種內建轉換快速選取、匯入並轉換資料，不必寫程式」出處。同一頁也說明 Data Wrangler 現在已經併進 SageMaker Canvas，不再是獨立入口；功能還在，位置換了。這種數量型的宣傳數字會隨版本增減，記得住「它負責視覺化的資料準備」比記住 300 這個數字有用。

題幹如果強調清理缺失值、編碼、移除重複資料、特徵工程而且少寫程式，優先想到 Data Wrangler。如果強調貸款核准對特定群體公不公平，或要解釋哪些特徵影響了預測，則優先想到 Clarify。

Clarify 不等於所有的模型營運工具。超參數搜尋屬於模型調校；持續觀察已部署模型的品質與漂移通常屬於模型監控；不寫程式建模則對應 Canvas。考題常把這些相鄰的功能互換名稱來做誘答。

需求線索優先聯想到的服務
視覺化清理與轉換資料SageMaker Data Wrangler
不寫程式建立模型SageMaker Canvas
建立高品質的標記資料SageMaker Ground Truth
偏見檢測與模型可解釋性SageMaker Clarify

推論模式則要看回應時間、單次工作大小與處理對象。即時推論適合需要低延遲、持續接收個別請求的服務；非同步推論適合單次請求比較大或處理比較久，而且呼叫端不必留在線上等；批次轉換適合一次處理已經備妥的整批資料。

非同步推論的兩個額度數字：AWS 官方的說法是非同步推論適合最大 1GB 的內容與最長一小時的處理時間，而且沒有請求時可以把執行個體縮到零出處。

不過非同步推論的關鍵不是死背額度，而是「提交工作、稍後取回結果」這個行為。題目如果是替整份離線資料集一次產生預測，通常該選批次轉換；如果是購物網站正在等一筆推薦，那就偏向即時推論。

代表題：研究人員上傳大型基因資料，每筆分析都要跑很久，而且不需要立即回應，該考慮哪種模式？

正解：非同步推論。呼叫端可以先送出請求，等處理完成後再取得結果。

持續運行的低延遲端點偏向即時推論；對整個既有資料集一次做離線預測，則更接近批次轉換。

主題四｜模型評估、公平性與可解釋性

觀念整理：數字告訴你多少，人類告訴你好不好

自動模型評估適合大量、可重複的定量比較，例如用 F1、準確率或語意相似度等指標算分數。人工評估則適合判斷語氣自不自然、內容切不切題、符不符合品牌調性，以及同理心這種難以完整量化的面向。

兩者是互補關係。自動分數高，不保證回應適合這個使用情境；人工覺得內容順暢，也取代不了大規模、一致的數值檢查。實務上應該先依任務定義什麼叫品質，再選對應的指標與人工評分準則。

透明度與可解釋性在貸款、醫療這類高影響情境特別重要。比較簡單的模型往往比較好說明，但複雜模型有時能抓到更多模式，所以效能與可解釋性之間可能要取捨。這不是「複雜一定比較準」或「透明一定犧牲效能」，而是要依風險、法規與業務目標來評估。

代表題：團隊要快速比較兩個模型的大量輸出，又要確認品牌語氣自不自然，該怎麼安排？

正解：自動評估負責可量化的大規模比較，人工評估補上語氣與適切性的判斷。

把人工評估說成只負責算統計分數，或把自動評估說成最適合判斷同理心，都是把兩者的角色顛倒了。

代表題：貸款模型要讓審查人員理解個別決策，是不是只要追求最高準確率就好？

正解：不是。還要考量公平性、透明度、可解釋性與錯誤造成的影響，必要時接受合理的效能取捨。

主題五｜生成式 AI 安全與 AWS 治理

觀念整理：攻擊、弱點、活動與組態是四件事

提示劫持（hijacking）可以理解成模型原本的任務被帶偏了，輸出轉向攻擊者想要的目標；越獄（jailbreaking）則強調想辦法繞過模型既有的安全限制。兩者可能重疊，判題時要看題幹強調的是「任務被改寫」還是「安全護欄被突破」。

漏洞管理（vulnerability management）是在找哪扇門窗沒鎖好：識別、評估並修補系統弱點。威脅偵測（threat detection）則像監視器與警報器：持續觀察日誌、流量或活動，找出正在發生或已經發生的可疑行為。

風險管理（risk management）的範圍更上層，包含辨識威脅、評估可能性與影響，再決定怎麼緩解與持續監控。法律與隱私著重權利、資料使用與法規；治理與合規著重政策、責任和控制；韌性則著重被影響之後還能不能維持或恢復服務。

AWS Config 的核心線索是持續記錄資源組態、追蹤組態變更，並依規則評估合規狀態。Amazon Inspector 偏向找軟體漏洞與暴露風險；AWS Audit Manager 協助蒐集稽核證據；AWS Artifact 提供 AWS 的合規文件。這些服務都跟安全或合規有關，但處理的問題不同。

服務範圍題要分清楚「服務品牌遍布全球」和「建立出來的資源隸不隸屬特定區域」。Lambda 函式與 Rekognition 的使用通常有區域性；IAM 一般被視為全球服務。AWS WAF 則要看它保護的是哪類資源，不能拿一個固定標籤回答所有情境。

代表題：一個回應原本在提供正常的讀書建議，後來卻被帶向不當的作弊內容；另一個提示則刻意包裝敏感要求以避開安全限制。這兩者怎麼分辨？

正解：前者著重任務被劫持，後者著重越獄。判斷點分別是「偏離原定目的」和「突破安全護欄」。

如果模型正常拒絕了敏感請求，代表護欄還在運作，那不能算越獄成功。

代表題：醫療組織要持續追蹤資源組態的變更，並自動檢查組態是否符合規則，該選哪個服務？

正解：AWS Config。題幹的決定性線索是組態歷史、變更追蹤與規則式的合規評估。

Inspector 檢查的是弱點，不是資源組態的歷史；Audit Manager 偏向稽核證據；Artifact 偏向下載合規報告與協議文件。

重點整理

  • 有標籤做預測是監督式；沒標籤找結構是非監督式。
  • K-Means 做分群；KNN 依已標記的鄰居做分類或迴歸。
  • 欠擬合對應高偏差；過度擬合對應高變異。
  • CNN 看空間特徵；RNN 處理序列關係；擴散模型反覆去雜訊。
  • Data Wrangler 準備資料；Ground Truth 標記資料；Canvas 不寫程式建模；Clarify 檢測偏見並解釋模型。
  • 即時推論等立即結果；非同步推論稍後取回；批次轉換處理整批離線資料。
  • 自動評估偏定量；人工評估偏定性，兩者互補。
  • 漏洞管理找弱點；威脅偵測找可疑活動；AWS Config 追蹤資源組態。

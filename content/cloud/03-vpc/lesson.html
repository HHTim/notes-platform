先建立空間感

從地理區域一路縮小到子網路

可以把 AWS 的網路想成一座城市：Region（區域）是城市所在的地理範圍，Availability Zone（可用區，AZ）是彼此隔離的基礎設施區域，VPC（虛擬私有雲）是你在城市裡圈出來的私人園區，Subnet（子網路）則是園區裡的分區。

層級白話比喻重點
Region一座城市所在的地理範圍AWS 資源所屬的區域
Availability Zone彼此隔離的基礎設施區域一個 Region 內有多個 AZ（至少三個）
VPC私人園區由你自己規劃的虛擬網路邊界
Subnet園區內的分區每個 Subnet 只屬於單一 AZ

高可用（High Availability，HA）的常見做法，是把同一套服務分散部署到不同 AZ。這樣單一 AZ 出事時，其他 AZ 還有機會繼續提供服務。

道路決定去向

Route Table 與公開、私有子網路

Route Table（路由表）像路標：它不負責准不准過，只決定封包下一站往哪走。每個 Subnet 都會關聯一張路由表，多個 Subnet 也可以共用同一張。

同一個 VPC 內通常有一條本地路由（local route），所以不同 Subnet 的資源可以透過 VPC 的路由功能互通；但流量還是要通過相關的安全規則才算過關。

公開子網路（Public Subnet）：它的路由表有一條通往 Internet Gateway 的路由。EC2 要直接跟網際網路來往，通常還需要公有 IPv4 位址或 Elastic IP，以及放行的安全規則。

私有子網路（Private Subnet）：沒有讓執行個體直接經由 Internet Gateway 對外通訊的路由。需要主動連外時，可以把預設路由指向放在公開子網路裡的 NAT Gateway。

公開子網路 ≠ 裡面的資源自動公開；路由、公有位址與安全規則，三個缺一不可。

三條常見流量路徑

封包實際上怎麼走

情境一：同一個 VPC 內，兩個私有子網路怎麼互通？

來源 EC2
→ 來源 ENI 的 Security Group 出站檢查
→ 來源 Subnet 的 Network ACL 出站檢查
→ 路由表的 local 路由
→ VPC 路由功能
→ 目的 Subnet 的 Network ACL 入站檢查
→ 目的 ENI 的 Security Group 入站檢查
→ 目的 EC2

情境二：公開子網路中的 EC2 怎麼連到網際網路？

有公有位址的 EC2
→ ENI
→ Security Group 與 Network ACL
→ 路由表：預設路由指向 Internet Gateway
→ Internet Gateway
→ 網際網路

情境三：私有子網路中的 EC2 怎麼主動連外？

私有 EC2
→ 私有 Subnet 的安全檢查與路由表
→ NAT Gateway（位於公開 Subnet）
→ 公開 Subnet 的路由表
→ Internet Gateway
→ 網際網路

NAT Gateway 會把來源的私有位址換成它對外使用的位址（來源網路位址轉換，SNAT），並記住連線狀態。它是讓私有資源「主動連出去」用的，不等於允許網際網路任意主動連進來。

兩種位址轉換

Internet Gateway 做的也是 NAT，只是一對一

情境二有個地方值得停下來想：EC2 的作業系統裡其實看不到自己的公有 IP。你登進去查它的網路設定（Linux 上就是 ip addr 這個指令），看到的只會是 VPC 配給它的私有位址。那外面的人是怎麼連到它的？答案是 Internet Gateway 一路在替它換位址。

AWS 的說明是：「Internet Gateway 在邏輯上代表你的執行個體提供一對一的 NAT，因此當流量離開你的 VPC 子網路前往網際網路時，回覆位址欄位會被設成該執行個體的公有 IPv4 位址或 Elastic IP 位址，而不是它的私有 IP 位址。」反方向也一樣，送往那個公有位址的流量，會先被轉換成執行個體的私有 IPv4 位址，才被送進 VPC出處。

「一對一」是指一個私有位址固定配一個公有位址，兩邊像門牌與郵政信箱一樣一對一掛勾。NAT Gateway 就不是這樣，它是多對一：一整批私有 EC2 共用它那一個對外位址出去。這個差別直接決定了「外面連不連得進來」。

比較項目Internet GatewayNAT Gateway
位址對應一對一：一個私有位址對一個公有位址多對一：多台私有 EC2 共用對外位址
EC2 自己要有公有位址嗎要，公有 IPv4 或 Elastic IP不用
連線方向內對外、外對內都可以只能由內主動往外
擺在哪裡掛在 VPC 上建在公開子網路裡

這段講的是 IPv4。IPv6 沒有這回事——AWS 同一頁寫的是「IPv6 位址是全球唯一的，因此預設就是公有的」，要對外通訊是讓 VPC 與子網路關聯一段 IPv6 位址範圍（CIDR 區塊，用「起始位址／斜線數字」寫成的一段連續位址）、並指派 IPv6 位址給執行個體，不經過這種位址轉換出處。

網卡才是網路身分

ENI、EC2 與 Security Group 的關係

ENI（Elastic Network Interface，彈性網路介面）就是虛擬網卡。EC2 是運算資源，它透過掛上 ENI 才取得私有 IP、所屬 Subnet 這些網路身分。

Security Group（安全群組）是 VPC 層級的資源，關聯的對象是 ENI，不是「住在某個 Subnet 裡」出處。把它想成包在 EC2 外面的保護膜很好懂，但更精確的說法是：規則是跟著網卡走的。

在條件允許時，ENI 可以從一台 EC2 卸下來，再掛到另一台 EC2。這樣就能保留部分網路設定，只換掉背後的運算資源。

兩道不同的門禁

Security Group 與 Network ACL

比較項目Security GroupNetwork ACL
保護範圍ENI（資源層級）Subnet 邊界
規則種類只有允許規則允許與拒絕規則都有
狀態有狀態（Stateful）無狀態（Stateless）
回程流量已允許連線的回應可自動通過入站、出站都要分別允許
評估方式綜合所有適用的規則依規則編號由小到大比對

Network ACL 是無狀態的，所以跨 Subnet 邊界時，要分別想來源端的出站規則與目的端的入站規則，回程流量也必須有對應規則才通得過。

預設規則會因為你用的是預設還是自訂 Network ACL 而不同；判讀現有環境時要直接去看實際規則，不要靠印象。

Security Group 的預設值則可以記成一句話：進來全拒、出去全放。AWS 列的規則特性原文是「當你第一次建立一個安全群組時，它沒有任何入站規則。因此在你加入入站規則之前，不允許任何入站流量」，以及「當你第一次建立一個安全群組時，它有一條允許該資源所有出站流量的出站規則」出處。

這解釋了一個常見現象：剛開好的 EC2 從外面連不進去（沒有入站規則），但機器自己連得出去、抓得到系統更新（出站全放）。要收緊出站也做得到——同一頁接著寫「如果你的安全群組沒有出站規則，就不允許任何出站流量」。

「進來全拒」這句要綁在自己新建的安全群組上。每個 VPC 都附一個名叫 default 的預設安全群組，它不一樣：它預設就帶一條入站規則，來源寫的是這個安全群組自己，效果是「掛著同一個安全群組的資源彼此可以互通」；出站則同樣是兩條全放（IPv4 與 IPv6 各一條）。AWS 自己也建議別用它——「我們建議你為特定資源或資源群組建立安全群組，而不是使用預設安全群組」出處。

建置順序

建立一個可以直接連外的基本網路

  1. 建立 VPC，並規劃 CIDR（位址範圍。這個斜線寫法怎麼讀、一段範圍能切出幾個位址、每個子網路又會先被拿走幾個，見第 8 課）。
  2. 在指定的 AZ 建立 Subnet。
  3. 建立 Internet Gateway，掛載到 VPC——掛載對象是 VPC，不是 Subnet出處；而且一個 VPC 同時只能掛一個出處。
  4. 在公開 Subnet 關聯的路由表中，加一條指向 Internet Gateway 的預設路由。
  5. 建立 EC2 放進該 Subnet，配置需要的公有位址與安全規則。

一個 Subnet 算不算公開，主要看它關聯的路由表能不能把網際網路流量送到 Internet Gateway。

重點整理

  • Subnet 只位於單一 AZ；跨 AZ 部署是提高可用性的常見做法。
  • Route Table 決定下一站怎麼走，Security Group 與 Network ACL 決定流量過不過得去。
  • Internet Gateway 讓公開資源連外；NAT Gateway 讓私有資源主動連外。
  • Security Group 有狀態、只有允許規則；Network ACL 無狀態，而且可以明確拒絕。
  • Security Group 關聯在 ENI 上，EC2 是透過 ENI 取得網路身分的。
  • 新建的 Security Group 預設進來全拒、出去全放；VPC 附的那個 default 安全群組則多一條「同群組互通」的入站規則。
  • Internet Gateway 做的是一對一的位址轉換，NAT Gateway 是多對一——所以只有前者外面連得進來。

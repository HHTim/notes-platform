字串

String、StringBuffer、StringBuilder 差在哪

面試官：字串三兄弟差在哪？什麼時候用哪個？

String 是不可變的（immutable）——宣告之後內容就不能改。每次看起來像「修改」的動作（串接、取代），其實都是產生一個全新的字串物件、占一塊新的記憶體。偶爾改一次沒差，放進迴圈大量串接就又慢又浪費。

所以才有另外兩兄弟——內容可變、修改時不再另闢記憶體：

類別內容可變執行緒安全速度出現版本
String不可變—（不可變本身就安全）—JDK 1.0
StringBuffer可變安全（多執行緒同時用不會壞）慢JDK 1.0
StringBuilder可變不保證快JDK 1.5

要改值就用 StringBuilder；真的有多執行緒同時改同一份，才用 StringBuffer

經典寫法——迴圈裡串大量字串：

StringBuilder sb = new StringBuilder();
for (String s : hugeArray) {
    sb.append(s);
}
String result = sb.toString();

集合框架

List、Set、Queue，和它們的迭代器

Collection 介面底下最常考的三個家族：List（有順序、允許重複）、Set（無順序、不允許重複——重複的直接不加入）、Queue（排隊，先進先出為主）。Map 是另一家人，存的是「鍵對值」，不繼承 Collection。

迭代器介面 java.util.Iterator 從 JDK 1.2 就有；Java 5 才加入 java.lang.Iterable 介面，它定義的 iterator() 方法會回傳一個迭代器出處。Collection 繼承 Iterable，所以 List、Set、Queue 都能給出迭代器——for-each 語法也是靠它。為什麼做成介面？ArrayList 有迭代器、HashSet 也有迭代器，統一都叫 Iterator，用法就一致。

List<String> list = new ArrayList<>();
Iterator<String> it = list.iterator();
while (it.hasNext()) {        // 還有下一個嗎？
    String s = it.next();     // 拿下一個
}

Array 和 ArrayList 差在哪

  • Array：長度固定（建立後不能改）、基本型別和物件都能放、執行效率高。
  • ArrayList：長度會自己長、只能放物件——基本型別要換成包裝類別（int 換成 Integer），通常搭配泛型使用。

ArrayList 和 LinkedList 怎麼選

  • ArrayList：底層是連續的陣列空間，可以用索引值直接取值（隨機存取），讀取快；但要在中間插入或刪除，得搬動後面整段資料。
  • LinkedList：底層是一個接一個的節點（node），沒有索引值、要遍歷才找得到元素；但插入刪除只要改動前後節點的接法，頻繁增刪時划算。

Vector 是 List 家族的老成員（JDK 1.0），跟 ArrayList 大同小異但「每個操作都同步」——每個動作都要拿一次鎖，浪費效能，實務上已被 ArrayList 與各種並行集合取代，面試知道它為什麼被淘汰就好。

泛型與 int／Integer

泛型（generics，JDK 1.5 出現）：在角括號裡先講好集合要放什麼型別，編譯時就能擋住放錯型別的程式碼。角括號裡只能放參考型別——所以是 List<Integer> 不是 List<int>。int 是基本型別，適合單純運算；Integer 是包裝類別，多了 parseInt()、compareTo() 這些方法可用。

物件導向

三本柱、介面與抽象類別

封裝欄位設 private、對外只開 public 的 get／set——資料不攤在陽光下，保護資料、也讓改動不外洩。
繼承父類別有的（欄位、方法），子類別繼承後也有；用來收掉重複的程式碼。宣告 final 的類別不能被繼承。
多型宣告父型別、執行時放子類別的實體（里氏替換原則）。多載＝同名方法、參數不同；複寫＝子類別改寫父類別的方法。

this 指當前物件、拿自己類別的成員；super 拿父類別的成員。存取修飾子由開到關：

修飾子誰能存取
public所有類別
protected同套件的類別＋所有子類別
（不寫，預設）同套件的類別
private只有自己類別內部

面試官：Java 可以多重繼承嗎？

類別不行，只能單一繼承——所以才有介面：一個類別可以同時實作很多個介面，補上多重繼承的需求。跟抽象類別的比較：

  • 抽象類別：不能實體化、只能被繼承；不一定要有抽象方法，但有抽象方法的類別一定要宣告 abstract；子類別必須實作所有抽象方法；一個類別只能繼承一個。
  • 介面：欄位預設是常數（public static final）、沒有建構子、介面之間可以再繼承；目的在降低程式之間的耦合。Java 8 起介面可以有帶實作的 default 方法與 static 方法（Java 9 起還有 private 方法），「介面方法一律抽象」已經是舊版本的答案出處。

instanceof 是二元運算子，測左邊的物件是不是右邊類別（或其子類別、介面實作）的實體；兩邊要有繼承關係，否則直接編譯錯誤。

static 的成員在類別第一次載入時就先就位，那時任何物件都還沒出生——所以 static 方法裡不能用 this。

加分題：一個類別裡可以再放類別嗎？可以，Java 1.1 起有四種內部類別（靜態、成員、區域、匿名），好處是能直接存取外部類別的 private 成員。

例外處理

兩種例外，和三個長很像的關鍵字

所有例外的根類別是 Throwable，分兩支：Error（系統層級的錯，例如記憶體滿了，抓也沒用）和 Exception。Exception 再分兩種：

  • checked exception（編譯器強迫你處理）：例如 IOException、FileNotFoundException——不用 try-catch 包住或用 throws 聲明，編譯不過。
  • unchecked exception（不強迫）：RuntimeException 家族，例如 ClassCastException（轉型失敗）、IndexOutOfBoundsException（索引越界）、NullPointerException（空指標）出處。

throw 是手動丟出一個例外；throws 掛在方法宣告上，聲明「這個方法可能丟例外，處理交給呼叫我的人」。

面試官：final、finally、finalize 差在哪？

  • final：修飾類別＝不能被繼承；修飾方法＝不能被複寫；修飾變數＝值不能再改（常數）；修飾物件參考＝不能再指向別的物件。
  • finally：例外處理的收尾區塊，寫在 catch 後面——無論例外有沒有被解決都會執行，所以拿來釋放資源（關資料庫連線、關檔案）。
  • finalize：宣告在 Object 的方法，垃圾回收器回收物件前會呼叫。這個機制已經走向淘汰：Java 9 起標記廢棄（deprecated），Java 18 起進一步標記為準備移除——現在面試答這題，要補上這句才是最新答案出處。

設計與框架

Design Pattern、MVC、Spring

設計模式（design pattern）不是現成的程式碼，是「這類問題通常這樣解」的方案描述，目標是讓程式可重複使用、有彈性。GoF 那本書把 23 種模式分三群：創建型、結構型、行為型。創建型五個：Factory Method、Abstract Factory、Builder、Prototype、Singleton出處。其中 Factory Method（工廠方法）一句話：父類別先定義「怎麼生出物件」的介面，讓子類別決定實際生出哪一種。

MVC＝Model-View-Controller，把「資料」「畫面」「指揮」三種職責拆開——職責單一互不影響、有利分工、元件可重用：

Spring：實作「控制反轉」（IoC，Inversion of Control——物件不自己生依賴，交給框架注入）的輕量框架。常考關鍵字：DI（依賴注入）、AOP（面向切面，把記錄、交易這類橫切關注點抽出來）、模組化（功能拆成一個個 jar，用多少裝多少）。

被問到自己的專題時

這一段是個人答法的整理，照原筆記保留，答的是一個訂房網站的畢業專題。

  • Coding rules：HTML 用 BEM 命名（Block__Element--Modifier）；類別名大駝峰（PascalCase）；變數小駝峰（camelCase）；常數全大寫並加上 小寫的 final 關鍵字出處。
  • 版本控制：Git 是版本控制系統（追蹤、管理程式碼的修改歷史，分散式、每人本機都能獨立工作）；GitHub 是架在 Git 上的程式碼代管平台（集中存放、pull request、問題追蹤）。一句話：Git 是工具，GitHub 是放工具產出的地方。
  • 負責的功能與分工：擔任組長——題目構想、分工、時程、每週對進度，版本控制上統一管理 main 分支；功能面負責廠商端的房型、行程、私房景點管理與上下架。分工做法：Figma 與前端靜態頁完成後先切大功能，再交由各自負責的組員實作。

重點整理

  • 字串要改值就用 StringBuilder；真的有多執行緒同時改，才用 StringBuffer。
  • List 有序可重複、Set 無序不重複；讀多用 ArrayList、插刪多用 LinkedList。
  • 類別只能單一繼承，介面補位——而且 Java 8 之後介面也能帶 default 方法。
  • final 鎖定、finally 必執行、finalize 已走向淘汰（Java 18 起標記準備移除）。
  • 答題公式：先一句話定義，再講差別與取捨，最後補一個版本或實務註記。

每一步都挑眼前最好的

貪婪是什麼、什麼時候對

收銀員找零錢：要找 67 元，先拿 50，再拿 10，再拿 5，再拿兩個 1，每次都拿「不超過剩下金額的最大面額」。這種每一步都做眼前最好的選擇，而且選了就不回頭的做法，叫貪婪演算法（greedy algorithm）。普林斯頓 Kevin Wayne 的講義（依 Kleinberg–Tardos《Algorithm Design》第 4 章）把收銀員的做法寫成：「每一輪加上一枚不會超過應付金額的最大面額硬幣」（At each iteration, add coin of the largest value that does not take us past the amount to be paid.）。出處

貪婪寫起來短、跑得快（常常是排序 O(n log n) 加掃一遍），難處在它不一定對。〈動態規劃入門〉的找零就是反例：面額 1、3、4 湊 6 元，貪婪拿 4 + 1 + 1 共 3 枚，最少其實是 3 + 3 兩枚。動態規劃把每種選擇都試過；貪婪只試一種，所以要先說服自己「眼前最好的那一步，不會害到後面」。

Wayne 的講義整理了三種證明貪婪正確的思路：出處

  • 一路領先（greedy algorithm stays ahead）：證明每一步之後，貪婪的結果「至少跟任何其他演算法一樣好」（its solution is at least as good as any other algorithm's）。
  • 結構上的下限（structural）：先找出「任何解都至少要這麼多」的下限，再證明貪婪剛好達到。後面的會議室題就是這種。
  • 交換論證（exchange argument）：「把任何一個解一步一步換成貪婪找到的解，而且品質不變差」（Gradually transform any solution to the one found by the greedy algorithm without hurting its quality.）。後面的「最多不重疊區間」用的就是這個。

面試時不必寫完整證明，但要能用一句話講出直覺，並且先想反例：試幾組小資料，看貪婪會不會輸給暴力解。你已經看過的貪婪：〈圖：BFS、DFS 與拓樸排序〉的 Dijkstra 每次拿目前最近的頂點；algs4 說它介紹的最小生成樹演算法（Prim、Kruskal）都是「貪婪演算法的特例」（they are special cases of the greedy algorithm）。出處

下面哪一句最能描述貪婪演算法？

  • 每步選眼前最好，選了不回頭
  • 把所有選法都試過再挑最好的
  • 把問題切成兩半各自解再合併
  • 先存下子問題的答案再拼起來

試遍所有選法是暴力或回溯；切兩半是分治；存子問題答案是動態規劃。貪婪只走一條路。

貪婪演算法最大的風險是什麼？

  • 一定比動態規劃慢很多
  • 需要非常多的記憶體
  • 只能用在已經排好序的資料
  • 眼前最好可能害到後面

面額 1、3、4 湊 6 元，先拿 4 看起來最好，結果要 3 枚，最佳是 2 枚。貪婪通常反而比較快、比較省空間。

「把任何一個最佳解一步一步換成貪婪的解，而且不會變差」是哪一種證明思路？

  • 一路領先
  • 結構上的下限
  • 交換論證
  • 數學歸納法求遞迴式

講義原文 Gradually transform any solution to the one found by the greedy algorithm without hurting its quality，就是交換論證。

想到一個貪婪解法，面試時第一件該做的檢查是？

  • 直接寫程式送出看結果
  • 找小例子跟暴力解比
  • 先算清楚空間複雜度
  • 先把它改寫成遞迴版本

貪婪錯的時候常常一組三、四個元素的小資料就看得出來。找不到反例，再講正確性的直覺。

下面哪一個演算法是貪婪的？

  • 合併排序
  • 0/1 背包的填表
  • 列出所有排列的回溯
  • Dijkstra

Dijkstra 每一步選目前最近、而且選了就定案。合併排序是分治，背包填表是動態規劃，列排列是回溯。

algs4 說 Kruskal、Prim 這些最小生成樹演算法是什麼的特例？

  • 貪婪演算法
  • 動態規劃
  • 二分搜尋
  • 回溯法

原文 they are special cases of the greedy algorithm：每次挑一條目前最輕、而且合法的邊。

收銀員的做法什麼時候對

找零：新臺幣面額可以貪婪，怪面額不行

Wayne 的講義先問「收銀員的做法對任何一組面額都是最佳嗎？」，答案是「不是」（Q. Is cashier's algorithm optimal for any set of denominations? A. No.），舉了兩個反例：美國郵票面額 1、10、21、34、70、100……湊 140 分，貪婪拿 100 + 34 + 六個 1 共 8 枚，最佳是 70 + 70 兩枚；面額 7、8、9 湊 15，貪婪先拿 9 之後就湊不出來了，但 7 + 8 可以。同一份講義也證明了「收銀員的做法對美國硬幣 1、5、10、25、100 是最佳的」（Theorem. Cashier's algorithm is optimal for U.S. coins { 1, 5, 10, 25, 100 }.）。出處 所以「貪婪對不對」看的是面額組合，不是演算法本身。

新臺幣呢？中央銀行說流通使用的鈔票有 100、200、500、1,000、2,000 元，「經常使用的硬幣則有 1 元、5 元、10 元、20 元及 50 元等 5 種」。出處 用〈動態規劃入門〉的最小硬幣數當標準答案，一個金額一個金額比對：

import java.util.Arrays;

public class Coins {
    // 貪婪（收銀員的做法）：每次拿不超過剩餘金額的最大面額
    static int greedy(int[] desc, int amount) {
        int count = 0;
        for (int c : desc) {
            count += amount / c;
            amount %= c;
        }
        return amount == 0 ? count : -1;               // 湊不出來回傳 -1
    }

    // 動態規劃：最少幾枚（〈動態規劃入門〉的寫法）
    static int[] dp(int[] coins, int max) {
        int[] f = new int[max + 1];
        Arrays.fill(f, Integer.MAX_VALUE);
        f[0] = 0;
        for (int x = 1; x <= max; x++)
            for (int c : coins)
                if (c <= x && f[x - c] != Integer.MAX_VALUE) f[x] = Math.min(f[x], f[x - c] + 1);
        return f;
    }

    static void compare(String name, int[] desc, int max, String unit) {
        int[] best = dp(desc, max);
        int diff = 0, first = -1;
        for (int x = 1; x <= max; x++) {
            int b = best[x] == Integer.MAX_VALUE ? -1 : best[x];
            if (greedy(desc, x) != b) { diff++; if (first < 0) first = x; }
        }
        System.out.print(name + "：1～" + max + " " + unit + "裡貪婪跟最佳解不同的有 " + diff + " 個");
        if (first > 0) {
            System.out.print("，第一個是 " + first + " " + unit + "（貪婪 " + greedy(desc, first) + " 枚，最少 " + best[first] + " 枚）");
        }
        System.out.println();
    }

    public static void main(String[] args) {
        compare("新臺幣 1、5、10、20、50、100、200、500、1000、2000", new int[]{2000, 1000, 500, 200, 100, 50, 20, 10, 5, 1}, 10000, "元");
        compare("面額 1、3、4", new int[]{4, 3, 1}, 100, "元");
        compare("美國郵票 1、10、21、34、70、100", new int[]{100, 70, 34, 21, 10, 1}, 300, "分");
        int[] postal = {100, 70, 34, 21, 10, 1};
        System.out.println("郵票湊 140 分：貪婪 " + greedy(postal, 140) + " 枚，最少 " + dp(postal, 140)[140] + " 枚（70 + 70）");
        System.out.println("面額 7、8、9 湊 15 元：貪婪 " + greedy(new int[]{9, 8, 7}, 15) + "，最少 " + dp(new int[]{9, 8, 7}, 15)[15] + " 枚");
    }
}

面額 1、3、4：1～100 元裡貪婪跟最佳解不同的有 24 個，第一個是 6 元（貪婪 3 枚，最少 2 枚）
美國郵票 1、10、21、34、70、100：1～300 分裡貪婪跟最佳解不同的有 157 個，第一個是 30 分（貪婪 10 枚，最少 3 枚）

新臺幣 1～10,000 元每一個金額，貪婪都跟最佳解一樣多枚；面額 1、3、4 在 100 元以內有 24 個金額會輸；郵票的例子 30 分就錯（21 + 九個 1 共 10 枚，10 + 10 + 10 只要 3 枚），140 分正是講義的例子。面額 7、8、9 湊 15 元，貪婪連解都找不到（回傳 -1）。只比對到 10,000 元，怎麼知道更大的金額也對？Kozen 與 Zaks 的論文證明：面額由小到大是 c1＝1、c2、…、cm，如果貪婪會出錯，最小的出錯金額一定落在 c3 + 1 < x < cm + cm−1 這個範圍（In this paper we show that if a counterexample exists, then the smallest one lies in the range c3 + 1 < x < cm + cm−1）。出處 新臺幣最大兩種是 2,000 和 1,000，上界是 3,000 元；3,000 元以內都沒有出錯的金額，就不會有任何出錯的金額。所以「新臺幣面額貪婪找零一定最少枚」是實算加上這個上界得到的結論。換一組面額，就要重新算一次；面試時說「這組面額我驗證過」比「貪婪就是對的」站得住。題目給的面額是任意的時候，一律用動態規劃。

  • 講義證明了所有國家的硬幣都可以
  • 貪婪演算法永遠是最佳的
  • 實算到一萬元，加上論文的上界

講義證明的是美國硬幣；中央銀行只公告面額。Kozen 與 Zaks 證明最小的出錯金額小於最大兩種面額相加（新臺幣是 3,000 元），實算到 10,000 元都沒有出錯，所以所有金額都對。

先排好，能合併的就在隔壁

區間題一：合併重疊區間

一堆區間（例如會議時段、交易的有效期間），把重疊的合併成一段。做法：依起點排序，再從左到右掃，跟「目前合併好的最後一段」比：起點不超過它的尾端就是重疊，把尾端延長；否則開新的一段。〈面試解題流程與題型對照〉的說法是：依起點排好序之後，能合併成同一段的區間一定連在一起，跟目前這段的尾端比就夠了。排序用〈排序與二分搜尋〉的 Comparator。

static List<int[]> merge(int[][] a) {
    int[][] s = a.clone();
    Arrays.sort(s, Comparator.comparingInt(x -> x[0]));
    List<int[]> out = new ArrayList<>();
    for (int[] cur : s) {
        int[] last = out.isEmpty() ? null : out.get(out.size() - 1);
        if (last != null && cur[0] <= last[1]) {
            last[1] = Math.max(last[1], cur[1]);    // 重疊：延長尾端（注意取 max）
        } else {
            out.add(new int[]{cur[0], cur[1]});
        }
    }
    return out;
}

合併（包在裡面）：[1, 10]
20000 組隨機測資，合併結果跟塗色數段不同的有 0 組

第三行是另外寫的對照：把每個區間的座標乘 2，在數線上逐點塗色，再數連成幾段（乘 2 是為了讓 [1,4]、[5,6] 中間的 4.5 留白，相接的 [1,4]、[4,6] 才會連成一段）。20,000 組隨機區間，兩邊結果全部一樣。

兩個容易錯的地方：

  • 尾端要取 max：[1, 10] 後面接 [2, 3]，新的尾端還是 10，不是 3。實跑第二行就是這個情況。
  • 端點相接算不算重疊，看題目：這段程式用 <=，[1, 5] 和 [5, 8] 會合併成 [1, 8]（LeetCode 56 題的定義）。會議室「5 點結束、5 點開始」通常不算撞期，那就是半開區間 [s, e)，比較要改成 <。下面幾題都會遇到這個選擇。

時間：排序 O(n log n)，掃一遍 O(n)，共 O(n log n)。

為什麼不依「結束時間」排序來合併？

  • 結束時間沒有辦法排序
  • 依結束時間排序會慢很多
  • 長區間會排在後面，得回頭改
  • 其實一樣，兩種排法都可以

例如 [1,10] 結束得晚，排在 [2,3]、[4,5] 後面，掃到它時要把前面兩段都吸收，單純「跟最後一段比」就不夠了。

最早結束的，留最多空間給後面

區間題二：最多能選幾個不重疊的區間

一間會議室，一堆會議申請，最多能排進幾場（不能撞期）？講義叫它區間排程（interval scheduling），並列了三種直覺的排法：最早開始、最早結束、最短的先。正確的是依結束時間由早到晚，能放就放（Consider jobs in ascending order of fj.），而且「最早結束優先的演算法是最佳的」（Theorem. The earliest-finish-time-first algorithm is optimal.）。出處

static int maxNonOverlap(int[][] a, Comparator<int[]> order) {
    int[][] s = a.clone();
    Arrays.sort(s, order);
    int count = 0, lastEnd = Integer.MIN_VALUE;
    for (int[] cur : s) {
        if (cur[0] >= lastEnd) { count++; lastEnd = cur[1]; }
    }
    return count;
}
依結束時間：4 個
依開始時間：3 個
依長度：1 個（同一組資料依結束時間 2 個）
最少要刪幾個才不重疊：7
1000 組隨機測資，依結束時間的答案跟試遍所有子集合不同的有 0 組

為什麼對？用交換論證的直覺：任何一個最佳排法，把它的第一場換成「最早結束的那場」，不會撞到後面的場次（因為它結束得最早），場數也不變；再對剩下的時段重複同樣的論證。講義的證明就是這樣：取貪婪與最佳解第一個不同的位置，問「為什麼不把最佳解的那一場換成貪婪的那一場？」（why not replace job jr+1 with job ir+1?），換完「仍然可行、仍然最佳」（solution still feasible and optimal）。出處 實跑也比對了 1,000 組隨機資料，跟「試遍所有子集合」的答案全部一樣。

另外兩種排法的反例都在實跑裡：依開始時間只排得進 3 場（一開始就選到很長的 [0, 6)）；依長度，[1,5) [4,7) [6,10) 會先選最短的 [4,7)，把兩邊都擋掉，只得 1 場，依結束時間是 2 場。

同一招的變形：LeetCode 435「最少刪幾個才不重疊」就是 n 減去最多能留幾個；452「最少幾支箭射破所有氣球」也是依結束位置排序，一支箭射在第一個結束點上；但 452 的氣球兩端都算，相接的兩顆一支箭就射得到，所以比較要從 cur[0] >= lastEnd 改成 cur[0] > lastEnd（照原樣寫，[1,2]、[2,3] 會算出 2 支，正解是 1 支）。起始值也要跟著改：452 的座標可以小到 Integer.MIN_VALUE，這時 MIN_VALUE > MIN_VALUE 不成立，第一顆氣球會被漏掉；把 lastEnd 改用 long 存、初值 Long.MIN_VALUE，或先把第一顆算一支再從第二顆開始比。時間都是排序的 O(n log n)。

  • 長度由短到長

  • 長度由長到短

同一時間最多幾場

區間題三：會議室最少要幾間

所有會議都要開，最少要幾間會議室？講義叫它區間分割（interval partitioning），用的是第二種證明思路，結構上的下限：在某個時間點同時進行的會議數叫深度（depth），「需要的會議室數 ≥ 深度」（Number of classrooms needed ≥ depth.），而且最早開始優先的做法剛好用到深度那麼多間，所以是最佳的。出處 兩種寫法：

  • 最小堆：依開始時間排序；堆裡放每間會議室「目前那場的結束時間」，堆頂就是最早空出來的那間。新會議的開始時間不早於堆頂，就沿用那間（取出、放回新的結束時間），否則開新的一間。講義的實作也是「把會議室存在優先佇列裡（鍵＝最後一場的結束時間）」（Store classrooms in a priority queue (key = finish time of its last lecture).）。優先佇列見〈堆積與優先佇列〉。
  • 掃描線：把開始時間、結束時間各自排序，像兩根手指往右掃；遇到開始就 +1、遇到已經過去的結束就 −1，途中的最大值就是答案。同一個時間點，先處理結束（半開區間的「5 點結束、5 點開始」不需要兩間）。
import java.util.*;

public class Rooms {
    // 會議室最少幾間（作法一）：依開始時間排序，最小堆存每間會議室的結束時間
    static int byHeap(int[][] a) {
        int[][] s = a.clone();
        Arrays.sort(s, Comparator.comparingInt(x -> x[0]));
        PriorityQueue<Integer> ends = new PriorityQueue<>();
        for (int[] m : s) {
            if (!ends.isEmpty() && ends.peek() <= m[0]) ends.poll();   // 最早空出來的那間可以用
            ends.offer(m[1]);
        }
        return ends.size();
    }

    // 作法二：掃描線。開始 +1、結束 −1，同一時間先處理結束
    static int bySweep(int[][] a) {
        int n = a.length;
        int[] starts = new int[n], ends = new int[n];
        for (int i = 0; i < n; i++) { starts[i] = a[i][0]; ends[i] = a[i][1]; }
        Arrays.sort(starts);
        Arrays.sort(ends);
        int rooms = 0, best = 0, j = 0;
        for (int i = 0; i < n; i++) {
            while (j < n && ends[j] <= starts[i]) { j++; rooms--; }   // 已經結束的先離場
            rooms++;
            best = Math.max(best, rooms);
        }
        return best;
    }

    public static void main(String[] args) {
        int[][] a = {{9, 10}, {9, 12}, {10, 11}, {10, 13}, {11, 14}, {13, 15}};
        System.out.println("最小堆：" + byHeap(a) + " 間，掃描線：" + bySweep(a) + " 間");
        System.out.println("[1,5) [5,8) 端點相接：" + byHeap(new int[][]{{1, 5}, {5, 8}}) + " 間");

        Random r = new Random(7);                      // 隨機測資：兩種作法比對，再跟「同時進行的最多場數」比對
        int bad = 0;
        for (int t = 0; t < 1000; t++) {
            int n = 1 + r.nextInt(12);
            int[][] m = new int[n][];
            for (int i = 0; i < n; i++) { int s = r.nextInt(20); m[i] = new int[]{s, s + 1 + r.nextInt(8)}; }
            int depth = 0;
            for (int x = 0; x < 30; x++) {
                int c = 0;
                for (int[] k : m) if (k[0] <= x && x < k[1]) c++;
                depth = Math.max(depth, c);
            }
            if (byHeap(m) != depth || bySweep(m) != depth) bad++;
        }
        System.out.println("1000 組隨機測資，兩種作法跟同時進行的最多場數不一致的有 " + bad + " 組");
    }
}

已經排好的，插一個進去

區間題四：插入區間

一串已經依起點排好、互不重疊的區間，插入一個新的，結果仍要排好、不重疊。不必整個重新排序：分三段掃一遍，左邊完全不碰的照抄、跟新區間重疊的全部吸收進來、右邊的照抄，O(n)。

static List<int[]> insert(int[][] a, int[] add) {
    List<int[]> out = new ArrayList<>();
    int i = 0, n = a.length;
    int s = add[0], e = add[1];
    while (i < n && a[i][1] < s) out.add(a[i++]);                  // 完全在左邊
    while (i < n && a[i][0] <= e) {                                // 跟新區間重疊：吸收進來
        s = Math.min(s, a[i][0]);
        e = Math.max(e, a[i][1]);
        i++;
    }
    out.add(new int[]{s, e});
    while (i < n) out.add(a[i++]);                                 // 完全在右邊
    return out;
}

記住最遠能到哪裡

跳躍遊戲與加油站

跳躍遊戲：nums[i] 是站在位置 i 最多能往前跳幾格，問能不能到最後一格。不必試每一種跳法，只要一路記住「目前能到的最遠位置」：走到某一格時它已經超過最遠位置，就到不了。最少跳幾次則像〈圖：BFS、DFS 與拓樸排序〉的 BFS 一層一層往外擴：每一層是「再跳一次能到的範圍」，走完一層就算一次。

加油站：環狀路線上有 n 站，第 i 站加 gas[i]，開到下一站要 cost[i]，問從哪一站出發能繞一圈。兩個觀察：總油量小於總消耗，從哪裡出發都不行；從 start 出發，從 i 開往 i + 1 時油不夠，那 start 到 i 之間任何一站出發也都到不了 i + 1（它們出發時油箱都是 0，不會比從 start 開過來時多），所以直接把起點換成 i + 1。

public class Jump {
    // 跳躍遊戲：nums[i] 是在位置 i 最多能往前跳幾格。能不能走到最後一格？
    static boolean canJump(int[] nums) {
        int farthest = 0;                              // 目前能到達的最遠位置
        for (int i = 0; i < nums.length; i++) {
            if (i > farthest) return false;            // 連這一格都到不了
            farthest = Math.max(farthest, i + nums[i]);
        }
        return true;
    }

    // 最少跳幾次：一層一層往外擴（像 BFS），每一層能到的範圍是 [start, end]
    static int minJumps(int[] nums) {
        int jumps = 0, end = 0, farthest = 0;
        for (int i = 0; i < nums.length - 1; i++) {
            farthest = Math.max(farthest, i + nums[i]);
            if (i == end) {                            // 這一層走完了，必須再跳一次
                jumps++;
                end = farthest;
            }
        }
        return jumps;
    }

    // 加油站：gas[i] 是第 i 站能加的油，cost[i] 是開到下一站要的油。從哪一站出發能繞一圈？
    static int gasStation(int[] gas, int[] cost) {
        int total = 0, tank = 0, start = 0;
        for (int i = 0; i < gas.length; i++) {
            total += gas[i] - cost[i];
            tank += gas[i] - cost[i];
            if (tank < 0) {                            // 從 start 出發到不了 i+1：start 到 i 之間都不行
                start = i + 1;
                tank = 0;
            }
        }
        return total < 0 ? -1 : start;                 // 總油量不夠，從哪裡出發都不行
    }

    public static void main(String[] args) {
        System.out.println("[2,1,3,0,1,2] 能到嗎？" + canJump(new int[]{2, 1, 3, 0, 1, 2}) + "，最少跳 " + minJumps(new int[]{2, 1, 3, 0, 1, 2}) + " 次");
        System.out.println("[1,2,0,0,3] 能到嗎？" + canJump(new int[]{1, 2, 0, 0, 3}));
        System.out.println("加油站 gas=[3,1,2,5,1] cost=[2,3,4,1,2]：從第 " + gasStation(new int[]{3, 1, 2, 5, 1}, new int[]{2, 3, 4, 1, 2}) + " 站出發");
        System.out.println("加油站 gas=[2,2,2] cost=[3,2,2]：" + gasStation(new int[]{2, 2, 2}, new int[]{3, 2, 2}));

        java.util.Random r = new java.util.Random(3);  // 隨機測資：跟逐站試、BFS 的答案比對
        int bad = 0;
        for (int t = 0; t < 2000; t++) {
            int n = 1 + r.nextInt(8);
            int[] nums = new int[n], gas = new int[n], cost = new int[n];
            for (int i = 0; i < n; i++) { nums[i] = r.nextInt(4); gas[i] = r.nextInt(6); cost[i] = r.nextInt(6); }
            int bfs = bfsJumps(nums);
            if (canJump(nums) != (bfs >= 0)) bad++;
            if (bfs >= 0 && minJumps(nums) != bfs) bad++;
            if (gasStation(gas, cost) != gasBrute(gas, cost)) bad++;
        }
        System.out.println("2000 組隨機測資，跟逐一嘗試的答案不同的有 " + bad + " 處");
    }

    static int bfsJumps(int[] nums) {                  // 一般 BFS：最少幾步到最後一格，到不了回傳 -1
        int n = nums.length;
        int[] d = new int[n];
        java.util.Arrays.fill(d, -1);
        d[0] = 0;
        java.util.ArrayDeque<Integer> q = new java.util.ArrayDeque<>();
        q.add(0);
        while (!q.isEmpty()) {
            int i = q.poll();
            for (int k = 1; k <= nums[i] && i + k < n; k++)
                if (d[i + k] < 0) { d[i + k] = d[i] + 1; q.add(i + k); }
        }
        return d[n - 1];
    }

    static int gasBrute(int[] gas, int[] cost) {       // 每一站都當起點試一次
        int n = gas.length;
        for (int s = 0; s < n; s++) {
            int tank = 0; boolean ok = true;
            for (int k = 0; k < n && ok; k++) {
                int i = (s + k) % n;
                tank += gas[i] - cost[i];
                if (tank < 0) ok = false;
            }
            if (ok) return s;
        }
        return -1;
    }
}

2000 組隨機測資，跟逐一嘗試的答案不同的有 0 處

三個函式都是 O(n)。這兩題的正確性這裡只講直覺，所以實跑另外用 2,000 組隨機資料跟「一般 BFS」與「每一站都當起點試一次」比對，全部一致。

[2,1,3,0,1,2] 能走到最後一格嗎？

  • 能，最少跳 5 次
  • 不能
  • 能，最少跳 1 次
  • 能，最少跳 2 次

從 0 跳到 2（nums[2] = 3），再從 2 跳到 5。實跑 true、2 次。

[1,2,0,0,3] 為什麼到不了最後一格？

  • 最遠只到位置 3，那裡是 0
  • 第一格就跳不動了
  • 最後一格是 3，數字太大了
  • 陣列的長度太短了一點

0+1=1、1+2=3、2+0=2、3+0=3，最遠到位置 3，那一格不能再往前，位置 4 超過最遠位置。

跳躍遊戲的 canJump 一路維護的是什麼？

  • 目前跳了幾次
  • 每一格的最少跳躍次數
  • 目前能到達的最遠位置
  • 還沒走過的格子

farthest = max(farthest, i + nums[i])；走到的格子 i 超過 farthest 就表示到不了。

加油站 gas=[3,1,2,5,1]、cost=[2,3,4,1,2]，從第幾站出發？（從 0 數）

  • 0
  • 1
  • 2
  • 3

每站 gas − cost 是 1、−2、−2、4、−1：從第 1 站開往第 2 站時油變 −1，換起點到 2；第 2 站又變負，換到 3；之後 4、3 都不負。總和 12 − 12 = 0，有解。實跑從第 3 站。

加油站題，什麼情況可以直接回傳 -1？

  • 總油量小於總消耗
  • 第一站的 gas 小於 cost
  • 有任何一站的 gas 小於 cost
  • 站的數量是奇數

總油量不夠繞一圈，從哪裡出發都不行。單一站 gas < cost 只表示不能從那站出發。

從 start 出發，從 i 開往 i + 1 時油不夠，為什麼直接把起點換成 i + 1，而不是 start + 1？

  • 因為 i + 1 離得比較近
  • 因為題目就是這樣規定
  • 其實換成 start + 1 才對
  • 中間站出發油不會比較多

從 start 開到中間某站時油箱 ≥ 0，從那站「重新出發」油箱是 0，不會更好。所以中間那些站都可以跳過，這讓整題變成 O(n)。

跳躍遊戲 II（最少跳幾次）的 minJumps 跟哪一個演算法的想法最像？

  • BFS
  • DFS
  • 二分搜尋
  • 合併排序

每一層是「再跳一次能到的範圍」，走完一層 jumps 加 1，跟 BFS 依步數一層一層拜訪一樣。實跑也拿一般 BFS 比對過。

先試反例，再決定

貪婪還是動態規劃，以及動手練

看到「最多、最少」的題目，可以先問兩個問題：有沒有一個排序或規則讓「眼前最好」看起來不會害到後面（最早結束、最遠能到）？拿三、四個元素的小例子跟暴力解比，找得到反例嗎？找不到反例、又講得出交換或領先的直覺，就用貪婪；找得到反例（怪面額找零、0/1 背包），就回到〈動態規劃入門〉。

「n 樣東西各有重量與價值，背包容量有限，每樣最多拿一次，求最大價值」，該用什麼？

  • 貪婪：價值除以重量最高的先拿
  • 依重量排序後合併
  • 動態規劃
  • 掃描線

這是 0/1 背包，〈動態規劃入門〉看過 MIT 的反例：照單位價值先拿會錯。東西不能切開時，要用動態規劃。

判斷一題能不能用貪婪，下面哪個做法最實在？

  • 看題目有沒有「最多」兩個字
  • 找小例子跟暴力解比
  • 看輸入資料有沒有排序
  • 看答案是不是整數

「最多、最少」的題目貪婪和動態規劃都可能，關鍵在有沒有反例。這課的每個貪婪都跟暴力解或動態規劃比對過（找零逐一比對每個金額，其他用隨機資料）。

下面哪一題不適合用貪婪？

  • 新臺幣面額找零最少枚數
  • 一間會議室最多排幾場
  • 能不能跳到最後一格
  • 任意面額找零最少枚數

任意面額可能出現 1、3、4 或 7、8、9 這種貪婪會錯的組合，要用動態規劃。其他三題都有可靠的貪婪規則。

重點整理

  • 貪婪：每一步選眼前最好、選了不回頭；快，但不一定對。證明思路有一路領先、結構上的下限、交換論證；面試先找反例，再講直覺。
  • 找零：收銀員的做法對美國硬幣有證明、對新臺幣面額實算到 10000 元，加上 Kozen 與 Zaks 的上界（最大兩種面額相加），可以確定所有金額都最佳；面額 1、3、4、郵票、7、8、9 都有反例。任意面額用動態規劃。
  • 合併區間：依起點排序，起點不超過目前尾端就合併，尾端取 max；端點相接算不算重疊看題目。
  • 最多不重疊區間：依結束時間排序、能放就放（交換論證）；最少刪幾個＝n 減去它；射氣球同招，但氣球兩端都算，比較改成 >。
  • 最少會議室＝最擁擠時的深度：依開始時間排序加最小堆（放結束時間），或開始、結束各自排序的掃描線，同時刻先處理結束；2406 是閉區間，比較改成 <。
  • 插入區間：左、重疊、右三段掃一遍，O(n)。
  • 跳躍遊戲：記住最遠能到哪裡；最少跳幾次像 BFS 數層數。加油站：總和不夠就 -1，開往下一站油不夠就把起點換到下一站。

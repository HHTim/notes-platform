先問為什麼，資料變多時會慢多少

複雜度在量什麼

同一個需求可以有很多種寫法。對帳程式在測試環境跑一百筆時，每種寫法都是一眨眼；上線後一天一百萬筆，有的寫法一樣一眨眼，有的要跑一整晚。複雜度（complexity）就是用來事先回答「資料量變大時，這個寫法會慢多少、吃多少記憶體」的工具，不用真的等到上線才知道。

直接量秒數不準，因為同一支程式在快的電腦上跑得快、慢的電腦上跑得慢。MIT 6.006 講義的做法是「數這個演算法總共做了幾次固定時間的基本動作」（Count number of fixed-time operations algorithm takes to return），並預期它「跟輸入的大小有關：輸入越大通常越久」（Expect to depend on size of input: larger input suggests longer time）。輸入的大小通常記作 n，例如交易筆數、帳戶數、字串長度。出處

數出來的步數常常長成 3n² + 5n + 100 這種樣子。大 O 符號（big O notation，也叫漸近符號：只看 n 很大很大時的趨勢）把它簡化成 O(n²)，規則只有兩條，講義原文是「忽略常數倍數與低次項」（Asymptotic Notation: ignore constant factors and low order terms）：出處

  • 去常數：3n² 的 3、n/2 的 ½ 都拿掉。換一台快兩倍的電腦，只會改變這個常數，不會改變「n 變兩倍時要多花幾倍時間」。
  • 取最高次項：3n² + 5n + 100 裡，n 等於一百萬時 n² 是一兆，5n 才五百萬，後面那些小項可以忽略，只留 n²。

嚴格的定義在 MIT 習題課講義：「非負函式 g(n) 屬於 O(f(n))，若且唯若存在正實數 c 與正整數 n₀，使得所有 n ≥ n₀ 都有 g(n) ≤ c·f(n)」（Non-negative function g(n) is in O(f(n)) if and only if there exists a positive real number c and positive integer n0 such that g(n) ≤ c · f(n) for all n ≥ n0.）。白話：n 夠大以後，g(n) 不會超過 f(n) 的某個固定倍數，所以 O 是一個上限。講義另外有 Ω（下限）與 Θ（上下限都對上、最貼的那個）。出處 照定義，O(n) 的程式也算 O(n²)（上限放寬一點也成立），但這樣講沒有資訊量。本課和這個模組寫 O 時，一律寫最貼近的那個等級。

大 O 只看 n 變大時的成長趨勢：去掉常數、只留最高次項

一段程式總共做 3n² + 5n + 100 步。照大 O 的寫法（去常數、只留最高次項），應該寫成什麼？

  • O(3n²)
  • O(n²)
  • O(n³)
  • O(3n² + 5n + 100)

最高次項是 3n²，再去掉常數 3，寫成 O(n²)。O(3n²) 留著常數、O(3n² + 5n + 100) 留著低次項，都不是大 O 的慣用寫法；O(n³) 是更高的等級，算錯了。

一段程式做 2n + 10 步，照大 O 的寫法應該寫成？

  • O(2n)
  • O(1)
  • O(n)
  • O(n²)

最高次項 2n，去掉常數 2 就是 O(n)。後面的 +10 是低次項（n 的零次方），直接拿掉。

一段程式不管輸入多大，都固定做 500 步。它的時間複雜度是？

  • O(1)
  • O(500)
  • O(n)
  • O(log n)

步數跟 n 無關就是常數時間，常數一律寫成 O(1)，不寫 O(500)。

一段程式做 n/2 步（只看一半的資料）。它的時間複雜度是？

  • O(n/2)
  • O(log n)
  • O(1)
  • O(n)

n/2 就是 ½ × n，去掉常數 ½ 還是 O(n)。只看一半資料會快一倍，但 n 變兩倍時它一樣變兩倍，成長趨勢跟 O(n) 相同。

一段程式做 n + log n 步。它的時間複雜度是？

  • O(log n)
  • O(n)
  • O(n log n)
  • O(n + log n)

n 長得比 log n 快，log n 是低次項，拿掉後是 O(n)。O(n log n) 是「相乘」，這裡是相加，不一樣。

一段程式做 n² + n³/1000 步。n 很大時它屬於哪個等級？

  • O(n²)，因為 n³ 前面有 1/1000
  • O(n² + n³)
  • O(n⁵)
  • O(n³)

常數 1/1000 再小也只是常數：n 超過 1000 以後，n³/1000 就比 n² 大，而且越拉越開。最高次項是 n³，所以是 O(n³)。n² 加 n³ 是相加不是相乘，不會變成 n⁵。

大 O 為什麼可以把常數倍數丟掉？

  • 因為實務上常數一定很小，跟 n 比起來可以直接忽略，不影響結果
  • 因為我們要比的是 n 變大時的成長趨勢；換快的電腦只改常數，不改趨勢
  • 因為 Java 編譯器會把常數最佳化掉
  • 因為常數只會出現在空間複雜度裡

常數可以很大（例如每筆都要做 100 次運算），丟掉它不是因為它小，而是因為它不影響「n 變兩倍時慢幾倍」。MIT 習題課講義說用漸近表現比較演算法，就是「為了忽略硬體效能的常數倍差異」（in order to ignore constant factor differences in hardware performance）。出處

換成時間比較有感覺。MIT 講義用「一秒做十億個基本動作」（one operation per cycle on a 1 GHz single-core machine）估算，n = 1,000 時：O(1) 約 1 奈秒、O(log n) 約 10 奈秒、O(n) 約 1 微秒、O(n log n) 約 10 微秒、O(n²) 約 1 毫秒，而指數等級 2¹⁰⁰⁰ 約是 10³⁰¹ 步，講義寫要「10²⁸¹ 個千年」（10281 millenia）。出處 同一個估法套到 n = 一百萬：O(n²) 是一兆步，約 1,000 秒、十七分鐘左右；O(n log n) 是兩千萬步，0.02 秒。這就是為什麼一百萬筆的對帳不能用兩兩比對。

大 O 只管 n 很大時的趨勢。n 很小的時候，常數大的 O(n) 寫法可能比常數小的 O(n²) 寫法還慢，所以測試資料只有幾十筆時看不出差別，資料量上去才會出事。

一個 O(n²) 的程式，n 從 1,000 變成 2,000，步數大約變成幾倍？

  • 2 倍
  • 8 倍
  • 4 倍
  • 差不多一樣

n² 裡的 n 變 2 倍，平方後是 2² = 4 倍。O(n) 才是 2 倍，O(n³) 是 8 倍。

一個 O(log n) 的程式，n = 1,000 時大約 10 步。n 變成 1,000,000（一千倍）時大約幾步？

  • 約 20 步
  • 約 10,000 步
  • 約 1,000 步
  • 約 100 步

log 1,000 ≈ 10、log 1,000,000 ≈ 20。資料多一千倍，O(log n) 只多 10 步，這就是二分搜尋在大資料上好用的原因。

下面哪一個是「由快到慢」的正確順序？

  • O(1)、O(n)、O(log n)、O(n log n)、O(n²)、O(2ⁿ)
  • O(1)、O(log n)、O(n)、O(n²)、O(n log n)、O(2ⁿ)
  • O(log n)、O(1)、O(n)、O(n log n)、O(2ⁿ)、O(n²)
  • O(1)、O(log n)、O(n)、O(n log n)、O(n²)、O(2ⁿ)

常數最快；log n 長得比 n 慢很多；n log n 比 n 多一個 log 倍；n² 比 n log n 大；2ⁿ 是指數，比任何 n 的次方都長得快。

照「一秒做十億步」估算，n = 1,000,000 時 O(n²) 的程式大約要跑多久？

  • 約 1 毫秒
  • 約 1 秒
  • 約 17 分鐘
  • 約 1 年

n² = 10¹² 步，除以每秒 10⁹ 步是 1,000 秒，約 16.7 分鐘。同樣的 n，O(n log n) 只要約 0.02 秒。

寫法甲做 n² 步，寫法乙做 100n 步。n = 5 時，哪個做的步數比較少？

  • 寫法乙，因為它是 O(n)
  • 寫法甲，25 步對 500 步
  • 一樣多
  • 無法比較，等級不同

5² = 25，100 × 5 = 500，n 很小時 O(n²) 的寫法反而比較少。大 O 只保證 n 夠大以後的趨勢：這兩個寫法在 n 超過 100 之後，寫法乙才會比較快。

六個等級，各配一段 Java 與職場例子

常見等級：從一步到位到組合爆炸

等級白話典型寫法職場例子
O(1)常數時間：不管資料多少都是固定幾步用索引拿陣列第 i 格帳戶編號就是陣列索引，直接拿那格的餘額
O(log n)對數時間：每一步把範圍砍掉一半在排好序的資料裡二分搜尋在照時間排好的交易紀錄裡找某一秒的那筆
O(n)線性時間：每筆看一次一層迴圈走過整個陣列加總今天每一筆交易金額
O(n log n)每筆都要參與 log n 輪的處理，常見於排序Arrays.sort把十萬筆交易照金額排序
O(n²)平方時間：每一筆都跟每一筆配對一次兩層迴圈都走過整份資料核心系統的每一筆，都到清算檔從頭找一遍有沒有對應
O(2ⁿ)指數時間：每多一筆資料，工作量就翻倍把每個元素「選或不選」的組合全部試一遍帳差了 7 元，找哪幾筆交易加起來剛好 7 元

O(log n) 為什麼這麼快：猜數字遊戲的做法（正式名稱是二分搜尋 binary search）：資料先排好序，每次看正中間那格，太小就丟掉它和左半、太大就丟掉它和右半。MIT 習題課講義說，「在已排序的陣列中找一個值，可以用二分搜尋在對數時間內解決」（finding a value in a sorted array ... can be solved in logarithmic time via binary search）。出處 細節在〈排序與二分搜尋〉。

O(n log n) 從哪來：好的排序法大致是「分 log n 層，每層把 n 筆都處理一次」。Java 對基本型別陣列用的雙軸快速排序，API 文件寫它「在所有資料上都提供 O(n log(n)) 的效能」（This algorithm offers O(n log(n)) performance on all data sets）。出處

O(2ⁿ) 為什麼可怕：n 筆交易，每筆都可以「選」或「不選」，組合數是 2 × 2 × … × 2 = 2ⁿ。10 筆有 1,024 種，20 筆就超過一百萬種，40 筆超過一兆種。這種寫法只能用在 n 很小的時候。

把六個等級寫進同一支程式，用一個計數器 steps 數「基本動作做了幾次」，再把 n 加倍，看步數怎麼變：

import java.util.Arrays;

public class StepCount {
    static long steps;   // 每做一次「基本動作」就加 1

    // O(1)：用索引直接拿第 i 個帳戶的餘額，不管有幾個帳戶都是一步
    static long balanceAt(long[] balances, int i) {
        steps++;
        return balances[i];
    }

    // O(log n)：在排好序的交易時間裡找某個時間，每看一次就砍掉一半
    static int findTime(long[] sortedTimes, long target) {
        int lo = 0, hi = sortedTimes.length - 1;
        while (lo <= hi) {
            steps++;
            int mid = lo + (hi - lo) / 2;
            if (sortedTimes[mid] == target) return mid;
            if (sortedTimes[mid] < target) lo = mid + 1; else hi = mid - 1;
        }
        return -1;
    }

    // O(n)：加總當天每一筆交易金額，每筆看一次
    static long total(long[] amounts) {
        long sum = 0;
        for (long a : amounts) { steps++; sum += a; }
        return sum;
    }

    // O(n²)：兩份清單逐筆比對：核心系統的每一筆，都到清算檔從頭找一遍
    static int unmatched(long[] core, long[] clearing) {
        int missing = 0;
        for (long id : core) {
            boolean found = false;
            for (long other : clearing) {
                steps++;
                if (id == other) { found = true; break; }
            }
            if (!found) missing++;
        }
        return missing;
    }

    // O(2ⁿ)：找「哪幾筆加起來剛好等於差額」，把每筆選或不選的組合全部試一遍
    static int countSubsets(long[] amounts, int i, long remain) {
        steps++;
        if (i == amounts.length) return remain == 0 ? 1 : 0;
        return countSubsets(amounts, i + 1, remain - amounts[i])   // 選第 i 筆
             + countSubsets(amounts, i + 1, remain);               // 不選第 i 筆
    }

    static long[] data(int n) {
        long[] a = new long[n];
        for (int i = 0; i < n; i++) a[i] = i;   // 0, 1, 2, …（已排序、彼此不同）
        return a;
    }

    public static void main(String[] args) {
        for (int n : new int[]{1_000, 2_000}) {
            long[] a = data(n);
            long[] other = data(n);
            other[n - 1] = -1;   // 清算檔少了最後一筆

            steps = 0; balanceAt(a, n / 2);        long s1 = steps;
            steps = 0; findTime(a, n + 5);         long s2 = steps;   // 找不到（比全部都大）：最壞情況
            steps = 0; total(a);                   long s3 = steps;
            steps = 0; unmatched(a, other);        long s4 = steps;
            System.out.printf("n=%,d  O(1)=%d  O(log n)=%d  O(n)=%,d  O(n²)=%,d%n", n, s1, s2, s3, s4);
        }
        for (int n : new int[]{10, 20}) {
            steps = 0;
            countSubsets(data(n), 0, 7);
            System.out.printf("n=%d  O(2ⁿ)=%,d%n", n, steps);
        }
    }
}

n=2,000  O(1)=1  O(log n)=11  O(n)=2,000  O(n²)=2,001,000
n=10  O(2ⁿ)=2,047

n 從 1,000 變 2,000（兩倍）：O(1) 不變、O(log n) 只多 1 步、O(n) 變 2 倍、O(n²) 從 500,500 變 2,001,000，約 4 倍。O(2ⁿ) 那行是 n 從 10 變 20，步數變成約 1,024 倍。O(n²) 那行是 500,500 而不是 1,000,000，因為每一筆找到對應就 break，平均只找一半；這個 ½ 就是大 O 去掉的常數。

O(n log n) 用 Arrays.sort 示範，在比較器裡數它比了幾次。要傳比較器只能排物件陣列（Long[]），這時 Arrays.sort 用的不是上面那個雙軸快速排序，而是另一種合併排序；API 文件寫它在資料順序打亂時「提供傳統合併排序的效能」（offering the performance of a traditional mergesort when the input array is randomly ordered）出處，而 algs4 寫合併排序排長度 N 的陣列「用 ½ N lg N 到 N lg N 次比較」（uses between 1/2 N lg N and N lg N compares），一樣是 O(n log n)。出處 兩種排序法的差別在〈陣列與字串〉。

import java.util.Arrays;
import java.util.Random;

public class SortCount {
    public static void main(String[] args) {
        for (int n : new int[]{1_000, 2_000}) {
            Long[] amounts = new Long[n];
            Random random = new Random(42);           // 固定種子：每次跑結果一樣
            for (int i = 0; i < n; i++) amounts[i] = (long) random.nextInt(1_000_000);
            long[] compares = {0};
            Arrays.sort(amounts, (x, y) -> { compares[0]++; return Long.compare(x, y); });
            System.out.printf("n=%,d  比較了 %,d 次%n", n, compares[0]);
        }
    }
}

執行結果：

n=1,000  比較了 8,683 次
n=2,000  比較了 19,358 次

n log n 在 n = 1,000 時約 10,000，實際比了 8,683 次，同一個量級。n 變兩倍，比較次數變 2.2 倍左右：比 2 倍多一點，比 4 倍少很多，這就是 O(n log n) 的樣子。

用客戶帳號到 HashMap 裡查客戶資料，一般說它的時間複雜度是？

  • O(n)
  • 平均 O(1)
  • O(log n)
  • O(n log n)

HashMap 的 get 在雜湊（hash：把鍵算成一個格子編號）分散得好的前提下是常數時間，所以說「平均 O(1)」。為什麼它做得到、什麼時候會變慢，在〈雜湊表：HashMap 怎麼做到幾乎一步找到〉。

在已排序的 1,000,000 筆資料裡做二分搜尋，最多大約要看幾次？

  • 約 1,000 次
  • 約 500,000 次
  • 1,000,000 次
  • 約 20 次

每看一次剩一半：一百萬除以 2 約 20 次就剩 1 筆（2²⁰ = 1,048,576）。500,000 是逐筆找的平均次數。

這段程式的時間複雜度是？（amounts 有 n 筆）

long max = Long.MIN_VALUE;
for (long x : amounts) {
    if (x > max) max = x;
}
  • O(n)
  • O(1)
  • O(log n)
  • O(n²)

一層迴圈，每筆看一次、每次做固定幾步，所以是 O(n)。

想找出陣列裡最大的那筆，有人寫「先 Arrays.sort，再拿最後一個」。這個寫法的時間複雜度是？

  • O(1)，因為拿最後一個只要一步
  • O(n)
  • O(n log n)
  • O(n²)

排序本身就是 O(n log n)，拿最後一個的 O(1) 是低次項。直接掃一遍找最大值只要 O(n)，比較快。

n 筆交易，每筆可以選或不選，總共有幾種組合？n = 10 時是多少？

  • 2ⁿ，n = 10 時是 20
  • n²，n = 10 時是 100
  • 2ⁿ，n = 10 時是 1,024
  • n!，n = 10 時是 3,628,800

每筆兩種選擇、n 筆相乘，2¹⁰ = 1,024。n! 是「排順序」的數量，不是「選或不選」。

照上面 StepCount 的結果，O(n²) 那行在 n = 2,000 時是 2,001,000。n = 4,000 時大約是多少？

  • 約 400 萬
  • 約 800 萬
  • 約 1,600 萬
  • 約 200 萬多一點

n 再變兩倍，O(n²) 再變約 4 倍：2,001,000 × 4 ≈ 800 萬。（照公式 n(n+1)/2 算是 8,002,000。）

O(2ⁿ) 的程式，n 從 20 變成 21，步數大約怎麼變？

  • 多 1 步
  • 多 21 步
  • 變 4 倍
  • 變 2 倍

2²¹ = 2 × 2²⁰，n 只多 1，工作量就翻倍。這也是「每多一筆資料，工作量翻倍」的意思。

十萬筆交易的金額放在一個 long[] 陣列裡，用 Arrays.sort 由小到大排好，時間複雜度是？

  • O(n)
  • O(n²)
  • O(log n)
  • O(n log n)

API 文件寫 Arrays.sort 對基本型別陣列提供 O(n log(n)) 的效能。比較型的排序一般就是這個等級。

核心系統有 n 筆、清算檔也有 n 筆，「核心系統的每一筆，都到清算檔從頭找一遍」的時間複雜度是？

  • O(n²)
  • O(n)
  • O(2n)
  • O(n log n)

外層 n 筆、每筆在內層最多找 n 次，n × n = n²。一萬筆就是一億次比對。先把清算檔放進 HashSet 再查，可以降到平均 O(n)。

SortCount 裡 n 從 1,000 變 2,000，比較次數從 8,683 變 19,358。這最符合哪個等級？

  • O(n)，因為 n 變 2 倍時比較次數也大約變 2 倍，多出來的只是誤差
  • O(n²)，因為變超過 2 倍
  • O(n log n)，略多於 2 倍、遠少於 4 倍
  • O(log n)

19,358 ÷ 8,683 ≈ 2.23。O(n) 會剛好 2 倍左右，O(n²) 會接近 4 倍；比 2 倍多一點正是 n log n 多出來的那個 log。

看程式碼自己算，迴圈怎麼數

從程式碼算複雜度的五個規則

算複雜度不用把每一行都數清楚，抓住「哪一段會跟著 n 變多」就好：

看到什麼怎麼算結果
單層迴圈跑 n 次迴圈次數 × 每次的成本（固定幾步）O(n)
兩層巢狀迴圈外層次數 × 內層次數都跑 n 次是 O(n²)；外 n 內 m 是 O(n·m)
迴圈變數每次除以 2 或乘以 2要幾次才從 n 變到 1O(log n)
兩段程式先後執行相加，再留大的那項O(n) 接 O(n²) 是 O(n²)；O(n) 接 O(m) 是 O(n + m)
遞迴總共呼叫幾次 × 每次做多少例如每次 n 減 1、每次固定幾步：O(n)

兩個常見的陷阱：

  • 內層從 i + 1 開始，還是 O(n²)。內層跑 n−1、n−2、…、1 次，加起來是 n(n−1)/2，去掉 ½ 和低次項還是 n²。MIT 講義分析找同生日的兩層迴圈（內層只跑到 k）時，結論同樣是 O(n²)。出處
  • 迴圈裡呼叫的方法本身也要算。一層迴圈裡面寫 list.contains(x)，看起來只有一層，但 ArrayList 的 API 文件說除了少數幾個方法，「其他操作都是線性時間」（All of the other operations run in linear time (roughly speaking).），contains 要從頭比到尾，整段就是 O(n²)。出處 字串在迴圈裡用 + 相加也是同一種隱藏成本，在〈陣列與字串〉講。

遞迴怎麼算（畫出呼叫樹、數有幾個節點）在〈遞迴與回溯〉細講，這課只需要知道「數總共呼叫幾次」。

巢狀相乘、先後相加、每次減半是 log n、迴圈裡呼叫的方法也要算進去

這段程式的時間複雜度是？

int count = 0;
for (int i = 0; i < n; i++) {
    count++;
}
  • O(1)
  • O(n)
  • O(log n)
  • O(n²)

迴圈跑 n 次，每次一步，O(n)。

這段程式的時間複雜度是？

int count = 0;
for (int i = 0; i < n; i += 2) {
    count++;
}
  • O(log n)
  • O(n/2)
  • O(n)
  • O(1)

i 每次加 2，跑 n/2 次。去掉常數 ½ 還是 O(n)。要每次「乘以 2」才會變 O(log n)，「加 2」只是常數倍快。

這段程式的時間複雜度是？

int count = 0;
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        count++;
    }
}
  • O(n)
  • O(2n)
  • O(n log n)
  • O(n²)

外層 n 次，每次內層都跑 n 次，相乘是 n²。

內層改成從 i + 1 開始，時間複雜度是？

int count = 0;
for (int i = 0; i < n; i++) {
    for (int j = i + 1; j < n; j++) {
        count++;
    }
}
  • O(n²)
  • O(n)
  • O(n log n)
  • O(n²/2)

總次數是 (n−1) + (n−2) + … + 1 = n(n−1)/2，約 n²/2。去掉常數 ½ 還是 O(n²)；O(n²/2) 留著常數，不是大 O 的寫法。

外層走 n 個帳戶、內層走 m 筆交易，時間複雜度是？

int count = 0;
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        count++;
    }
}
  • O(n²)
  • O(n + m)
  • O(n·m)
  • O(m)

兩個輸入大小不同，要分開寫：外 n 次、內 m 次，相乘是 O(n·m)。寫成 O(n²) 等於假設 m 跟 n 一樣大。

兩個迴圈先後執行（不是巢狀），時間複雜度是？

int count = 0;
for (int i = 0; i < n; i++) count++;
for (int j = 0; j < m; j++) count++;
  • O(n·m)
  • O(n + m)
  • O(n)
  • O(n²)

先跑 n 次、再跑 m 次，相加是 n + m。不知道 n、m 誰大，兩個都要留著。

前面一段 O(n)、後面一段巢狀 O(n²)，整段的時間複雜度是？

int count = 0;
for (int i = 0; i < n; i++) count++;
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) count++;
  • O(n + n²)
  • O(n³)
  • O(n)
  • O(n²)

n + n² 相加後只留最高次項 n²。先後執行是相加，不是相乘，所以不會變 n³。

這段程式的時間複雜度是？

int count = 0;
for (int i = n; i > 1; i /= 2) {
    count++;
}
  • O(log n)
  • O(n)
  • O(n/2)
  • O(1)

i 每次除以 2，從 n 除到 1 要 log n 次。n = 1,024 時跑 10 次。

這段程式的時間複雜度是？

int count = 0;
for (int i = 1; i < n; i *= 2) {
    count++;
}
  • O(n)
  • O(2ⁿ)
  • O(log n)
  • O(n²)

i 是 1、2、4、8……每次乘以 2，乘 log n 次就超過 n。跟每次除以 2 一樣是 O(log n)。2ⁿ 是「步數」翻倍，這裡翻倍的是 i，步數反而很少。

外層跑 n 次，內層每次乘以 2，時間複雜度是？

int count = 0;
for (int i = 0; i < n; i++) {
    for (int j = 1; j < n; j *= 2) {
        count++;
    }
}
  • O(n²)
  • O(n log n)
  • O(log n)
  • O(n)

內層是 O(log n)，外層 n 次，相乘是 O(n log n)。

內層固定跑 100 次（例如一天有 100 種手續費代碼要逐一檢查），時間複雜度是？

int count = 0;
for (int i = 0; i < n; i++) {
    for (int j = 0; j < 100; j++) {
        count++;
    }
}
  • O(n²)
  • O(100)
  • O(n + 100)
  • O(n)

100 跟 n 無關，是常數。總共 100n 步，去掉常數是 O(n)。兩層迴圈不一定是 O(n²)，要看內層會不會跟著 n 變多。

list 是有 n 個元素的 ArrayList，a 是長度 n 的陣列。這段程式的時間複雜度是？

int count = 0;
for (int x : a) {
    if (list.contains(x)) count++;
}
  • O(n²)
  • O(n)
  • O(n log n)
  • O(1)

看起來只有一層迴圈，但 ArrayList.contains 每次要從頭比，本身就是 O(n)。n 次 × O(n) = O(n²)。把 list 換成 HashSet，contains 平均 O(1)，整段就是平均 O(n)。

這段程式在數一個正整數 n 有幾位數。時間複雜度是？

int digits = 0;
while (n > 0) {
    n /= 10;
    digits++;
}
  • O(n)
  • O(n/10)
  • O(1)
  • O(log n)

每次除以 10，跟每次除以 2 一樣是對數等級（以 10 為底的 log n 跟以 2 為底的只差常數倍）。n = 1,000,000 只跑 7 次。

三層巢狀迴圈，每層都跑 n 次，時間複雜度是？

int count = 0;
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        for (int k = 0; k < n; k++)
            count++;
  • O(3n)
  • O(n²)
  • O(n³)
  • O(2ⁿ)

n × n × n = n³。每多一層跑 n 次的巢狀迴圈，次方就加 1。

內層迴圈只在 i == 0 那一次執行。整段的時間複雜度是？

int count = 0;
for (int i = 0; i < n; i++) {
    if (i == 0) {
        for (int j = 0; j < n; j++) count++;
    }
    count++;
}
  • O(n²)
  • O(n)
  • O(n log n)
  • O(1)

內層只跑一次（n 步），外層 n 次各做一步，總共約 2n 步，是 O(n)。巢狀不一定相乘，要看內層實際跑了幾次。

外層 i 是 1、2、4、8……，內層跑 i 次。整段的時間複雜度是？

int count = 0;
for (int i = 1; i < n; i *= 2) {
    for (int j = 0; j < i; j++) {
        count++;
    }
}
  • O(n log n)
  • O(log n)
  • O(n²)
  • O(n)

內層次數是 1 + 2 + 4 + … 加到小於 n 的最大 2 的次方，總和不到 2n，所以是 O(n)。外層 log n 次，但每次的內層不一樣長，不能直接拿「log n × n」相乘。

這個遞迴方法每次把 n 減 1、每層只做固定幾步。呼叫 f(n) 的時間複雜度是？

static int f(int n) {
    if (n == 0) return 0;
    return f(n - 1) + 1;
}
  • O(n)
  • O(1)
  • O(log n)
  • O(2ⁿ)

f(n) 呼叫 f(n−1)、再呼叫 f(n−2)……一路到 f(0)，總共 n + 1 次呼叫，每次固定幾步，O(n)。每次只呼叫自己一次，不會分叉成 2ⁿ。

同一個程式，三種講法

最壞、平均、攤銷

同一段程式，遇到不同的資料，步數可能不一樣。在沒排序的 n 筆交易裡逐筆找某一筆：第一筆就是它，1 步；最後一筆才是它或根本沒有，n 步。所以講複雜度時要說清楚是哪一種：

說法意思例子
最壞情況挑最花時間的那種輸入來算：不管輸入長怎樣，都不會比它更久逐筆搜尋最壞 O(n)；快速排序最壞 O(n²)
平均情況對各種可能的輸入取平均（要先假設輸入怎麼分布）快速排序平均 O(n log n)；HashMap 的 get 平均 O(1)
攤銷（amortized）把偶爾一次很貴的成本，平均分攤到每一次操作：看一連串操作的總成本ArrayList.add 攤銷 O(1)

注意最壞、平均跟前面的 O、Θ 是兩件事：最壞、平均講的是「拿哪一種輸入來算」，O、Θ 講的是「這個等級是上限，還是剛好」。例如逐筆搜尋，最壞情況（要找的不在裡面）剛好是 n 步，是 Θ(n)；最好情況（第一筆就是）是 Θ(1)。本模組寫 O 時一律寫最貼近的等級，所以「最壞 O(n)」的意思就是「最壞情況的等級是 n」。

最壞情況的意思，algs4 寫的是「不管輸入是什麼，程式的執行時間都小於某個上限」（Running time of a program is less than a certain bound (as a function of the input size), no matter what the input.）。出處 快速排序是平均與最壞差很多的例子：algs4 寫它「平均約用 2N ln N 次比較」（~2 N ln N compares ... on the average），「最壞約 N²/2 次，但先隨機洗牌可以避開這種情況」（~N²/2 compares in the worst case, but random shuffling protects against this case）。出處

平均情況背後一定有假設。HashMap 的 API 文件寫 get 與 put 是常數時間，但前面有條件：「假設雜湊函式把元素適當地分散到各個桶」（桶，bucket：雜湊表裡的一格）（This implementation provides constant-time performance for the basic operations (get and put), assuming the hash function disperses the elements properly among the buckets.）。出處 所以面試講「HashMap 查詢 O(1)」時，要講成「平均 O(1)」。

攤銷跟平均不一樣，它不靠輸入的機率，講的是「一整串操作加起來」的保證。algs4 的說法：「攤銷分析對一連串操作提供最壞情況的效能保證」（Amortized analysis provides a worst-case performance guarantee on a sequence of operations.）。出處 MIT 講義的定義：「k 次操作總成本不超過 k·T(n)，就說每次操作攤銷成本是 T(n)」（Operation has amortized cost T(n) if k operations cost at most ≤ kT(n)）。出處

最常被問的例子是 ArrayList.add。ArrayList 底下是一個陣列，格子滿了就開一個更大的新陣列、把舊的全部搬過去。搬家那一次是 O(n)，但不是每次都搬。API 文件原句：「add 與 addLast 操作是攤銷常數時間，也就是說，加入 n 個元素需要 O(n) 時間」（The add, and addLast operations runs in amortized constant time, that is, adding n elements requires O(n) time.）。出處 這裡的 add 是加在尾端的 add(e)；插到中間的 add(index, e) 要把後面整段往右搬，屬於文件說的「其他操作都是線性時間」。

新陣列開多大？API 文件只說「成長策略的細節沒有規定，只保證加入一個元素的攤銷成本是常數」（The details of the growth policy are not specified beyond the fact that adding an element has constant amortized time cost.）。出處 實際做法要看原始碼：OpenJDK 25 的 ArrayList.grow 把「偏好的成長量」設成 oldCapacity >> 1（舊容量的一半），也就是新容量約為舊的 1.5 倍；用預設建構子建立的清單，第一次放東西時開 DEFAULT_CAPACITY，也就是 10 格。出處 照這個公式模擬，數一數總共搬了多少個元素：

public class GrowthCost {
    public static void main(String[] args) {
        for (int n : new int[]{1_000, 1_000_000}) {
            int capacity = 10;      // 第一次放東西時開 10 格
            long copies = 0;        // 擴容時總共搬了幾個元素
            int grows = 0;          // 擴容了幾次
            for (int size = 0; size < n; size++) {   // 放第 size+1 個元素
                if (size == capacity) {              // 格子滿了
                    copies += size;                  // 開新陣列，舊的全部搬過去
                    capacity += capacity >> 1;       // 新容量是舊的 1.5 倍
                    grows++;
                }
            }
            System.out.printf("放 %,d 個：擴容 %d 次，搬了 %,d 個，平均每次 add 多搬 %.2f 個%n",
                    n, grows, copies, (double) copies / n);
        }
    }
}

執行結果：

放 1,000 個：擴容 12 次，搬了 2,456 個，平均每次 add 多搬 2.46 個
放 1,000,000 個：擴容 29 次，搬了 2,430,972 個，平均每次 add 多搬 2.43 個

放一百萬個只擴容 29 次，平均每次 add 多搬約 2.4 個，跟 n 無關，所以是攤銷 O(1)。關鍵是「每次按比例放大」：MIT 習題課講義說，多配置的空間只要跟目前大小成固定比例，就能達到攤銷常數時間（allocating any constant fraction of additional space will achieve the amortized bound）。出處 如果每次只多加固定 10 格，每 10 次就要搬一次家，搬的總數是 10 + 20 + 30 + … + n，約 n²/20，總成本變成 O(n²)。

已經知道要放多少筆時，可以用 new ArrayList<>(容量) 或 ensureCapacity 一次開夠，API 文件說這「可能減少逐步重新配置的次數」（This may reduce the amount of incremental reallocation.）。出處

在沒排序的 n 筆交易裡逐筆找某個交易編號，最壞情況的時間複雜度是？

  • O(1)
  • O(log n)
  • O(n)
  • O(n²)

要找的在最後一筆或根本不存在時，n 筆都要看過，O(n)。沒排序不能用二分搜尋。

同一個逐筆搜尋，最好的情況是什麼、多少步？

  • 第一筆就是要找的，O(1)
  • 要找的在正中間，O(n/2)
  • 每筆都要看，O(n)
  • 最好和最壞一樣，都是 O(n)

第一筆就命中時只看 1 次，O(1)。最好情況通常沒什麼參考價值，面試問的多半是最壞或平均。

ArrayList 的 add(e) 單獨一次，最壞要多久？

  • O(1)，因為 API 文件說它是常數時間，任何一次都不會超過
  • O(n)，剛好遇到擴容要把舊元素全部搬過去
  • O(log n)
  • O(n²)

文件說的是「攤銷」常數時間。剛好碰上格子滿的那一次，要把 n 個舊元素搬到新陣列，那一次是 O(n)。

從空的 ArrayList 開始，連續 add(e) n 次，總共要多少時間？

  • O(n²)，因為每次 add 最壞 O(n)
  • O(n log n)
  • O(1)
  • O(n)

API 文件原句：「adding n elements requires O(n) time」。貴的那幾次間隔越來越長，總和還是 O(n)。拿「每次最壞 O(n)」乘以 n 會高估。

在有 n 個元素的 ArrayList 最前面插入：list.add(0, x)。時間複雜度是？

  • 攤銷 O(1)，跟加在尾端的 add(e) 一樣，偶爾擴容才比較慢
  • O(log n)
  • O(n)，後面 n 個元素都要往右移一格
  • O(1)，只是改第 0 格

插到中間或最前面，後面每一個都要往右搬一格，是 O(n)。攤銷 O(1) 只講尾端的 add(e)。

HashMap 的 API 文件說 get、put 是常數時間，前提是什麼？

  • 鍵必須是字串
  • 雜湊函式把元素適當地分散到各個桶
  • 容量必須是 2 的次方
  • 只能在單一執行緒使用

文件原句是 assuming the hash function disperses the elements properly among the buckets。所以要說「平均 O(1)」，分散得不好（很多鍵撞在一起）就會變慢。

有人說「快速排序是 O(n log n)」。照 algs4 的說法，這句話要補上什麼才完整？

  • 不用補，快速排序每次都把資料切成兩半，任何輸入都是 O(n log n)
  • 要補「最好情況是 O(n)」
  • 要補「空間是 O(n²)」
  • 那是平均情況；最壞約 N²/2 次比較，也就是 O(n²)

algs4 寫快速排序平均約 2N ln N 次比較、最壞約 N²/2 次，先隨機洗牌可以避開最壞情況。平均與最壞要分開講。

「攤銷 O(1)」跟「平均 O(1)」差在哪？

  • 沒有差別，只是兩種叫法
  • 攤銷是最好情況，平均是最壞情況
  • 攤銷是一整串操作的總成本保證，不靠輸入的機率；平均要先假設輸入怎麼分布
  • 攤銷只用在空間複雜度，平均只用在時間複雜度，兩者量的東西根本不同

algs4：攤銷分析對一連串操作提供最壞情況的保證。ArrayList 連續 add n 次一定是 O(n)，不需要假設資料長怎樣；HashMap 的平均 O(1) 則要假設雜湊分散得好。

時間之外，還要算記憶體

空間複雜度

空間複雜度算的是程式額外用了多少記憶體，跟 n 怎麼一起長。輸入本身占的空間通常不算，算的是你另外開的陣列、集合、還有遞迴疊起來的呼叫。

  • 只用幾個變數（sum、i、max）：O(1)。
  • 複製一份陣列、開一個跟輸入一樣大的 HashSet：O(n)。
  • 開一個 n × n 的二維表格：O(n²)。
  • 遞迴深度 n 層：O(n)。這一項最容易漏掉。

遞迴為什麼吃空間？Java 虛擬機規格寫，每條執行緒有自己的呼叫堆疊（call stack：方法一層一層呼叫時，像疊盤子一樣疊起來的紀錄），堆疊需要的深度超過允許的上限，就丟出 StackOverflowError；出處 而且「每呼叫一次方法就建立一個新的框」（A new frame is created each time a method is invoked.），方法結束才拆掉。出處 框（frame）就是一次呼叫用到的小抽屜，放參數、區域變數、算到一半的結果。sumRecursive(n) 要一路疊到 sumRecursive(0) 才開始往回算，同時有 n 個抽屜開著：

public class SpaceDemo {
    // 空間 O(1)：不管 n 多大，只用 sum 和 i 兩個變數
    static long sumLoop(int n) {
        long sum = 0;
        for (int i = 1; i <= n; i++) sum += i;
        return sum;
    }

    // 空間 O(n)：每呼叫一層就在呼叫堆疊上多一格，要疊 n 層才開始往回算
    static long sumRecursive(int n) {
        if (n == 0) return 0;
        return n + sumRecursive(n - 1);
    }

    public static void main(String[] args) {
        System.out.println(sumLoop(10) + " " + sumRecursive(10));
        System.out.println(sumLoop(10_000_000));
        try {
            System.out.println(sumRecursive(10_000_000));
        } catch (StackOverflowError e) {
            System.out.println("遞迴版：StackOverflowError");
        }
    }
}

執行結果：

55 55
50000005000000
遞迴版：StackOverflowError

兩個版本時間都是 O(n)，但迴圈版空間 O(1)，一千萬也算得出來；遞迴版空間 O(n)，一千萬層就把堆疊疊爆了。實際能疊幾層要看堆疊大小的設定，但「深度跟 n 成正比」不會變。

用空間換時間是最常見的取捨。檢查一批交易編號有沒有重複，有三種寫法：

import java.util.Arrays;
import java.util.HashSet;
import java.util.Set;

public class Duplicate {
    // 做法一：兩兩比對。時間 O(n²)，額外空間 O(1)
    static boolean byPairs(long[] ids) {
        for (int i = 0; i < ids.length; i++)
            for (int j = i + 1; j < ids.length; j++)
                if (ids[i] == ids[j]) return true;
        return false;
    }

    // 做法二：先排序，重複的會排在隔壁。時間 O(n log n)，額外空間看排序法；這裡複製一份，O(n)
    static boolean bySorting(long[] ids) {
        long[] copy = ids.clone();          // 不改呼叫端的陣列
        Arrays.sort(copy);
        for (int i = 1; i < copy.length; i++)
            if (copy[i] == copy[i - 1]) return true;
        return false;
    }

    // 做法三：放進 HashSet，看過的記下來。時間平均 O(n)，額外空間 O(n)
    static boolean bySet(long[] ids) {
        Set<Long> seen = new HashSet<>();
        for (long id : ids)
            if (!seen.add(id)) return true;   // add 回傳 false 表示本來就有
        return false;
    }

    public static void main(String[] args) {
        long[] ids = {9001, 9002, 9003, 9002};
        System.out.println(byPairs(ids) + " " + bySorting(ids) + " " + bySet(ids));
        System.out.println(Arrays.toString(ids));   // 做法二沒有動到原陣列
    }
}

執行結果：

true true true
[9001, 9002, 9003, 9002]
寫法時間額外空間什麼時候選
兩兩比對O(n²)O(1)資料很少，或記憶體非常吃緊
先排序O(n log n)本例複製一份，O(n)；直接排原陣列也不保證只多用 O(1)：OpenJDK 25 的排序碰到由好幾段已排好的資料組成的陣列時，會另開一個同樣大小的暫存陣列出處本來就需要排序後的結果
HashSet平均 O(n)O(n)大部分情況的預設選擇

這段程式的額外空間複雜度是？

long sum = 0;
for (int i = 0; i < a.length; i++) {
    sum += a[i];
}
  • O(n)，因為 a 有 n 個元素
  • O(1)
  • O(log n)
  • O(n²)

只多用了 sum 和 i 兩個變數，跟 n 無關，O(1)。輸入陣列 a 本身不算額外空間。

這段程式的額外空間複雜度是？

int[] copy = a.clone();
Arrays.sort(copy);
  • O(1)
  • O(log n)
  • O(n²)
  • O(n)

clone 複製出一個跟 a 一樣長的新陣列，至少 O(n)。

為 n 個帳戶開一張「誰轉帳給過誰」的表：boolean[][] sent = new boolean[n][n];。額外空間是？

  • O(n²)
  • O(n)
  • O(2n)
  • O(1)

n 列、每列 n 格，共 n² 格。一萬個帳戶就是一億格，所以這種表只適合 n 不大的時候。

上面的 sumRecursive(n)，額外空間複雜度是？

  • O(1)，因為它沒有開任何陣列或集合，只用了參數 n
  • O(log n)
  • O(n)，同時有 n 層呼叫的框疊在堆疊上
  • O(n²)

沒開陣列不代表沒用空間。遞迴到最深時有 n 個框同時存在，空間 O(n)，太深就 StackOverflowError。

這段程式把陣列原地反轉（只在原陣列裡交換）。額外空間是？

for (int i = 0, j = a.length - 1; i < j; i++, j--) {
    int t = a[i];
    a[i] = a[j];
    a[j] = t;
}
  • O(n)
  • O(n/2)
  • O(1)
  • O(log n)

只用了 i、j、t 三個變數，沒有另外開陣列，額外空間 O(1)。時間是 O(n)（交換 n/2 次）。

面試時，怎麼把複雜度講清楚

回答複雜度的順序

下面是建議的講法，不是哪份官方文件規定的；重點是讓面試官聽得出你知道自己在算什麼：

  • 先講 n 是什麼。「n 是交易筆數」。有兩個輸入就用兩個字母：「n 個帳戶、m 筆交易」。
  • 先講時間，再講空間。「時間 O(n)，每筆看一次；額外空間 O(1)，只用了幾個變數」。
  • 說清楚是哪一種。HashMap 講「平均 O(1)」，ArrayList 尾端加入講「攤銷 O(1)」，快速排序講「平均 O(n log n)、最壞 O(n²)」。
  • 說出假設。「假設雜湊分散得好」「假設內建排序是 O(n log n)」。用到的函式庫方法也要算進去，例如迴圈裡的 contains。
  • 主動提取捨。先講暴力解的複雜度，再講怎麼用空間換時間降下來，例如兩兩比對 O(n²) 改成 HashSet 平均 O(n)、多用 O(n) 空間。

一段完整的回答聽起來像這樣：「n 是交易筆數。暴力解兩兩比對是 O(n²) 時間、O(1) 空間。改成邊走邊放進 HashSet，每筆平均 O(1)，總共平均 O(n) 時間，代價是 O(n) 的額外空間。另一個做法是先排序再比相鄰的，O(n log n) 時間。」

面試官問「你這個解法的複雜度是多少」，建議先講什麼？

  • 直接報一個 O(…) 就好，越短越好
  • 先講 n 代表什麼，再講時間複雜度，然後講空間複雜度
  • 先講空間複雜度，因為伺服器的記憶體比 CPU 時間貴，面試官最在意
  • 先講最好情況，因為最好看

沒講 n 是什麼，O(n) 就沒有意義；時間通常是面試官最先關心的，接著補空間。

你先寫出兩兩比對的 O(n²) 解，面試官問「能不能更快」。下面哪個方向是用空間換時間？

  • 把兩層迴圈的順序對調，讓比較少的那份資料放在外層先跑
  • 改用 while 迴圈
  • 邊走邊把看過的放進 HashSet，時間降到平均 O(n)，多用 O(n) 空間
  • 內層從 i + 1 開始

對調迴圈、改用 while 都不改變次數；內層從 i + 1 開始只少一半，還是 O(n²)。放進 HashSet 才是真的降一個等級，代價是記憶體。

你的解法是「先排序，再掃一遍」。總時間複雜度怎麼講？

  • O(n log n)：排序 O(n log n) 加掃描 O(n)，取大的
  • O(n)：掃描只要一遍
  • O(n² log n)：排序和掃描兩段的複雜度要相乘
  • O(log n)

先後執行相加、留最高的項，O(n log n)。只有「每一次掃描都要重新排序」才會相乘。

重點整理

  • 複雜度量的是 n 變大時步數（或記憶體）怎麼長；大 O 去掉常數、只留最高次項。O 是上限，本模組寫最貼近的等級。
  • 由快到慢：O(1)、O(log n)、O(n)、O(n log n)、O(n²)、O(2ⁿ)。n 變兩倍時，O(n) 變 2 倍、O(n²) 變 4 倍、O(log n) 只多 1 步、O(2ⁿ) 是 n 多 1 就翻倍。
  • 看程式碼：巢狀相乘、先後相加、每次乘或除以 2 是 log n、內層固定次數只算常數；迴圈裡呼叫的方法（例如 ArrayList.contains）也要算進去。兩個輸入分開寫成 n、m。
  • 最壞、平均講的是「拿哪一種輸入來算」，跟 O 的「上限」是兩件事：最壞是挑最花時間的輸入；平均要先假設輸入分布（HashMap 平均 O(1)）；攤銷是一串操作的總成本平均分攤（ArrayList.add 攤銷 O(1)，單次最壞 O(n)）。
  • 空間複雜度算額外用的記憶體；遞迴深度 n 層就是 O(n) 空間，太深會 StackOverflowError。
  • 面試：先講 n 是什麼，再講時間、空間，說清楚最壞／平均／攤銷與假設，最後提取捨。

算過的，不要再算

從費氏數列接上：什麼是動態規劃

〈遞迴與回溯〉看過：照定義寫的費氏數列 fib(30) 要呼叫 2,692,537 次，因為同一個 fib(k) 被重算了很多遍；加上備忘錄（memoization，把算過的答案存起來，下次直接查）之後只要 59 次，時間從 O(2ⁿ) 降到 O(n)。那一課說，這招往下延伸就是動態規劃（dynamic programming，簡稱 DP）。

動態規劃的基本想法分三步：出處

  1. 把複雜的問題遞迴拆成一些比較簡單的子問題。
  2. 把每個子問題的答案存起來。
  3. 最後用存起來的答案解出原本的問題。

每個子問題只解一次（不是一解再解），所以避開了執行時間可能的指數爆炸。

兩個條件

不是每個遞迴都該用動態規劃。值得用、也用得上的題目有兩個特徵：

  • 重疊子問題（overlapping subproblems）：同一個小題目會被問很多次。費氏數列裡 F(3) 同時是 F(5) 和 F(4) 的一部分。把子問題之間「誰需要誰」畫成一張有向無環圖，相依關係有重疊時（某個子問題被兩個以上的子問題需要，也就是圖裡有入度大於 1 的頂點）才是動態規劃。出處 合併排序也是遞迴拆小，但左半和右半互不重疊，子問題圖是一棵樹（這叫分治法），存答案沒有用。
  • 最佳子結構（optimal substructure）：大題目的最好答案，可以用小題目的最好答案拼出來。例如「湊 6 元最少幾枚硬幣」：如果最後一枚是 3 元，剩下的 3 元也一定要用最少的方式湊。能寫出這種遞迴解，就表示問題能拆成子問題。出處

題目看到「最多、最少、最長、有幾種方法」，而且暴力解要試遍所有選法、會指數爆炸時，就先想想能不能用動態規劃。

天真的遞迴 fib(5) 總共呼叫 15 次。這 15 次裡，fib(2) 被算了幾次？

  • 1 次
  • 2 次
  • 3 次
  • 5 次

fib(5) 分出 fib(4)、fib(3)；fib(4) 又分出 fib(3)、fib(2)；兩個 fib(3) 各分出一個 fib(2)。合起來 fib(2) 出現 3 次，〈遞迴與回溯〉的呼叫樹也是這樣。

下面哪一個問題有「重疊子問題」，最適合用動態規劃？

  • 爬樓梯：第 n 階要用前兩階的答案
  • 合併排序：左半與右半各自排好之後再合併
  • 二分搜尋：每次只往其中一半繼續找
  • 反轉一條鏈結串列，把箭頭全部掉頭

爬到第 n − 1 階的答案，在算第 n 階、第 n + 1 階時都會用到，重疊了。合併排序的左右半不重疊；二分搜尋每次只走一邊；反轉串列沒有子問題要重用。

用白話講「最佳子結構」，下面哪一句最貼切？

  • 大題的最好答案，可由小題的最好答案拼成
  • 子問題切得越小，最後拼出來的答案就越好
  • 每個子問題的答案只能被拿來用一次
  • 題目裡一定要出現最大值或最小值

例如湊 6 元最少的方法，拿掉最後一枚之後，剩下的也一定是湊那個金額最少的方法。「只能被用一次」剛好跟重疊子問題相反。

合併排序也是把問題拆成子問題遞迴解，為什麼通常不叫它動態規劃？

  • 因為它從頭到尾都沒有用到陣列
  • 因為它的時間是 O(n log n)，不夠快
  • 因為它其實不是遞迴，是迴圈
  • 因為左右兩半不重疊，存了也用不到

每一段只被排序一次，沒有子問題被重複需要，存答案沒有好處，這叫分治法，子問題圖是一棵樹。

在費氏數列的子問題相依圖裡（上圖），F2 被哪些子問題需要？

  • 只有 F3
  • F4 和 F3
  • F5 和 F4
  • F1 和 F0

F4 = F3 + F2，F3 = F2 + F1，所以 F4 和 F3 都需要 F2。反過來，F2 需要的是 F1 和 F0。

「列出 {1, 2, 3} 的所有排列」適合用動態規劃嗎？

  • 適合，排列有 n! 種，存起來可以變快
  • 適合，因為它具有最佳子結構
  • 不適合，要列出每一種，沒有可重用的答案
  • 不適合，因為這種題目只能用 BFS 解

要把每一種都列出來，輸出本身就有 n! 種，存答案省不了；這是〈遞迴與回溯〉的回溯法。動態規劃適合算「最多、最少、有幾種」這類一個數字的答案。

費氏數列加了備忘錄之後，時間複雜度從 O(2ⁿ) 降到多少？

  • O(n²)
  • O(log n)
  • O(1)
  • O(n)

n + 1 個子問題，每個只真的算一次，每次只做一次加法，所以是 O(n)。

同一張表，兩個方向填

由上而下（備忘錄）對由下而上（填表）

同一個動態規劃有兩種寫法：出處

  • 由上而下（top-down）：照原本的遞迴寫，但把解過的每個子問題結果存起來，下次需要同一個子問題時就用存起來的值，不必從頭再解。就是備忘錄。
  • 由下而上（bottom-up）：算出所有子問題的解，從最簡單的子問題開始，逐步建出越來越複雜的子問題的解。通常是一個陣列加一個迴圈，叫填表。

由下而上就是照子問題的拓樸順序解（通常用迴圈）。出處 也就是說，填表的順序要保證「要用到的格子都已經填好了」，跟拓樸排序要求「前置條件先排」是同一件事。

public class Fib {
    // 由上而下：遞迴＋備忘錄，需要誰才去算誰
    static long[] memo;
    static long topDown(int n) {
        if (n <= 1) return n;
        if (memo[n] != 0) return memo[n];              // 算過就直接查（F(n) 在 n ≥ 2 時不會是 0）
        return memo[n] = topDown(n - 1) + topDown(n - 2);
    }

    // 由下而上：從最小的子問題開始，一格一格把表填滿
    static long bottomUp(int n) {
        if (n <= 1) return n;
        long[] f = new long[n + 1];
        f[0] = 0;                                      // 初始值
        f[1] = 1;
        for (int i = 2; i <= n; i++) f[i] = f[i - 1] + f[i - 2];   // 轉移式：用前兩格算出這一格
        return f[n];                                   // 答案在最後一格
    }

    // 空間壓縮：每一格只用到前兩格，留兩個變數就夠
    static long twoVars(int n) {
        long prev = 0, cur = 1;                        // F(0)、F(1)
        if (n == 0) return 0;
        for (int i = 2; i <= n; i++) {
            long next = prev + cur;
            prev = cur;
            cur = next;
        }
        return cur;
    }

    public static void main(String[] args) {
        int n = 50;
        memo = new long[n + 1];
        System.out.println(topDown(n) + " " + bottomUp(n) + " " + twoVars(n));
        for (int i = 0; i <= 10; i++) System.out.print(bottomUp(i) + " ");
        System.out.println();
    }
}

備忘錄用 0 代表「還沒算」只在答案不可能是 0 時才行（費氏數列 n ≥ 2 時都大於 0）。答案可能是 0 的題目，要先把陣列填成 -1，或用 Long 陣列以 null 代表沒算過。另外，long 只裝得下到 F(92)；實跑 bottomUp(93) 會溢位變成負數 -6246583658587674878。

哪一種寫法只會算「真的用得到」的子問題？

  • 由上而下（遞迴＋備忘錄）
  • 由下而上（填表）
  • 兩種都會把所有子問題算一遍
  • 兩種都只算用得到的

由上而下從原問題開始遞迴，碰到誰才算誰；由下而上照順序把整張表填滿，有些格子可能根本用不到。

由下而上填費氏數列的表，f[6] 是多少？

  • 5
  • 6
  • 13
  • 8

f[0..6] 是 0、1、1、2、3、5、8。實跑第二行輸出的第 7 個數就是 8。

下面的填表把迴圈條件寫錯了。n = 5 時回傳什麼？

long[] f = new long[n + 1];
f[0] = 0;
f[1] = 1;
for (int i = 2; i < n; i++) f[i] = f[i - 1] + f[i - 2];
return f[n];
  • 5
  • 0
  • 3
  • 丟出 ArrayIndexOutOfBoundsException

i < n 讓迴圈只填到 f[4]，f[5] 從沒被填，保持陣列的預設值 0。陣列長度是 n + 1，讀 f[5] 不會越界。

由下而上填表時，格子的填寫順序要滿足什麼？

  • 用到的格子都要先填好
  • 一定要由大到小填
  • 一定要隨機打亂順序，避免偏差
  • 先填答案那一格，再往回填

這就是「照子問題的拓樸順序」填表。費氏數列要由小到大；有些題目（例如背包壓成一維）反而要由大到小，看的是相依關係。

用由上而下（遞迴＋備忘錄）算 topDown(100000)，最可能出什麼問題？

  • 結果會比由下而上的版本小
  • 時間會退化成指數級
  • 備忘錄陣列會存不下
  • 遞迴太深，堆疊溢位

第一次呼叫會一路遞迴到 topDown(1)，十萬層呼叫同時在堆疊上。時間仍是 O(n)；陣列存十萬個 long 也沒問題（只是數字早就溢位了）。

某一題的子問題答案可能是 0。備忘錄用 int[] memo、以 memo[i] != 0 判斷「算過了」，會出什麼事？

  • 子問題的答案會算錯
  • 答案是 0 的格子每次都被當成沒算過
  • 編譯就會失敗，int 不能比 0
  • 完全沒問題，0 本來就代表沒算過

答案本身仍然正確，但 0 跟「還沒算」分不出來，那些格子就失去備忘錄的效果，最壞又回到指數時間。改用 -1 當沒算過，或用 Long 陣列以 null 表示。

由下而上要照子問題的拓樸順序解。這裡的「拓樸順序」指的是？

  • 每個子問題排在需要它的子問題前面
  • 子問題依照編號由大到小依序排好
  • 子問題依照各自答案的大小排序
  • 只要隨便一種順序都可以

把「誰需要誰」畫成有向無環圖，拓樸順序保證被需要的先算。就是〈圖：BFS、DFS 與拓樸排序〉裡「前置條件先排」的同一個概念。

四個問題問自己

解題四步驟：狀態、轉移式、初始值、答案在哪

寫遞迴（也就是寫動態規劃）的完整步驟：出處

  1. 定義子問題。
  2. 把子問題的解用遞迴關係連起來。
  3. 確認子問題之間沒有環（有拓樸順序）。
  4. 寫出初始情況。
  5. 說明原問題的答案從哪個子問題來。
  6. 分析時間。

面試時濃縮成四個問題就好。先講兩個名詞：狀態是「dp[i] 這一格代表什麼」，轉移式是「怎麼用比較小的格子算出這一格的公式」。

步驟問自己爬樓梯的回答
1. 狀態dp[i] 代表什麼？要能用一句話講完dp[i]＝爬到第 i 階的走法數
2. 轉移式最後一步有哪幾種選擇？每種選擇之前的狀態是什麼？最後一步爬 1 階（從 i − 1 來）或 2 階（從 i − 2 來）：dp[i] = dp[i − 1] + dp[i − 2]
3. 初始值最小的幾個狀態，答案直接知道是多少？dp[0] = 1（還沒爬，算一種）、dp[1] = 1
4. 答案在哪原題目對應哪一格（或哪幾格取最大）？dp[n]

第一步要用文字描述子問題的意思。出處 狀態講不清楚，後面三步一定會亂。填表順序（第五件事）通常由轉移式決定：dp[i] 用到比較小的 i，就由小到大填。

public class Stairs {
    // 一次爬 1 階或 2 階，爬到第 n 階有幾種走法
    static long ways(int n) {
        long[] dp = new long[n + 1];                   // dp[i]：爬到第 i 階的走法數
        dp[0] = 1;                                     // 站在地面：什麼都不做也算一種
        if (n >= 1) dp[1] = 1;
        for (int i = 2; i <= n; i++) {
            dp[i] = dp[i - 1] + dp[i - 2];             // 最後一步是 1 階，或是 2 階
        }
        return dp[n];
    }

    public static void main(String[] args) {
        for (int n = 1; n <= 6; n++) System.out.print(ways(n) + " ");
        System.out.println();
        System.out.println(ways(45));
    }
}

爬樓梯（一次 1 或 2 階），ways(5) 是多少？

  • 13
  • 8

dp 依序是 1、1、2、3、5、8，第 5 階是 8。實跑第一行的第 5 個數就是 8。

爬樓梯的狀態 dp[i]，最清楚的定義是哪一句？

  • 爬到第 i 階總共有幾種走法
  • 第 i 步爬了幾階
  • 從第 i 階爬到頂還剩幾階
  • 爬到第 i 階最少要幾步

題目問的是走法數，狀態就定成「到第 i 階的走法數」，答案才會在 dp[n]。「最少幾步」是另一個題目。

如果一次可以爬 1、2 或 3 階，轉移式該改成什麼？

  • dp[i] = dp[i − 1] + dp[i − 2]
  • dp[i] = 3 × dp[i − 1]
  • dp[i] = dp[i − 1] × dp[i − 2] × dp[i − 3]
  • dp[i] = dp[i − 1] + dp[i − 2] + dp[i − 3]

最後一步有三種選擇，各自之前的狀態是 i − 1、i − 2、i − 3，走法數相加。走法是「或」的關係，要相加不是相乘。

接上題（一次 1、2 或 3 階），初始值 dp[0] = 1、dp[1] = 1、dp[2] = 2。dp[4] 是多少？

  • 5
  • 7
  • 8
  • 4

dp[3] = 2 + 1 + 1 = 4，dp[4] = dp[3] + dp[2] + dp[1] = 4 + 2 + 1 = 7。

為什麼爬樓梯的初始值設 dp[0] = 1，而不是 0？

  • 因為陣列的預設值是 0，要改掉才看得出來
  • 從地面直接跨 2 階也算一種走法
  • 因為 Java 陣列的索引是從 1 開始的
  • 只是習慣，設成 0 結果也完全一樣

dp[2] = dp[1] + dp[0]，其中 dp[0] 代表「最後一步直接從地面跨 2 階」那一種。設成 0 的話 dp[2] 會少算這種，變成 1。

承上題，如果真的寫成 dp[0] = 0、dp[1] = 1，其他照舊，ways(3) 會算出多少（正確答案是 3）？

  • 3
  • 1
  • 2
  • 0

dp[2] = 1 + 0 = 1，dp[3] = 1 + 1 = 2。初始值錯一格，後面每一格都跟著錯。

四個步驟裡，應該最先決定的是哪一個？

  • 狀態 dp[i] 的意思
  • 轉移式要怎麼寫
  • 初始值要填多少
  • 答案在表的哪一格

轉移式、初始值、答案位置都是根據狀態的意思推出來的。狀態沒講清楚，轉移式就寫不出來。

上面的 Stairs.ways(n)，時間與空間各是多少？

  • 時間 O(2ⁿ)，空間 O(n)
  • 時間 O(n)，空間 O(1)
  • 時間 O(n)，空間 O(n)
  • 時間 O(n²)，空間 O(n)

一個 n + 1 格的陣列，每格算一次、每次 O(1)。空間 O(1) 是壓縮成兩個變數之後的版本。

找零錢，貪婪不一定對

最小硬幣數：每一格看最後一枚用哪個

題目：有幾種面額的硬幣（每種數量不限），湊出某個金額最少要幾枚？湊不出來回傳 -1。照四步驟：

  • 狀態：dp[x]＝湊出 x 元最少要幾枚。
  • 轉移式：最後一枚可以是任何一種面額 c（c ≤ x），之前要湊出 x − c 元：dp[x] = min(dp[x − c] + 1)，對每個 c 取最小。
  • 初始值：dp[0] = 0（0 元不用硬幣）；其他先填一個「不可能」的大數，代表還湊不出來。
  • 答案：dp[amount]，還是那個大數就回傳 -1。
import java.util.Arrays;

public class Coins {
    // 湊出 amount 最少要幾枚硬幣；湊不出來回傳 -1
    static int minCoins(int[] coins, int amount) {
        int INF = amount + 1;                          // 比任何可能的答案都大，當作「湊不出來」
        int[] dp = new int[amount + 1];                // dp[x]：湊出 x 元最少幾枚
        Arrays.fill(dp, INF);
        dp[0] = 0;                                     // 0 元不需要硬幣
        for (int x = 1; x <= amount; x++) {
            for (int c : coins) {
                if (c <= x && dp[x - c] + 1 < dp[x]) {
                    dp[x] = dp[x - c] + 1;             // 最後一枚用 c，剩下 x - c 元
                }
            }
        }
        System.out.println(Arrays.toString(dp));
        return dp[amount] == INF ? -1 : dp[amount];
    }

    // 貪婪法：每次都拿最大的面額（不一定對）
    static int greedy(int[] coinsDesc, int amount) {
        int count = 0;
        for (int c : coinsDesc) {
            count += amount / c;
            amount %= c;
        }
        return amount == 0 ? count : -1;
    }

    public static void main(String[] args) {
        System.out.println(minCoins(new int[]{1, 3, 4}, 6));
        System.out.println("貪婪法 " + greedy(new int[]{4, 3, 1}, 6));
        System.out.println(minCoins(new int[]{2}, 3));

為什麼不能每次拿最大的面額？那叫貪婪法（greedy，每一步都選眼前看起來最好的）：6 元先拿 4，剩 2 元只能拿兩個 1，共 3 枚；但 3 + 3 只要 2 枚。貪婪法只看眼前，動態規劃把每種「最後一枚」都試過。有些面額組合用貪婪剛好會對，但題目給的面額不一定是那種，面試要用動態規劃。

INF 設成 amount + 1 而不是 Integer.MAX_VALUE：因為轉移式會做 dp[x − c] + 1，MAX_VALUE + 1 會溢位變成負數，反而被當成最小。複雜度：金額 A、面額 k 種，表有 A + 1 格，每格試 k 種，時間 O(A × k)，空間 O(A)。

面額 1、3、4，dp[5]（湊 5 元最少幾枚）是多少？

  • 1
  • 2
  • 3
  • 5

4 + 1 共 2 枚。看轉移式：dp[4] + 1 = 2、dp[2] + 1 = 3、dp[1] + 1 = 2，取最小 2。實跑的表第 6 格也是 2。

最小硬幣數的轉移式是哪一個？

  • dp[x] = dp[x − 1] + dp[x − 2]
  • dp[x] = 所有 c 的 dp[x − c] 加總
  • dp[x] = 所有 c 的 dp[x − c] + 1 取最小
  • dp[x] = x ÷ 最大面額，有餘數就無條件進位

每一種「最後一枚」都試，加上那一枚，取最少。取總和是在算「有幾種湊法」，那是另一題；除以最大面額就是貪婪法。

為什麼 dp 除了 dp[0] 之外，一開始要填成一個很大的數，而不是 0？

  • 因為 Java 的陣列預設就是很大的數
  • 取最小值時，填 0 的格子永遠蓋不掉
  • 為了讓整個程式跑得比較快一點
  • 為了讓 dp[0] 可以順利設成 0

取 min 時，原本的 0 永遠最小，任何真正的答案都蓋不掉它。填「不可能的大數」代表還湊不出來，有更好的才會換掉。

面額只有 2 元與 5 元，湊 9 元最少幾枚？

面額 1、3、4 湊 6 元，「每次拿最大面額」的貪婪法會用幾枚？

  • 2

  • 4

為什麼 INF 用 amount + 1，而不用 Integer.MAX_VALUE？

  • MAX_VALUE 太大，陣列根本放不下
  • amount + 1 比較好記，也比較好讀
  • 兩者完全沒差別，只是寫法不同
  • MAX_VALUE + 1 會溢位成負數

int 的最大值加 1 會變成最小的負數，反而被 min 選中。答案最多 amount 枚（全用 1 元），amount + 1 已經夠當「不可能」。

背包只裝得下這麼重

0/1 背包（簡化版）

題目：有 n 樣東西，各有重量和價值，背包最多裝重量 W。每樣東西最多拿一次（拿或不拿，所以叫 0/1），總價值最大是多少？子問題定為「只用前 i 樣東西、容量 j 時的最大價值」，轉移式是兩種選擇取大的：不拿第 i 樣（答案跟只用前 i − 1 樣一樣），或拿第 i 樣（得到它的價值，再用剩下的容量 j − 重量裝前 i − 1 樣），後者只在放得下時才能選。出處

  • 狀態：dp[i][j]＝只考慮前 i 樣、容量 j 時的最大價值。
  • 轉移式：dp[i][j] = max(dp[i − 1][j], dp[i − 1][j − w] + v)，第二項只在 j ≥ w 時成立（w、v 是第 i 樣的重量與價值）。
  • 初始值：dp[0][j] = 0（沒有東西可拿）、dp[i][0] = 0（容量 0）。Java 陣列預設就是 0。
  • 答案：dp[n][W]。
import java.util.Arrays;

public class Knapsack {
    // 0/1 背包：每樣東西最多拿一次，總重不超過 cap，價值最大是多少
    static int twoD(int[] w, int[] v, int cap) {
        int n = w.length;
        int[][] dp = new int[n + 1][cap + 1];          // dp[i][j]：只考慮前 i 樣、容量 j 時的最大價值
        for (int i = 1; i <= n; i++) {
            for (int j = 0; j <= cap; j++) {
                dp[i][j] = dp[i - 1][j];               // 不拿第 i 樣
                if (j >= w[i - 1]) {                   // 放得下才能拿
                    dp[i][j] = Math.max(dp[i][j], dp[i - 1][j - w[i - 1]] + v[i - 1]);
                }
            }
        }
        for (int[] row : dp) System.out.println(Arrays.toString(row));
        return dp[n][cap];
    }

    // 空間壓縮成一維：j 一定要由大到小，才不會同一樣東西拿兩次
    static int oneD(int[] w, int[] v, int cap) {
        int[] dp = new int[cap + 1];
        for (int i = 0; i < w.length; i++) {
            for (int j = cap; j >= w[i]; j--) {
                dp[j] = Math.max(dp[j], dp[j - w[i]] + v[i]);
            }
        }
        return dp[cap];
    }

    public static void main(String[] args) {
        int[] w = {1, 3, 4, 5};
        int[] v = {1, 4, 5, 7};
        System.out.println(twoD(w, v, 7));
        System.out.println(oneD(w, v, 7));
    }
}

0/1 背包的轉移式，「拿第 i 樣」那一項是什麼？（w、v 是第 i 樣的重量與價值）

  • dp[i][j − w] + v
  • dp[i − 1][j] + v
  • dp[i − 1][j − w] + v
  • dp[i − 1][j − v] + w

拿了第 i 樣，剩下的容量 j − w 只能裝前 i − 1 樣（每樣只能拿一次）。用 dp[i][j − w] 等於允許第 i 樣再拿一次，那是數量不限的背包。

dp[0][j] 全部是 0，代表什麼意思？

  • 還沒考慮任何東西，什麼都拿不了
  • 背包的容量是 0，什麼都放不下
  • 第 0 樣東西本身沒有任何價值
  • 背包已經裝滿了，不能再放

i = 0 表示「前 0 樣」，沒有東西可拿，價值當然是 0。容量 0 是 dp[i][0] 那一欄。

（重量, 價值）是 (6, 6)、(9, 9)、(10, 12)，容量 15。最大價值是多少？

  • 12
  • 15
  • 21
  • 27

拿 6 和 9 兩樣，重 15、值 15。拿 10 那樣之後剩 5，誰都放不下，只有 12。三樣全拿重 25 超重。實跑一維版本也是 15。

為什麼 0/1 背包不能用「價值除以重量最高的先拿」？

  • 因為除法會產生小數，誤差太大
  • 因為這樣算比動態規劃慢很多
  • 先拿划算的，剩餘容量可能浪費掉
  • 其實可以，只是面試官不喜歡

(10, 12) 單位價值最高，拿了之後剩 5 放不下別的，總共 12，不如 6 + 9 的 15。東西不能切開，就要每種組合都考慮到。

n 樣東西、容量 W，二維背包表的時間複雜度是多少？

  • O(n + W)
  • O(2ⁿ)
  • O(n log W)
  • O(n × W)

表有 (n + 1) × (W + 1) 格，每格只做一次比較。O(2ⁿ) 是把每種拿法都列出來的暴力解。

填背包表時，第 i 列的每一格只會用到哪一列的格子？

  • 第 i − 1 列（正上方與左上方）
  • 第 i 列自己左邊已經填好的格子
  • 下一列，也就是第 i + 1 列
  • 整張表的任何一格都可能用到

兩種選擇都是看「前 i − 1 樣」的答案，也就是上一列。所以表可以一列一列往下填，也能壓成只留一列。

兩串字的共同部分

最長共同子序列（LCS）

子序列（subsequence）是從字串裡刪掉一些字、剩下的字照原順序排出來的結果，不必連續。從 x 刪掉一些字、從 y 刪掉一些字，剩下的兩個字串相等，就叫共同子序列；LCS 問題是找最長的那一個。例如 GGCACCACG 與 ACGGCGGATACG 的 LCS 是 GGCAACG，長度 7。出處

  • 狀態：dp[i][j]＝a 的前 i 個字與 b 的前 j 個字的 LCS 長度。
  • 轉移式：看兩邊的最後一個字。一樣的話，它一定可以算進 LCS：dp[i − 1][j − 1] + 1；不一樣，至少有一邊的最後一個字用不到，丟掉其中一邊取大的：max(dp[i − 1][j], dp[i][j − 1])。
  • 初始值：任一邊是空字串，LCS 是 0：第 0 列、第 0 欄都是 0。
  • 答案：dp[m][n]，右下角。

也可以用「後綴」（從第 i 個字到結尾）當子問題，三種情況一模一樣：起頭的字相同就一起去掉、加 1；不同就丟掉其中一個、取較大的。出處 這裡改用「前綴」，表從左上往右下填，比較直覺；兩種寫法的答案相同。

public class Lcs {
    // 最長共同子序列：dp[i][j] 是 a 的前 i 個字與 b 的前 j 個字的 LCS 長度
    static int lcs(String a, String b) {
        int m = a.length(), n = b.length();
        int[][] dp = new int[m + 1][n + 1];            // 第 0 列、第 0 欄是空字串，都是 0
        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                if (a.charAt(i - 1) == b.charAt(j - 1)) {
                    dp[i][j] = dp[i - 1][j - 1] + 1;   // 最後一個字一樣：一起算進去
                } else {
                    dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);   // 丟掉其中一邊的最後一個字
                }
            }
        }
        for (int[] row : dp) System.out.println(java.util.Arrays.toString(row));
        return dp[m][n];
    }

    public static void main(String[] args) {
        System.out.println(lcs("ABCDE", "ACE"));
    }
}

  • max(dp[i − 1][j], dp[i][j − 1])
  • dp[i − 1][j] + dp[i][j − 1]
  • dp[i − 1][j − 1]

相同的那個字可以放進 LCS，再接上兩邊都去掉這個字之後的 LCS。取 max 是字不同時的寫法。

  • 兩個字串的第一個字剛好不同

一路往上爬的最長子序列

最長遞增子序列（LIS）

題目：一串數字裡，最長的「嚴格遞增」子序列有多長（一樣不必連續）？這題要用一個技巧：直接用「前 i 個」當子問題接不起來，因為不知道接上去會不會遞增；要在子問題加一個條件，固定「一定包含某個元素」，才接得起來。出處

  • 狀態：dp[i]＝以 nums[i] 結尾的最長遞增子序列長度。
  • 轉移式：nums[i] 可以接在任何比它小的 nums[j]（j < i）後面：dp[i] = max(dp[j] + 1)，對所有 j < i 且 nums[j] < nums[i]。
  • 初始值：每個 dp[i] 至少是 1（只有自己）。
  • 答案：所有 dp[i] 的最大值，因為最長的那條不一定在最後一個數結束。

對稱的寫法是用「以 A[i] 開頭的後綴」當子問題，一樣取所有子問題答案的最大值，時間 O(|A|²)。出處

import java.util.Arrays;

public class Lis {
    // 最長遞增子序列（O(n²)）：dp[i] 是「以 nums[i] 結尾」的最長遞增子序列長度
    static int lis(int[] nums) {
        int n = nums.length;
        int[] dp = new int[n];
        Arrays.fill(dp, 1);                            // 只有自己一個，長度 1
        int best = 0;
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < i; j++) {
                if (nums[j] < nums[i]) dp[i] = Math.max(dp[i], dp[j] + 1);   // 接在 nums[j] 後面
            }
            best = Math.max(best, dp[i]);              // 答案不一定在最後一格
        }
        System.out.println(Arrays.toString(dp));
        return best;
    }

    public static void main(String[] args) {
        System.out.println(lis(new int[]{10, 9, 2, 5, 3, 7, 101, 18}));
    }
}

兩層迴圈，O(n²) 時間、O(n) 空間。這題可以加速到 O(n log n)。出處 常見的做法是另外維護一個「長度 k 的遞增子序列，結尾最小可以是多少」的陣列，用二分搜尋更新它（〈排序與二分搜尋〉）。面試先寫 O(n²) 版本，再說得出有更快的做法就夠了。

LIS 的狀態 dp[i] 定義成「以 nums[i] 結尾」的最長遞增子序列，為什麼不定義成「前 i 個數裡」的最長遞增子序列？

  • 知道結尾是誰，才能判斷接不接得上
  • 因為 Java 陣列的索引只能從 0 開始
  • 因為這樣定義比較省記憶體空間
  • 兩種定義其實完全一樣

要接 nums[i]，得知道前一段的最後一個數比它小。「前 i 個裡最長的」不記得結尾是誰，接不起來，這就是要替子問題加條件的原因。

  • 5
  • 8

例如 1、4、5、9 或 3、4、5、6，長度 4。實跑的 dp 是 [1, 1, 2, 1, 3, 4, 2, 4]，最大值 4。

同上，nums = {3, 1, 4, 1, 5, 9, 2, 6}，dp[6]（以 2 結尾）是多少？

  • 1
  • 3
  • 4
  • 2

2 前面比它小的只有兩個 1，dp 都是 1，所以 dp[6] = 1 + 1 = 2（例如 1、2）。

nums = {1, 2, 3, 0}，dp 是 [1, 2, 3, 1]。答案是多少？

  • 1
  • 4
  • 0

答案是 dp 的最大值 3（1、2、3），不是最後一格的 1。這就是程式裡另外記 best 的原因。

nums = {2, 2, 2}，用上面的程式（嚴格遞增），LIS 是多少？

  • 0
  • 1
  • 2

條件是 nums[j] < nums[i]，相等不能接。每個 2 只能自己一個，答案 1。題目若要「不遞減」，就要改成 <=。

上面的 LIS 寫法時間複雜度是多少？還有更快的做法嗎？

  • O(n)，沒有更快的
  • O(2ⁿ)，可以加備忘錄變成 O(n²)
  • O(n log n)，已經最快
  • O(n²)；有 O(n log n) 的做法

每個 i 都往前看所有 j，兩層迴圈 O(n²)。可以加速到 O(n log n)，常見做法搭配二分搜尋。

只留下一輪會用到的

空間壓縮，以及怎麼認出動態規劃題

填表時，如果每一格只用到「前幾格」或「上一列」，更早的格子就可以丟掉，空間跟著變小。代價是表不完整了：要還原答案本身（不只是長度或最大值）時，通常要從最後一格沿著整張表往回走，例如找出 LCS 字串就是把填表的步驟倒著走回去，這時就不能丟。出處

  • 只用前兩格（費氏、爬樓梯）：留兩個變數，空間 O(1)，上面 Fib.twoVars 就是。
  • 只用上一列和這一列左邊那格（LCS 長度）：留兩列，空間從 O(m × n) 降到 O(n)。
  • 只用上一列的正上方與左上方（0/1 背包）：可以壓成一列，但 j 要由大到小。
public class Rolling {
    // LCS 只要長度時，每一格只用到上一列和這一列左邊那格：留兩列就夠
    static int lcsTwoRows(String a, String b) {
        int n = b.length();
        int[] prev = new int[n + 1], cur = new int[n + 1];
        for (int i = 1; i <= a.length(); i++) {
            for (int j = 1; j <= n; j++) {
                cur[j] = a.charAt(i - 1) == b.charAt(j - 1)
                        ? prev[j - 1] + 1
                        : Math.max(prev[j], cur[j - 1]);
            }
            int[] t = prev; prev = cur; cur = t;       // 這一列變成下一輪的「上一列」
        }
        return prev[n];
    }

    // 一維背包，j 由小到大（錯誤示範）：同一樣東西會被拿好幾次
    static int knapsackWrong(int[] w, int[] v, int cap) {
        int[] dp = new int[cap + 1];
        for (int i = 0; i < w.length; i++) {
            for (int j = w[i]; j <= cap; j++) {
                dp[j] = Math.max(dp[j], dp[j - w[i]] + v[i]);
            }
        }
        return dp[cap];
    }

    public static void main(String[] args) {
        System.out.println(lcsTwoRows("ABCDE", "ACE"));
        int[] w = {2}, v = {3};                         // 只有一樣東西：重 2、值 3
        System.out.println(Knapsack.oneD(w, v, 4) + " " + knapsackWrong(w, v, 4));
    }
}
3
3 6

背包壓成一列時，dp[j] 要用的是「上一列」的 dp[j − w]。j 由小到大的話，dp[j − w] 在這一輪已經被改過了（已經算進這樣東西），等於同一樣東西拿了第二次：上面的例子只有一樣重 2、值 3 的東西，容量 4 正確答案是 3，錯誤版本拿了兩次變成 6。由大到小時，dp[j − w] 還沒被這一輪碰過，仍是上一列的值。（反過來，題目若是「每樣東西數量不限」，由小到大正好就是對的，最小硬幣數就是這種。）

怎麼認出動態規劃題

線索例子
問「最多、最少、最長、最大價值」最小硬幣數、背包、LCS、LIS
問「有幾種方法」爬樓梯、格子從左上走到右下有幾條路
每一步有幾種選擇，暴力解要試遍所有組合每樣東西拿或不拿、每個字留或刪
貪婪法找得到反例面額 1、3、4 湊 6；背包 (6, 6)、(9, 9)、(10, 12)

要把每一種組合本身都列出來（所有排列、所有子集），就不是動態規劃，是〈遞迴與回溯〉的回溯法。

LCS 只要長度、改成只留兩列，空間從 O(m × n) 降到多少？

  • O(1)
  • O(n)（b 的長度）
  • O(m + n) 的平方
  • 不變，還是 O(m × n)

每一格只用到上一列和這一列左邊那格，留 prev、cur 兩列，各 n + 1 格。時間還是 O(m × n)。

用 twoVars 的寫法（prev = 0, cur = 1，從 i = 2 跑到 n），n = 7 時回傳什麼？

  • 8
  • 21
  • 13
  • 7

F(7) = 13：每一輪 next = prev + cur，依序算出 1、2、3、5、8、13。

0/1 背包壓成一維時，內層迴圈 j 為什麼要由大到小？

  • 由大到小跑得比較快
  • 由小到大的話同一樣會拿兩次
  • 因為陣列要從尾巴開始填
  • 兩種方向結果一樣，只是習慣

一維陣列裡左邊的格子，在由小到大時已經被這一輪更新過。實跑的反例：只有一樣（重 2、值 3）、容量 4，正確是 3，由小到大算出 6。

下面哪一題最像動態規劃題？（格子題只能往右或往下走）

  • 印出一個集合的所有子集
  • 在排序好的陣列裡找某個數
  • 把一條鏈結串列整條反轉
  • 格子從左上走到右下有幾條路

問「有幾種方法」，而且每格的路數等於上方加左方的路數，子問題大量重疊。印出所有子集要用回溯；找數用二分搜尋；反轉串列沒有子問題。

要印出 LCS 的「字串本身」（不只是長度），為什麼通常不能只留兩列？

  • 往回找要用到整張表
  • 因為兩列的長度不一樣
  • 因為字串不能存在 int 陣列裡
  • 其實可以，兩列就夠

往回找 LCS 要看每一格是從左上、上方還是左方來的，需要整張表；還原 LCS 就是把填表的步驟倒著走回去。

重點整理

  • 動態規劃＝把問題拆成子問題、每個子問題的答案存起來只算一次。用得上的兩個條件：重疊子問題（同一個小題被問很多次）、最佳子結構（大題的最好答案由小題的最好答案拼成）。
  • 由上而下＝遞迴＋備忘錄，只算用得到的，可能遞迴太深；由下而上＝陣列＋迴圈填表，順序要讓被用到的格子先填好（子問題的拓樸順序）。
  • 四步驟：狀態 dp[i] 用一句話講清楚 → 轉移式看「最後一步有哪些選擇」→ 初始值 → 答案在哪一格（LIS 是取最大值）。
  • 爬樓梯 dp[i] = dp[i − 1] + dp[i − 2]，dp[0] = 1；最小硬幣數 dp[x] = min(dp[x − c] + 1)，其他格先填「不可能的大數」，貪婪法會錯。
  • 0/1 背包 dp[i][j] = max(不拿 dp[i − 1][j]，拿 dp[i − 1][j − w] + v)，時間 O(n × W)；壓成一維時 j 由大到小。
  • LCS：字相同取左上 + 1，不同取上方與左方的較大值，O(m × n)；LIS：dp[i] 以 nums[i] 結尾，O(n²)，有 O(n log n) 的做法。
  • 只用到前幾格或上一列就能壓空間：費氏與爬樓梯 O(1)、LCS 長度兩列；要還原答案本身時通常要整張表。

解題流程：六個步驟

MIT 6.006 第一堂課開宗明義：這門課要教的是「解決計算問題，並且讓別人明白你的解法是正確而且有效率的」（The goal of this class is to teach you to solve computation problems, and to communicate that your solutions are correct and efficient.）。出處 面試的程式題也是兩件事都要：寫對，並且把想法說出來。下面的六步是常見的做法，不是每場面試都一樣；有的面試官會直接跳到某一步，跟著對方的節奏調整就好。

  1. 問清楚。先用自己的話把題目說一遍，再問：輸入有多大（n 最大多少）、值的範圍（會不會有負數、會不會超過 int）、可不可能是空的、有沒有重複、找不到答案時回傳什麼。MIT 講義提醒「輸入的大小常叫做 n，但不一定」（Size of input is often called ‘n’, but not always!）出處，兩個輸入就分開叫 n 和 m（〈複雜度：程式跑多快、吃多少記憶體〉的寫法）。
  2. 先講暴力解。想得到的最直接寫法，哪怕是 O(n²)，先說出來並講出它的複雜度。這證明你至少能解，也給後面的優化一個比較的基準。MIT 講義的「怎麼解演算法問題」（How to Solve an Algorithms Problem）把方法分成兩條路：化成已知的問題（用學過的資料結構或演算法），或自己設計，第一個列的就是暴力法（Brute Force）。出處
  3. 找瓶頸，再優化。指出暴力解慢在哪一行（通常是內層迴圈在「找東西」），再想哪個資料結構能把那個「找」變快。下一段的對照表就是在做這件事。
  4. 寫程式。變數取有意義的名字，邊寫邊說這一段在做什麼。先寫主流程，細節（例如輸入檢查）可以先說「這裡要處理空陣列」再補。
  5. 自己跑一遍。寫完不要直接說「好了」，拿一個小例子照程式一行一行走，再拿邊界例子（空的、一個元素、全部一樣）走一次。跑出錯就回去改。
  6. 講複雜度。照〈複雜度：程式跑多快、吃多少記憶體〉的順序：n 是什麼、時間、空間、是最壞還是平均或攤銷，最後提還能怎麼取捨。

拿 LeetCode 第 1 題 Two Sum 的情境走一次：在陣列裡找兩個數加起來等於目標，回傳它們的索引。問清楚之後（有沒有一定有答案？同一個元素能不能用兩次？），先講暴力解：每一對都試，O(n²)。瓶頸是內層迴圈在「找補數」，換成 HashMap 一次查到，平均 O(n)（細節見〈雜湊表：HashMap 怎麼做到幾乎一步找到〉）。兩種寫法放在一起，再用邊界例子跑：

import java.util.Arrays;
import java.util.HashMap;
import java.util.Map;

public class TwoSumFlow {
    // 第一步：暴力解。每一對都試，O(n²) 時間、O(1) 額外空間
    static int[] brute(int[] nums, int target) {
        for (int i = 0; i < nums.length; i++)
            for (int j = i + 1; j < nums.length; j++)
                if (nums[i] + nums[j] == target) return new int[] {i, j};
        return new int[0];                                // 沒有答案：回傳空陣列（先跟面試官講好）
    }

    // 第二步：優化。邊走邊記「值 → 索引」，先查補數再放，O(n) 平均時間、O(n) 額外空間
    static int[] fast(int[] nums, int target) {
        Map<Integer, Integer> seen = new HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            Integer j = seen.get(target - nums[i]);
            if (j != null) return new int[] {j, i};
            seen.put(nums[i], i);                          // 先查再放：同一個元素不會用兩次
        }
        return new int[0];
    }

    public static void main(String[] args) {
        int[][] inputs = {{2, 7, 11, 15}, {3, 3}, {3, 2, 4}, {}, {5}, {-1, -2, -3}};
        int[] targets = {9, 6, 6, 1, 5, -5};
        for (int k = 0; k < inputs.length; k++) {
            int[] a = brute(inputs[k], targets[k]);
            int[] b = fast(inputs[k], targets[k]);
            System.out.println(Arrays.toString(inputs[k]) + " 目標 " + targets[k]
                    + " → 暴力 " + Arrays.toString(a) + "，雜湊 " + Arrays.toString(b));
        }
    }
}

執行結果：

[2, 7, 11, 15] 目標 9 → 暴力 [0, 1]，雜湊 [0, 1]
[3, 3] 目標 6 → 暴力 [0, 1]，雜湊 [0, 1]
[3, 2, 4] 目標 6 → 暴力 [1, 2]，雜湊 [1, 2]
[] 目標 1 → 暴力 []，雜湊 []
[5] 目標 5 → 暴力 []，雜湊 []
[-1, -2, -3] 目標 -5 → 暴力 [1, 2]，雜湊 [1, 2]

這幾個測試各有用意：[3, 3] 測重複元素；[3, 2, 4] 目標 6 測「同一個元素不能用兩次」（3 + 3 不算，因為只有一個 3）；空陣列和只有一個元素測邊界；負數測值的範圍。暴力解留著當對照，兩種寫法答案一致，優化版才算可信。

問清楚 → 暴力解 → 找瓶頸 → 寫程式 → 自己跑 → 講複雜度；先求對、再求快、最後說清楚

拿到題目之後，照這課的流程，第一件事做什麼？

  • 直接寫出最快的解法，展現實力
  • 用自己的話重述題目，問清楚範圍與邊界
  • 先講這題的時間與空間複雜度
  • 先把測試案例寫成程式碼

沒問清楚就寫，常常寫到一半才發現有負數、有重複或可能是空的。先確認規格，後面每一步才有依據。

講完 O(n²) 的暴力解之後，下一步通常是？

  • 直接開始寫暴力解，寫完就交
  • 說明 O(n²) 已經是最好的
  • 指出慢在哪一行，想用哪個資料結構把那一步變快
  • 換一種程式語言重寫

優化要從瓶頸下手：Two Sum 慢在內層迴圈「找補數」，換成 HashMap 一次查到。〈複雜度：程式跑多快、吃多少記憶體〉的規則也是先找最貴的那一段。

Two Sum 用 HashMap 時「先查補數、再把自己放進去」。如果反過來先放再查，[3, 2, 4] 目標 6 可能出什麼錯？

  • 回傳 [0, 0]：3 查到了自己
  • 永遠找不到答案，回傳空陣列
  • HashMap 會丟出 ConcurrentModificationException
  • 回傳 [1, 2]，跟先查再放的結果一樣

3 先被放進去，接著查 6 − 3 = 3 就查到自己，回傳 [0, 0]，同一個元素被用兩次。先查再放，表裡只有「前面的」元素。這是〈雜湊表：HashMap 怎麼做到幾乎一步找到〉的查補數手法。

程式寫完之後，最該先拿哪一組例子自己跑一遍？

  • 一百萬筆隨機資料，看會不會超時
  • 題目給的範例就夠了，不用再跑別的
  • 只跑自己覺得會出錯的那個例子
  • 小的正常例子，加上空的、一個、重複

小例子手算得出答案，邊界例子最常出錯。一百萬筆的資料面試時沒辦法手動驗證。

講複雜度時，照〈複雜度：程式跑多快、吃多少記憶體〉的順序，第一句該說什麼？

  • 「這是 O(n)」，直接講結論
  • 先講 n 是什麼
  • 「這已經是最佳解，不能更快」
  • 「空間不重要，只講時間」

不先說 n 是什麼，O(n) 沒有意義；兩個輸入時要分開寫成 n、m。接著才講時間、空間與是哪一種（最壞、平均、攤銷）。

先認題型，再挑工具

看到題目的特徵，該想到什麼

MIT 講義說解題的第一條路是「化成一個你已經會的問題（用資料結構或演算法）」（Reduce to a problem you already know (use data structure or algorithm)）。出處 下面這張表把本模組各課的招式整理成「看到什麼就想到什麼」。這是常見的對應，不是保證：同一題常有好幾種解法，表裡寫的是最先值得試的那一個。

陣列已經由小到大排好，要找兩個數加起來等於目標，而且只能用 O(1) 額外空間。先想到哪一招？

  • 雙指標，左右往中間走
  • HashMap 查補數，邊走邊記
  • 回溯，列出所有兩兩組合
  • 堆積，每次拿出最小的兩個

排好序加上 O(1) 空間，就是雙指標：和太小左邊往右、太大右邊往左。HashMap 也能解但要 O(n) 空間。見〈雙指標、滑動視窗與前綴和〉。

陣列沒有排序，要找兩個數加起來等於目標，回傳兩個原本的索引。平均最快的做法是？

  • 先排序，再用雙指標找
  • 兩層迴圈，每一對都試一次
  • HashMap 邊走邊查補數
  • 二分搜尋，對每個數找它的補數

HashMap 平均 O(n)。先排序會打亂原本的索引，還要 O(n log n)；兩層迴圈是 O(n²)。見〈雜湊表：HashMap 怎麼做到幾乎一步找到〉。

找字串裡「不含重複字元的最長連續子字串」。先想到哪一招？

  • 回溯，列出所有子字串再挑
  • 單調堆疊，記下每個字元的位置
  • 拓樸排序，依字元先後排好
  • 滑動視窗，遇到重複就收左端

「連續」加上「最長」是滑動視窗的典型特徵。列出所有子字串是 O(n²) 個以上，太慢。見〈雙指標、滑動視窗與前綴和〉。

陣列裡有負數，要數「和剛好等於 k 的連續子陣列有幾個」。為什麼不適合用滑動視窗？

  • 負數讓「擴張就變大」不成立，該改用前綴和
  • 滑動視窗只能用在字串，不能用在數字陣列
  • 滑動視窗的時間其實是 O(n²)，太慢
  • 其實滑動視窗可以，這題沒有問題

滑動視窗靠「擴張和變大、收縮和變小」決定方向，負數會破壞這個性質。前綴和把「區間和」變成兩個前綴相減，再用 HashMap 數補數。見〈雙指標、滑動視窗與前綴和〉。

資料一筆一筆串流進來、總量非常大，要隨時回答「目前第 k 大的是誰」（k 很小）。最適合的是？

  • 每來一筆就把全部資料重新排序
  • 大小為 k 的最小堆
  • 用 HashSet 存全部資料，查的時候再找
  • 用堆疊存最近 k 筆，頂端就是答案

堆積只保留 k 筆，每筆進來 O(log k)。每次重新排序要 O(n log n)，資料越多越慢。見〈堆積與優先佇列〉。

迷宮的每一步代價都一樣，要求從起點到終點的最少步數。先想到哪一招？

  • DFS，一路走到底再退回來
  • 回溯，列出所有路徑再挑最短
  • BFS，用佇列一層層往外
  • 動態規劃，從終點往回填表

BFS 一層一層擴張，第一次碰到終點時走的就是最少步數。DFS 先碰到的路不一定最短；列出所有路徑是指數級。見〈圖：BFS、DFS 與拓樸排序〉。

有一堆課程，某些課要先修完別的課才能上。要排出一個修課順序，或判斷根本排不出來（循環相依）。這是？

  • 二分搜尋
  • 滑動視窗
  • 單調堆疊
  • 拓樸排序

「誰要在誰之前」就是有向圖的相依關係，拓樸排序排得出順序，排不完就代表有循環。見〈圖：BFS、DFS 與拓樸排序〉。

二維格子裡 1 是陸地、0 是海，要數有幾座島（上下左右相連的陸地算一座）。做法是？

  • DFS 或 BFS 把整座島標成走過，計數加 1
  • 對每一列做二分搜尋，找出陸地的邊界
  • 把格子攤平成一列再排序，數連續的 1
  • 用兩個堆疊做佇列，依序處理每一格

島就是格子圖上的連通區域，走訪一次標記一座。走鄰居前先檢查出界（〈陣列與字串〉的二維陣列手法）。見〈圖：BFS、DFS 與拓樸排序〉。

要列出一組數字所有可能的排列。先想到哪一招？

  • 回溯，加 used 陣列
  • 動態規劃，填一張排列數的表
  • 堆積，每次拿最小的數排下去
  • 前綴和，算出每個位置的總和

「所有」排列就是回溯；答案本身就有 n! 個，沒辦法更快。見〈遞迴與回溯〉。

爬 n 階樓梯，每次可以爬 1 或 2 階，問有幾種爬法。這題的特徵與做法是？

  • 列出所有爬法再數，用回溯最快
  • 單調堆疊，記下每一階的高度
  • 方法數＋重複子問題：動態規劃
  • BFS，找從地面到頂端的最短路徑

到第 i 階的方法數＝到 i − 1 階的加到 i − 2 階的，跟費氏數列同一個長相。天真遞迴是指數級，存起來就是線性。見〈遞迴與回溯〉的備忘錄與〈動態規劃入門〉。

判斷一個只含括號的字串是否正確配對。用什麼？

  • 佇列，讀到右括號就跟最早的比
  • HashSet，記下出現過的括號
  • 堆疊，右括號跟頂端比
  • 二分搜尋，找對應的另一半

右括號要配「最近一個還沒配到的左括號」，正好是堆疊頂端。見〈堆疊與佇列〉。

對每一天的溫度，算出要再等幾天才會更熱。O(n) 的做法是？

  • 每一天往後一天一天找
  • 單調堆疊放索引
  • 先排序溫度，再二分搜尋
  • 回溯，列出每一天之後的所有組合

每個索引進出堆疊各一次，O(n)；往後找最壞 O(n²)；排序會打亂日期順序。見〈堆疊與佇列〉。

只拿到鏈結串列的 head，不知道長度，要走一次就找到中間的節點。用什麼？

  • 二分搜尋，找中間的位置
  • 先轉成陣列再取中間的那一格
  • 快慢指標
  • 堆疊，全部推進去再彈出一半

fast 走到底時 slow 剛好在中點，O(n) 時間、O(1) 額外空間。轉成陣列要 O(n) 額外空間。見〈鏈結串列〉。

要知道陣列裡有沒有重複的數，平均最快的做法是？

  • 放進 HashSet，add 回傳 false
  • 兩層迴圈，每兩個數都拿出來比一次
  • 對每一個數，在陣列裡做二分搜尋
  • 單調堆疊，彈出時檢查兩數是否相等

HashSet 平均 O(n)；兩兩比是 O(n²)；先排序再看相鄰是 O(n log n)。見〈雜湊表：HashMap 怎麼做到幾乎一步找到〉。

要存一堆交易的時間戳記，常常要問「不晚於某時間的最近一筆是哪一筆」。選哪個 Java 類別？

  • HashMap
  • ArrayDeque
  • TreeMap
  • PriorityQueue

TreeMap 的鍵有順序，可以找「不超過 x 的最大鍵」，O(log n)。HashMap 不保證順序，找不到「最接近的」。見〈樹與二元搜尋樹〉。

要一層一層印出二元樹的節點（同一層印在同一行）。用什麼？

  • 佇列，每層先記大小
  • 堆疊，每層的節點推進去再彈出
  • HashMap，用深度當鍵
  • 二分搜尋，找每一層的起點

層序走訪就是樹上的 BFS，用佇列；先記 size，才知道這一層有幾個。見〈樹與二元搜尋樹〉。

在排好序的一百萬筆資料裡找某個值。最快的做法與複雜度是？

  • 從頭一筆一筆找，O(n)
  • 放進 HashSet 再查，O(1)
  • 回溯
  • 二分搜尋，O(log n)，大約 20 步

每次砍一半，2²⁰ 約一百萬，20 步內找到。放進 HashSet 光是放就要 O(n)。見〈排序與二分搜尋〉。

給一堆時間區間，要把重疊的合併。通常第一步是？

  • 放進堆疊
  • 依起點排序，再從左到右一個一個合併
  • 用 HashMap 記每個時間點
  • 回溯列出所有合併方式

排好序之後，會重疊的區間一定相鄰，掃一遍就合併完，總共 O(n log n)。見〈排序與二分搜尋〉。

要找陣列裡出現次數最多的前 k 個數。常見的組合是？

  • 只用堆疊，依次數推進去再彈出
  • 只用二分搜尋，在排好序的陣列裡找
  • 先 HashMap 計數，再用堆積挑前 k 名
  • 回溯，列出所有大小為 k 的組合

兩步各用一個工具：計數是〈雜湊表：HashMap 怎麼做到幾乎一步找到〉，挑前 k 名是〈堆積與優先佇列〉。

做一個 LRU 快取（容量滿了丟掉最久沒用的），get 與 put 都要平均 O(1)。Java 裡最省事的做法是？

  • ArrayList，每次用過就移到最後面
  • TreeMap，依使用時間當鍵排序
  • PriorityQueue，依使用時間排先後
  • LinkedHashMap（存取順序）

HashMap 負責 O(1) 找到，雙向串列負責 O(1) 移到最前與刪掉最舊；LinkedHashMap 內部就是這樣。ArrayList 移動是 O(n)。見〈雜湊表：HashMap 怎麼做到幾乎一步找到〉與〈鏈結串列〉。

看 n 就知道要多快

從輸入大小反推可以接受的複雜度

〈複雜度：程式跑多快、吃多少記憶體〉用 MIT 講義的假設估算時間：「一秒做十億個基本動作」，講義的原文是「以 1 GHz 單核心機器、每個時脈做一個運算為準」（Time estimate below based on one operation per cycle on a 1 GHz single-core machine）。出處 實際寫程式時，大 O 裡的「一步」通常是好幾個基本動作（讀陣列、比較、加法、呼叫方法），所以下面保守一點，用一秒 10⁸ 步來估。這是估算用的假設，不是規則：不同機器、不同語言、不同常數，實際時間差好幾倍都有可能。

n 的上限大約可以接受的複雜度估算常見對應
10 左右O(n!)、O(n · n!)10! = 3,628,800列出所有排列（〈遞迴與回溯〉）
20 左右O(2ⁿ)、O(n · 2ⁿ)2²⁰ ≈ 10⁶，乘上 20 ≈ 2 × 10⁷列出所有子集
500 左右O(n³)500³ ≈ 1.25 × 10⁸三層迴圈
5,000 左右O(n²)5,000² = 2.5 × 10⁷兩層迴圈、二維的動態規劃表
10⁵ 到 10⁶O(n log n)10⁶ × 20 = 2 × 10⁷排序、堆積、每步二分搜尋
10⁷ 以上O(n) 或 O(log n)10⁷ 步約 0.1 秒掃一遍、雜湊表、雙指標

用法舉例：題目說 n 最多 10⁵。O(n²) 是 10¹⁰ 步，照一秒 10⁸ 步要 100 秒，就算照一秒 10⁹ 步也要 10 秒，太慢；O(n log n) 約 1.7 × 10⁶ 步，0.02 秒內。所以還沒寫，就知道兩層迴圈不行，要往排序、堆積、雜湊表、雙指標這些方向想。反過來，n 最多 20 時，看到「所有子集」也不用怕 2ⁿ。

先看 n：10 左右可以 n!、20 左右可以 2ⁿ、5,000 左右可以 n²、10⁵ 以上要 n log n 以內

題目寫 n 最多 10⁵。照一秒約 10⁸ 步估算，下面哪一個複雜度最慢但還能接受？

  • O(n log n)
  • O(n²)
  • O(n³)
  • O(2ⁿ)

n log n 約 1.7 × 10⁶ 步，很快；n² 是 10¹⁰ 步，要 100 秒左右。所以兩層迴圈不行，n log n 以內才可以。

題目寫 n 最多 20，要求列出所有子集。2ⁿ 的寫法可以嗎？

  • 不行，2ⁿ 是指數級，一定太慢
  • 可以，2²⁰ 約一百萬
  • 不行，要先想出 O(n) 的做法
  • 只有 n 小於 10 時才可以

指數級在 n 很小時完全沒問題；而且答案本身就有 2ⁿ 個子集，不可能更少。重點是看 n 的上限，不是一看到指數就放棄。見〈遞迴與回溯〉。

照〈複雜度：程式跑多快、吃多少記憶體〉「一秒十億步」的估算，n = 10⁶ 時 O(n²) 大約要跑多久？

  • 約 1 毫秒
  • 約 1 秒
  • 約 17 分鐘
  • 約 1 年

n² = 10¹² 步，除以每秒 10⁹ 步是 1,000 秒，約 16.7 分鐘。跟〈複雜度〉那一課的練習同一個算法。

題目的 n 最多 5,000，你想到的寫法是兩層迴圈 O(n²)。合理的判斷是？

  • 2,500 萬步左右，可以接受，先寫出來
  • 一定太慢，必須想到 O(n)
  • 要先改成遞迴才會快
  • n 不重要，只看程式碼長短

5,000² = 2.5 × 10⁷，照一秒 10⁸ 步不到一秒。估算告訴你什麼時候「夠快就好」，不用硬想更難的解法。

檢查什麼要問自己常見的寫法

溢位：Java 不會提醒你

Java 語言規格寫 int 的範圍是「-2147483648 到 2147483647（含）」（For int, from -2147483648 to 2147483647, inclusive）出處，而且「整數運算子不會以任何方式表示溢位」（The integer operators do not indicate overflow or underflow in any way.）出處。加法溢位時，結果是數學上的和只留下低位元，「正負號會跟真正的和不一樣」（If overflow occurs, then the sign of the result is not the same as the sign of the mathematical sum of the two operand values.）。出處 想讓溢位直接報錯，可以用 Math.addExact：「回傳兩數的和，如果結果超出 int 就丟出例外」（Returns the sum of its arguments, throwing an exception if the result overflows an int.）。出處

public class Overflow {
    public static void main(String[] args) {
        int max = Integer.MAX_VALUE;
        System.out.println(max);              // 2147483647
        System.out.println(max + 1);          // 溢位：不會報錯，直接繞成負數

        int left = 2_000_000_000, right = 2_100_000_000;
        System.out.println((left + right) / 2);           // 相加先溢位，中點算錯
        System.out.println(left + (right - left) / 2);    // 先減再加，不會溢位

        int[] big = {1_500_000_000, 1_500_000_000};
        int sumInt = 0;
        long sumLong = 0;
        for (int x : big) {
            sumInt += x;
            sumLong += x;
        }
        System.out.println(sumInt + " / " + sumLong);     // int 加總錯了，long 才對

        try {
            Math.addExact(max, 1);                        // 想讓溢位直接報錯
        } catch (ArithmeticException e) {
            System.out.println("addExact：" + e.getMessage());
        }
    }
}

執行結果：

2147483647
-2147483648
-97483648
2050000000
-1294967296 / 3000000000
addExact：integer overflow

兩個二十億相加，數學上是正的，印出來卻是負的，程式照樣往下跑。int 大約只到 21 億，交易金額加總、兩個大數相乘、二分搜尋算中點，都是常見的出事地點（中點的寫法〈陣列與字串〉也提過）。

寫完先跑：空的、一個、兩個、重複、負數、最大值；加總用 long，中點寫 left + (right − left) / 2

System.out.println(Integer.MAX_VALUE + 1); 印出什麼？

  • 2147483648
  • 丟出 ArithmeticException
  • -2147483648
  • 0

整數運算子不會表示溢位，結果只留低位元，繞成最小的負數。要報錯得用 Math.addExact。

left 是二十億、right 是二十一億（都是 int）。(left + right) / 2 的結果是？

  • 2050000000
  • 一個負數，因為相加時先溢位了
  • 丟出例外
  • 編譯錯誤

兩數相加超過 int 上限先繞成負數，再除以 2 還是負數（實跑是 -97483648）。寫成 left + (right - left) / 2 就是正確的 2050000000。

要把十萬筆交易金額（每筆最多十億，int）加總。總和的變數該用什麼型別？

  • long
  • int，因為每一筆都放得進 int
  • short
  • char

每一筆放得進 int，不代表加總放得進：兩筆十億多就超過 21 億。long 的上限約 9.2 × 10¹⁸。

用快慢指標找串列中點，程式寫完後最需要特別拿來跑的輸入是？

  • 一百個節點的普通串列
  • 節點值全部都不一樣的串列
  • 空串列、一個節點、兩個節點
  • 值已經由小到大排好序的串列

fast.next.next 這類寫法最容易在很短的串列上出現 NullPointerException。〈鏈結串列〉的清單就是空、一個、兩個、動到頭、動到尾。

回溯把答案存成 result.add(path)，最後印出一堆空清單。對照檢查清單，這屬於哪一項？

  • 溢位
  • 空輸入
  • 索引邊界
  • 存答案時沒有複製

result 存的是同一個 path 的參考值，path 最後被撤銷成空的。要寫 new ArrayList<>(path)。見〈遞迴與回溯〉。

用遞迴走一棵可能退化成一條長鏈、有一百萬個節點的樹，最該擔心什麼？

  • 加總時的整數溢位
  • 遞迴太深，StackOverflowError
  • HashMap 碰撞變成 O(n)
  • 樹裡有重複的值

遞迴的深度等於樹高，退化成鏈時就是一百萬層，呼叫堆疊放不下。可以改成迴圈或自己用 ArrayDeque 當堆疊。見〈遞迴與回溯〉與〈樹與二元搜尋樹〉。

程式裡需要一個堆疊，下面哪個寫法符合 Java 文件的建議？

  • new Stack<>()
  • new Vector<>()
  • Deque 宣告、new ArrayDeque<>()
  • new LinkedList<>()，因為可以放 null

Deque 與 Stack 兩份文件都建議用 Deque 的實作取代 Stack；ArrayDeque 不收 null，正好避開 null 被當成「空了」的混淆。見〈堆疊與佇列〉。

跨課混在一起考

綜合練習

前面各段的練習已經混了各課的觀念，下面再加幾題需要同時想到兩課的題目。每題的解析都寫明回哪一課。

兩個排好序的鏈結串列要合併成一個排好序的串列，O(1) 額外空間。關鍵手法是？

  • 全部倒進陣列，排序後再串回去
  • 虛擬頭節點加 tail，接上較小的
  • 用 HashMap 記下每個值出現幾次
  • 回溯，試所有接法挑排好序的那一個

兩邊各一個指標往前比，O(m + n) 時間、O(1) 額外空間；虛擬頭節點讓第一個節點不用特別處理。倒進陣列要額外空間。見〈鏈結串列〉。

k 個排好序的串列要合併，總共 N 個節點。比「兩兩依序合併」更好的做法是？

  • 全部節點放進 HashSet 再取出
  • 每次掃過 k 個串列的頭找最小的
  • 用堆疊把每一個串列都反轉
  • k 個頭放進最小堆

堆積裡永遠只有 k 個，每次拿出與放回各 O(log k)，總共 O(N log k)。每次掃 k 個頭是 O(N · k)。見〈鏈結串列〉與〈堆積與優先佇列〉。

一個遞迴解法超時，你發現同一組參數被算了很多次。最直接的改法是？

  • 改用 Stack 類別，讓呼叫變快
  • 把遞迴改成兩個執行緒同時跑
  • 加大 JVM 堆疊，讓遞迴可以更深
  • 加備忘錄，算過的存起來

重複的子問題存起來，每組參數只算一次，天真費氏從指數級降成 O(n) 就是這招。見〈遞迴與回溯〉與〈動態規劃入門〉。

面試官問：「你的解法用 HashMap，複雜度是多少？」最完整的回答是？

  • 「O(1)，因為 HashMap 是常數時間」
  • 「O(n)，HashMap 是常數，空間不用講」
  • 先講 n，再講平均時間 O(n)、空間 O(n)，並提最壞的前提
  • 「跟暴力解一樣，都是 O(n²)」

先講 n、再講時間與空間、說清楚是平均，並提最壞的前提。見〈複雜度：程式跑多快、吃多少記憶體〉與〈雜湊表：HashMap 怎麼做到幾乎一步找到〉。

用佇列做 BFS 時，Java 該選哪個類別當佇列？

  • ArrayDeque，用 offer 與 poll
  • Stack，用 push 與 pop
  • PriorityQueue
  • TreeMap

ArrayDeque 文件說它當佇列用時可能比 LinkedList 快；Stack 是後進先出，會把 BFS 變成往深處鑽；PriorityQueue 依大小出隊，不是先進先出。見〈堆疊與佇列〉與〈圖：BFS、DFS 與拓樸排序〉。

二元搜尋樹依序插入 1、2、3……n，搜尋的時間變成多少？為什麼？

  • O(log n)，二元搜尋樹永遠是 log n
  • O(1)
  • O(n)，樹退化成一條鏈，高度等於 n
  • O(n²)

二元搜尋樹的操作是 O(h)，依序插入每個新節點都接在右邊，h = n。要保證 O(log n) 就用平衡樹，例如 TreeMap 的紅黑樹。見〈樹與二元搜尋樹〉。

對已排序陣列做二分搜尋，算中點時寫 (lo + hi) / 2。陣列很大時可能出什麼事？

  • 沒事，陣列索引不可能大到溢位
  • lo + hi 溢位變負數
  • 編譯器會自動把它改成 long 計算
  • 二分搜尋會退化成 O(n)

兩個大索引相加會溢位。寫成 lo + (hi - lo) / 2 就不會。見這課的溢位一段與〈陣列與字串〉。

要在一份很長的交易紀錄裡，找出「總金額剛好是 k 的連續一段」有幾段，金額有正有負（退款是負的）。做法與複雜度是？

  • 滑動視窗，左右兩端往右推，O(n)
  • 兩層迴圈列出每一段，O(n²)，n 大也沒問題
  • 前綴和加 HashMap，O(n)
  • 先排序再用雙指標，O(n log n)

有負數就不能用滑動視窗；排序會打亂「連續」。前綴和把區間和變成兩個前綴相減，HashMap 一次查到。見〈雙指標、滑動視窗與前綴和〉與〈雜湊表：HashMap 怎麼做到幾乎一步找到〉。

重點整理

  • 解題六步：問清楚（範圍、邊界、回傳什麼）→ 暴力解與複雜度 → 找瓶頸優化 → 寫程式 → 自己用小例子與邊界跑 → 講複雜度。這是建議做法，跟著面試官的節奏調整。
  • 認題型：找有沒有、找補數用雜湊表；排好序找兩數用雙指標；連續子陣列用滑動視窗、有負數用前綴和；前 k 個用堆積；最少步數用 BFS；相依順序用拓樸排序；所有組合用回溯；最佳值且子問題重複用動態規劃。
  • 看 n 反推：照一秒約 10⁸ 步保守估算，10 左右可以 n!、20 左右可以 2ⁿ、5,000 左右可以 n²、10⁵ 以上要 n log n 以內。這是估算，不是規則。
  • 自我檢查：空輸入、一個元素、重複元素、負數、溢位、索引邊界、遞迴深度、存答案要複製。
  • Java 的 int 只到 2147483647，溢位不報錯；加總用 long、中點寫 left + (right - left) / 2、要報錯用 Math.addExact。
  • 四週計畫照課序刷約四十題，每題做完用六步講一遍。

尋寶紙條，一張指向下一張

節點與指標：鏈結串列長什麼樣

想像一場尋寶遊戲：第一張紙條寫著一個數字，還寫著「下一張藏在冰箱上」；冰箱上那張又寫著數字和下一張的位置……一直到某張寫著「沒有下一張了」。這就是鏈結串列（linked list）：每一筆資料放在一個節點（node）裡，節點除了資料，還記著下一個節點在哪，這個欄位通常叫 next。最後一個節點的 next 是 null，表示到底了。

鏈結串列可以用遞迴來定義：它要嘛是空的（null），要嘛是一個指向節點的參考，這個節點有一筆資料，以及一個指向另一條鏈結串列的參考。出處 Java 沒有 C 語言那種可以做加減的指標，next 其實是一個參考（reference，記著物件在哪裡的變數）；演算法書與面試習慣把它叫「指標」，這課也這樣叫。

手上只有第一個節點的參考，叫 head（頭）。要拿索引 3 的節點（跟陣列一樣從 0 數，也就是第 4 個），就得從 head 沿著 next 走 3 步，沒辦法像陣列那樣用「起點＋3 格」直接算出位置：

鏈結串列從開頭插入與刪除只要 Θ(1)，但取、改索引 i 的元素都要 O(n)。出處（Θ 讀作 theta，表示「剛好是這個等級」；記號見〈複雜度：程式跑多快、吃多少記憶體〉。）整理成表：

操作陣列（含 ArrayList）單向鏈結串列
取索引 i 的元素O(1)：起點＋i 格O(n)：從 head 走 i 步
在最前面插入、刪除O(n)：後面每格都要搬出處O(1)：改 head 就好
在「已經拿到的某個節點」後面插入、刪除O(n)：後面每格都要搬O(1)：改兩三個 next
找某個值在不在O(n)（沒排序時）O(n)
額外記憶體連續一塊，幾乎沒有額外欄位每個節點多一個 next

第三列要特別注意前提：鏈結串列的插入刪除快，是在已經站在那個位置的時候；如果要先從頭找到第 i 個再插入，找的那段還是 O(n)。〈Java 基礎快答〉講的 LinkedList 插入刪除只要改動前後節點的接法，指的就是改接這一步。陣列那一欄：ArrayList 除了取值、設值與尾端加入，其他操作大致都是線性時間，插在最前面就屬於這一類出處；細節見〈陣列與字串〉。

單向與雙向

只有 next 的叫單向鏈結串列（singly linked list），只能往後走。每個節點再多一個指向前一個節點的 prev，就是雙向鏈結串列（doubly linked list），可以往回走；拿到某個節點時，要刪掉它自己也是 O(1)（單向的得先找到它的前一個）。代價是每個節點多一個欄位、每次插入刪除要多改幾條箭頭。Java 的 java.util.LinkedList 就是 List 與 Deque 介面的雙向鏈結串列實作。出處 面試題常給自己定義的單向串列（像 LeetCode 的 ListNode），所以這課主要寫單向。

單向鏈結串列有 n 個節點，手上只有 head。要取第 1,000 個節點的值，要多久？

  • O(1)
  • O(log n)
  • O(n)
  • O(n²)

沒辦法用位置直接算，只能從 head 沿著 next 一步一步走，步數跟位置成正比，最壞 O(n)。

已經拿到串列中某個節點 node 的參考，要在它後面插入一個新節點，要多久？

  • O(1)
  • O(log n)
  • O(n)
  • 要看串列多長

只要改新節點與 node 的 next 兩條箭頭，跟串列長度無關。慢的是「先找到 node」那一段。

在一個有 n 個元素的 ArrayList 最前面插入一個元素（add(0, x)），要多久？

  • O(1)，只是改索引 0 那一格
  • O(log n)，因為會先二分搜尋位置
  • 攤銷 O(1)，跟加在尾端一樣
  • O(n)，後面每個元素都要往後搬一格

陣列的格子是連續的，插在最前面就得把原本的 n 個元素全部往後挪一格。這正是鏈結串列在頭插入比較快的地方。

同樣存 n 個整數，哪一種每個元素要多花額外記憶體記「下一個在哪」？

  • int[] 陣列
  • 鏈結串列
  • 兩者一樣
  • 都不用，JVM 會自動算出來

鏈結串列的每個節點除了值，還多一個 next 參考（雙向的再多一個 prev）。陣列靠「連續」就知道下一格在哪。

雙向鏈結串列比單向多了什麼能力？

  • 能往回走，拿到節點時 O(1) 刪掉它自己
  • 可以用索引在 O(1) 內直接取到第 i 個
  • 不必再處理 null，最後一個會自動接回第一個
  • 每個節點占的記憶體比單向的少一些

多了 prev，就能從節點往前找到前一個，刪自己只要接起前後兩個。取第 i 個還是要走；最後接回第一個是另一種「環狀串列」；多一個欄位反而更占記憶體。

單向鏈結串列的最後一個節點，它的 next 是什麼？

  • 指向 head
  • 指向自己
  • 值為 0 的節點
  • null

null 表示「沒有下一個了」，走訪就是走到 null 停下來。接回 head 的是環狀串列，不是一般的單向串列。

從頭走到 null

自己寫 ListNode：建立與走訪

面試題給的串列常是這個樣子的類別（LeetCode 的也叫 ListNode）。下面這個版本多了兩個小工具：build 把一串數字接成串列，show 印出整條串列；後面的程式都會用到它們，要跟這個檔放在同一個資料夾一起編譯。

class ListNode {
    int val;
    ListNode next;                     // 指向下一個節點；最後一個節點的 next 是 null

    ListNode(int val) { this.val = val; }

    // 從一串數字建一條串列，回傳頭節點
    static ListNode build(int... values) {
        ListNode dummy = new ListNode(0);
        ListNode tail = dummy;
        for (int v : values) {
            tail.next = new ListNode(v);
            tail = tail.next;
        }
        return dummy.next;
    }

    // 走訪：從頭開始，一路沿著 next 走到 null
    static String show(ListNode head) {
        StringBuilder sb = new StringBuilder();
        for (ListNode cur = head; cur != null; cur = cur.next) {
            sb.append(cur.val).append(" -> ");
        }
        return sb.append("null").toString();
    }
}

show 裡的那個 for 迴圈就是走訪的標準寫法，普林斯頓列的寫法一模一樣：for (Node x = first; x != null; x = x.next)。出處 用一個變數 cur（current，目前這個）從頭開始，每處理完一個就跳到 cur.next，cur 變成 null 就停。build 裡的 dummy 是一個「假的頭」，第三段會講它的用處。

public class Basics {
    static int length(ListNode head) {
        int n = 0;
        for (ListNode cur = head; cur != null; cur = cur.next) n++;
        return n;
    }

    public static void main(String[] args) {
        ListNode head = ListNode.build(3, 1, 4);
        System.out.println(ListNode.show(head));
        System.out.println(length(head));
        System.out.println(head.next.val);           // 第二個節點的值
        System.out.println(ListNode.show(null) + "，長度 " + length(null));
    }
}

null，長度 0

兩件事要記住：head 是整條串列唯一的入口，把 head 弄丟（例如直接 head = head.next 往下走）就再也找不回前面的節點，所以走訪都另外用 cur。另外，空串列就是 head == null，好的寫法要讓空串列也不出錯，像上面的 length(null) 回傳 0。

串列是 3 -> 1 -> 4 -> null。下面印出什麼？

    s += cur.val;
}
System.out.println(s);

三個節點都會走到：3 + 1 + 4 = 8。cur 變成 null 時迴圈條件不成立就停，不會去讀 null 的 val。

  • 3
  • 1
  • 4
  • null

head 是 3，head.next 是 1，head.next.next 是 4。

串列只有一個節點 7 -> null。執行 System.out.println(head.next.val); 會怎樣？

  • 印出 7（head 自己的值）
  • 印出 0（int 的預設值）
  • 印出 null（沒有下一個）
  • 丟出 NullPointerException

head.next 是 null，再去讀 null 的 val 就是空指標例外。要讀 x.next 的東西之前，先確定 x.next 不是 null。

串列是 3 -> 1 -> 4 -> null。下面想算長度，印出什麼？

int n = 0;
ListNode cur = head;
while (cur.next != null) {
    n++;
    cur = cur.next;
}
System.out.println(n);

條件是「還有下一個」，cur 停在最後一個節點時就不進迴圈了，最後一個沒被數到，少了 1。而且 head 是 null 時第一次判斷就會丟空指標例外。

下面印出什麼？

ListNode a = ListNode.build(1, 2);
ListNode b = a;
b = b.next;
System.out.println(ListNode.show(a));

  • 2 -> null
  • 1 -> null
  • 2 -> 1 -> null

b = b.next 只是讓 b 這個變數改指第二個節點，沒有改任何節點的 next，串列本身沒變，a 還是指向 1。

下面印出什麼？

ListNode a = ListNode.build(1, 2, 3);
a.next = null;
System.out.println(ListNode.show(a));
  • 1 -> 2 -> 3 -> null
  • null
  • 1 -> null
  • 2 -> 3 -> null

這次改的是節點本身的 next：1 不再指向 2，從 a 出發只走得到 1。2 和 3 沒人指向，就此弄丟了。

下面這段要找最後一個節點。head 是什麼的時候它會出錯？

ListNode cur = head;
while (cur.next != null) {
    cur = cur.next;
}
  • 串列是空的（head 是 null）時
  • 串列只有一個節點、next 是 null 時
  • 串列有兩個以上節點、走到最後一個時
  • 任何情況都不會出錯，迴圈條件已經檢查過了

head 是 null 時，第一次判斷 cur.next 就丟出 NullPointerException。只有一個節點時 cur.next 是 null，迴圈直接不進去，回到 head 本身，正確。

先接後面，再接前面

插入、刪除與虛擬頭節點

串列的插入與刪除，都只是「改幾條箭頭」。普林斯頓列的基本動作：在開頭插入、刪掉開頭都很容易；要在尾端插入，就另外記著最後一個節點。出處 下面四個方法涵蓋所有基本情況：

import static java.lang.System.out;

public class InsertDelete {
    // 在最前面插入：新節點指向舊的頭，再把頭換成新節點
    static ListNode addFirst(ListNode head, int val) {
        ListNode node = new ListNode(val);
        node.next = head;
        return node;                                   // 新的頭
    }

    // 在 prev 後面插入：先接後面、再接前面，順序不能反
    static void insertAfter(ListNode prev, int val) {
        ListNode node = new ListNode(val);
        node.next = prev.next;                         // ① 新節點先抓住後面那段
        prev.next = node;                              // ② prev 再改指新節點
    }

    // 刪掉 prev 的下一個節點：讓 prev 跳過它
    static void deleteAfter(ListNode prev) {
        prev.next = prev.next.next;
    }

    // 刪掉所有值等於 target 的節點；虛擬頭節點讓「刪到頭」不用特別處理
    static ListNode removeAll(ListNode head, int target) {
        ListNode dummy = new ListNode(0);
        dummy.next = head;
        ListNode prev = dummy;
        while (prev.next != null) {
            if (prev.next.val == target) {
                prev.next = prev.next.next;            // 刪掉後 prev 不動，再檢查新的下一個
            } else {
                prev = prev.next;
            }
        }
        return dummy.next;
    }

    public static void main(String[] args) {
        ListNode head = ListNode.build(3, 1, 4);
        head = addFirst(head, 9);
        out.println(ListNode.show(head));
        insertAfter(head.next, 7);                     // 插在 3 後面
        out.println(ListNode.show(head));
        deleteAfter(head);                             // 刪掉 9 後面那個（3）
        out.println(ListNode.show(head));
        out.println(ListNode.show(removeAll(ListNode.build(6, 6, 2, 6, 5), 6)));
    }
}

9 -> 3 -> 7 -> 1 -> 4 -> null
9 -> 7 -> 1 -> 4 -> null
2 -> 5 -> null

插入：順序不能反

insertAfter 的兩行如果寫反，先做 prev.next = node，原本 prev 後面那一段就沒有人抓著了，再做 node.next = prev.next 只會讓 node 指向自己。口訣是先讓新節點抓住後面，再讓前面改指新節點：

刪除：讓前一個跳過它

單向串列要刪一個節點，得先拿到它的前一個，因為要改的是前一個的 next。被跳過的節點沒有人指向它，Java 的垃圾回收會把它收掉，不必自己釋放。

虛擬頭節點（dummy head）

刪除要靠「前一個」，可是頭節點沒有前一個，所以「要刪的剛好是頭」得另外寫一段。虛擬頭節點（dummy head，在真正的頭前面先放一個不存資料的假節點）讓每個真節點都有前一個，刪頭和刪中間就變成同一種寫法，最後回傳 dummy.next。雙向串列也常用同一招：頭尾各放一個假節點，省掉額外的情況。出處

removeAll 還有一個細節：刪掉 prev.next 之後 prev 不往前走，因為新的 prev.next 還沒檢查過；連續兩個 6 時，少了這個判斷就會漏刪。

node.next = prev.next;

  • 1 -> null
  • 丟出 NullPointerException
  • 0 -> null（虛擬頭節點）

三個都被刪掉，dummy.next 變成 null，回傳 null。回傳的是 dummy.next，所以虛擬頭節點不會跑進結果裡。

下面是 removeAll 的錯誤版本：刪掉之後 prev 也照樣往前走。對 6 -> 6 -> 2 -> null 刪 6，結果是什麼？

while (prev.next != null) {
    if (prev.next.val == 6) prev.next = prev.next.next;
    prev = prev.next;
}
  • 2 -> null
  • 6 -> 2 -> null
  • 6 -> 6 -> 2 -> null
  • null

刪掉第一個 6 之後，prev 馬上走到第二個 6，第二個 6 就沒被檢查到。刪完要停在原地，再檢查新的下一個。

單向串列有 n 個節點，手上只有 head。要刪掉最後一個節點，得先找到誰？要多久？

  • 只要最後一個節點本身，O(1)
  • head 本身，O(1)
  • 倒數第二個節點，要從頭走過去，O(n)
  • 倒數第二個節點，用二分搜尋 O(log n)

刪除要改前一個的 next，單向串列沒辦法從最後一個往回找，只能從頭走到倒數第二個。雙向串列加上尾端參考才能 O(1)。

為什麼刪除題常在最前面加一個虛擬頭節點？

  • 讓串列從頭走到尾的走訪速度變快一些
  • 讓單向串列變成可以往回走的雙向串列
  • 讓 Java 的垃圾回收不要收走被刪掉的節點
  • 讓頭也有「前一個」，刪頭不必另外寫

刪除要改前一個節點的 next，頭本來沒有前一個；加上 dummy 之後每個節點都有，最後回傳 dummy.next 即可。它不影響速度，也不改變單向雙向。

把每一條箭頭掉頭

反轉串列

反轉串列是串列題的第一關，很多題目（例如判斷回文串列）都會用到。做法是從頭走到尾，把每個節點的 next 改成指向前一個。要用三個變數：prev（已經反轉好那段的頭）、cur（正在處理的）、next（先記住下一個，不然改完箭頭就找不到了）。

import static java.lang.System.out;

public class Reverse {
    static ListNode reverse(ListNode head) {
        ListNode prev = null;
        ListNode cur = head;
        while (cur != null) {
            ListNode next = cur.next;                  // ① 先記住下一個，不然等一下會弄丟
            cur.next = prev;                           // ② 箭頭改指向前一個
            prev = cur;                                // ③ prev 往前走一格
            cur = next;                                // ④ cur 往前走一格
        }
        return prev;                                   // cur 走到 null 時，prev 是新的頭
    }

    static ListNode reverseRecursive(ListNode head) {
        if (head == null || head.next == null) return head;
        ListNode newHead = reverseRecursive(head.next); // 先把後面那段反轉好
        head.next.next = head;                         // 原本的下一個改指回自己
        head.next = null;
        return newHead;
    }

    public static void main(String[] args) {
        out.println(ListNode.show(reverse(ListNode.build(1, 2, 3, 4))));
        out.println(ListNode.show(reverseRecursive(ListNode.build(1, 2, 3, 4))));
        out.println(ListNode.show(reverse(null)) + " / " + ListNode.show(reverse(ListNode.build(5))));
    }
}

4 -> 3 -> 2 -> 1 -> null
null / 5 -> null

空串列與一個節點的情況，迴圈分別跑零次、一次，結果都對，不用特別處理。遞迴版只要點到：它先把「後面那段」反轉好，再把自己接到尾巴。遞迴版程式短，但每一層呼叫都占一格呼叫堆疊，額外空間是 O(n)，串列很長時可能 StackOverflowError；面試先寫迴圈版。遞迴本身怎麼想，見〈遞迴與回溯〉。

對 1 -> 2 -> 3 -> null 執行迴圈版 reverse，第一輪跑完時，各變數是什麼？

  • prev 是 null，cur 是 1，1 的 next 是 2
  • prev 是 2，cur 是 3，2 的 next 是 1
  • prev 是 1，cur 是 2，1 的 next 是 2
  • prev 是 1，cur 是 2，1 的 next 是 null

第一輪：存 next = 2，1 的 next 改指 prev（null），prev 走到 1，cur 走到 2。從 cur 出發還是 2 -> 3，從 prev 出發是 1 -> null。

下面的反轉忘了先存 next。對 1 -> 2 -> 3 -> null 執行後，從 prev 印出來長怎樣？

ListNode prev = null, cur = head;
while (cur != null) {
    cur.next = prev;
    prev = cur;
    cur = cur.next;
}
  • 3 -> 2 -> 1 -> null
  • 1 -> null
  • 1 -> 2 -> 3 -> null
  • 迴圈永遠不會結束

第一輪就把 1 的 next 改成 null，接著 cur = cur.next 拿到的是剛改的 null，迴圈結束。2 和 3 弄丟了，這就是為什麼要先存 next。

迴圈版 reverse 最後如果寫成 return cur;，會回傳什麼？

  • 反轉後的頭
  • 原本的頭
  • null
  • 最後一個被處理的節點

迴圈是跑到 cur 變成 null 才停，所以 cur 一定是 null。新的頭在 prev。

下面印出什麼？

ListNode head = ListNode.build(1, 2, 3);
ListNode r = reverse(head);
System.out.println(ListNode.show(head) + " / " + ListNode.show(r));
  • 1 -> 2 -> 3 -> null / 3 -> 2 -> 1 -> null
  • 3 -> 2 -> 1 -> null / 3 -> 2 -> 1 -> null
  • 1 -> null / 3 -> 2 -> 1 -> null
  • null / 3 -> 2 -> 1 -> null

反轉是就地改箭頭，不是複製一條新的。head 還指著節點 1，而 1 現在是尾巴，next 是 null，所以從 head 只看得到 1。

迴圈版反轉的時間與額外空間是多少？

  • 時間 O(n)，額外空間 O(n)
  • 時間 O(n²)，額外空間 O(1)
  • 時間 O(n log n)，額外空間 O(1)
  • 時間 O(n)，額外空間 O(1)

每個節點處理一次，只用 prev、cur、next 三個變數，跟 n 無關。

遞迴版反轉的額外空間為什麼是 O(n)？

  • 每個節點對應一層沒結束的呼叫，占呼叫堆疊
  • 它會先把整條串列複製一份，再反轉複製出來的那條
  • 它要用一個長度 n 的陣列記住所有節點
  • 遞迴版其實也是 O(1)，跟迴圈版一樣

要先一路呼叫到最後一個節點才開始回頭，n 層呼叫同時存在，每層都占堆疊空間。程式裡沒有複製節點，也沒用陣列。

兩個人，一個走一步、一個走兩步

快慢指標：找中點、判斷有環、找環的入口

快慢指標：兩個指標從頭出發，slow 一次走一步，fast 一次走兩步。只靠兩個變數，就能回答幾個看起來要「先知道長度」或「記下走過哪裡」的問題。

import static java.lang.System.out;

public class FastSlow {
    // 慢的一次走一步、快的一次走兩步；快的走到底時，慢的在中間
    static ListNode middle(ListNode head) {
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
        }
        return slow;                                   // 偶數個節點時，回傳中間兩個的後一個
    }

    static boolean hasCycle(ListNode head) {
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) return true;             // 比的是「同一個節點」，不是值相等
        }
        return false;                                  // 快的走到 null：沒有環
    }

    static ListNode cycleStart(ListNode head) {
        ListNode slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;
            if (slow == fast) {                        // 相遇了：一個回到頭，兩個都改成一次一步
                ListNode p = head;
                while (p != slow) {
                    p = p.next;
                    slow = slow.next;
                }
                return p;                              // 再次相遇的地方就是環的入口
            }
        }
        return null;
    }

    public static void main(String[] args) {
        out.println(middle(ListNode.build(1, 2, 3, 4, 5)).val);
        out.println(middle(ListNode.build(1, 2, 3, 4, 5, 6)).val);

        ListNode head = ListNode.build(1, 2, 3, 4, 5, 6);
        ListNode tail = head;
        while (tail.next != null) tail = tail.next;
        out.println(hasCycle(head));
        tail.next = head.next.next;                    // 6 接回 3，做出一個環
        out.println(hasCycle(head));
        out.println(cycleStart(head).val);
    }
}

4
false
true

找中點

fast 走的距離永遠是 slow 的兩倍，所以 fast 走到底時，slow 剛好在一半。迴圈條件 fast != null && fast.next != null 兩個都要：前者處理偶數個節點（fast 會走到 null），後者處理奇數個（fast 停在最後一個），也保證 fast.next.next 不會讀到 null 的欄位。偶數個時這個寫法回傳中間兩個的後一個（1 到 6 回傳 4）。

判斷有環

如果最後一個節點的 next 不小心接回前面，串列就有環（cycle），從頭走永遠走不到 null。最直接的辦法是把走過的節點放進 HashSet，再次看到就有環，但要 O(n) 額外空間。快慢指標一般稱為 Floyd 演算法，又叫「龜兔賽跑」演算法。

  • 名字來自 Robert W. Floyd，是電腦科學家 Donald Knuth 把這個發明歸給他；但 Floyd 發表過的論文裡找不到這個演算法，可能是歸錯了人。
  • 做法：只用兩個指標，以不同速度沿著序列移動，只需要常數個記憶體位置。出處

為什麼一定會撞上？沒有環時，fast 會先走到 null，回傳 false。有環時兩個遲早都進到環裡，之後每走一輪 fast 都比 slow 多走一步，兩者在環上的距離每輪縮短 1，所以一定會在某一輪剛好相遇，不會「跳過去」。比較要用 slow == fast（是不是同一個節點），不能比 val，因為不同節點可以存同樣的值。

找環的入口

相遇之後，讓一個指標回到 head，兩個都改成一次走一步，再次相遇的地方就是環的入口。理由（用下圖的數字）：設 head 到入口要走 a 步、入口到相遇點 b 步、環長 L。相遇時 slow 走了 a + b，fast 走了兩倍，多出來的 a + b 一定是繞了整數圈，也就是 a + b 是 L 的倍數。所以從相遇點再走 a 步，等於在環上總共走了 b + a，剛好回到入口；從 head 走 a 步也到入口，兩個就在那裡會合。

用上面的 middle 處理 1 -> 2 -> 3 -> 4 -> 5 -> 6 -> 7 -> null，回傳哪個節點？

  • 3
  • 4
  • 5
  • 7

七個節點的中間是第 4 個。fast 走 1、3、5、7 停下（next 是 null），slow 走 1、2、3、4。

用上面的 middle 處理 1 -> 2 -> 3 -> 4 -> null，回傳哪個節點？

  • 2
  • 3
  • 4
  • null

fast 從 1 跳到 3，再跳到 null（3 的下一個的下一個），停；slow 走了兩步到 3。偶數個時回傳中間兩個的後一個。

把找中點的迴圈條件改成下面這樣，處理 1 -> 2 -> 3 -> 4 -> null，slow 停在哪？

while (fast.next != null && fast.next.next != null) {
    slow = slow.next;
    fast = fast.next.next;
}
  • 2
  • 3
  • 4
  • 丟出 NullPointerException

fast 在 1 時可以跳到 3；在 3 時 3.next.next 是 null，不跳了。slow 只走一步到 2。這個寫法在偶數個時回傳中間兩個的前一個（但 head 是 null 時會出錯）。

迴圈條件只寫 while (fast != null)，迴圈裡照樣 fast = fast.next.next。對 1 -> 2 -> 3 -> null 會怎樣？

  • slow 停在 2，跟原本的寫法結果一樣
  • slow 停在 3，偶數奇數都差一格
  • 丟出 NullPointerException
  • 迴圈永遠不會結束，fast 一直在繞

fast 從 1 跳到 3；3 不是 null，再進迴圈時 fast.next 是 null，讀 null.next 就丟例外。奇數個節點時 fast 會停在最後一個，所以一定要加 fast.next != null。

判斷有環時，為什麼要比 slow == fast，而不是 slow.val == fast.val？

  • 不同節點可能存同樣的值，會誤判成有環
  • == 比較快，而且結果其實跟比 val 一樣
  • val 是 int，Java 不能用 == 比較 int
  • 比 val 會讓 fast 一次跳過 slow 兩格

例如 5 -> 7 -> 7 -> null 沒有環，但第一輪 slow 在第一個 7、fast 在第二個 7，比值就會回傳 true。要比的是「是不是同一個節點」。

判斷串列有沒有環，下面兩種做法的額外空間各是多少？（一）把走過的節點放進 HashSet；（二）快慢指標。

  • 都是 O(1)
  • （一）O(n)、（二）O(1)
  • （一）O(1)、（二）O(n)
  • 都是 O(n)

HashSet 最多要存 n 個節點；快慢指標只用兩個變數。兩種的時間都是 O(n)。

找環的入口：快慢指標已經相遇了。下一步怎麼做？

  • 相遇點就是環的入口，直接回傳相遇的節點
  • 讓 fast 改成一次走三步，再找一次相遇點
  • 一個回到 head，都改成一次一步，會合處是入口
  • 從相遇點開始數出環的長度，再除以 2 得到入口

相遇點通常不是入口（上面的例子相遇在 5、入口在 3）。從 head 與相遇點同速前進 a 步，會在入口會合。

串列是 1 → 2 → 3 → 4，4 的 next 接回 2。用上面的 cycleStart，回傳哪個節點？

  • 1
  • 2
  • 3
  • 4

環是 2、3、4，第一個進入環的節點是 2。實跑也是 2。

有環時，fast 會不會剛好「跳過」slow，永遠碰不到？

  • 不會，進環後距離每輪縮短 1，一定剛好相遇
  • 會，環長是偶數時 fast 就可能剛好跳過
  • 會，所以相遇之後還要多跑一圈確認
  • 不會，因為 fast 一進環就會停下來等 slow

fast 每輪比 slow 多走一步，從 slow 的角度看 fast 每輪靠近一格，距離從 d 變 d − 1……一路到 0，不可能從 1 跳到 −1。

拉鍊與量尺

合併兩個排序串列、刪除倒數第 k 個

合併兩個排序串列

兩條已經由小到大排好的串列，合成一條排好的。像拉拉鍊：每次比兩條的開頭，小的那個接到結果後面，那條往後走一格。結果的頭還不知道是誰，所以又用虛擬頭節點，tail 記著結果目前的尾巴。

import static java.lang.System.out;

public class Merge {
    static ListNode merge(ListNode a, ListNode b) {
        ListNode dummy = new ListNode(0);
        ListNode tail = dummy;
        while (a != null && b != null) {
            if (a.val <= b.val) {                      // 相等時先拿 a，順序穩定
                tail.next = a;
                a = a.next;
            } else {
                tail.next = b;
                b = b.next;
            }
            tail = tail.next;
        }
        tail.next = (a != null) ? a : b;               // 剩下的那條整段接上
        return dummy.next;
    }

    public static void main(String[] args) {
        out.println(ListNode.show(merge(ListNode.build(1, 4, 6), ListNode.build(2, 3, 7, 9))));
        out.println(ListNode.show(merge(null, ListNode.build(5))));
    }
}
1 -> 2 -> 3 -> 4 -> 6 -> 7 -> 9 -> null
5 -> null

這一招也是合併排序（merge sort）在串列上的「合併」那一步，〈排序與二分搜尋〉會用到。

刪除倒數第 k 個

直覺做法是走兩趟：先數出長度 n，再從頭走到第 n − k 個（從 1 數，正好是要刪的前一個）。一趟做完的做法像拿一把長度固定的量尺：fast 先走 k 步，然後 fast 和 slow 一起走，兩者始終差 k 步；fast 停在最後一個節點時，slow 就停在倒數第 k 個的前一個，正好是刪除需要的位置。兩個指標都從虛擬頭節點出發，要刪的是頭（k 等於長度）時也不必特別處理。

import static java.lang.System.out;

public class RemoveNth {
    // 刪掉倒數第 k 個：快的先走 k 步，之後兩個一起走
    static ListNode removeNthFromEnd(ListNode head, int k) {
        ListNode dummy = new ListNode(0);
        dummy.next = head;
        ListNode fast = dummy, slow = dummy;
        for (int i = 0; i < k; i++) fast = fast.next;
        while (fast.next != null) {                    // fast 停在最後一個節點
            fast = fast.next;
            slow = slow.next;
        }
        slow.next = slow.next.next;                    // slow 停在要刪的前一個
        return dummy.next;
    }

    public static void main(String[] args) {
        out.println(ListNode.show(removeNthFromEnd(ListNode.build(10, 20, 30, 40, 50), 2)));
        out.println(ListNode.show(removeNthFromEnd(ListNode.build(10, 20, 30), 3)));
        out.println(ListNode.show(removeNthFromEnd(ListNode.build(10), 1)));
    }
}
10 -> 20 -> 30 -> 50 -> null
20 -> 30 -> null
null

這段程式假設 k 介於 1 和串列長度之間（LeetCode 第 19 題的條件）；k 比長度大時，fast 先走的那段就會走到 null 而出錯，實務上要先檢查。

合併 1 -> 3 -> null 與 2 -> 4 -> null。迴圈第一輪做完時，a、b 各指向誰？

  • a 指向 1，b 指向 4
  • a 指向 3，b 指向 4
  • a 指向 1，b 指向 2
  • a 指向 3，b 指向 2

第一輪比 1 和 2，1 比較小，接到 tail 後面，a 往後走到 3；b 沒動，還在 2。

用上面的 merge 合併 1 -> 5 -> null 與 2 -> 3 -> 4 -> null，結果是什麼？

  • 1 -> 2 -> 3 -> 4 -> null
  • 1 -> 5 -> 2 -> 3 -> 4 -> null
  • 2 -> 3 -> 4 -> 1 -> 5 -> null
  • 1 -> 2 -> 3 -> 4 -> 5 -> null

依序接上 1、2、3、4，這時 b 走完了，迴圈結束，把 a 剩下的 5 整段接上。

合併迴圈結束後，為什麼一行 tail.next = (a != null) ? a : b; 就夠了，不用再寫迴圈一個一個接？

  • 剩下那段已排好也串好，接上開頭就全接上
  • Java 會自動把剩下的節點一個一個複製過去
  • 剩下的那段最多只會剩一個節點，接一次就夠
  • 這行其實只接了一個節點，剩下的會被丟掉

串列的好處就在這：剩下那條的節點之間 next 本來就接好了，接上第一個等於接上全部，O(1)。剩下的可能有很多個節點。

兩條長度分別是 m 和 n 的排序串列，用上面的方法合併，時間與額外空間各是多少？

  • 時間 O(m × n)，額外空間 O(1)
  • 時間 O(m + n)，額外空間 O(m + n)
  • 時間 O(m + n)，額外空間 O(1)
  • 時間 O((m + n) log(m + n))，額外空間 O(1)

每輪接上一個節點，最多 m + n 輪；只改既有節點的 next，沒有建立新節點（dummy 只有一個）。

用上面的 removeNthFromEnd 處理 1 -> 2 -> 3 -> 4 -> 5 -> null、k = 1，結果是什麼？

  • 2 -> 3 -> 4 -> 5 -> null
  • 1 -> 2 -> 3 -> 5 -> null
  • 1 -> 2 -> 3 -> 4 -> null
  • 1 -> 2 -> 3 -> 4 -> 5 -> null

倒數第 1 個就是最後一個 5。fast 先走 1 步，之後同步走到 fast 是 5，slow 在 4，刪掉 4 的下一個。

對 10 -> 20 -> 30 -> 40 -> null 刪倒數第 2 個（k = 2）。fast 停在最後一個節點時，slow 停在哪？

  • 10
  • 20
  • 30
  • dummy

倒數第 2 個是 30，slow 要停在它的前一個 20。fast 先從 dummy 走到 20，再同步：fast 到 30、slow 到 10；fast 到 40、slow 到 20。

刪除倒數第 k 個時，為什麼 fast、slow 要從虛擬頭節點出發，而不是從 head？

  • 從 head 出發的話，整個過程會多走一趟
  • 要刪的是頭時，slow 才有「前一個」可以停
  • 虛擬頭節點可以讓 fast 每步走得比較快
  • 從 head 出發會讓串列不小心接成一個環

要刪的是頭時，「前一個」只有 dummy。實跑 10、20、30 刪倒數第 3 個得到 20 -> 30，就是靠 slow 停在 dummy。

刪除倒數第 k 個，「先數長度、再走到第 n − k 個」的兩趟做法，跟快慢指標的一趟做法比，下面哪句對？

  • 兩種都是 O(n) 時間、O(1) 空間，只差走幾遍
  • 兩趟做法是 O(n²)，一趟做法才是 O(n)
  • 兩趟做法要 O(n) 額外空間，一趟只要 O(1)
  • 兩趟做法在 k 等於 1 時會算錯位置

走兩遍是 2n 步，還是 O(n)，也只需要幾個變數。一趟做法是面試常被追問的寫法，但複雜度等級一樣。

內建的怎麼用，自己寫的怎麼不出錯

Java 的 LinkedList，以及寫串列題最常踩的坑

實務上很少自己寫串列，用的是 java.util.LinkedList：

import java.util.LinkedList;

public class JdkLinkedList {
    public static void main(String[] args) {
        LinkedList<String> list = new LinkedList<>();
        list.add("B");                                 // 加在尾端
        list.addFirst("A");                            // 加在頭
        list.addLast("C");
        System.out.println(list);
        System.out.println(list.get(1));               // 有索引，但要一格一格走過去
        System.out.println(list.removeFirst() + " " + list.removeLast() + " " + list);
    }
}
[A, B, C]
B
A C [B]

它是雙向串列，頭尾的加入與移除都是改幾條箭頭；用索引取值時，會從開頭或結尾走過去，看哪一端離指定的索引比較近。出處 所以 get(i) 還是 O(n)，在迴圈裡 for (int i = 0; i < list.size(); i++) list.get(i) 會變成 O(n²)，走訪要用 for-each（〈集合與泛型〉講過）。要當佇列或堆疊用，ArrayDeque 當佇列時可能比 LinkedList 快出處，見〈堆疊與佇列〉。

三種最常見的錯

錯誤長什麼樣怎麼避免
空指標讀 x.next.val、fast.next.next 時，x.next 或 fast.next 其實是 null每次要讀 a.b 之前，先確定 a 不是 null；迴圈條件把要用到的都檢查進去
弄丟下一個節點先改了 cur.next，才發現原本後面那段找不到了改箭頭之前先用變數存起 cur.next；插入時先接後面再接前面

另外兩個小地方：會改變頭的方法（插在最前面、反轉、刪頭）一定要回傳新的頭，呼叫端也要接住；比較「是不是同一個節點」用 ==，比較「值一不一樣」才用 val。

list 是有 n 個元素的 LinkedList。下面這段的時間複雜度是多少？

long sum = 0;
for (int i = 0; i < list.size(); i++) {
    sum += list.get(i);
}
  • O(n)
  • O(n log n)
  • O(n²)
  • O(1)

每次 get(i) 都要從比較近的一端走過去，平均走 n/4 步左右，n 次加起來是 O(n²)。改用 for-each 只要 O(n)。

LinkedList 有 1,000,000 個元素，呼叫 get(999_998)（倒數第二個）大約要走幾步？

  • 大約 999,998 步
  • 大約 500,000 步
  • 大約 20 步
  • 大約 1、2 步

文件寫它會從離索引比較近的那一端走過去。倒數第二個從尾端往回只要一步左右。從頭走才要將近一百萬步。

寫完一個「刪除串列中所有值為 x 的節點」的方法，下面哪一組測試最能抓到邊界錯誤？

  • 空串列、一個節點、全部都是 x、x 在頭、x 在尾
  • 三組一般的長串列，x 都出現在串列中間
  • 一條一萬個節點的串列，專門測速度夠不夠快
  • 只測一組 x 不在串列裡的情況，確認不會刪錯

串列題的錯幾乎都出在邊界：空的、只有一個、動到頭、動到尾、連續好幾個要刪。中間的一般情況反而最不容易錯。

下面這行在什麼情況會丟出 NullPointerException？

if (cur.next.val == target) { ... }
  • cur.next.val 等於 target 時
  • cur 是最後一個節點時
  • cur 是第一個節點時
  • target 是負數時

cur 是最後一個時 cur.next 是 null，再讀 .val 就丟例外（cur 本身是 null 時也會）。所以迴圈條件要先確認 cur.next != null。

重點整理

  • 鏈結串列的節點存值和 next，最後一個指向 null；手上只有 head。取索引 i 的元素 O(n)，在頭、或在已經拿到的節點後面插入刪除 O(1)，但「先找到位置」還是 O(n)。
  • Java 的 LinkedList 是雙向串列，get(i) 從比較近的一端走過去，仍是 O(n)；當佇列用選 ArrayDeque。
  • 走訪：for (cur = head; cur != null; cur = cur.next)，另外用 cur 走，別動 head。
  • 插入先接後面再接前面；刪除要拿到前一個，改成 prev.next = prev.next.next；虛擬頭節點讓刪頭不必特別處理，最後回傳 dummy.next。
  • 反轉：先存 next、改箭頭、prev 與 cur 各前進一格，回傳 prev；迴圈版 O(n) 時間、O(1) 空間，遞迴版多 O(n) 呼叫堆疊。
  • 快慢指標：條件 fast != null && fast.next != null；fast 到底時 slow 在中點；有環一定相遇（比 == 不比值）；相遇後一個回到 head、同速前進，會合處是環的入口。
  • 合併兩個排序串列 O(m + n)、O(1) 額外空間；刪倒數第 k 個讓 fast 先走 k 步、從 dummy 出發。寫完必測空串列、一個、兩個、動到頭、動到尾。

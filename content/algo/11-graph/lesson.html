人與人、服務與服務之間的線

圖的名詞：頂點、邊、有向與無向、有權與無權

把「一堆東西，以及它們兩兩之間的關係」畫出來，就是一張圖（graph）。普林斯頓《Algorithms》的定義是：圖是「一組頂點，加上一組各自連接兩個頂點的邊」（A graph is a set of vertices and a collection of edges that each connect a pair of vertices）。出處 東西叫頂點（vertex，也叫節點），關係叫邊（edge）。職場上到處都是圖：

  • 轉帳關係：每個帳戶是頂點，「甲轉錢給乙」是一條從甲指向乙的邊，金額可以記在邊上。
  • 服務相依：每個微服務是頂點，「付款服務要呼叫帳務服務」是一條邊；要決定誰先啟動、某個服務掛了會影響誰，都是在圖上找路。
  • 好友關係、路網、課程先修：一樣是頂點加邊。

邊有兩種分法。有向（directed）的邊有方向，(u, v) 跟 (v, u) 是兩條不同的邊；無向（undirected）的邊沒有方向，連起來就是雙方互相。MIT 6.006 講義的寫法：有向邊是「有順序的一對頂點」（Directed edges are ordered pairs），無向邊是「沒有順序的一對」（Undirected edges are unordered pairs）。出處 另一種分法是邊上有沒有數字：有數字（距離、金額、耗時）叫有權（weighted），那個數字叫權重；沒有就是無權，每條邊都算「一步」。

幾個後面會一直用到的詞：

這些定義都出自普林斯頓的名詞表：度數是「連在這個頂點上的邊數」、環是「起點與終點相同的路徑」、連通塊是「最大的連通子圖」；入度是「指向它的邊數」（The indegree of a vertex is the number of edges pointing to it）。出處有向圖 名詞表還有一句：樹是「沒有環的連通圖」（A tree is an acyclic connected graph），所以〈樹與二元搜尋樹〉的樹，其實是圖的一種特例。圖的大小用兩個數字描述：頂點數 V、邊數 E，這課的複雜度都用它們表示。

兩種存法：鄰接串列對鄰接矩陣

程式裡存一張圖有兩種常見做法：

  • 鄰接串列（adjacency list）：像通訊錄，每個頂點記一份「我的鄰居有誰」。普林斯頓的實作就用它：「一個用頂點編號當索引的陣列，每一格是一條清單，列出跟這個頂點有邊相連的頂點」（a vertex-indexed array of lists of the vertices connected by an edge to each vertex）。出處
  • 鄰接矩陣（adjacency matrix）：像一張 V × V 的對照表，第 u 列第 v 欄記「u 與 v 之間有沒有邊」。普林斯頓的 AdjMatrixGraph 一建立就配置 new boolean[V][V]。出處
import java.util.ArrayList;
import java.util.List;

public class MatrixVsList {
    public static void main(String[] args) {
        int n = 4;
        int[][] edges = {{0, 1}, {0, 2}, {1, 2}, {2, 3}};

        boolean[][] matrix = new boolean[n][n];          // 鄰接矩陣：n × n 格
        List<List<Integer>> list = new ArrayList<>();    // 鄰接串列：每個頂點一條清單
        for (int i = 0; i < n; i++) list.add(new ArrayList<>());
        for (int[] e : edges) {
            matrix[e[0]][e[1]] = matrix[e[1]][e[0]] = true;
            list.get(e[0]).add(e[1]);
            list.get(e[1]).add(e[0]);
        }

        for (boolean[] row : matrix) {
            StringBuilder sb = new StringBuilder();
            for (boolean b : row) sb.append(b ? 1 : 0).append(' ');
            System.out.println(sb.toString().trim());
        }
        System.out.println(list);
        System.out.println("1 和 3 相鄰嗎？矩陣 " + matrix[1][3] + "，串列 " + list.get(1).contains(3));
    }
}

BFS：用佇列一層一層找

廣度優先搜尋（breadth-first search，BFS）像石頭丟進水裡的漣漪：先看離起點一步的所有頂點，再看兩步的，再看三步的。普林斯頓的描述：先檢查「沿一條邊走得到」的頂點，再檢查「沿兩條邊走得到」的，依此類推；做法是用一個佇列，放「已經標記、但鄰居還沒檢查」的頂點，然後重複兩件事直到佇列空了：從佇列拿出下一個頂點 v；把 v 所有還沒標記的鄰居標記起來、放進佇列（Remove the next vertex v from the queue. Put onto the queue all unmarked vertices that are adjacent to v and mark them.）。出處 佇列（先進先出）在〈堆疊與佇列〉講過，先發現的先處理，所以一定是近的先處理完。

這課的範例圖有 7 個頂點，邊是 0-1、0-2、1-3、2-3、2-5、3-4、5-6。每條清單裡的鄰居照編號由小到大排，這樣走訪順序才固定（換了鄰居的順序，順序就會變）。

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Deque;
import java.util.List;

public class Graphs {
    // 無向圖：鄰接串列。adj.get(u) 是 u 的鄰居清單
    static List<List<Integer>> undirected(int n, int[][] edges) {
        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
        for (int[] e : edges) {
            adj.get(e[0]).add(e[1]);                   // 無向：兩邊都要加
            adj.get(e[1]).add(e[0]);
        }
        return adj;
    }

    // BFS：用佇列一層一層往外，順便記下每個頂點離起點幾步
    static List<Integer> bfs(List<List<Integer>> adj, int start, int[] dist) {
        List<Integer> order = new ArrayList<>();
        Arrays.fill(dist, -1);                         // -1 表示還沒到過
        Deque<Integer> queue = new ArrayDeque<>();
        dist[start] = 0;
        queue.offer(start);
        while (!queue.isEmpty()) {
            int u = queue.poll();
            order.add(u);
            for (int v : adj.get(u)) {
                if (dist[v] == -1) {                   // 放進佇列的當下就標記，才不會重複放
                    dist[v] = dist[u] + 1;
                    queue.offer(v);
                }
            }
        }
        return order;
    }

    // DFS（遞迴）：一路往深處走，走不下去再退回來
    static void dfs(List<List<Integer>> adj, int u, boolean[] visited, List<Integer> order) {
        visited[u] = true;
        order.add(u);
        for (int v : adj.get(u)) {
            if (!visited[v]) dfs(adj, v, visited, order);
        }
    }

    public static void main(String[] args) {
        int[][] edges = {{0, 1}, {0, 2}, {1, 3}, {2, 3}, {2, 5}, {3, 4}, {5, 6}};
        List<List<Integer>> adj = undirected(7, edges);
        System.out.println("鄰接串列 " + adj);

        int[] dist = new int[7];
        System.out.println("BFS 順序 " + bfs(adj, 0, dist));
        System.out.println("離 0 幾步 " + Arrays.toString(dist));

        List<Integer> order = new ArrayList<>();
        dfs(adj, 0, new boolean[7], order);
        System.out.println("DFS 順序 " + order);
    }
}

為什麼 BFS 能找最短路徑

因為它是照「離起點幾步」的順序拜訪的：所有一步到得了的，都比兩步的先處理。所以某個頂點第一次被發現時，用的就是最少的步數。普林斯頓的命題：對任何從 s 走得到的頂點 v，BFS 算出的是 s 到 v 的最短路徑，「沒有哪條路徑的邊數比它少」（no path from s to v has fewer edges）。出處 注意這裡的「最短」是邊數最少；邊上有權重時就不成立了，本課最後一段會講。

要印出路徑本身，就在發現 v 時記下「v 是從誰走過來的」（parent），最後從終點一路往回走到起點、再反轉。MIT 講義把這些 parent 合起來叫最短路徑樹（shortest paths tree）。出處

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Collections;
import java.util.Deque;
import java.util.List;

public class ShortestPath {
    // BFS 記下每個頂點是從誰走過來的，最後從終點倒著走回起點
    static List<Integer> path(List<List<Integer>> adj, int s, int t) {
        int[] parent = new int[adj.size()];
        Arrays.fill(parent, -2);                         // -2：還沒到過
        parent[s] = -1;                                  // 起點沒有前一個
        Deque<Integer> queue = new ArrayDeque<>();
        queue.offer(s);
        while (!queue.isEmpty()) {
            int u = queue.poll();
            if (u == t) break;                           // 終點一出佇列就可以停
            for (int v : adj.get(u)) {
                if (parent[v] == -2) {
                    parent[v] = u;
                    queue.offer(v);
                }
            }
        }
        if (parent[t] == -2) return List.of();           // 走不到
        List<Integer> p = new ArrayList<>();
        for (int v = t; v != -1; v = parent[v]) p.add(v);
        Collections.reverse(p);
        return p;
    }

    public static void main(String[] args) {
        int[][] edges = {{0, 1}, {0, 2}, {1, 3}, {2, 3}, {2, 5}, {3, 4}, {5, 6}};
        List<List<Integer>> adj = Graphs.undirected(7, edges);
        System.out.println(path(adj, 0, 4));
        System.out.println(path(adj, 0, 6));
        System.out.println(path(adj, 4, 6));
    }
}

0 到 4 有兩條三步的路（經過 1 或經過 2），BFS 回傳哪一條取決於鄰居的順序；兩條都是最短。

複雜度

每個頂點最多進佇列一次、出佇列一次；每個頂點出佇列時把它的清單掃一遍，所有清單加起來是 O(E)。總共 O(V + E)，普林斯頓的原句是「BFS 最壞的時間與 V + E 成正比」（BFS takes time proportional to V + E in the worst case）。出處 額外空間是佇列加 visited，O(V)。

標記要在放進佇列的當下做，不是拿出來時才做。晚一步標記的話，同一個頂點可能被好幾個鄰居各放進佇列一次，結果還是對（拿出時要跳過已標記的），但會多做很多事。

BFS 用來存「發現了、但還沒處理」頂點的資料結構是什麼？

  • 佇列，先進先出
  • 堆疊，後進先出
  • 優先佇列，最小的先出
  • 雜湊表，沒有順序

先發現的離起點比較近，要先處理，正好是先進先出。換成堆疊就會變成一路往深處走，那是 DFS。

用範例圖（邊 0-1、0-2、1-3、2-3、2-5、3-4、5-6，鄰居由小到大），從 3 出發做 BFS，拜訪順序是？

  • 3, 4, 2, 1, 5, 0, 6
  • 3, 1, 2, 4, 0, 5, 6

  • 4

最短是 3 → 2 → 5 → 6，三條邊。實跑的 dist 陣列也是 3。

從 0 出發的 BFS（就是上面那張佇列表），拿出 1 並處理完它的鄰居之後，佇列裡是什麼？

  • [3]
  • [3, 2]
  • [2, 3, 0]
  • [2, 3]

拿出 0 後佇列是 [1, 2]；拿出 1，鄰居 0 已標記、3 沒有，放 3 到尾端，變成 [2, 3]。

另一張無向圖，邊是 0-1、0-3、1-2、3-4、2-4，鄰居由小到大。從 0 出發做 BFS，順序是？

  • 0, 1, 2, 4, 3
  • 0, 1, 3, 2, 4
  • 0, 3, 1, 4, 2
  • 0, 1, 3, 4, 2

0 的鄰居 1、3 先進；拿出 1 放 2；拿出 3 放 4；之後拿出 2、4。照「一步的、再兩步的」排。

BFS 能保證找到最短路徑，前提是什麼？

  • 邊都算一步（無權），比的是邊數
  • 圖一定要是有向圖，而且邊都指向外面
  • 圖裡不能有任何環，否則會繞圈
  • 起點的度數要是全圖最大的

BFS 照步數一層一層找，所以最少邊數一定先找到。有權重時，邊數少不一定總權重小。有向、有環都不影響。

BFS 的時間複雜度是多少（V 個頂點、E 條邊、用鄰接串列）？

  • O(V + E)
  • O(V × E)
  • O(V²)
  • O(E log V)

每個頂點進出佇列各一次，每條清單掃一遍，加起來 O(V + E)。用鄰接矩陣的話，每個頂點要掃一整列，變成 O(V²)。

把 BFS 改成「從佇列拿出來時才標記 visited」，放進佇列時不檢查也不標記。結果會怎樣？

  • 拜訪順序和效能都跟原本完全一樣
  • 有些頂點永遠不會被拜訪到
  • 同一個頂點會重複進佇列，多做白工
  • 佇列永遠不會空，變成無窮迴圈

還沒拿出來前它都沒被標記，其他鄰居會再放一次。拿出時再檢查 visited 就能跳過重複的，不會無窮迴圈，但佇列可能塞到 O(E) 個。

有向圖的邊是 0→1、1→2、3→1。從 0 出發做 BFS，會拜訪哪些頂點？

  • 0, 1, 2, 3
  • 0, 1, 3
  • 0, 1, 2
  • 只有 0

有向圖只能順著箭頭走：0 到 1、1 到 2。3→1 是指向 1 的，從 1 走不回 3。

走到死巷再回頭

DFS：遞迴或堆疊，一路走到底

深度優先搜尋（depth-first search，DFS）像走迷宮：選一條路一直走，走到死巷就退回上一個岔路口，換一條還沒走過的。普林斯頓的描述只有兩步：拜訪一個頂點時，先標記它，再遞迴拜訪它所有還沒標記的鄰居（Mark it as having been visited. Visit (recursively) all the vertices that are adjacent to it and that have not yet been marked.）。出處 MIT 講義的白話是「沿著任一條路走到卡住，再退回去，直到找到還沒探索的路」（follow any path until you get stuck, backtrack until finding an unexplored path to explore）。出處

上面 Graphs 類別裡的 dfs 就是這樣寫的，從 0 出發的順序是 0、1、3、2、5、6、4：從 0 走到 1，1 走到 3，3 的第一個沒拜訪的鄰居是 2，2 走到 5，5 走到 6；6 沒有新鄰居，退回 5、退回 2、退回 3，3 還有 4 沒去，走到 4。

不用遞迴：自己管一個堆疊

遞迴本身就是用呼叫堆疊在記「還沒走完的岔路口」（〈遞迴與回溯〉）。圖很大、路很長時，遞迴可能太深而 StackOverflowError，這時改成自己用 ArrayDeque 當堆疊：

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.List;

public class DfsStack {
    // DFS（堆疊）：不用遞迴，自己管一個堆疊
    static List<Integer> dfs(List<List<Integer>> adj, int start) {
        List<Integer> order = new ArrayList<>();
        boolean[] visited = new boolean[adj.size()];
        Deque<Integer> stack = new ArrayDeque<>();
        stack.push(start);
        while (!stack.isEmpty()) {
            int u = stack.pop();
            if (visited[u]) continue;                    // 同一個頂點可能被推進去好幾次
            visited[u] = true;
            order.add(u);
            List<Integer> nb = adj.get(u);
            for (int i = nb.size() - 1; i >= 0; i--) {   // 反著推，小的鄰居才會先被拿出來
                if (!visited[nb.get(i)]) stack.push(nb.get(i));
            }
        }
        return order;
    }

    public static void main(String[] args) {
        int[][] edges = {{0, 1}, {0, 2}, {1, 3}, {2, 3}, {2, 5}, {3, 4}, {5, 6}};
        System.out.println("DFS 順序 " + dfs(Graphs.undirected(7, edges), 0));
    }
}
DFS 順序 [0, 1, 3, 2, 5, 6, 4]

兩個細節讓它跟遞迴版順序一樣：鄰居反著推（堆疊後進先出，最後推的最先拿出來）；拿出來時才標記，並跳過已標記的。跟 BFS 不同，這裡要拿出時才標記，否則順序會跟遞迴版不一樣。面試寫哪一種都可以，但要能說出順序為什麼是這樣。

BFS 與 DFS 怎麼選

BFSDFS
工具佇列遞迴或堆疊
拜訪順序一層一層，近的先一條路走到底再回頭
無權最短路徑可以不行，找到的路不一定最短
時間O(V + E)O(V + E)
常用在最短步數、一層一層擴散（例如多個起點同時往外）連通塊、走得到嗎、找環、拓樸排序的另一種做法、回溯

MIT 講義也說 DFS 解的是「走不走得到」，回傳的路徑「不一定是最短的」（not necessarily shortest）；兩者都可以重複「從還沒拜訪的頂點再出發」把整張圖走完，時間都是 O(|V| + |E|)，每出發一次找到的就是一個連通塊。出處

用範例圖（邊 0-1、0-2、1-3、2-3、2-5、3-4、5-6，鄰居由小到大），從 5 出發做遞迴 DFS，拜訪順序是？

  • 5, 2, 0, 1, 3, 4, 6
  • 5, 2, 6, 0, 3, 1, 4
  • 5, 6, 2, 0, 1, 3, 4
  • 5, 2, 0, 1, 3, 6, 4

5 先去 2；2 先去 0；0 去 1；1 去 3；3 的 1、2 都拜訪過，去 4；一路退回 5 才去 6。從 5 出發的 BFS 順序才是 5, 2, 6, 0, 3, 1, 4。

同一張圖從 3 出發做遞迴 DFS，拜訪順序是？

  • 3, 1, 2, 4, 0, 5, 6
  • 3, 4, 2, 5, 6, 0, 1
  • 3, 1, 0, 2, 5, 6, 4
  • 3, 1, 0, 2, 4, 5, 6

3 去 1，1 去 0，0 的下一個是 2，2 去 5，5 去 6；退回 3 才去 4。3, 1, 2, 4… 是 BFS 的順序。

無向圖的邊是 0-1、0-3、1-2、3-4、2-4，鄰居由小到大。從 0 出發做遞迴 DFS，順序是？

  • 0, 1, 3, 2, 4
  • 0, 3, 4, 2, 1
  • 0, 1, 2, 3, 4
  • 0, 1, 2, 4, 3

0 去 1，1 去 2，2 去 4，4 的鄰居 2 已拜訪、3 沒有，去 3。0, 1, 3, 2, 4 是 BFS。

從 0 出發，下面哪一個工具搭配會得到 DFS 的拜訪方式？

  • 堆疊，或直接寫遞迴
  • 佇列
  • 優先佇列
  • 只能用遞迴，不能用迴圈

後進先出讓最新發現的先處理，就會一路往深處走。遞迴靠的是呼叫堆疊；自己用 ArrayDeque 當堆疊也可以。

在 DfsStack 裡，如果鄰居改成「照順序推」（不反著推），從 0 出發的順序會變成什麼？（範例圖）

  • 0, 1, 3, 2, 5, 6, 4
  • 0, 1, 2, 3, 5, 4, 6
  • 0, 2, 5, 6, 3, 4, 1
  • 0, 2, 3, 1, 4, 5, 6

推 1、2 後先拿出 2；2 推 3、5，先拿出 5；5 推 6，拿出 6；接著拿出 3，推 1、4，先拿出 4，最後是 1。還是 DFS，只是先走大的鄰居。

要找「從起點走到終點最少要幾步」（每步都一樣），該用哪一個？

  • DFS，因為它會走得比較遠
  • BFS
  • 兩個都可以，結果一樣
  • 都不行，一定要用 Dijkstra

BFS 照步數一層一層找，第一次碰到終點就是最少步數。DFS 找到的路不一定最短。每步一樣（無權）不需要 Dijkstra。

遞迴版 DFS 在一張「一條長長的線」的圖上（0-1-2-…-999999）會有什麼風險？

  • 拜訪的順序會整個亂掉
  • 某些頂點會被漏掉沒拜訪
  • 時間會變成 O(V²)
  • 遞迴太深，呼叫堆疊撐爆

每往下一個頂點就多一層呼叫，一百萬層會撐爆呼叫堆疊。改用自己管的堆疊就不受這個限制。時間還是 O(V + E)。

要算一張無向圖有幾個連通塊，下面哪個做法正確？

  • 從 0 做一次 DFS，數總共拜訪了幾個頂點
  • 每個沒拜訪的頂點出發一次，數出發幾次
  • 數整張圖總共有幾條邊
  • 數度數是 0 的頂點有幾個

每次從新的、沒拜訪過的頂點出發，就會把它那一塊全部標記起來；出發的次數就是連通塊數。只做一次只找得到起點那一塊。

DFS 的時間複雜度是多少（鄰接串列）？

  • O(V²)
  • O(V + E)
  • O(2^V)
  • O(E log E)

每個頂點只拜訪一次，拜訪時掃一次自己的清單，加起來 O(V + E)，跟 BFS 一樣。標記過就不再走，所以不會指數爆炸。

格子也是一張圖

格子題：島嶼數量

很多題目給的是一張二維格子（地圖、棋盤、圖片像素），乍看不像圖，其實每一格都是頂點，跟上下左右的格子之間有邊。最經典的是「島嶼數量」：1 是陸地、0 是水，上下左右相連的陸地算同一座島，問有幾座。這就是在數連通塊：每遇到一塊還沒走過的陸地，島數加一，然後用 DFS 把整座島「淹掉」（改成 0），之後就不會再數到它。

public class Islands {
    static final int[][] DIRS = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};   // 上下左右

    static int count(char[][] grid) {
        int islands = 0;
        for (int r = 0; r < grid.length; r++) {
            for (int c = 0; c < grid[0].length; c++) {
                if (grid[r][c] == '1') {
                    islands++;                           // 碰到一塊沒走過的陸地：新的島
                    sink(grid, r, c);                    // 把整座島淹掉，之後就不會再數到
                }
            }
        }
        return islands;
    }

    static void sink(char[][] grid, int r, int c) {
        if (r < 0 || c < 0 || r >= grid.length || c >= grid[0].length) return;   // 出界
        if (grid[r][c] != '1') return;                   // 是水，或已經淹過
        grid[r][c] = '0';                                // 標記走過（直接改格子當 visited）
        for (int[] d : DIRS) sink(grid, r + d[0], c + d[1]);
    }

    public static void main(String[] args) {
        String[] rows = {
            "11000",
            "11010",
            "00010",
            "10001"
        };
        char[][] grid = new char[rows.length][];
        for (int i = 0; i < rows.length; i++) grid[i] = rows[i].toCharArray();
        System.out.println(count(grid));
    }
}
4

格子有 R 列 C 欄，頂點是 R × C 個，每個頂點最多 4 條邊，所以 O(V + E) 就是 O(R × C)。三個常見的坑：先檢查出界再讀格子（順序反了會 ArrayIndexOutOfBoundsException）；標記要在遞迴下去之前（不然兩格互相呼叫停不下來）；直接改輸入的格子很省事，但如果題目或呼叫端還要用原本的資料，就另外開一個 boolean[][] visited。很大的格子用遞迴可能太深，可以改用 BFS（佇列放座標 int[]{r, c}）。

sink 如果把兩個檢查的順序對調，先寫 if (grid[r][c] != '1') return; 再檢查出界，會怎樣？

  • 結果一樣，只是每格多檢查一次、跑得比較慢
  • 島的數量會少算一座
  • 會無窮遞迴停不下來

R 列 C 欄的格子，島嶼數量這個做法的時間複雜度是多少？

  • O(R × C)

  • 結果一樣，只是不能再呼叫第二次
  • 島的數量會少算，有些島被跳過
  • 兩塊陸地互相呼叫，遞迴停不下來

沒標記的話，(0,0) 呼叫 (0,1)，(0,1) 又呼叫回 (0,0)，永遠走不完，最後 StackOverflowError。改格子就是 visited。

先修課排在前面

拓樸排序：Kahn 演算法與偵測有環

系統開機時，設定服務要先起來，資料庫才能起來，帳務服務又要等資料庫和快取。把「A 要在 B 之前」畫成 A→B，問「可以照什麼順序全部啟動」，就是拓樸排序（topological sort）。MIT 講義的定義：拓樸順序是一種排列，讓每一條邊 (u, v) 都滿足 u 排在 v 前面（every edge (u, v) ∈ E satisfies f(u) < f(v)）；而且有向圖只有在沒有環時才排得出來（a directed graph admits a topological ordering if and only if it is a DAG）。出處 有環就是「A 等 B、B 又等 A」，誰都起不來。課程先修（修完程式設計才能修資料結構）、建置工具的模組相依、試算表的公式計算順序，都是同一個問題。

Kahn 演算法：入度歸零就輪到你

入度是「還有幾個前置條件沒完成」。做法是：先把入度 0 的頂點放進佇列；每拿出一個就排進結果，然後把它指向的每個頂點入度減 1，減到 0 的就放進佇列。普林斯頓習題的描述：用一個陣列記每個頂點的入度，先把所有入度 0 的放進佇列，然後重複「拿出一個並排上順序；把它每條邊指向的頂點入度減 1；減到 0 就放進佇列」（If decrementing any entry causes it to become 0, insert the corresponding vertex onto the source queue.）。出處 這個做法常以提出者的名字叫 Kahn 演算法。

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Deque;
import java.util.List;

public class Topo {
    // Kahn 演算法：入度是 0 的先排；排掉一個，就把它指向的頂點入度減 1
    static List<Integer> kahn(int n, int[][] edges) {
        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
        int[] indegree = new int[n];
        for (int[] e : edges) {                          // e[0] → e[1]：e[0] 要排在 e[1] 前面
            adj.get(e[0]).add(e[1]);
            indegree[e[1]]++;
        }
        System.out.println("入度 " + Arrays.toString(indegree));

        Deque<Integer> queue = new ArrayDeque<>();
        for (int v = 0; v < n; v++) if (indegree[v] == 0) queue.offer(v);
        List<Integer> order = new ArrayList<>();
        while (!queue.isEmpty()) {
            int u = queue.poll();
            order.add(u);
            for (int v : adj.get(u)) {
                if (--indegree[v] == 0) queue.offer(v);  // 前置條件都排完了，輪到它
            }
        }
        if (order.size() < n) return null;               // 有頂點的入度永遠降不到 0：有環
        return order;
    }

    public static void main(String[] args) {
        String[] name = {"config", "db", "cache", "auth", "account", "payment", "gateway"};
        int[][] edges = {{0, 1}, {0, 2}, {1, 3}, {1, 4}, {2, 4}, {3, 6}, {4, 5}, {5, 6}};
        List<Integer> order = kahn(7, edges);
        List<String> names = new ArrayList<>();
        for (int v : order) names.add(name[v]);
        System.out.println("啟動順序 " + names);

        int[][] withCycle = {{0, 1}, {1, 2}, {2, 1}};    // 1 等 2、2 又等 1
        System.out.println("有環時 " + kahn(3, withCycle));
    }
}

三件要記住的事：

  • 拓樸順序通常不只一種。db 與 cache 都只等 config，誰先誰後都對；上面的結果只是這個程式（照邊的放入順序、用佇列）跑出來的那一種。檢查一個順序合不合法，只要看每一條邊的起點是不是都排在終點前面。
  • 順便偵測有環。環上的頂點彼此等待，入度永遠降不到 0，不會進佇列；所以排完時結果少於 V 個，就表示有環。上面第二個例子 1 等 2、2 又等 1，只排得出 0 一個，少於 3 個，所以回傳 null。
  • 複雜度 O(V + E)。算入度掃一次所有邊；每個頂點進出佇列一次，拿出時掃一次自己的邊。

另一種做法用 DFS：普林斯頓的命題是「有向無環圖的 DFS 後序反過來就是拓樸順序」（Reverse postorder in a DAG is a topological sort；後序是每個頂點的鄰居都拜訪完、要退回時才記下它）。出處 MIT 講義也有同一個主張並附證明：有向無環圖裡，把 DFS「拜訪完每個頂點」的先後順序反過來，就是拓樸順序（If G = (V, E) is a DAG, the reverse of a finishing order is a topological order）。出處 面試用 Kahn 比較好講，也比較好順便判斷有環。

  • 那 2 個頂點的入度本來就是 0

判斷一個給定的順序是不是合法的拓樸順序，最直接的方法是什麼？

  • 檢查每一條邊 u→v，u 都排在 v 前面

定義就是每條邊都要起點在前。合法順序常有好幾種，跟某一次程式跑出來的不同不代表錯；只看頭尾也不夠。

Dijkstra：有權重的最短路徑

邊上有權重（例如每段路的公里數、每次轉介的手續費）時，「邊數最少」不等於「總權重最小」：

這時用 Dijkstra 演算法：用優先佇列（每次拿出最小的那個）放「目前已知的距離」，每次拿出距離最小的頂點，用它去更新鄰居（經過它比較近就改掉，叫鬆弛，relax）。普林斯頓的命題：Dijkstra 解「權重不為負」的單一起點最短路徑，「時間與 E log V 成正比」（solves the single-source shortest-paths problem in edge-weighted digraphs with nonnegative weights using extra space proportional to V and time proportional to E log V）。出處 log 那一項來自優先佇列：Java 的 PriorityQueue 文件寫，放入與取出（offer、poll）是 O(log(n))。出處 優先佇列怎麼做到的見〈堆積與優先佇列〉。

import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
import java.util.PriorityQueue;

public class Dijkstra {
    // 有權重（不能是負數）的最短路徑：每次從優先佇列拿出「目前最近」的頂點
    static long[] shortest(int n, int[][] edges, int s) {
        List<List<int[]>> adj = new ArrayList<>();
        for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
        for (int[] e : edges) adj.get(e[0]).add(new int[]{e[1], e[2]});   // e[0] → e[1]，權重 e[2]

        long[] dist = new long[n];
        Arrays.fill(dist, Long.MAX_VALUE);
        dist[s] = 0;
        PriorityQueue<long[]> pq = new PriorityQueue<>((a, b) -> Long.compare(a[1], b[1]));
        pq.offer(new long[]{s, 0});
        while (!pq.isEmpty()) {
            long[] top = pq.poll();
            int u = (int) top[0];
            if (top[1] > dist[u]) continue;              // 舊的紀錄，已經有更短的了
            for (int[] e : adj.get(u)) {
                int v = e[0];
                long nd = dist[u] + e[1];
                if (nd < dist[v]) {                      // 經過 u 再到 v 比較近：更新
                    dist[v] = nd;
                    pq.offer(new long[]{v, nd});
                }
            }
        }
        return dist;
    }

    public static void main(String[] args) {
        int[][] edges = {{0, 1, 4}, {0, 2, 1}, {2, 1, 2}, {1, 3, 1}, {2, 3, 5}};
        System.out.println(Arrays.toString(shortest(4, edges, 0)));
    }
}
[0, 3, 1, 4]

面試只要知道三件事：權重不能是負的（這課的程式假設如此）；工具從佇列換成優先佇列；複雜度 O(E log V)。每條邊權重都一樣時，退回用 BFS 就好，O(V + E) 更快。

union-find（互斥集合）：快速判斷「是不是同一群」

有些題目只關心「這兩個頂點連不連得到」，而且邊是一條一條加進來的，例如「每加入一筆轉帳關係，就問兩個帳戶現在是不是同一個往來群組」。每次都重做一次 DFS 太慢，這時用 union-find（互斥集合，disjoint set）：把東西分群、能快速判斷兩個是不是同一群的資料結構。每一群選一個代表，find(x) 找 x 那一群的代表，union(a, b) 把兩群合併。普林斯頓的版本按大小合併（weighted quick-union）：把小的那群掛到大的底下，證明了樹的深度最多 lg n，所以三個操作最壞都是 O(log n)（the worst-case order of growth of the cost of find(), connected(), and union() is log n）。下面的程式再加上路徑減半（path halving）。它是路徑壓縮（找的時候讓路上的節點直接指向根）的簡化版：找的時候順手讓經過的節點改指向祖父，也就是父節點的父節點。普林斯頓的說法是它「讓找的路徑上每隔一個節點改連到祖父」（makes every other node on the find path link to its grandparent）。至於有多快：普林斯頓對「按大小合併＋路徑壓縮」的說法是，每次操作的攤銷成本（把偶爾一次很貴的成本平均分攤到每次操作）「已知會被一個叫反阿克曼函數的函數限制住，在實務上會遇到的任何 n 都小於 5」（The amortized cost per operation for this algorithm is known to be bounded by a function known as the inverse Ackermann function and is less than 5 for any conceivable value of n that arises in practice），也就是近乎常數。路徑減半是簡化版，實務上效果相近。出處

public class UnionFind {
    private final int[] parent, size;
    private int components;

    UnionFind(int n) {
        parent = new int[n];
        size = new int[n];
        components = n;
        for (int i = 0; i < n; i++) { parent[i] = i; size[i] = 1; }   // 一開始每個人自成一組
    }

    int find(int x) {                                    // 找 x 所在那一組的代表（根）
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];               // 路徑減半：順手指向祖父，讓樹變矮
            x = parent[x];
        }
        return x;
    }

    boolean union(int a, int b) {                        // 合併兩組；本來就同組回傳 false
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;
        if (size[ra] < size[rb]) { int t = ra; ra = rb; rb = t; }
        parent[rb] = ra;                                 // 小的那組掛到大的底下
        size[ra] += size[rb];
        components--;
        return true;
    }

    public static void main(String[] args) {
        UnionFind uf = new UnionFind(6);
        int[][] links = {{0, 1}, {1, 2}, {3, 4}, {2, 0}};
        for (int[] l : links) System.out.print(uf.union(l[0], l[1]) + " ");
        System.out.println();
        System.out.println(uf.components + " " + (uf.find(0) == uf.find(2)) + " " + (uf.find(0) == uf.find(3)));
    }
}
true true true false
3 true false

第四次 union(2, 0) 回傳 false：2 和 0 早就同一群，再加這條邊會形成環。所以 union-find 也常拿來判斷「無向圖加一條邊會不會成環」。6 個頂點最後剩 3 群：{0, 1, 2}、{3, 4}、{5}。

0→2（1）→1（2）→3（1），共 4。0→1→3 是 5，0→2→3 是 6。實跑結果 dist[3] = 4。

邊上有不同的權重、而且都不是負數，要找單一起點到其他頂點的最短距離。該用哪一個？

  • Dijkstra，用優先佇列
  • BFS，因為它找的是最短路徑
  • DFS
  • 拓樸排序

BFS 的最短是邊數最少，不管權重。權重不為負時用 Dijkstra。拓樸排序只處理先後順序。

Dijkstra 演算法的時間複雜度（普林斯頓用優先佇列的版本）是多少？

  • O(V + E)
  • O(E log V)
  • O(V²)，跟 BFS 一樣
  • O(2^V)

每條邊最多觸發一次優先佇列操作，每次 O(log)，所以是 E log V 的等級。BFS 才是 O(V + E)。

union-find 的 union(a, b) 回傳 false 代表什麼？

  • a 或 b 不在這個結構裡
  • 合併失敗了，要再重試一次
  • 兩群的大小剛好一樣，無法合併
  • 兩者本來就同一群，這條邊會成環

兩個的代表相同就不必合併，回傳 false。在無向圖上，同一群的兩點再連一條邊就是環。

6 個頂點，依序 union(0, 1)、union(2, 3)、union(1, 3)、union(4, 5)、union(0, 2)。最後有幾群？

  • 2
  • 1
  • 3
  • 4

前三次把 0、1、2、3 併成一群；第四次 4、5 一群；第五次 0 和 2 已經同群，不變。剩 {0, 1, 2, 3} 和 {4, 5} 兩群。

按大小合併為什麼要「把小的那群掛到大的底下」？

  • 讓 union 可以回傳正確的 true 或 false
  • 讓群組的代表永遠是編號最小的
  • 讓樹不會長得太高，find 最壞只要 O(log n)
  • 讓每一群的大小都一樣

隨便掛可能掛成一長條，find 要走 O(n) 步。小的掛到大的底下，普林斯頓證明深度最多 lg n。

重點整理

  • 圖＝頂點＋邊；邊分有向無向、有權無權。入度是幾條邊指向它；樹是沒有環的連通圖；有向無環圖（DAG）才能拓樸排序。
  • 鄰接串列空間 O(V + E)、列鄰居快，是預設選擇；鄰接矩陣空間 O(V²)、判斷兩點有沒有邊 O(1)，適合頂點少、邊很密。頂點是字串時用 Map<String, List<String>>。
  • BFS 用佇列、放進佇列時就標記，一層一層拜訪，第一次發現就是無權圖的最短步數；記 parent 可以印出路徑。
  • DFS 用遞迴或堆疊，一路走到底再回頭；用來數連通塊、判斷走不走得到、找環。圖很深時改用自己的堆疊，避免 StackOverflowError。
  • BFS 與 DFS 都是 O(V + E)。格子題每格是頂點、上下左右是邊，先檢查出界、先標記再往下走，時間 O(R × C)。
  • Kahn 演算法：入度 0 的進佇列，拿出一個就把它指向的入度減 1、減到 0 的進佇列；排不完 V 個就有環。合法順序常有好幾種，檢查方法是每條邊起點都在前。
  • 有權重（不為負）用 Dijkstra＋優先佇列，O(E log V)；只問「是不是同一群」、邊一條條加進來時用 union-find（互斥集合），按大小合併（小的掛到大的底下）加路徑減半。

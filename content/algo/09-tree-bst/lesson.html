倒過來長的樹，先學名詞

樹的名詞：根、葉、深度、高度

公司的組織圖就是一棵樹（正式名稱是樹 tree）：最上面是總經理，下面是各部門主管，主管下面是組員。每個人只有一個直屬上司，但可以帶好幾個人。資料夾也一樣：一個資料夾可以放很多子資料夾，但每個子資料夾只在一個地方。

跟〈鏈結串列〉一樣，樹由節點（node）組成，節點之間用參考連起來；差別是鏈結串列每個節點只指向下一個，樹的節點可以指向好幾個孩子。每個節點最多兩個孩子的樹叫二元樹（binary tree），兩個孩子分成左、右。普林斯頓的課本這樣遞迴地定義它：「二元樹要嘛是空的（null），要嘛是一個節點，連到兩棵互不相交的二元樹」（A binary tree is defined recursively: it is either empty (null) or a node containing links to two disjoint binary trees.）。出處 這個定義本身就是遞迴，所以樹的題目大多用遞迴解。

名詞白話上圖的例子
根（root）最上面那個，沒有父節點5
父節點、孩子直接連著的上下兩個：上面是父、下面是孩子11 的父節點是 4，孩子是 7 和 2
葉（leaf）沒有孩子的節點7、2、13、右下的 4
子樹（subtree）某個節點連同它底下全部以 4 為根的左子樹：4、11、7、2
深度（depth）從根走到這個節點要經過幾條邊根 0；8 是 1；7 是 3
高度（height）從這個節點往下，走到最深的節點要幾條邊；整棵樹的高度就是根的高度整棵樹 3；11 是 1；葉子是 0

這組定義照 MIT 6.006 講義：根「沒有父節點」（The root of a tree has no parent）、葉「沒有孩子」（A leaf of a tree has no children）、深度是「從這個節點到根的路徑長度」、高度是「以它為根的子樹裡，任何節點的最大深度」（max depth of any node in the subtree rooted at <X>）。出處 路徑長度數的是邊，所以只有一個根的樹高度是 0，algs4 的 BST.java 也這樣寫（a 1-node tree has height 0）。出處

數節點還是數邊，各處不一樣。普林斯頓 introcs 也數邊：樹的高度是「從根到葉子的任何一條路徑上，最多有幾個連結」（The height of a tree is the maximum number of links on any path from the root node to a leaf node.）。出處 LeetCode 的「最大深度」題（104 題）數的則是最長那條路徑上的節點數，所以上圖的答案是 4。寫題目前先看清楚它數的是什麼，面試時講清楚自己用哪一種。

Java 沒有內建的「樹節點」類別，題目通常給你這樣一個類別：

下面哪一個不是二元樹？

  • 只有一個根節點的樹
  • 每個節點都只有右孩子、排成一直線的樹
  • 有一個節點下面掛了三個孩子的樹
  • 空樹（null）

二元樹每個節點最多兩個孩子；有三個孩子就不是。只有根、排成一直線、空樹都符合「最多兩個」的定義。

用上面的 TreeNode，怎麼判斷 node 是葉子？

  • node == null
  • node.val == 0 && node.left == null，值是 0 而且沒有左孩子
  • node.left == null || node.right == null
  • node.left == null && node.right == null

葉子是左右兩個孩子「都」沒有。用 || 會把只有一個孩子的節點也當成葉子；node == null 是空樹，不是葉子。

每個節點都拜訪一次，差在什麼時候處理自己

四種走訪：前序、中序、後序、層序

走訪（traversal）就是把每個節點都看一次。鏈結串列只有一條路，跟著 next 走就好；樹每個節點有兩條路，要決定先走哪邊、什麼時候處理自己。普林斯頓課本說：「遞迴馬上就能派上用場」（Recursion comes immediately to the rescue.），先處理左子樹、再處理根、再處理右子樹，這叫中序走訪。出處 同樣三步，把「處理自己」挪到最前面就是前序，挪到最後面就是後序：

走訪順序口訣常用在
前序 preorder自己 → 左 → 右先處理自己，再交給孩子複製一棵樹、把樹存成文字
中序 inorder左 → 自己 → 右自己夾在左右中間二元搜尋樹由小到大列出
後序 postorder左 → 右 → 自己孩子都做完才輪到自己算子樹的大小、高度，刪除整棵樹
層序 level order一層一層、由左到右離根近的先處理按層列印、找最短的層數

這跟〈遞迴與回溯〉的 down 與 up 是同一件事：印的位置在遞迴呼叫之前或之後，決定了順序。下面四張圖用同一棵樹，圓圈旁的數字是第幾個被處理：

層序走訪不用遞迴，用佇列。〈堆疊與佇列〉說過，佇列是先進先出：把根放進去，每拿出一個，就把它的左右孩子排到後面。先進來的是上一層，所以會一層一層處理。algs4 的 BST.java 就是這樣寫 levelOrder()：拿出一個節點、記下它的鍵，再把左右孩子放進佇列。出處 要把每一層分開，就在每一層開始時先記下佇列裡有幾個（size），只拿這麼多個；迴圈裡放進去的是下一層的。

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.List;
import java.util.Queue;

public class Traversals {
    static class TreeNode {                 // 一個節點：自己的值，加上左右兩個孩子
        int val;
        TreeNode left, right;
        TreeNode(int val) { this.val = val; }
        TreeNode(int val, TreeNode left, TreeNode right) {
            this.val = val; this.left = left; this.right = right;
        }
    }

    // 前序：自己 → 左 → 右
    static void preorder(TreeNode node, List<Integer> out) {
        if (node == null) return;           // 終止條件：空的子樹什麼都不做
        out.add(node.val);
        preorder(node.left, out);
        preorder(node.right, out);
    }

    // 中序：左 → 自己 → 右
    static void inorder(TreeNode node, List<Integer> out) {
        if (node == null) return;
        inorder(node.left, out);
        out.add(node.val);
        inorder(node.right, out);
    }

    // 後序：左 → 右 → 自己
    static void postorder(TreeNode node, List<Integer> out) {
        if (node == null) return;
        postorder(node.left, out);
        postorder(node.right, out);
        out.add(node.val);
    }

    // 層序：用佇列，一層一層由左到右
    static List<List<Integer>> levelOrder(TreeNode root) {
        List<List<Integer>> levels = new ArrayList<>();
        if (root == null) return levels;
        Queue<TreeNode> queue = new ArrayDeque<>();
        queue.offer(root);
        while (!queue.isEmpty()) {
            int size = queue.size();        // 這一層有幾個：先記下來，迴圈中佇列會變長
            List<Integer> level = new ArrayList<>();
            for (int i = 0; i < size; i++) {
                TreeNode node = queue.poll();
                level.add(node.val);
                if (node.left != null) queue.offer(node.left);    // 下一層排到後面
                if (node.right != null) queue.offer(node.right);
            }
            levels.add(level);
        }
        return levels;
    }

    public static void main(String[] args) {
        //         50
        //       /    \
        //     30      70
        //    /  \    /  \
        //  20   40  60   80
        TreeNode root = new TreeNode(50,
                new TreeNode(30, new TreeNode(20), new TreeNode(40)),
                new TreeNode(70, new TreeNode(60), new TreeNode(80)));

        List<Integer> pre = new ArrayList<>(), in = new ArrayList<>(), post = new ArrayList<>();
        preorder(root, pre);
        inorder(root, in);
        postorder(root, post);
        System.out.println("前序 " + pre);
        System.out.println("中序 " + in);
        System.out.println("後序 " + post);
        System.out.println("層序 " + levelOrder(root));
    }
}

執行結果（Java 21）：

前序 [50, 30, 20, 40, 70, 60, 80]
中序 [20, 30, 40, 50, 60, 70, 80]
後序 [20, 40, 30, 60, 80, 70, 50]
層序 [[50], [30, 70], [20, 40, 60, 80]]

複雜度：四種都是每個節點處理一次，時間 O(n)。MIT 講義說中序走訪「O(n) 時間，因為列出每個節點只做 O(1) 的工作」（Runs in O(n) time, since O(1) work is done to list each node）。出處 空間：遞迴版看呼叫堆疊最深幾層，就是樹的高度 h，O(h)；樹排成一直線時 h = n − 1，就變 O(n)。層序版看佇列最多同時放幾個，最寬的一層可能有大約 n/2 個，O(n)。

前序自己先、中序自己中間、後序自己最後；層序用佇列，一層一層

下面的練習，用這棵樹（跟上面的不一樣）：

        A
       / \
      B   C
     / \   \
    D   E   F

上面這棵 A〜F 的樹，前序走訪的順序是？

  • A B D E C F
  • D B E A C F
  • D E B F C A
  • A B C D E F

前序是自己 → 左 → 右：A，然後整個左子樹 B D E，再右子樹 C F。D B E A C F 是中序、D E B F C A 是後序、A B C D E F 是層序。

同一棵樹，中序走訪的順序是？

  • A B D E C F
  • D B E A C F
  • D E B F C A
  • B D E A C F

左 → 自己 → 右：先把 A 的左子樹做完（D B E），再 A，再右子樹。C 沒有左孩子，所以 C 先、F 後。

同一棵樹，後序走訪的順序是？

  • D E B F C A
  • D B E F C A
  • F C E D B A
  • A C F B E D

左 → 右 → 自己：B 的子樹是 D E B，C 的子樹是 F C，最後才是 A。F C E D B A 是把前序整個倒過來，不是後序。

同一棵樹，層序走訪的順序是？

  • A B D E C F
  • A C B F E D
  • D E F B C A
  • A B C D E F

一層一層由左到右：第 0 層 A，第 1 層 B C，第 2 層 D E F。

哪一種走訪，根一定是第一個？

  • 前序與層序
  • 只有中序
  • 只有後序
  • 四種都是

前序先處理自己，層序從根那一層開始，所以根都排第一。中序的根在中間，後序的根在最後。

哪一種走訪，根一定是最後一個？

  • 前序
  • 中序
  • 後序
  • 層序

後序是孩子都處理完才輪到自己，根要等整棵樹都做完。

要算每個節點底下有幾個節點（子樹大小），最自然的是哪一種走訪？

  • 前序，因為根先處理
  • 後序，因為要先知道左右子樹各有幾個，才能算自己
  • 層序，因為一層一層數下去，每一層的節點數加起來就是答案
  • 中序，因為它會排序

自己的大小 = 左子樹大小 + 右子樹大小 + 1，要等左右都算完才能算自己，正好是後序的順序。

把前序走訪程式裡 out.add(node.val) 移到兩個遞迴呼叫的中間，它就變成哪一種走訪？

  • 還是前序
  • 後序
  • 層序
  • 中序

三種遞迴走訪的程式只差「處理自己」那一行放在哪裡：最前面是前序、中間是中序、最後是後序。層序要改用佇列，不是挪一行就好。

層序走訪的程式，為什麼要在每一層開始前先寫 int size = queue.size();？

  • 因為 queue.size() 很慢，存起來比較快
  • 因為迴圈裡會把下一層的孩子放進佇列，佇列會變長；先記下來才知道這一層只有幾個
  • 因為 ArrayDeque 在迴圈裡呼叫 size() 會丟出 ConcurrentModificationException，所以一定要先存起來
  • 不寫也一樣，只是習慣

不先記下來，迴圈條件每次讀到的 size 都包含剛放進去的下一層，兩層就混在一起了。只要整串順序、不分層時，才可以不記。

遞迴的中序走訪，在一棵 n 個節點、高度 h 的樹上，時間與額外空間各是多少？

  • 時間 O(h)、空間 O(1)
  • 時間 O(n)、空間 O(1)
  • 時間 O(n)、空間 O(h)
  • 時間 O(n log n)、空間 O(n)

每個節點處理一次是 O(n)；呼叫堆疊最深是從根到最深的葉子，h 層，空間 O(h)。平衡時 h 約 log n，排成一直線時 h 約 n。

一棵每層都塞滿的樹有 7 個節點（像本段的 50 那棵）。層序走訪時，佇列裡最多同時有幾個節點？

  • 1
  • 2
  • 4
  • 7

處理完 70 之後，佇列裡是最下層的 20、40、60、80，共 4 個。滿的樹最下層約占一半，所以層序走訪的空間是 O(n)。

層序走訪用的是哪一種資料結構，為什麼？

  • 堆疊，因為後放進去的孩子要先處理，這樣才能由上往下一層一層走
  • 佇列，因為先放進去的上一層要先處理
  • HashMap，用層數當鍵
  • 排序好的陣列

上一層的節點先進佇列，也先出來，它們的孩子排在後面，所以一層一層處理。用堆疊會變成先往深處走，接近前序。

只有一個節點的樹，四種走訪的結果是？

  • 只有層序有結果，其他三種是空的
  • 前序和後序有結果，中序是空的
  • 會丟出 NullPointerException
  • 四種都只有那一個節點

左右子樹都是 null，遞迴碰到 null 直接回傳；只剩處理自己那一步，所以四種都是同一個節點。

某棵樹的中序走訪結果是 1 3 5 7 9，而且它是二元搜尋樹。把每個節點的值都加 10，中序走訪的結果是？

  • 11 13 15 17 19
  • 19 17 15 13 11
  • 順序會亂掉，要重算
  • 1 3 5 7 9

每個值都加同一個數，大小關係不變，樹的形狀也沒變，走訪順序一樣，只是值變了。

交給左右子樹，再合併

遞迴解樹題的套路

大部分樹的題目都可以照同一個套路想，跟〈遞迴與回溯〉的兩個要素一樣：

  • 空樹（null）的答案是什麼？這是終止條件。最大深度是 0、節點數是 0、「有沒有某條路」是 false。
  • 假設左右子樹的答案已經算好了，自己的答案怎麼合併？最大深度是 1 + 兩邊較大的；節點數是左 + 右 + 1。

不要在腦中展開每一層，只要相信遞迴會把子樹的答案算對。三個常見題目：

  • 最大深度（數節點，跟 LeetCode 一樣）：空樹 0；否則 1 + max(左, 右)。
  • 對稱：左右兩邊像照鏡子。比的不是「左對左」，而是「左邊的左孩子」對「右邊的右孩子」、「左邊的右孩子」對「右邊的左孩子」，所以要寫一個同時拿兩個節點的輔助方法。
  • 路徑和：從根走到葉子，路上的值加起來等不等於目標。每往下一層就把目標減掉自己的值交給孩子；到了葉子才檢查剩下的是不是剛好等於葉子的值。
public class TreeRecursion {
    static class TreeNode {
        int val;
        TreeNode left, right;
        TreeNode(int val) { this.val = val; }
        TreeNode(int val, TreeNode left, TreeNode right) {
            this.val = val; this.left = left; this.right = right;
        }
    }

    // 套路：空樹的答案是什麼？左右子樹各自的答案拿到之後，怎麼合成自己的答案？

    // 最大深度（數節點）：空樹 0；否則 1 + 左右較深的那邊
    static int maxDepth(TreeNode node) {
        if (node == null) return 0;
        return 1 + Math.max(maxDepth(node.left), maxDepth(node.right));
    }

    // 對稱：左右兩邊像照鏡子。比的是「左的左」對「右的右」、「左的右」對「右的左」
    static boolean isSymmetric(TreeNode root) {
        return root == null || mirror(root.left, root.right);
    }
    static boolean mirror(TreeNode a, TreeNode b) {
        if (a == null && b == null) return true;
        if (a == null || b == null) return false;
        return a.val == b.val && mirror(a.left, b.right) && mirror(a.right, b.left);
    }

    // 路徑和：從根走到某個葉子，路上的值加起來剛好等於 target 嗎
    static boolean hasPathSum(TreeNode node, int target) {
        if (node == null) return false;
        if (node.left == null && node.right == null) return node.val == target;   // 葉子
        int rest = target - node.val;                                            // 剩下的交給孩子
        return hasPathSum(node.left, rest) || hasPathSum(node.right, rest);
    }

    public static void main(String[] args) {

        //       / \
        //      4   8
        //     /   / \

        //   /  \
        //  7    2

                new TreeNode(4, new TreeNode(11, new TreeNode(7), new TreeNode(2)), null),
                new TreeNode(8, new TreeNode(13), new TreeNode(4)));
        System.out.println("最大深度 " + maxDepth(t));
        System.out.println("路徑和 22：" + hasPathSum(t, 22) + "，路徑和 26：" + hasPathSum(t, 26)
                + "，路徑和 9：" + hasPathSum(t, 9));

        //     / \
        //    2   2
        //   / \ / \

                new TreeNode(2, new TreeNode(3), new TreeNode(4)),

                new TreeNode(2, null, new TreeNode(3)));

二元搜尋樹：搜尋與插入

圖書館的書照編號排，找書時先看中間那排，編號比較小就往左邊走、比較大就往右邊走。二元搜尋樹（binary search tree，簡稱 BST）就是把這個規則放在每一個節點上。algs4 的定義：「每個節點有一個可比較的鍵，而且這個節點的鍵比它左子樹所有節點的鍵都大，比它右子樹所有節點的鍵都小」（the key in any node is larger than the keys in all nodes in that node's left subtree and smaller than the keys in all nodes in that node's right subtree）。出處 注意是「左子樹所有節點」，不只是左孩子，驗證 BST 時這點會出事。

搜尋：從根開始，要找的比目前的小就往左、大就往右，相等就找到了，走到 null 就是沒有。每往下一層就丟掉另一邊整棵子樹，跟〈複雜度：程式跑多快、吃多少記憶體〉的二分搜尋同一個道理。插入：跟搜尋走同一條路，走到 null 的那個位置就是新節點要掛的地方；新節點一定是葉子。

中序走訪會得到排好序的結果。中序是先左再自己再右，左子樹都比自己小、右子樹都比自己大，所以印出來由小到大。普林斯頓課本說中序走訪「依鍵的大小順序處理 BST 的節點」（processes the nodes in a BST in key-sorted order）。出處 反過來說，中序走訪結果沒有由小到大，它就不是 BST。最小的鍵是一直往左走到底的那個，最大的是一直往右走到底的那個。

複雜度看樹的高度。algs4：搜尋、插入、找最小最大、刪除等操作「在最壞情況下，所花的時間都跟樹的高度成正比」（all take time proportional to the height of the tree, in the worst case）。出處 高度又看插入的順序：

  • 平衡：每層都差不多塞滿，高度約 log n，搜尋 O(log n)。algs4 證明，鍵用隨機順序插入時，搜尋平均約比較 2 ln N 次（about 1.39 lg N）。出處
  • 退化成鏈：普林斯頓課本寫，最壞情況下「BST 基本上就是一條多浪費了一個參考的鏈結串列，插入與查詢都要線性時間」（the BST is essentially a linked list with an extra wasted link, where put operations and get requests take linear time.），而且「這個最壞情況實務上並不少見，例如依序插入鍵時就會發生」（it arises, for example, when we insert the keys in order）。出處
import java.util.ArrayList;
import java.util.List;
import java.util.Random;

public class Bst {
    static class Node {
        int key;
        Node left, right;
        Node(int key) { this.key = key; }
    }

    Node root;
    int compares;                                   // 數比較了幾次

    // 搜尋：比自己小往左、比自己大往右，走到 null 就是沒有
    boolean contains(int key) {
        Node x = root;
        while (x != null) {
            compares++;
            if (key == x.key) return true;
            x = key < x.key ? x.left : x.right;
        }
        return false;
    }

    // 插入：跟搜尋走同一條路，走到 null 的地方掛上新節點
    void insert(int key) {
        if (root == null) { root = new Node(key); return; }
        Node x = root;
        while (true) {
            if (key == x.key) return;               // 已經有了：這裡選擇不重複放
            if (key < x.key) {
                if (x.left == null) { x.left = new Node(key); return; }
                x = x.left;
            } else {
                if (x.right == null) { x.right = new Node(key); return; }
                x = x.right;
            }
        }
    }

    // 刪除：回傳刪完之後這棵子樹的根
    static Node delete(Node x, int key) {
        if (x == null) return null;
        if (key < x.key) x.left = delete(x.left, key);
        else if (key > x.key) x.right = delete(x.right, key);
        else {
            if (x.left == null) return x.right;     // 沒有左孩子：右孩子頂上來（葉子時是 null）
            if (x.right == null) return x.left;     // 沒有右孩子：左孩子頂上來
            Node next = x.right;                    // 兩個孩子都有：找右子樹裡最小的（後繼者）
            while (next.left != null) next = next.left;
            x.key = next.key;                       // 把後繼者的值搬上來
            x.right = delete(x.right, next.key);    // 再把後繼者從右子樹刪掉
        }
        return x;
    }

    static void inorder(Node x, List<Integer> out) {
        if (x == null) return;
        inorder(x.left, out);
        out.add(x.key);
        inorder(x.right, out);
    }

    // 高度：數邊；空樹 -1、只有根的樹 0
    static int height(Node x) {
        if (x == null) return -1;
        return 1 + Math.max(height(x.left), height(x.right));
    }

    public static void main(String[] args) {
        Bst t = new Bst();
        for (int k : new int[]{50, 30, 70, 20, 40, 60, 80, 65}) t.insert(k);
        List<Integer> keys = new ArrayList<>();
        inorder(t.root, keys);
        System.out.println("中序 " + keys + "，高度 " + height(t.root));

        t.compares = 0;
        System.out.println("找 65：" + t.contains(65) + "，比較 " + t.compares + " 次");
        t.compares = 0;
        System.out.println("找 35：" + t.contains(35) + "，比較 " + t.compares + " 次");

        t.root = delete(t.root, 20);                // 葉子
        t.root = delete(t.root, 60);                // 只有一個孩子（65）
        t.root = delete(t.root, 50);                // 兩個孩子：根換成後繼者
        keys.clear();
        inorder(t.root, keys);
        System.out.println("刪掉 20、60、50 之後：中序 " + keys + "，根是 " + t.root.key);

        // 同樣 1023 個鍵，插入順序不同，樹的高度差很多
        int n = 1023;
        Bst sorted = new Bst();
        for (int k = 1; k <= n; k++) sorted.insert(k);           // 由小到大插入
        List<Integer> shuffled = new ArrayList<>();
        for (int k = 1; k <= n; k++) shuffled.add(k);
        java.util.Collections.shuffle(shuffled, new Random(7));  // 固定種子：每次結果一樣
        Bst random = new Bst();
        for (int k : shuffled) random.insert(k);
        sorted.compares = 0;
        random.compares = 0;
        for (int k = 1; k <= n; k++) { sorted.contains(k); random.contains(k); }   // 每個鍵都找一次
        System.out.printf("依序插入：高度 %d，平均每次找要比較 %.1f 次%n", height(sorted.root), (double) sorted.compares / n);
        System.out.printf("打亂插入：高度 %d，平均每次找要比較 %.1f 次%n", height(random.root), (double) random.compares / n);
    }
}

BST 裡最小的鍵在哪裡？

  • 一定是根
  • 一定是最下面那一層、最靠左邊的那個葉子，所以要先找到最深的一層
  • 從根一直往左走，走到沒有左孩子的那個節點
  • 要走訪整棵樹才知道

比自己小的都在左邊，一直往左走到底就是最小的。那個節點可能還有右孩子，不一定是葉子。時間是 O(h)，不用走訪整棵樹。

一棵 BST 有 n 個節點，搜尋最壞要多少時間？

  • 一律 O(1)，跟雜湊表一樣
  • 一律 O(log n)，因為每往下一層就丟掉另一邊，跟二分搜尋一樣
  • 一律 O(n log n)

  • 插入會丟出例外，因為 BST 不接受由小到大依序插入的鍵
  • 樹的高度會是 log n
  • 每個新鍵都掛在最右邊，樹變成一條鏈，之後搜尋是 O(n)

普通的 BST 不會自己平衡，依序插入正是課本說的最壞情況。實務上直接用會自己平衡的 TreeMap。

  • 位置隨機

插入就是搜尋到 null 的那一格掛上去，所以一定是葉子，原本的節點都不用動。

拿掉一個節點，順序不能亂

二元搜尋樹：刪除

刪除分三種情況，難的是第三種：

  • 葉子：直接拿掉，父節點那一邊改成 null。
  • 只有一個孩子：讓那個孩子頂上來，接到自己的位置。
  • 兩個孩子都有：父節點只有一個位置可以接，放不下兩個孩子。algs4 介紹的做法是 T. Hibbard 在 1962 年提出的：「用它的後繼者取代它」（delete a node x by replacing it with its successor）。後繼者是「右子樹裡最小的那個」（its successor is the node with the smallest key in its right subtree），中序順序裡緊接在它後面的鍵。這樣換「不會破壞樹的順序，因為 x 和後繼者之間沒有別的鍵」（The replacement preserves order in the tree because there are no keys between x.key and the successor's key.）。出處

上面 Bst.delete 照這三種情況寫，程式裡先刪葉子 20、再刪只有一個孩子的 60、最後刪有兩個孩子的根 50，中序結果一直保持由小到大。刪除的時間一樣是 O(h)：往下找到它，再往下找後繼者。

algs4 也提醒，一直用這個方法刪除再隨機插入，樹會慢慢往一邊歪（The BST becomes skewed toward the left.）。出處 這又是需要平衡樹的理由之一。

在 BST 裡刪除一個葉子，要怎麼做？

  • 把父節點指向它的那一邊改成 null 就好
  • 要找後繼者來取代它
  • 要把整棵樹重新建一次，才能確保其他節點的順序還是對的
  • 要把它的兄弟節點也一起刪掉

葉子沒有孩子，拿掉不會影響別人。後繼者只有在兩個孩子都有時才需要。

在 8、3、10、1、6、14 依序插入的 BST 裡刪除 10（它只有右孩子 14），刪完之後 14 的父節點是誰？

  • 3
  • 6
  • 8
  • 14 變成根

只有一個孩子時，讓孩子頂到自己的位置：14 接到 8 的右邊。

在同一棵樹（8、3、10、1、6、14）刪除根 8，照 Hibbard 的方法，新的根是誰？

  • 6，左子樹最大的
  • 10，右子樹最小的
  • 14，最大的
  • 3，根的左孩子直接頂上來，右子樹接到它下面

後繼者是右子樹裡最小的：右子樹是 10、14，最小的是 10。用左子樹最大的 6（前驅者）也可以保持順序，但這課照 algs4 用後繼者。

為什麼後繼者（右子樹裡最小的）一定沒有左孩子？

  • 因為後繼者一定是葉子
  • 因為右子樹不會有左孩子
  • 因為如果它有左孩子，那個左孩子比它更小，它就不是右子樹裡最小的
  • 因為後繼者一定在右子樹的最下面一層，下面已經沒有位置可以放孩子

找最小的方法是一直往左走到底，停下來的那個就是沒有左孩子的。它可能還有右孩子，所以不一定是葉子，但刪它最多只是「一個孩子」的情況。

會自己保持平衡的樹

平衡樹與 Java 的 TreeMap

普通的 BST 遇到依序插入就退化。平衡樹在插入、刪除時會自己調整形狀，讓高度一直維持在 O(log n)。MIT 講義的說法：「在動態操作下維持 O(log n) 高度的二元樹，叫做平衡的」（A binary tree that maintains O(log n) height under dynamic operations is called balanced）。出處 常見的有 AVL 樹與紅黑樹（red-black tree）。algs4 寫紅黑樹「高度不超過 2 lg N」，搜尋、插入、刪除等操作「在最壞情況下都是對數時間」（take logarithmic time in the worst case）。出處 它怎麼旋轉、怎麼著色，面試很少要求手寫，知道「它保證 O(log n)」以及 Java 哪裡用到它就夠了。

Java 的 TreeMap 就是紅黑樹。API 文件第一句：「以紅黑樹為基礎的 NavigableMap 實作」（A Red-Black tree based NavigableMap implementation.），並保證 containsKey、get、put、remove「有 log(n) 的時間成本保證」（This implementation provides guaranteed log(n) time cost for the containsKey, get, put and remove operations.）。出處 TreeSet 的 add、remove、contains 也是同樣的保證。出處 〈雜湊表：HashMap 怎麼做到幾乎一步找到〉講的 HashMap 樹化，桶裡換上的也是紅黑樹，最壞從 O(n) 改善到 O(log n)（鍵可以比大小時），就是這裡說的平衡效果。

因為是 BST，TreeMap 走訪時就是中序，鍵由小到大；「小於等於 x 的最大鍵」這類查詢（floorKey、ceilingKey）在〈雜湊表：HashMap 怎麼做到幾乎一步找到〉已經示範過。

import java.util.TreeMap;

public class TreeMapDemo {
    public static void main(String[] args) {
        TreeMap<String, Integer> balance = new TreeMap<>();   // 鍵會照字串順序排好
        balance.put("C003", 900);
        balance.put("A001", 1200);
        balance.put("B002", 500);
        System.out.println(balance);                           // 走訪就是中序：鍵由小到大
        System.out.println(balance.firstKey() + " " + balance.lastKey());
        System.out.println(balance.headMap("C003"));           // 比 C003 小的那些
    }
}

底下是什麼雜湊表紅黑樹（會自己平衡的 BST）
get、put平均 O(1)保證 O(log n)
走訪順序不保證鍵由小到大
適合只要查有沒有、查值要排序、找最接近的鍵、範圍查詢

Java 的 TreeMap 底下是什麼？

  • 紅黑樹，一種會自己保持平衡的二元搜尋樹
  • 排好序的陣列
  • 雜湊表
  • 普通的二元搜尋樹，不會自己平衡，所以依序 put 時要小心退化

API 文件第一句就是 A Red-Black tree based NavigableMap implementation。因為會自己平衡，依序 put 也不會退化。

把 1 到 1,000,000 依序 put 進 TreeMap，之後一次 get 要多久？

  • O(n)，因為依序插入會讓樹往右邊一直長，退化成一條鏈
  • O(log n)，紅黑樹會自己平衡，API 文件保證 log(n)
  • O(1)
  • O(n log n)

依序插入會讓「普通」BST 退化，但 TreeMap 會在插入時調整形狀，get 有 log(n) 的保證。

用 for 走訪一個 TreeMap<Integer, String> 的 keySet()，鍵的順序是？

  • 放進去的順序
  • 不保證任何順序
  • 由大到小
  • 由小到大

TreeMap 依鍵的自然順序（或給的 Comparator）排序，走訪就像 BST 的中序。保留放入順序的是 LinkedHashMap。

只需要用帳號查餘額，不需要排序。HashMap 跟 TreeMap 該選哪個？

  • HashMap，平均 O(1)，比 TreeMap 的 O(log n) 快
  • TreeMap，因為「保證」的 O(log n) 一定比只是「平均」的 O(1) 更快更穩
  • 兩個一樣快
  • 都不行，要用 ArrayList

不需要順序時，雜湊表的平均 O(1) 比較快；需要排序或找最接近的鍵時才用 TreeMap。

兩個面試常見題

驗證 BST 與最低共同祖先

驗證一棵樹是不是 BST。常見的錯是只比自己和孩子：每個節點的左孩子比自己小、右孩子比自己大，看起來都對，整棵樹卻可能不是 BST，因為定義要求的是「左子樹所有節點」。正確做法是一路往下傳「允許的範圍」：往左走時，上限變成自己；往右走時，下限變成自己。algs4 的 BST.java 檢查方法 isBST(node, min, max) 就是這樣寫，註解說它檢查「以 x 為根的樹，所有鍵都嚴格介於 min 與 max 之間」（is the tree rooted at x a BST with all keys strictly between min and max）。出處 另一個做法是做一次中序走訪，檢查有沒有每個都比前一個大。

最低共同祖先（lowest common ancestor，簡稱 LCA）：兩個節點往上追，最先碰到的共同長輩。在 BST 裡可以用大小關係直接找：兩個都比目前的小，答案在左邊；兩個都比目前的大，答案在右邊；一個小一個大（或其中一個就是目前這個），目前這個就是分岔點，也就是答案。時間 O(h)。一般二元樹（不是 BST）沒有大小可用，要改用後序的想法：左右子樹各自回報有沒有找到，兩邊都找到的那個節點就是答案；或自己就是 p、q 其中一個（另一個在它底下），答案也是自己，例如下面程式裡的 LCA(30, 20) = 30。

public class ValidateLca {
    static class TreeNode {
        int val;
        TreeNode left, right;
        TreeNode(int val) { this.val = val; }
        TreeNode(int val, TreeNode left, TreeNode right) {
            this.val = val; this.left = left; this.right = right;
        }
    }

    // 錯誤寫法：只跟自己的孩子比
    static boolean naive(TreeNode node) {
        if (node == null) return true;
        if (node.left != null && node.left.val >= node.val) return false;
        if (node.right != null && node.right.val <= node.val) return false;
        return naive(node.left) && naive(node.right);
    }

    // 正確寫法：一路帶著「允許的範圍」往下傳。用 long 當邊界，int 的最大最小值也能放進樹裡
    static boolean isValid(TreeNode node, long low, long high) {
        if (node == null) return true;
        if (node.val <= low || node.val >= high) return false;
        return isValid(node.left, low, node.val)       // 左邊：上限變成自己
            && isValid(node.right, node.val, high);    // 右邊：下限變成自己
    }

    // 最低共同祖先（BST 版）：兩個都比自己小就往左，都比自己大就往右，否則就是自己
    static TreeNode lca(TreeNode root, int p, int q) {
        TreeNode x = root;
        while (x != null) {
            if (p < x.val && q < x.val) x = x.left;
            else if (p > x.val && q > x.val) x = x.right;
            else return x;                             // 分岔點（或其中一個就是自己）
        }
        return null;
    }

    public static void main(String[] args) {
        //      50
        //     /  \
        //   30    70
        //  /  \
        // 20   60   ← 60 比 30 大，放 30 的右邊看似合理，但它在 50 的左子樹裡，必須小於 50
        TreeNode bad = new TreeNode(50,
                new TreeNode(30, new TreeNode(20), new TreeNode(60)),
                new TreeNode(70));
        System.out.println("只比孩子：" + naive(bad) + "；帶範圍：" + isValid(bad, Long.MIN_VALUE, Long.MAX_VALUE));

        TreeNode good = new TreeNode(50,
                new TreeNode(30, new TreeNode(20), new TreeNode(40)),
                new TreeNode(70, new TreeNode(60), new TreeNode(80)));
        System.out.println("合法的 BST：" + isValid(good, Long.MIN_VALUE, Long.MAX_VALUE));
        System.out.println("LCA(20, 40) = " + lca(good, 20, 40).val);
        System.out.println("LCA(20, 60) = " + lca(good, 20, 60).val);
        System.out.println("LCA(30, 20) = " + lca(good, 30, 20).val);
    }
}

執行結果：

只比孩子：true；帶範圍：false
合法的 BST：true
LCA(20, 40) = 30
LCA(20, 60) = 50
LCA(30, 20) = 30

第一行：60 是 30 的右孩子，比 30 大，只比孩子會說它對；但 60 在 50 的左子樹裡，必須小於 50，帶範圍的檢查走到 60 時上限是 50，判定不合法。邊界用 long，樹裡出現 Integer.MAX_VALUE 也比得出來；〈陣列與字串〉講過 int 的邊界問題。

這棵樹：根 10，左孩子 5、右孩子 15；15 的左孩子是 6。它是 BST 嗎？

  • 是，因為每個節點的左孩子都比自己小
  • 不是，6 在 10 的右子樹裡，必須大於 10
  • 是，因為中序走訪是 5 10 6 15
  • 不是，因為 15 只有左孩子，BST 每個節點都要有兩個孩子

6 比 15 小，只看它和 15 的關係是對的，但它在根 10 的右子樹，必須比 10 大。中序走訪 5 10 6 15 沒有由小到大，也證明它不是。

帶範圍驗證時，從節點 50 往左走，範圍怎麼變？

  • 下限變成 50
  • 範圍不變
  • 上下限都變成 50，因為往下走就要以目前的節點為準
  • 上限變成 50，下限不變

左子樹全部要比 50 小，所以上限換成 50；下限沿用從上面傳下來的。往右走則是下限換成 50。

用中序走訪驗證 BST，要檢查什麼？

  • 第一個是不是最小的
  • 最後一個是不是根
  • 每一個都比前一個大
  • 長度是不是奇數

BST 的中序結果一定嚴格遞增（本課不放重複鍵），只要有一個不比前一個大就不是。

在 50、30、70、20、40、60、80 這棵 BST 裡，20 和 40 的最低共同祖先是？

  • 50
  • 30
  • 20
  • 40

從 50 開始：20、40 都比 50 小，往左到 30；20 < 30 < 40，在這裡分岔，答案 30。

同一棵樹，20 和 60 的最低共同祖先是？

  • 30
  • 70
  • 50
  • 沒有共同祖先

20 比 50 小、60 比 50 大，在根就分岔了，答案 50。

同一棵樹，30 和 20 的最低共同祖先是？

  • 50
  • 20
  • 沒有，因為 30 是 20 的父節點
  • 30

一個節點也算是自己的祖先。走到 30 時，其中一個就是自己，停在這裡，答案 30。

BST 版的 LCA 寫法，時間複雜度是？

  • O(n)，要走訪整棵樹
  • O(h)，每一步只往一邊走
  • O(1)
  • O(n log n)，每一層都要排序一次

它跟搜尋一樣從根往下、每步選一邊，最多走樹的高度那麼多步。一般二元樹的 LCA 沒有大小可用，才需要 O(n) 走訪。

重點整理

  • 名詞：根沒有父節點、葉沒有孩子；深度是從根往下幾條邊，高度是往下到最深的節點幾條邊（只有根的樹高度 0）；n 個節點有 n − 1 條邊。LeetCode 的最大深度數節點。
  • 走訪：前序自己 → 左 → 右、中序左 → 自己 → 右、後序左 → 右 → 自己，三種用遞迴、只差處理自己那行的位置；層序用佇列，每層先記 size。時間都是 O(n)，遞迴空間 O(h)。
  • 遞迴套路：先想空樹回傳什麼，再想左右子樹的答案怎麼合成自己的；對稱比外側對外側、內側對內側；路徑和到葉子才檢查。
  • BST：左子樹全部比我小、右子樹全部比我大；中序走訪由小到大。搜尋與插入沿一條路往下，新節點一定是葉子；操作時間 O(h)：平衡約 O(log n)，依序插入會退化成鏈 O(n)。
  • 刪除：葉子直接拿掉、一個孩子就讓孩子頂上、兩個孩子用後繼者（右子樹最小的）取代。
  • TreeMap 是紅黑樹，get、put、remove 保證 O(log n)，走訪時鍵由小到大；不需要順序時 HashMap 平均 O(1) 比較快。
  • 驗證 BST 要帶範圍往下傳（或檢查中序是否遞增），只比孩子會漏；BST 的 LCA 看兩個鍵是不是在同一邊，O(h)。

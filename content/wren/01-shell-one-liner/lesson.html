先拆開，再合起來

一長串指令其實是幾個小動作

shell 是終端機裡負責讀指令、執行指令的那支程式，macOS 預設的是 zsh。安裝教學常常給一整行，照貼就能跑，但看不懂就沒辦法在出錯時知道錯在哪。讀的方法是先找 &&，從那裡切開，每一段各看各的。

cd ~/proj/wren-lab && python3 -m venv .venv && ls .venv/bin/ && git status --short
段落做什麼屬於哪一類
cd ~/proj/wren-lab進到專案資料夾準備
python3 -m venv .venv在這個資料夾建一個 Python 虛擬環境做事
ls .venv/bin/列出虛擬環境裡的執行檔驗收
git status --short確認 Git 沒把新資料夾當成要追蹤的檔案驗收

好的一行通常長這樣：前面做事，後面馬上驗收。做完一件事就確認結果，出錯時才知道是哪一步壞的。

讀一長串指令：從 && 切開，分成準備、做事、驗收三類

資料夾與路徑

為什麼第一段幾乎都是 cd

  • cd 是 change directory，切換目前所在的資料夾。
  • ~ 代表自己的家目錄，例如 /Users/你的帳號。
  • 相對路徑：.venv、.venv/bin/ 這種不是 / 或 ~ 開頭的路徑，是從「目前所在的資料夾」算起。
  • $PWD 是一個變數，內容是目前所在資料夾的完整路徑。

後面幾段用的都是相對路徑，所以要先 cd。沒有先切過去，.venv 就會建在別的地方。

檔名開頭是 . 的檔案或資料夾是隱藏的，一般的 ls 不會列出來，要用 ls -a 才看得到。.venv、.gitignore 都是這一類。

三種串接符號

三種串接方式，差在要不要看前一段的結果

每個指令跑完都會回傳一個結束代碼（exit code）：0 代表成功，其他數字代表失敗。串接符號就是看這個數字決定要不要跑下一段。出處

寫法下一段什麼時候跑用在哪
A && BA 成功才跑 B有先後關係的步驟，前一步失敗就不該繼續
A ; B不管 A 成不成功都跑 B兩件互不相干的事
A || BA 失敗才跑 B失敗時的替代動作或提示訊息

安裝步驟用 &&，是因為 cd 如果失敗（資料夾名稱打錯），後面還繼續跑的話，東西會裝到錯的地方。

|| 常拿來讓「找不到」變成一句看得懂的話：

$ which wren || echo "還沒裝，正常"
wren not found
還沒裝，正常

which wren 找不到指令，結束代碼不是 0，所以接著跑 echo。外面再包一層括號 ( ... )，整組就可以放進 && 串裡而不會讓整串中斷。

cd ~/proj/wrenlab && python3 -m venv .venv，資料夾名稱打錯了（正確是 wren-lab）。會發生什麼？

  • 虛擬環境建在家目錄
  • 虛擬環境建在目前所在的資料夾
  • cd 失敗，後面那段不會跑
  • shell 會自動建立 wrenlab 資料夾

&& 只在前一段成功時才跑下一段。cd 找不到資料夾會失敗，整串就停在那裡。換成 ; 的話，虛擬環境就會建在目前所在的資料夾。

引號

什麼時候一定要加引號

shell 在把指令交給程式之前，會先自己處理一些特殊符號。不想讓它處理，就用引號包起來。

情況不加引號會怎樣寫法
參數裡有方括號zsh 把 [...] 當成比對檔名的樣式，找不到符合的檔案就報 no matches found，後面的程式根本沒被執行pip install "wrenai[mcp]"
路徑裡可能有空白被拆成兩個參數"$PWD/.venv/bin/wren"
有 *、?同樣被當成比對檔名的樣式grep --include='*.py'

zsh 的檔名比對找不到符合的檔案時，預設直接出錯而不是把原字串傳下去。出處

雙引號和單引號的差別：

  • 雙引號 "..."：裡面的 $PWD 這類變數還是會被換成實際的值。
  • 單引號 '...'：裡面每個字都照原樣，$ 也不處理。
$ echo "$PWD/.venv"
/Users/tim/proj/wren-lab/.venv
$ echo '$PWD/.venv'
$PWD/.venv

heredoc

把多行文字直接交給指令

heredoc（here-document）是在指令後面直接寫一段多行文字，當成那個指令的輸入。寫法是 << 加一個自己挑的結束記號，從下一行開始，到某一行剛好只有那個記號為止。出處

cat > /tmp/profile.yml <<YAML
datasource: duckdb
url: $PWD/sample-db
format: duckdb
YAML
  • cat 把收到的文字印出來。
  • > 檔名 把本來要印在螢幕上的內容改成寫進檔案；檔案已經存在會整個蓋掉。
  • <<YAML … YAML 中間三行就是 cat 收到的文字。YAML 只是記號，寫成 EOF 也可以。

結束記號有沒有加引號，決定裡面的 $ 會不會被處理：

寫法裡面的 $PWD用在哪
<<YAML換成實際路徑設定檔需要填入目前的路徑
<<'PY'照原樣不動送一段程式碼給直譯器（一行一行讀程式碼並執行的程式，例如 python），不想讓 shell 改到任何字

第二種常跟 python - 搭配。- 的意思是程式碼不從檔案讀，改從標準輸入讀，也就是 heredoc 送進來的那一段：

.venv/bin/python - <<'PY'
import duckdb
c = duckdb.connect('sample-db/jaffle_shop.duckdb', read_only=True)
print(c.sql("select count(*) from orders").fetchall())
PY

想用 heredoc 產生一個設定檔，裡面要有一行是目前資料夾的完整路徑。結束記號該怎麼寫？

  • <<'EOF'，加單引號
  • <<EOF，不加引號
  • 兩種寫法結果一樣
  • heredoc 裡不能用變數，要先手動查好路徑

不加引號時，heredoc 裡的 $PWD 會被換成實際路徑。加了單引號，檔案裡就會是 $PWD 這四個字。

mkdir -p、ln -sf、which

讓一個指令在任何資料夾都打得到

在終端機打 wren，shell 會依序到 PATH 這個變數列出的資料夾裡找同名的執行檔。執行檔如果放在專案的 .venv/bin/ 裡，不在 PATH 上，就只能打完整路徑。解法是在 PATH 上的某個資料夾放一個捷徑。

mkdir -p ~/.local/bin && ln -sf "$PWD/.venv/bin/wren" ~/.local/bin/wren && which wren
段落意思
mkdir -p建資料夾。-p：已經存在不出錯，中間缺的上層資料夾一起建 出處
ln -s建符號連結（symbolic link），也就是捷徑，不是複製一份。原本的檔案更新，捷徑指到的就是新的 出處
-f目的地已經有同名的檔案就直接換掉
"$PWD/.venv/bin/wren"捷徑指向哪裡。要用完整路徑；寫相對路徑的話，會從捷徑所在的資料夾算起，就找不到了
~/.local/bin/wren捷徑放在哪、叫什麼
which wren印出 shell 實際找到的是哪一個 wren

which 印出的路徑不是預期的那個，表示 PATH 裡排在前面的資料夾有另一個同名的指令。

ls、git status --short、lsof

三個拿來驗收的指令

ls 資料夾列出內容。bin 是 binary 的縮寫，慣例上放可以直接執行的程式。
git status --short用精簡格式列出有變動的檔案，一個檔案一行；什麼都沒印代表沒有變動。
lsof 檔案列出哪些程式正開著這個檔案。沒有程式開著時結束代碼不是 0，可以接 ||。

git status --short 每行開頭有兩個字元的狀態：出處

開頭意思
??Git 還沒追蹤的新檔案
 M改過，還沒加進暫存區（Git 裡「準備放進下一次提交」的清單）
M 改過，已經加進暫存區

lsof 用在檔案被鎖住的時候，找出是誰開著它：出處

$ lsof sample-db/jaffle_shop.duckdb || echo "沒有程式開著這個檔"
沒有程式開著這個檔

重點整理

  • 讀一長串指令先從 && 切開，每段各看各的；常見的結構是準備、做事、驗收。
  • && 是前一段成功才繼續，; 是不管結果都繼續，|| 是失敗才跑。
  • 相對路徑從目前的資料夾算起，所以第一段常是 cd。
  • 參數裡有 [ ]、*、空白或變數時加引號；zsh 遇到比對不到的方括號會直接報 no matches found。
  • heredoc 的結束記號不加引號會處理 $，加單引號則照原樣。
  • ln -sf 完整路徑 捷徑位置 加上 which，可以讓專案裡的指令在任何資料夾都打得到。

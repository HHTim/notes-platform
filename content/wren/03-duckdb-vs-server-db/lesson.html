同一句 SQL，走的路不一樣

有伺服器的資料庫與嵌入式資料庫

MySQL、PostgreSQL 是一支一直開著的伺服器程式，別的程式透過網路連進去。DuckDB 是嵌入式資料庫（in-process database）：資料庫引擎是一個函式庫，直接跑在使用它的那支程式裡，預設沒有另外的伺服器。出處

MySQL、PostgreSQL：先有伺服器
  • 安裝並啟動伺服器程式，它會一直開著。
  • 設定帳號、密碼、連接埠（MySQL 預設 3306、PostgreSQL 預設 5432）。
  • 連線：用戶端填主機、連接埠、帳號、密碼。
  • 執行：SQL 送到伺服器，伺服器算完把結果傳回來。
  • 多人同時用：全部交給伺服器協調。
DuckDB：只有一個檔案
  • 不用啟動任何東西，裝一個函式庫就好。
  • 沒有帳號密碼，資料庫就是一個 .duckdb 檔。
  • 連線：程式直接打開那個檔案。
  • 執行：SQL 在你自己的程式裡算，不經過網路。
  • 多個程式同時用：靠檔案鎖，規則比較嚴。

SQLite 也是嵌入式資料庫。DuckDB 跟它的差別是用途：SQLite 偏向一筆一筆的讀寫，DuckDB 是為分析設計的，資料照欄位存放，做加總、分組這類查詢比較快。出處

「記憶體資料庫」是另一件事，指資料只放在記憶體、不寫進硬碟。DuckDB 可以這樣用（連線時不給檔名），但它的特點是「跑在你的程式裡」，不是「資料只在記憶體」；有給檔名時資料會存在硬碟上的檔案裡。

四個差別，一項一項對

實際用起來差在哪

差別MySQL、PostgreSQLDuckDB

SQL 語法本身差別不大。DuckDB 的語法刻意貼近 PostgreSQL，select、join、group by 的寫法都一樣。

會 MySQL 的人用 DuckDB，要重新適應的不是語法，是「沒有伺服器」帶來的鎖

Could not set lock on file

檔案被鎖住：規則、症狀、排除

沒有伺服器，就沒有人居中協調誰在讀、誰在寫。DuckDB 用檔案鎖保護資料，一個資料庫檔只有兩種開法：出處

情況可不可以
一個程式用讀寫模式打開可以，但這時其他程式都進不來，唯讀也不行
多個程式都用唯讀模式打開可以
一個讀寫，其他唯讀不行

圖形化工具（例如 DBeaver）預設用讀寫模式連線，所以它連著的時候，別的程式就算只想讀也打不開：

_duckdb.IOException: IO Error: Could not set lock on file
"…/sample-db/jaffle_shop.duckdb": Conflicting lock is held in
/Applications/DBeaver.app/Contents/MacOS/dbeaver (PID 52174) …

錯誤訊息已經寫出是哪個程式（DBeaver）和它的行程編號（PID）。排除的步驟：

  • 放掉鎖：在那個程式裡中斷連線。中斷後鎖還在，就把整個程式關掉。
  • 確認：lsof 檔案路徑 || echo "沒有程式開著這個檔"，看到後面那句才算放開。
  • 自己的程式用唯讀開：只是要看資料時，連線加上唯讀選項，例如 Python 的 duckdb.connect(路徑, read_only=True)。大家都唯讀，就可以同時開。

DuckDB 也可以啟動成伺服器，讓多個程式同時寫入同一個資料庫，那是另外的用法；直接打開檔案時，適用的就是上面這張表。出處

拿到別人給的 DuckDB 或 SQLite 檔案時，先問一句「現在有沒有程式正在寫這個檔」。有的話請對方複製一份，不要直接連正在使用中的那一份。

DBeaver 用預設設定連著 a.duckdb。這時另一支 Python 程式用 read_only=True 去開同一個檔，會怎樣？

  • 可以開，因為唯讀不需要鎖
  • 打不開，出現鎖檔錯誤
  • 可以開，但查到的是舊資料
  • DBeaver 會被強制中斷連線

一個程式用讀寫模式開著時，其他程式連唯讀都進不來。要同時開，兩邊都得是唯讀。

catalog、schema、table

三層名稱：jaffle_shop.main.customers

DuckDB 裡一張表的完整名稱有三層：

層範例是什麼
catalog（資料庫）jaffle_shop打開的那個資料庫檔。沒有另外取名時，名字就是檔名去掉副檔名：jaffle_shop.duckdb → jaffle_shop 出處
schemamain資料庫裡的一層分類。DuckDB 預設的 schema 叫 main，PostgreSQL 的預設則是 public
tablecustomers資料表

一個連線可以同時掛上好幾個資料庫檔，所以才需要最前面那一層來區分。只想寫 select * from customers 的話，先用 USE 指定預設的資料庫與 schema：出處

USE jaffle_shop.main;
SELECT * FROM customers;

要知道一個資料庫裡有什麼，查 information_schema.tables。這是 SQL 標準定義的一組系統檢視表，DuckDB、PostgreSQL、MySQL 都有，SQLite 沒有。出處 再用 describe 看欄位：

select table_name, table_type from information_schema.tables order by 1;
describe customers;

table_type 是 BASE TABLE 代表真的存了資料，VIEW 代表存的是一段查詢。

.duckdb 是二進位檔，用文字編輯器打開只會看到亂碼。要看內容得用懂這個格式的工具：DBeaver、DuckDB 自己的命令列工具，或程式語言的 DuckDB 套件。

重點整理

  • MySQL、PostgreSQL 是一直開著的伺服器；DuckDB 是跑在你程式裡的函式庫，資料庫就是一個檔案。
  • DuckDB 為分析設計，語法貼近 PostgreSQL。
  • 同一個檔案：一個程式讀寫，或多個程式唯讀，不能混用。
  • 鎖檔錯誤會寫出佔用的程式與 PID；中斷那個程式的連線，再用 lsof 確認。
  • 表的完整名稱是「資料庫.schema.表」，資料庫名稱預設是檔名去掉副檔名，預設 schema 是 main。
  • information_schema.tables 列出有哪些表，describe 列出欄位與型別。

語意層

Wren AI 負責哪一段

讓 AI 直接看資料庫寫 SQL，常錯在三個地方：該用哪幾張表、怎麼接；「營收」這種詞到底怎麼算；欄位的值代表什麼。這些答案多半不在資料庫裡。

Wren AI 的做法是把這些答案寫成檔案，叫做語意層（semantic layer）。AI 代理人（會自己下指令、跑查詢的 AI 工具，例如 Claude Code）寫 SQL 之前先讀這一層，寫好的 SQL 再交給 Wren 轉成資料庫實際能跑的版本。出處

wrenaiPython 套件。裝完多一個 wren 指令，所有功能都從它進去。
MDLModeling Definition Language，語意層的檔案格式（YAML）：有哪些模型、欄位、關聯，各自是什麼意思。
profile一筆連線設定：連哪一種資料庫、在哪裡。
memory把問過的問題和當時的 SQL 記下來，下次遇到意思相近的問題可以找回來參考。

安裝分三件事：裝套件、讓 wren 指令到處打得到、建 profile。

pip install "wrenai[…]"

裝套件：先決定要哪幾組 extras

wrenai 把不是每個人都需要的功能拆成好幾組 extras。出處 常用的幾組：

extras帶進什麼什麼時候需要
postgres、mysql、mssql、bigquery…該資料庫的驅動程式（讓 Python 能跟那一種資料庫溝通的套件）要連那一種資料庫時。DuckDB 的驅動是內建的，不用另外選
memoryLanceDB、sentence-transformers（會帶進 torch）要用語意比對的記憶功能
memory-onnxLanceDB、onnxruntime、tokenizers同上，但不裝 torch
main互動式提問介面、瀏覽器設定頁用的套件想用問答方式或網頁表單建立設定
mcpMCP（Model Context Protocol，讓 AI 工具呼叫外部功能的共通規格）的 Python 套件要把 Wren 當成 MCP 伺服器，給其他 AI 工具呼叫
cd ~/proj/wren-lab
.venv/bin/pip install --upgrade pip
.venv/bin/pip install "wrenai[postgres,memory,main,mcp]"
.venv/bin/wren version        # wrenai 0.18.0

wrenai 0.18.0 需要 Python 3.11 以上。選了 memory 這組，虛擬環境會長到 1.8 GB 左右。光 torch 就佔 600 多 MB，是最大的一個；加上跟著它進來的 transformers、scipy 等套件，超過一半。下載時間看網路速度，實測約二十分鐘。

少裝一組不用重來，補跑 .venv/bin/pip install "wrenai[mcp]" 就會只裝缺的部分。

嵌入模型、向量、LanceDB、torch

memory 這組到底裝了什麼

記憶功能要做的事是：新問題進來，找出以前問過、意思相近的問題。字面比對做不到這件事，例如「有幾個顧客下過一次以上的訂單」和「回購的顧客有多少人」幾乎沒有相同的字。

  • 嵌入模型（embedding model）：把一句話轉成一串數字（向量）的模型。意思相近的句子，轉出來的數字也相近。wrenai 預設用 paraphrase-multilingual-MiniLM-L12-v2，支援多國語言，每句話轉成 384 個數字。出處
  • torch（PyTorch）：執行神經網路模型的函式庫。嵌入模型是一個小型神經網路，需要有引擎來跑它。torch 還包含訓練模型等許多功能，所以體積很大。出處
  • onnxruntime：另一種引擎，主要用來執行已經訓練好的模型，體積小很多。memory-onnx 這組用它取代 torch，跑的是同一個模型。出處
  • LanceDB：專門存向量的資料庫，擅長「找出跟這串數字最接近的前幾筆」。跟 DuckDB 一樣是嵌入式的，資料就放在本機的檔案裡，不用架伺服器。出處
一般的資料表向量
要開伺服器PostgreSQL、MySQLPostgreSQL 加 pgvector 擴充套件
不用伺服器，資料是本機檔案DuckDB、SQLiteLanceDB

為什麼不直接用 PostgreSQL 存向量

  • 這份索引隨時可以重建。問題和 SQL 的正本是專案裡的 Markdown 檔（knowledge/sql/），向量索引只是從它們產生出來的。為了一份可以重建的東西架一台資料庫伺服器不划算。
  • 你常常沒有地方可以寫。要查的那台資料庫通常只給唯讀帳號，不能建表、不能裝擴充套件；把自己工具的索引寫進別人的正式資料庫也不恰當。
  • 裝完就能用。不需要先架伺服器、設定帳號。

沒裝 memory 或 memory-onnx 時，記憶功能仍然可以用，只是退回文字比對，對不上換句話說的問題。

ln -sf 與 which

讓 wren 在任何資料夾都打得到

wren 裝在專案的 .venv/bin/ 裡，換個資料夾就得打一長串相對路徑。在 PATH 上的資料夾放一個捷徑：

$ mkdir -p ~/.local/bin && ln -sf "$PWD/.venv/bin/wren" ~/.local/bin/wren && which wren && wren version
/Users/tim/.local/bin/wren
wrenai 0.18.0

前提是 ~/.local/bin 已經在 PATH 裡，用 echo $PATH 可以確認。

wren profile add

建 profile：告訴 wren 資料庫在哪

profile 的作用等於資料庫工具裡的「新增連線」。先把設定寫成一個 YAML 檔，再匯入：

cat > /tmp/jaffle-profile.yml <<YAML
datasource: duckdb
url: $PWD/sample-db
format: duckdb
YAML
wren profile add jaffle-shop --from-file /tmp/jaffle-profile.yml && cat ~/.wren/profiles.yml
欄位填什麼
datasource資料庫的種類
urlDuckDB 要填放 .duckdb 檔的資料夾，不是檔案本身。Wren 會把資料夾裡每個 .duckdb 檔都掛上去
format檔案格式

wren profile add 名稱 除了 --from-file，還可以用 --ui（開瀏覽器表單）或 --interactive（一題一題問）。存檔之後它會實際連一次資料庫：

Profile 'jaffle-shop' added.
→ Validating connection...
✓ Connection validated

active: jaffle-shop
profiles:
  jaffle-shop:
    datasource: duckdb
    url: /Users/tim/proj/wren-lab/sample-db
    format: duckdb
  • ✓ Connection validated：真的連上了，不只是把設定存起來。
  • active：目前使用中的 profile。
  • url 是完整路徑：heredoc 裡的 $PWD 已經換成實際的資料夾。

為什麼存在家目錄，不存在專案裡

連到真正的資料庫時，連線設定會牽涉帳號密碼，不該進 Git。Wren 的分工是：語意層（描述資料的意思）放在專案裡、進 Git、大家共用；profile（怎麼連）留在每台電腦的 ~/.wren/，所以每台電腦要各建一次。

Wren 怎麼打開 DuckDB

Wren 是用唯讀模式把每個檔案掛上去的，掛上去的名字是檔名去掉副檔名。這帶來兩個結果：

  • 不會改到資料，但別的程式用讀寫模式開著同一個檔時，Wren 會連不上，出現 Failed to attach。
  • 資料庫名稱就是檔名：jaffle_shop.duckdb 在 Wren 裡叫 jaffle_shop，寫語意層時要填這個名字。

DuckDB 的資料庫檔放在 /data/shop/sales.duckdb。profile 的 url 該填什麼？

  • /data/shop/sales.duckdb
  • sales
  • duckdb://localhost/sales
  • /data/shop

DuckDB 的 url 填的是放資料庫檔的資料夾。sales 是掛上去之後的資料庫名稱，寫語意層時才用到。

重點整理

  • Wren AI 把「資料代表什麼意思」寫成檔案（語意層），讓 AI 寫 SQL 前先讀。
  • extras 依需要選：資料庫驅動、memory 或 memory-onnx、main、mcp；少裝可以補裝。
  • 記憶功能靠嵌入模型把句子轉成向量，LanceDB 負責找最接近的；torch 或 onnxruntime 是跑模型的引擎。
  • 向量索引可以從專案裡的 Markdown 重建，所以用本機檔案型的 LanceDB 就夠了。
  • profile 存在 ~/.wren/profiles.yml，不進 Git；語意層放在專案裡。
  • DuckDB 的 url 填資料夾；Wren 以唯讀模式掛上檔案，資料庫名稱是檔名去掉副檔名。

python3、python2、python4

為什麼指令叫 python3

Python 2 和 Python 3 的語法互不相容，兩個版本並存了很多年，所以系統用 python2、python3 兩個名字區分。Python 2 在 2020 年 1 月 1 日停止維護。出處 名字就沿用下來：3.11、3.15 都叫 python3，沒有 python4 這個指令。

$ python3 --version
Python 3.15.2
$ which python3
/opt/homebrew/bin/python3

套件會寫明最低要哪一版 Python，裝之前先看 python3 --version 夠不夠新。

跟 JDK 比

Python 是工具，也是放套件的地方

寫過 Java 的人容易把 Python 想成 JDK：一套拿來執行程式的工具。差別在第三方套件（別人寫好、要另外下載的函式庫）放在哪裡。

JavaPython
執行程式的工具JDK 裡的 JVM、javacpython3 直譯器
標準函式庫在 JDK 裡在 Python 裡
第三方套件放哪~/.m2/repository/，同一個套件的不同版本各自分開放預設裝進 Python 自己的 site-packages 資料夾，同名套件只能有一個版本
誰決定專案用哪一版每個專案的 pom.xml專案可以用 requirements.txt 寫明版本，但同一份 Python 裡還是只放得下一個版本，後裝的蓋掉先裝的

所以一份 Python 只要裝了第三方套件，它就同時是一個「環境」。兩個專案要同一個套件的不同版本，裝進同一份 Python 就會互相蓋掉。

JDK 不會因為專案用了哪個套件而改變；Python 預設會

python3 -m venv .venv

虛擬環境：每個專案一份自己的套件資料夾

虛擬環境（virtual environment）是專案資料夾裡的一個子資料夾，裡面有指回原本 Python 的連結，加上一份獨立的 site-packages。直譯器共用，套件各放各的。出處

$ cd ~/proj/wren-lab && python3 -m venv .venv && ls .venv/bin/ && git status --short
activate
activate.csh
activate.fish
Activate.ps1
pip
pip3
pip3.15
python
python3
python3.15
段落意思
python3用哪一份 Python 執行，建出來的虛擬環境就是那一版
-m venv-m 後面接模組名稱，意思是把那個模組當成程式來執行；venv 是標準函式庫裡專門建虛擬環境的模組，不用另外裝 出處
.venv要建立的資料夾名稱。可以自己取，.venv 是慣用的名字；開頭的 . 讓它成為隱藏資料夾

驗收看兩件事：

  • .venv/bin/ 裡有 python、pip。幾個 activate 開頭的檔案是給不同 shell 用的同一支啟用腳本。
  • git status --short 什麼都沒印。Python 3.13 起，venv 會在新建的資料夾裡自動放一個 .gitignore，所以 Git 不會把裡面幾千個檔案當成新檔案。出處
$ cat .venv/.gitignore
# Created by venv; see https://docs.python.org/3/library/venv.html
*

內容只有一個 *，意思是這個資料夾裡所有檔案都忽略。

用比 3.13 舊的 Python 建虛擬環境時沒有這個檔案，要自己把 .venv/ 寫進專案的 .gitignore。

externally-managed-environment

有些 Python 直接不讓你裝套件

作業系統或套件管理工具（例如 Homebrew、Debian 的 apt）裝的 Python，可以在標準函式庫的資料夾裡放一個叫 EXTERNALLY-MANAGED 的檔案，宣告「這份 Python 歸我管」。pip 看到這個檔案，就會拒絕把套件裝進這份 Python，錯誤訊息是 externally-managed-environment。出處

$ ls /opt/homebrew/opt/python@3.15/Frameworks/Python.framework/Versions/3.15/lib/python3.15/EXTERNALLY-MANAGED
/opt/homebrew/opt/python@3.15/…/lib/python3.15/EXTERNALLY-MANAGED

遇到這個錯誤，正確的做法是建虛擬環境，把套件裝進去。虛擬環境不受這個限制。

pip install

把套件裝進虛擬環境

.venv/bin/pip install --upgrade pip
.venv/bin/pip install "wrenai[postgres,memory,main]"
段落意思
.venv/bin/pip用虛擬環境裡的 pip，套件會裝進 .venv 的 site-packages
install從 PyPI（Python 的官方套件庫，角色等於 Maven Central）下載並安裝 出處
--upgrade pip把 pip 自己更新到最新版。虛擬環境裡的 pip 是跟著 Python 打包的那一版，可能比較舊
wrenai套件名稱
[postgres,memory,main]extras：選裝的功能組。套件作者把不是每個人都需要的相依套件分成幾組，用方括號指定要哪幾組 出處
外面的 "..."zsh 會把方括號當成比對檔名的樣式，不加引號會報 no matches found

套件裝好之後才發現少一組 extras，再跑一次只寫那一組就好，已經裝過的會跳過：

.venv/bin/pip install "wrenai[mcp]"

不用 activate 也可以

很多教學會先打 source .venv/bin/activate，之後直接打 pip、python。這個指令主要做的事是把 .venv/bin 排到 PATH 最前面。每次都寫完整路徑 .venv/bin/pip 效果一樣，而且從指令本身就看得出用的是哪一份，不會因為忘記啟用而裝錯地方。

Requirement already satisfied、Collecting、Successfully installed

讀懂 pip 的輸出

pip 一次會印出幾十行，看每行的開頭就能分類：

開頭意思
Requirement already satisfied已經裝過、版本符合要求，跳過
Collecting、Downloading缺的套件，正在下載
Using cached以前下載過，用電腦上存的那份
Successfully installed …這次實際新裝的套件與版本。只要看這一行就知道結果
ERROR失敗。把最後二三十行留下來看
Requirement already satisfied: wrenai[mcp] in ./.venv/lib/python3.15/site-packages (0.18.0)
Collecting mcp<2,>=1.19 (from mcp[cli]<2,>=1.19; extra == "mcp"->wrenai[mcp])
  Downloading mcp-1.30.0-py3-none-any.whl.metadata (9.3 kB)
…
Successfully installed attrs-26.1.0 httpcore-1.0.9 httpx-0.28.1 … mcp-1.30.0 …

mcp<2,>=1.19 是版本限制：要 1.19 以上、未滿 2。extra == "mcp"->wrenai[mcp] 說明這個套件是因為 wrenai 的 mcp 這組 extras 才被帶進來的。

裝完可以用兩個指令檢查：

  • .venv/bin/pip show 套件名：有沒有裝、裝的是哪一版。沒裝會印 Package(s) not found。
  • .venv/bin/pip check：已安裝的套件之間版本有沒有衝突。沒問題會印 No broken requirements found.

pip 的輸出有四十幾行 Requirement already satisfied，最後一行是 Successfully installed mcp-1.30.0 …。這次安裝的結果是？

  • 失敗，因為大部分套件都沒有安裝
  • 全部套件重新安裝了一次
  • 要再執行一次才會真的安裝
  • 成功，只補裝了缺的那幾個套件

Requirement already satisfied 是已經裝過所以跳過，不是錯誤。實際新裝了什麼看 Successfully installed 那一行。

重點整理

  • Python 預設把第三方套件裝進直譯器自己的 site-packages，同名套件只能有一版；JDK 不會這樣。
  • python3 -m venv .venv 建出一份專案專用的套件資料夾，直譯器還是共用原本那份。
  • Python 3.13 起，venv 會自動放一個內容是 * 的 .gitignore。
  • Homebrew、apt 管的 Python 有 EXTERNALLY-MANAGED 檔，pip 會拒絕直接安裝，要用虛擬環境。
  • pip install "套件[extras]"：方括號是選裝的功能組，在 zsh 一定要加引號。
  • pip 的輸出看最後的 Successfully installed；pip show、pip check 用來驗收。

拿到映像檔

三條路：下載、自己做、離線搬

映像檔和容器的關係第 4 課講過（食譜、成品、跑起來的那一份），這裡直接進操作。

方式什麼時候用指令
從 registry 下載拿現成的（公開或公司內部的）docker image pull nginx:1.27
用 Dockerfile 做把自己的程式包成映像檔docker image build -t myapp:1.0 .
從檔案匯入連不上 registry，只能請別人給你一包docker image load -i nginx.tar
 
docker image ls                    # 看目前有哪些
docker image inspect nginx:1.27    # 看細節：CPU 架構、基於哪個系統
docker image rm nginx:1.27         # 刪掉

刪不掉的時候先看有沒有容器在用它。容器只是停掉還不夠——只要那個容器還存在，它跟映像檔的關係就還在，得先把容器 rm 掉，映像檔才刪得動。

離線搬運

save 和 load 要成對

# 匯出成一個檔
docker image save nginx:1.27 -o nginx.tar

# 在另一台匯入
docker image load -i nginx.tar

save 把映像檔的每一層和它的設定打包起來，load 在另一邊還原。網路連不到 registry 的環境就靠這一招。

另外還有一招是 docker container commit：進到容器裡改東西，再把當下的狀態存成新的映像檔。能用，但別當常態。這樣做出來的映像檔沒有配方，別人看不出你改了什麼，下次也重現不出來。正式的做法是把每個步驟寫進 Dockerfile。

第一份配方

Dockerfile 就是一張純文字的施工單

FROM nginx:1.27-alpine
COPY index.html /usr/share/nginx/html/index.html
docker image build -t my-nginx:1.0 .
docker container run -d --name my-nginx -p 8080:80 my-nginx:1.0

-t my-nginx:1.0 是給成品取名字加標籤；最後那個 . 是建置內容（build context）——你告訴 Docker「這個資料夾裡的檔案我建的時候要用得到」，COPY 就是從這裡面撈。

同一個 -t，在不同指令裡是不同意思：docker build -t 的 t 是 tag（標籤），docker run -t 的 t 是 tty（偽終端機）。原筆記整理的這張對照表很實用，值得記起來。

指令各管什麼

九個常用指令的分工

指令做什麼要注意
FROM從哪個映像檔開始疊官方的優先，而且要指定版本，別用 latest
WORKDIR設定後面指令的工作目錄目錄不存在會自己建
COPY把建置內容裡的檔案複製進去一般複製都用它
ADD複製，而且會自動解開壓縮檔真的需要那個「自動」時才用
RUN建的時候執行指令（裝套件之類）每一行 RUN 都疊一層，能合併就合併
ENV設環境變數會留在映像檔裡，容器跑起來還讀得到
ARG設建置參數建完就沒了，容器裡看不到
CMD容器啟動時的預設指令或預設參數會被 docker run 後面接的指令蓋掉
ENTRYPOINT固定要執行的那支主程式常跟 CMD 搭配，一個當工具一個當參數

原筆記說「官方映像優先、固定版本不要用 latest、盡量挑體積小的」——查證後和 Docker 官方的建置建議一致：標籤是會被發佈者改掉的（mutable），要保證每次拿到完全一樣的東西，最硬的做法是釘內容摘要（digest）而不是標籤。出處

另外有一個順序上的坑：Docker 官方文件明寫「ARG 是唯一可以寫在 FROM 前面的指令」，ENV 不行出處。而且寫在 FROM 前面的 ARG 只能用在 FROM 那一行，要在後面用得再宣告一次。

最容易搞混的兩組

ARG 對 ENV：差在活多久

兩個都是設變數，差別在作用時間，不是型別。原筆記做過一個很清楚的實驗：兩份 Dockerfile 分別用 ARG 和 ENV 設同一個版本號，build 出來的映像檔跑起來版本都對；但進到容器裡打 env，只有 ENV 那個看得到變數，ARG 那個找不到。

# 建的時候用，建完就消失
ARG VERSION=2.0.1
RUN wget https://example.com/tool-${VERSION}.tar.gz

# 建的時候和跑的時候都在，會留在映像檔裡
ENV TZ=Asia/Taipei

不改 Dockerfile 也能換 ARG 的值：

docker image build -t myapp:2.0.0 --build-arg VERSION=2.0.0 .

正因為 ENV 會跟著映像檔留下來，密碼、權杖這種東西不要用 ENV 寫死在 Dockerfile 裡——拿到映像檔的人就讀得到。敏感資料交給專門的機密管理機制處理。

CMD 對 ENTRYPOINT：一個會被蓋掉，一個不會

CMD 設的是預設指令：docker run 後面如果你接了別的指令，CMD 就被忽略。ENTRYPOINT 設的則是那支主程式：docker run 後面接的東西會變成它的參數，蓋不掉它。真要整個換掉得另外加 --entrypoint，官方文件對這個旗標的說明就是「Overwrite the default ENTRYPOINT of the image」。出處

FROM alpine:3.20
ENTRYPOINT ["echo"]
CMD ["hello"]

直接跑，印出 hello；後面接 world，CMD 的預設參數被換掉，變成印 world。把 ENTRYPOINT 想成固定的工具、CMD 想成工具預設帶的參數，這組搭配就通了。

Dockerfile 裡只能有一個 CMD 生效：官方文件寫「列了多個 CMD，只有最後一個算數」。出處 還有一個原筆記踩過的狀況：什麼 CMD 都沒寫時，容器啟動會沿用基礎映像檔（FROM 那個）自己帶的預設指令。

建快一點

常改的放後面，不該送的別送

映像檔是一層一層疊的，某一層的快取失效，它後面每一層都要重建。所以把變動少的步驟放前面、常改的程式碼放最後：

FROM python:3.12-slim
WORKDIR /app

# 變動少：先裝相依套件
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 變動多：最後才複製程式碼
COPY app.py .
CMD ["python", "app.py"]

這樣改 app.py 的時候，裝套件那一層的快取還留得住。原筆記把 COPY app.py 放在裝套件前面，結果每改一次程式碼，連裝套件都要重跑一次。

另一個省時間的地方是建置內容。. 代表「整個目前目錄打包送給 Docker」，但你的 Dockerfile 可能只 COPY 一個檔。用 .dockerignore 把不用送的排掉：

.git/
.venv/
__pycache__/
*.log

官方文件對這兩件事的建議一樣：apt-get update 要和 apt-get install 寫在同一個 RUN 裡（避免用到過期的套件清單），以及用 .dockerignore 排掉跟建置無關的檔案。出處

縮小成品

多階段建置：鷹架不要跟著交屋

編譯器就像蓋房子的鷹架——蓋的時候要，住進去不需要。多階段建置的做法是：第一段用有編譯器的映像檔編出成品，第二段換一個精簡的映像檔，只把成品搬過去。

FROM gcc:14 AS builder
WORKDIR /src
COPY hello.c .
RUN gcc --static -o hello hello.c

FROM alpine:3.20
COPY --from=builder /src/hello /usr/local/bin/hello
ENTRYPOINT ["/usr/local/bin/hello"]

最終的映像檔只有最後那一段，加上你明確搬進去的東西。原筆記做過同一份 C 程式的對照：直接用 gcc 映像檔出貨的成品很肥，改成兩段之後小非常多。

換基礎映像檔的時候記得確認 CPU 架構和系統函式庫對得上——用 docker image inspect 看 Architecture 和 Os 兩個欄位。

分享出去

重新標記，再推上 registry

docker image tag myapp:1.0 你的帳號/myapp:1.0
docker login
docker image push 你的帳號/myapp:1.0

原筆記在這裡卡過一次：直接 docker image push hello:1.0 會失敗。Docker Hub 的命名規則是——沒有帳號前綴的名字（像 nginx:latest）是保留給官方映像檔的，你自己的要寫成 帳號/名稱:標籤。

tag 不會複製一整份，它只是給同一包內容再掛一個名字。推之前確認 registry 位址和登入權限；登入憑證不要寫進 Dockerfile。

重點整理

  • 映像檔三條來路：從 registry 下載、用 Dockerfile 建、從封存檔匯入；容器還在（就算停掉）就刪不掉它用的映像檔。
  • commit 出來的映像檔沒有配方，正式專案要把步驟寫進 Dockerfile。
  • ARG 建完就消失、ENV 會留在映像檔裡；只有 ARG 能寫在 FROM 前面。
  • CMD 會被 docker run 後面的指令蓋掉，ENTRYPOINT 不會（真要換得加 --entrypoint）；兩個搭配＝固定工具＋預設參數。
  • 某一層快取失效，後面全部重建——所以常改的程式碼放最後；.dockerignore 減少送進去的檔案。
  • 多階段建置：編譯器留在第一段，最終成品只帶走編好的東西。

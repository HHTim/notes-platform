實作篇・開場

前面講的是道理，這一課開始動手

第 4 課已經把 Docker 的三個東西講完了：Dockerfile 是食譜、映像檔（image）是成品、容器是跑起來的那一份。這一課不重講那三個詞，只補上手指頭的部分——實際要打哪些指令、每個參數在做什麼。

動手前先記住一句原筆記講了三次的話：容器是一種技術，Docker 只是這個技術的其中一個實作品。常常把兩個字當同義詞用，是因為 Docker 是最成功、用得最廣的那一個。這件事背後有一整套標準在撐著，那是第 20 課的內容。

Docker Engine真正在做事的那一支程式（正式名稱：容器引擎）。它負責建映像檔、開容器、管網路。
Docker CLI你在終端機打 docker 時用的那個介面。它自己不做事，只把你的要求送給 Engine。
Registry映像檔倉庫，大家共用的架子（第 4 課提過）。預設是 Docker Hub。

裝之前

Linux 容器要的是 Linux 核心，所以 Mac 和 Windows 得墊一層

容器靠的是 Linux 核心內建的兩個機制（第 3 課說過：一個讓你只看得到自己的東西，一個限制你能吃多少資源）。在 Linux 上這兩個機制本來就在，Docker Engine 直接用就好；在 macOS 和 Windows 上沒有 Linux 核心，所以得先有一個 Linux 環境，容器再跑在那裡面。

原筆記在這裡用粗體連寫三次「Docker Engine 只能 run 在 Linux 環境」。更精確的說法是：Linux 容器需要 Linux 核心。Docker 官方文件寫的是「Docker Engine 透過 Docker Desktop 在 Windows、macOS、Linux 上都取得到」，而且 Windows 上還有另一條跑 Windows 容器的路線出處。對 Mac 和 Windows 上要跑 Linux 容器的人來說，結論一樣：中間會有一層 Linux，只是你通常感覺不到。那一層長什麼樣，第 17 課拆開來看。

裝完第一件事

兩行指令確認「打得到」

docker version
docker info

docker version 會分兩段印出來：上面是 Client（你的 CLI），下面是 Server（Docker Engine）。只看到 Client 那一段，就是 Engine 還沒起來——在 Mac 和 Windows 上通常是那層 Linux 還沒開。docker info 則列出現在有幾個容器、幾個映像檔、資料存在哪裡。

docker ＋ 你要管的東西 ＋ 要做的動作 ＋ 選項

docker image ls           # 管的是映像檔，動作是列出來
docker container ls       # 管的是容器，動作是列出來
docker container stop web # 管的是容器，動作是停掉名叫 web 的那個

很多寫法有簡寫，例如 docker container ls 可以寫成 docker ps。原筆記兩種都用，還混用了 docker container ps——查證後這確實是有效的別名（docker container ls、docker container list、docker container ps、docker ps 官方文件列為同一個指令）。出處 剛學的時候建議打完整寫法，一眼看得出你在動哪一類東西。

第一個容器

一行指令，跑起一個網頁伺服器

docker container run --name web -d -p 8080:80 nginx
這一段在做什麼
--name web幫這個容器取名叫 web。不取的話 Docker 會亂配一個（原筆記跑出來的是 xenodochial_clarke 這種）。
-d丟到背景跑，終端機馬上還你。
-p 8080:80把你這台機器的 8080 埠接到容器裡的 80 埠。順序是「主機：容器」，不要反。
nginx要用哪個映像檔。沒寫版本就是 latest。

跑起來之後開瀏覽器連 http://127.0.0.1:8080 就看得到 nginx 的預設首頁。

這一行按下去，Docker 依序做了這些事：

  • 先在本機找有沒有 nginx 這個映像檔。
  • 沒有就去 registry（預設 Docker Hub）下載。
  • 用映像檔開一個新容器，並且給它一層自己的可寫空間。
  • 配一個容器內部用的位址，把 8080 對到容器的 80。
  • 執行映像檔裡設定好的那個開機指令（nginx 這個映像檔是跑一支叫 docker-entrypoint.sh 的腳本）。

latest 不是「永遠是最新版」的保證，它只是「沒指定版本時預設拿的那個標籤」，而它指到的內容會變。正式環境要指定測過的版本——這件事第 15 課再細講。

三種跑法

前景、背景、互動

背景（加 -d）
  • 終端機立刻還你，可以繼續打別的指令。
  • 關掉終端機，容器照跑。
  • 看不到即時輸出，要靠 logs 去撈。
  • 跑網站、資料庫這種長命的服務就用這個。
前景（不加 -d）
  • 輸出直接印在畫面上，適合邊跑邊看。
  • 終端機被佔住，不能做別的。
  • 按 Ctrl + C 會把容器停掉，因為那個訊號直接送進容器。
  • 想脫離但不停掉：Ctrl + P 接 Ctrl + Q。

第三種是互動——你要在容器裡面打指令：

# 開一個新容器，直接進到它的 shell
docker container run -it --rm ubuntu sh

# 進到一個已經在跑的容器裡
docker container exec -it web sh

-i 是保持標準輸入（STDIN，也就是「你打的字送得進去」）開著；-t 是配一個偽終端機（TTY，讓你有提示符號、能按 Tab 補字、能按 Ctrl + C）。兩個一起用才有像在本機終端機操作的感覺。只給 -i 會沒有提示符號，只給 -t 則可能打不進字。

run 和 exec 差在哪？run 是開一個新容器；exec 是在已經在跑的容器裡再起一支程式。所以從 exec 開出來的 shell 打 exit 離開，容器還是 Up；但如果你離開的是容器的主程式，容器就跟著結束。

不是每個映像檔裡都有 bash。精簡的映像檔（例如 Alpine 那一類）通常只有 sh，所以 sh 是比較保險的第一次嘗試。

容器是什麼東西

它不是縮小版的虛擬機，它就是一支程式

第 3 課從「共用作業系統」的角度講過差別，這裡補上一個從外面看得到的證據：在主機上用 ps 看，容器裡的程式就實實在在出現在主機的程序清單裡，只是被關進自己的房間、被限制了能吃多少 CPU 和記憶體。

docker container top web    # 看這個容器裡有哪些程序

所以會有這個後果：主程式停了，容器就退出了。容器沒有「開機、待機、關機」那一套，它的命跟那支主程式綁在一起。

收尾

看得到、停得掉、刪得乾淨

# 只列還在跑的
docker container ls

# 連停掉的一起列（-a 就是 all）
docker container ls -a

# 看紀錄，-f 是持續跟著跑
docker container logs web
docker container logs -f web

# 停止、重開、刪除
docker container stop web
docker container start web
docker container rm web

停止（stop）不等於刪除（rm）。停掉的容器還在，連同它那層可寫空間裡的檔案；只有刪掉容器，那層才跟著消失。跑一次性的工作可以加 --rm，跑完自動刪掉，就不會累積一堆 Exited 的殘骸。

要一次處理很多個，用括號把清單餵進去：

docker container stop $(docker container ls -aq)   # -q 只印 ID

docker system prune 這類指令一次會清掉多種「目前沒在用」的東西——停掉的容器、沒人用的映像檔、沒人掛的網路。加上 -a 之後範圍更大。在還不確定它會掃到什麼之前，先用 ls 把要刪的列出來看過，再動手。

重點整理

  • 容器是技術，Docker 是實作品之一；在 Mac 和 Windows 上跑 Linux 容器，中間一定墊了一層 Linux（Windows 另有跑 Windows 容器的路線）。
  • docker version 只印出 Client 那一段，就是 Engine 沒起來。
  • -p 的順序是「主機埠：容器埠」；-d 丟背景；-a 是列出全部（含停掉的）。
  • run 開新容器，exec 在既有容器裡再起一支程式；離開 exec 的 shell 不會停掉容器。
  • 容器就是一支被隔離、被限制資源的程式——主程式停了，容器就退出。
  • 停止只是停程式，刪除才會連那層可寫空間一起帶走。

讀完這課你會

  • 說出 Docker 的三個角色（你打指令的那支、真正做事的那支、放映像檔的那個倉庫）各管什麼、怎麼互相講話
  • 看一眼手上的 Linux 就知道該用 dnf、apt 還是 zypper 裝東西
  • 知道把帳號加進 docker 群組等於交出這台機器的管理權，以及官方怎麼說這件事

實作篇・補課

第 14 課給了三個名字，這課把它們接起來

第 14 課開頭列過 Docker Engine、Docker CLI、Registry 三個名字，但沒講它們之間是怎麼傳話的。這一課補上那條線，順便把「在別人的機器上從零裝一套」會遇到的兩件事講完：挑對套件管理工具，以及那個看起來只是求方便、其實是資安決定的 docker 群組。

指令怎麼打在第 14 課，映像檔與 Dockerfile 在第 15 課，資料保存與 Compose 在第 16 課，dockerd 底下還分成哪幾棒在第 17 課——這課都不重講。

架構

你打的 docker 自己不做事，它只是去下單

Docker 官方文件第一句就把它定性了：「Docker uses a client-server architecture. The Docker client talks to the Docker daemon, which does the heavy lifting of building, running, and distributing your Docker containers.」——用戶端－伺服器架構（client-server，白話：一邊負責下單、另一邊負責做事，兩邊是分開的兩支程式）。出處

角色白話官方怎麼說
Docker 用戶端（docker）你在終端機打字的那個介面，負責把要求送出去「The Docker client (docker) is the primary way that many Docker users interact with Docker. When you use commands such as docker run, the client sends these commands to dockerd, which carries them out.」
Docker 背景服務（dockerd）真正在做事的那支，一直開著等人來下單（這種一直待命的背景程式，正式名稱叫 daemon，中文常譯作常駐程式）「The Docker daemon (dockerd) listens for Docker API requests and manages Docker objects such as images, containers, networks, and volumes.」
映像檔倉庫（registry）放映像檔的架子，大家上傳下載都在這裡（第 4 課提過）「A Docker registry stores Docker images. Docker Hub is a public registry that anyone can use, and Docker looks for images on Docker Hub by default.」

兩邊怎麼講話？官方寫「The Docker client and daemon communicate using a REST API, over UNIX sockets or a network interface.」出處——REST API（白話：一套講好的呼叫格式，像網頁瀏覽器連網站那樣，一邊送要求、一邊回結果），走的管道則是本機的一個通訊用檔案，或直接走網路。

Docker Desktop 不是第四個角色，它是把上面這些包成一個桌面軟體：「Docker Desktop is an easy-to-install application for your Mac, Windows, or Linux environment that enables you to build and share containerized applications and microservices.」出處Mac 和 Windows 上它底下還墊了一層 Linux，那層是第 17 課的內容。

順序是先有映像檔，才有容器：官方對兩者的定義是「An image is a read-only template with instructions for creating a Docker container.」與「A container is a runnable instance of an image.」——容器是映像檔「跑起來的那一份」，不是一個先開好、再等映像檔放進去的空殼出處。第 4 課的三個詞（食譜、成品、跑起來的那一份）講的就是這個方向。

中間那條管道

一個檔案，決定了誰使喚得動 dockerd

在 Linux 上，用戶端跟背景服務預設不走網路，而是走一個特別的檔案。官方的 dockerd 說明寫得很直白：「By default, a unix domain socket (or IPC socket) is created at /var/run/docker.sock, requiring either root permission, or docker group membership.」出處

Unix domain socket（白話：同一台機器上兩支程式互相講話用的一個特殊檔案，長得像檔案，但裡面不存資料，只負責傳話）。所以「我打 docker ps 卻說權限不足」不是 docker 這支指令不給你用，而是你碰不到那個檔案。

ls -l /var/run/docker.sock
# srw-rw----. 1 root docker 0 ...
#  ↑         ↑    ↑
#  s＝這是 socket 檔   擁有者是 root   群組是 docker

讀到這裡就看得出，要碰得到那個 socket 有兩條路：用 sudo 借一下 root 的身分（sudo ＝ superuser do，以系統管理員身分執行這一行），或者把自己放進 docker 這個群組。後者方便得多，也正是下面要特別講的那一段。

裝之前

先認出手上這台是哪一種 Linux

Linux 有很多套發行版（distribution，白話：同一個核心配上不同的預裝軟體與管理工具，各自打包成一套作業系統），而裝軟體用的套件管理工具（白話：幫你下載、安裝、升級、移除軟體並處理相依關係的那支指令）各家不同。裝 Docker 之前得先認人。

cat /etc/os-release     # 看 ID 和 ID_LIKE 兩欄，就知道自己屬於哪一系
which dnf apt zypper    # 哪個印得出路徑，就有哪個
系別常見成員套件管理工具
Red Hat 系RHEL、CentOS、Fedora、Amazon Linuxdnf（yum 是它的前身）
Debian 系Debian、Ubuntuapt（或舊寫法 apt-get）
SUSE 系SLES、openSUSEzypper

三欄各自查得到：Docker 官方的 RHEL 安裝頁用的是 sudo dnf install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin出處；Ubuntu 安裝頁用的是 sudo apt install 加同一串套件名出處；SUSE 官方對自家工具的定義是「Zypper is a command-line package manager for installing, updating and removing packages.」出處

Amazon Linux 2023 上，yum 實際上是 dnf 的別名或符號連結，兩者指向同一個程式，建議優先用 dnf。AWS 官方文件寫「The default software package management tool in AL2023 is DNF.」以及「In AL2023 the yum command is still available, but as a pointer to the dnf command.」（符號連結＝一個指向另一個檔案的捷徑，點它等於點到原本那個）出處AL2023 走的是 Fedora 的架構：AWS 自己寫「The AL2023 GA version includes components from Fedora 34, 35, and 36.」，同時也提醒它不能直接對應到某一版 Fedora。出處

一個會影響你裝到什麼的前提：套件名叫 docker 跟叫 docker-ce 是兩個來源。打 sudo yum install docker -y，拿的是那台機器自己的倉庫；Docker 官方安裝頁的支援清單列的是 CentOS、Debian、Fedora、Raspberry Pi OS（32 位元）、RHEL、Ubuntu，沒有 Amazon Linux，也沒有 SUSE出處；官方並在安裝頁提醒「Your Linux distribution may provide unofficial Docker packages, which may conflict with the official packages provided by Docker.」出處自己練習用哪個都行，只是要知道版本與支援窗口不一樣，而且兩邊裝在一起會打架。

裝完

裝好不等於跑起來，而且它偷偷替你開了一個群組

Docker 官方 RHEL 安裝頁在安裝指令後面接了一句很重要的話：「This command installs Docker, but it doesn't start Docker. It also creates a docker group, however, it doesn't add any users to the group by default.」出處兩件事：要自己啟動，而且docker 群組已經存在、只是空的。

sudo systemctl enable --now docker   # 官方寫法：現在啟動，而且以後開機自動啟動
docker --version                     # 確認裝了哪一版

有些教學用的是 sudo service docker start 與 sudo service docker status，照著做在今天的機器上也會動——service 在有 systemd 的系統（systemd 是現在多數 Linux 用來管開機與背景服務的那一套；systemctl 就是操作它的指令）上會被轉給 systemctl。差別只在官方那行多做了一件事：enable 會讓它以後開機自動啟動，start 只管這一次。出處

最要小心的一步

docker 群組＝這台機器的 root

每打一次指令就要加 sudo 很煩，所以幾乎每份教學都會教你把自己加進 docker 群組：

sudo usermod -aG docker $USER
newgrp docker

官方「Linux post-installation steps」頁給的就是這兩行（-a 是附加、不覆蓋原有群組，-G 指定群組，$USER 是目前的使用者）。另外官方也寫「Log out and log back in so that your group membership is re-evaluated.」——newgrp docker 是不想登出時的替代做法，虛擬機使用者可能要整台重開才生效。出處

但是同一頁在這兩行旁邊掛了一則很容易被跳過的警告：

「The docker group grants root-level privileges to the user.」出處

為什麼加一個群組就等於給了系統管理員權限？因為 dockerd 本身是以 root 在跑，而任何能使喚它的人都能叫它做 root 才做得到的事。官方的安全說明頁（「Docker daemon attack surface」那一段）三句話就講完了：「This daemon requires root privileges unless you opt-in to Rootless mode」、「First of all, only trusted users should be allowed to control your Docker daemon.」、「This means that you can start a container where the /host directory is the / directory on your host; and the container can alter your host filesystem without any restriction.」出處——把整台主機的根目錄掛進容器，然後隨便改。

所以這不是一個「方便設定」，是一個權限決定：

  • 自己的練習機、拋棄式的雲端機器：加，沒問題，反正這台就是你的。
  • 多人共用的機器、正式環境：加誰進去等於發一把管理員鑰匙，要當成發帳號在管。
  • 不想給這麼大權限，官方提供另一條路：「To run Docker without root privileges, see Run the Docker daemon as a non-root user (Rootless mode).」出處——rootless 模式（白話：讓 dockerd 以一般使用者的身分跑，能碰到的東西就只有那個使用者能碰的），代價是有些功能受限。

回頭看前面那張圖就懂了：用戶端跟背景服務是分開的兩支，中間那條管道也可以走網路。所以「誰碰得到那條管道」這件事，跟「誰是這台機器的管理員」是同一個問題。

重點整理

  • Docker 是用戶端－伺服器架構：docker 負責下單，dockerd 負責做事，兩邊用 REST API 溝通，走本機的通訊檔案或網路。
  • 映像檔在前、容器在後——容器是映像檔跑起來的那一份，不是先開好再塞映像檔的空殼。
  • Linux 上那條管道預設是 /var/run/docker.sock，官方寫明要 root 權限或 docker 群組成員才碰得到。
  • 裝之前先看 /etc/os-release：Red Hat 系用 dnf、Debian 系用 apt、SUSE 系用 zypper；套件名 docker 與 docker-ce 來源不同，別混裝。
  • 官方套件裝完不會自己啟動，也不會把任何人加進 docker 群組——那兩步都要你自己決定。
  • 加進 docker 群組＝官方明說的 root 等級權限；共用或正式機器上要當成發管理員鑰匙，不想給就看 rootless 模式。
